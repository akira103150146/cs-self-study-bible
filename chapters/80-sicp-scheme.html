為什麼是 Lisp:程式即資料

1958 年,麻省理工學院的 John McCarthy 在一份影響深遠的論文裡發明了一門語言,叫做 Lisp(LISt Processing)。它的初衷是人工智慧研究——McCarthy 認為, 要讓電腦「思考」,就要讓它能方便地操作符號(symbol)和清單(list)。 但 Lisp 無意間揭示了一件讓電腦科學家興奮到睡不著的事:

在 Lisp 裡,程式碼和資料的形式完全一樣——都是括號包起來的清單。 這意味著,你可以用程式來產生、分析、甚至執行其他程式。

「程式即資料(code as data)」——這不只是一個語法技巧,而是一整套哲學:計算的本質是 符號轉換,語言本身應該是它所能表達之最優雅的形式。 這個信念後來催生了巨集(macro)、元程式設計(metaprogramming),乃至於現代的抽象語法樹操作。

1975 年,Gerald Jay Sussman 與 Guy Steele 在 MIT 設計了 Scheme—— Lisp 家族裡最小、最乾淨的方言。它去掉了 Lisp 歷史積累的複雜性, 只留下最核心的幾個規則,讓你用最少的語法理解最多的計算原理。 1985 年,Harold Abelson、Gerald Sussman 和 Julie Sussman 以 Scheme 為語言, 寫出了《計算機程式的構造與解釋(Structure and Interpretation of Computer Programs,SICP)》—— 這本書在 MIT 連續使用了二十年,被無數人列為「改變了我對程式設計看法」的那本書。

接下來五章,我們會跟著 SICP 第 1–4 章的脈絡走。這一章是入口: 先學會 Scheme 語法,再理解抽象如何一層一層疊高,直到你能用幾十行程式碼建構一個完整的語言直譯器。

📜
Lisp 1958 — 計算史上最長壽的語言

John McCarthy 在 1958 年提出 Lisp,並在 1960 年發表論文 "Recursive Functions of Symbolic Expressions and Their Computation by Machine"。 Lisp 是史上第一個採用垃圾回收(garbage collection)的語言,也是第一個讓函式成為一級值的主流語言。 Scheme(1975)、Common Lisp(1984)、Racket(1994)、Clojure(2007)都是它的後代。 六十多年後的 2024 年,Lisp 方言仍在許多領域活躍——這對一門程式語言來說幾乎是奇蹟。

🔑
本部主線:抽象的層次

SICP 的核心問題是:抽象是如何建立的?從最基本的算術運算式,到程序抽象、資料抽象,再到直譯器—— 每一層都是把複雜性「藏起來」、用更簡單的介面表達。學這一章,不只是學 Scheme 語法; 你是在學「如何用抽象管理複雜度」的思維方式。

Scheme 五分鐘:前綴記法與求值組合

Scheme 的語法幾乎沒有語法。整門語言只有一種句型:運算式(expression)。 每個運算式要麼是一個基本值(數字、字串、布林……),要麼是一個 組合(combination)——用括號包起來的清單,第一個元素是運算子,其餘是運算元: 

; 基本值:直接求值為自身
42          ; → 42
"hello"     ; → "hello"
#t          ; → true
#f          ; → false

; 組合:前綴記法 (運算子 運算元...)
(+ 1 2)            ; → 3
(* 6 7)            ; → 42
(- 100 37)         ; → 63
(/ 10 4)           ; → 5/2  (Scheme 保留精確分數!)

; 組合可以任意嵌套
(+ (* 3 5) (- 10 6))  ; → (+ 15 4) → 19
(* (+ 2 3) (- 7 1))   ; → (* 5 6) → 30

注意兩件事。第一,Scheme 的 (/ 10 4) 給出 5/2 而不是 2.5—— 它預設保留精確有理數。要得到浮點數,用 (/ 10.0 4) 或 (exact->inexact 5/2)。 第二,括號不是「分組」,括號就是「呼叫」——開括號就代表「我要呼叫一個程序」。 沒有運算子優先序、沒有結合律的歧義,一切都由括號決定。

命名與複合程序

用 (define 名稱 值) 給一個值取名字;用 (define (名稱 參數...) 主體) 定義程序: 

; 給一個值取名
(define pi 3.14159265)
(define size 2)
(* size pi)          ; → 6.2831853...

; 定義程序:square 把 x 乘以自己
(define (square x)
  (* x x))

; 定義程序:cube 把 x 乘三次(後面 sum-cubes 會用到)
(define (cube x)
  (* x x x))

(square 5)           ; → 25
(square (+ 2 3))     ; → 25  (先算 (+ 2 3) = 5,再 square)

; 複合程序:用已定義的程序建更複雜的程序
(define (sum-of-squares x y)
  (+ (square x) (square y)))

(sum-of-squares 3 4)  ; → (+ 9 16) → 25

; 進一步抽象:用 sum-of-squares 定義 f(a) = (a+1)² + (2a)²
(define (f a)
  (sum-of-squares (+ a 1) (* 2 a)))

(f 5)  ; → sum-of-squares(6, 10) → (+ 36 100) → 136

注意 (define (square x) (* x x)) 只是 (define square (lambda (x) (* x x))) 的 「語法糖(syntactic sugar)」——Scheme 把「函式定義」和「把一個 lambda 值指派給名字」合併成同一個語法。 這不是偶然:在 Scheme 裡,程序和值是同一種東西。

🔑
Scheme 的三個核心規則

1. 前綴記法:所有運算都是 (運算子 運算元...)。
2. define 兩用:給值取名、也定義程序——後者只是前者的語法糖。
3. 一切都是運算式:每個運算式有一個值;程序體的最後一個運算式就是回傳值。
記住這三條,你就讀懂了 Scheme 99% 的語法。

代換模型:程序如何「算」出答案

你剛看到 (f 5) 最後算出 136。但電腦是怎麼算的?SICP 給了一個直覺模型, 叫做代換模型(substitution model):把程序體裡所有出現形式參數(formal parameter)的地方, 用對應的實際引數(argument)替換掉,然後對得到的運算式求值。 

; 用代換模型追蹤 (sum-of-squares 3 4)

(sum-of-squares 3 4)
; 取出 sum-of-squares 的定義主體,把 x 換成 3、y 換成 4:
→ (+ (square 3) (square 4))
; 繼續展開 square:
→ (+ (* 3 3) (square 4))
→ (+ 9 (square 4))
→ (+ 9 (* 4 4))
→ (+ 9 16)
→ 25

代換模型是一個「思考工具」,不是真實的直譯器實作(真實實作用環境/幀,第 76 章會講)。 但在理解程序的行為時,它非常有用。

應用序 vs 正則序:先算誰?

上面的展開有一個選擇:什麼時候對引數求值?有兩種策略:

  • 應用序(applicative-order):先對所有引數求值,再把值代入程序體。Scheme 採用這種。
  • 正則序(normal-order):先把程序體展開(引數不求值,直接代入運算式形式),直到只剩基本運算式再求值。正則序是惰性求值(lazy evaluation)的基礎,但嚴格的惰性求值還需加上記憶化(memoization),第 76、77 章會實作。
; 以 (square (+ 2 3)) 為例:

; === 應用序(Scheme 預設) ===
(square (+ 2 3))
→ (square 5)        ; 先把引數 (+ 2 3) 算成 5
→ (* 5 5)           ; 再代入 square 的主體
→ 25

; === 正則序 ===
(square (+ 2 3))
→ (* (+ 2 3) (+ 2 3))  ; 先展開:把 x 換成運算式 (+ 2 3)
→ (* 5 5)               ; 然後再對每個運算元求值
→ 25

對這個例子,兩者結果相同。但當引數有副作用(如印出訊息)時,兩者的行為就不一樣了。 Haskell 等純函數式語言以正則序為基礎並加入記憶化,形成真正的惰性求值(lazy evaluation),讓你可以操作「無限清單」; Scheme 預設應用序,行為更可預測、效率通常也更高。

ℹ️
呼叫堆疊與代換模型

代換模型在概念上對應了你在第 3 章「函式、抽象與遞迴」學過的呼叫堆疊(call stack)—— 每一層「展開」都對應一個新的堆疊框。第 76 章我們會引入「環境模型」取代代換模型,屆時你會看到現代直譯器實際上如何用環境幀(frame)追蹤每層呼叫的名稱綁定。

條件、謂詞與牛頓法求平方根

光有算術還不夠。真正有趣的程序需要分支(branching)。Scheme 提供兩種條件式: cond(多路分支)和 if(二路分支)。 

; cond:多路條件
; 語法:(cond (謂詞1 值1) (謂詞2 值2) ... (else 預設值))
(define (abs x)
  (cond ((< x 0) (- x))   ; 如果 x < 0,回傳 -x
        ((= x 0) 0)        ; 如果 x = 0,回傳 0
        (else x)))         ; 否則回傳 x

; if:二路條件
; 語法:(if 謂詞 true分支 false分支)
(define (abs-if x)
  (if (< x 0)
      (- x)
      x))

; 謂詞可以用 and / or / not 組合
(define (between? x lo hi)
  (and (>= x lo) (<= x hi)))

(between? 5 1 10)   ; → #t
(between? 0 1 10)   ; → #f

注意 Scheme 的真/假值:#t 是真,#f 是假。 任何不是 #f 的值都被視為真——包括 0、空字串—— 這與 Python 不同。

牛頓法求平方根:抽象的第一個大例子

SICP 用平方根作為第一個「真正」的計算範例,因為它優雅地示範了迭代改進(successive approximation)。 核心想法來自古巴比倫人:若 $g$ 是 $x$ 的平方根的近似值,那 $\frac{g + x/g}{2}$ 是更好的近似值。

SICP 把這個方法拆成幾個小程序,每個只負責一件事: 

; 判斷 guess 是否已經夠好(誤差 < 0.001)
(define (good-enough? guess x)
  (< (abs (- (square guess) x)) 0.001))

; 用巴比倫法改進 guess
(define (improve guess x)
  (average guess (/ x guess)))

; average 是輔助程序
(define (average a b)
  (/ (+ a b) 2))

; 迭代:若不夠好就繼續改進
(define (sqrt-iter guess x)
  (if (good-enough? guess x)
      guess
      (sqrt-iter (improve guess x) x)))

; 對外介面:從 1.0 開始猜
(define (my-sqrt x)
  (sqrt-iter 1.0 x))

(my-sqrt 2.0)    ; → 1.4142156...
(my-sqrt 9.0)    ; → 3.00009...
(my-sqrt 100.0)  ; → 10.0000046...

注意 sqrt-iter 呼叫自己——這是遞迴(recursion)。 但這個遞迴很特別:呼叫自己是它做的最後一件事。下一節我們會看到, 這種「尾遞迴(tail recursion)」在 Scheme 裡保證不會堆疊溢位。

這裡有個值得停下來欣賞的設計:我們沒有用任何迴圈語句,卻實現了迭代改進。 「迭代」被表達為帶有更新參數的遞迴呼叫。程序結構直接對應數學上「不停精化」的概念。

ℹ️
牛頓法的數學原理

這裡用的是「巴比倫法」,也叫「牛頓-拉弗森法(Newton-Raphson method)」求 $f(x) = x^2 - n$ 的根。 更一般的牛頓法可以求任意方程式的根,本書第 55 章「數值方法」有完整介紹。 有趣的是,第 6 節的 fixed-point 程序讓我們用更高層次的抽象重新表達這個求根過程。

✏️ 練習 74.1 思考

以下程序計算 sqrt 有一個微妙的問題:對「非常小的數」(如 (my-sqrt 0.0001))和 「非常大的數」(如 (my-sqrt 1e13))結果可能不準確或不收斂。 你能分析原因嗎?SICP 習題 1.7 提示:可以用「相鄰兩次猜測的改變量佔猜測本身的比例」 來代替固定誤差閾值。請用 Scheme 寫出改進版的 good-enough?。

看解答

問題分析: 原版 good-enough? 用絕對誤差 0.001。對 x = 0.0001，square(guess) 和 x 都很小，0.001 的容忍度太大，導致過早停止。對 x = 1e13，浮點精度不足以讓差值降到 0.001，可能永遠不收斂。

解法: 改用「前後兩次猜測的相對變化量」作為終止條件:

; 改進版:觀察猜測值的相對變化
(define (good-enough? guess x)
  (define new-guess (improve guess x))
  (< (abs (- new-guess guess))
     (* guess 0.00001)))   ; 相對誤差小於 0.001%

(define (sqrt-iter guess x)
  (if (good-enough? guess x)
      guess
      (sqrt-iter (improve guess x) x)))

(my-sqrt 0.0001)  ; → 0.01000000369...  (更準確)
(my-sqrt 1e13)    ; → 3162277.660168...  (能收斂)

程序產生的處理程序:遞迴 vs 迭代

一個程序被呼叫時,電腦會執行一個處理程序(process)。不同的程序產生不同「形狀」的處理程序。 SICP 用階乘(factorial)作為第一個展示:同樣是「計算 $n!$」,可以產生截然不同的處理程序。

線性遞迴:先展開,再收縮

; 遞迴版階乘:每一步「推遲」一個乘法
(define (factorial n)
  (if (= n 1)
      1
      (* n (factorial (- n 1)))))

; 追蹤 (factorial 4) 的展開:
; (factorial 4)
; (* 4 (factorial 3))
; (* 4 (* 3 (factorial 2)))
; (* 4 (* 3 (* 2 (factorial 1))))
; (* 4 (* 3 (* 2 1)))       ; 開始收縮
; (* 4 (* 3 2))
; (* 4 6)
; 24

這個處理程序先長大、再縮小:展開時累積了一串「還沒算的乘法」(延遲操作), 到達 base case 後才一個個算回來。這叫線性遞迴處理程序(linear recursive process)—— 它需要的空間與時間都與 $n$ 成正比：$\Theta(n)$。

線性迭代:狀態在參數裡

; 迭代版階乘:用 acc 累積,不推遲任何運算
(define (factorial n)
  (fact-iter 1 1 n))

(define (fact-iter product counter max-count)
  (if (> counter max-count)
      product
      (fact-iter (* counter product)
                 (+ counter 1)
                 max-count)))

; 追蹤 (factorial 4) 的展開:
; (fact-iter 1 1 4)   ; product=1, counter=1
; (fact-iter 1 2 4)   ; product=1, counter=2
; (fact-iter 2 3 4)   ; product=2, counter=3
; (fact-iter 6 4 4)   ; product=6, counter=4
; (fact-iter 24 5 4)  ; counter > max-count,回傳 24

這個處理程序扁平往前:每一步都是完整狀態(product、counter、max-count), 沒有任何「等回來再算」。這叫線性迭代處理程序(linear iterative process)—— 時間仍是 $\Theta(n)$,但空間是 $\Theta(1)$(固定三個變數)。

關鍵點:雖然迭代版在語法上也是「程序呼叫自己」,但它是尾遞迴(tail recursion)—— 遞迴呼叫是最後一步,不留任何待計算的工作。Scheme 標準保證對尾遞迴做尾呼叫消除(TCO), 因此這個版本占用固定空間,可以安全地處理 $n = 10^6$ 甚至更大。

樹狀遞迴:費氏數列

遞迴不只有線性形狀。費氏數列(Fibonacci sequence)的直接定義產生樹狀遞迴(tree-recursive process): 

(define (fib n)
  (cond ((= n 0) 0)
        ((= n 1) 1)
        (else (+ (fib (- n 1))
                 (fib (- n 2))))))

(fib 5)   ; → 5
(fib 10)  ; → 55
(fib 30)  ; 很慢!...

計算 (fib 5) 需要分叉成兩個子問題 (fib 4) 和 (fib 3), 每個又再分叉……最終形成一棵二元樹。(fib 1) 和 (fib 0) 被計算了大量重複次數。 這個處理程序的時間複雜度是 $\Theta(\phi^n)$(其中 $\phi \approx 1.618$ 是黃金比例), 指數成長、極其昂貴。但它的程式碼直接對應數學定義,優雅至極。

迭代版的費氏則只需 $\Theta(n)$: 

; 迭代版:用兩個變數追蹤 fib(i) 和 fib(i+1)
(define (fib n)
  (fib-iter 1 0 n))

(define (fib-iter a b count)
  (if (= count 0)
      b
      (fib-iter (+ a b) a (- count 1))))
; a 追蹤 fib(k+1),b 追蹤 fib(k),count 從 n 倒數到 0

成長量級與快速求冪

SICP 用 $\Theta$ 符號(Theta notation) 描述「資源需求隨輸入規模成長的方式」。 你在第 26 章「演算法複雜度」已學過 $O$ 符號； $\Theta$ 比 $O$ 更精確,要求上界和下界同時成立(精確量級),而 $O$ 只要求上界。

一個漂亮的例子是快速求冪(fast exponentiation): 計算 $b^n$,注意 $b^n = (b^{n/2})^2$(若 $n$ 為偶數)。 

(define (fast-expt b n)
  (cond ((= n 0) 1)
        ((even? n) (square (fast-expt b (/ n 2))))
        (else (* b (fast-expt b (- n 1))))))

(fast-expt 2 10)   ; → 1024
(fast-expt 3 100)  ; 輕鬆計算 3^100!

每次 $n$ 是偶數就讓問題規模減半,因此步數是 $\Theta(\log n)$——相較於原版的 $\Theta(n)$, 計算 $2^{1000}$ 從需要 1000 步縮短到約 10 步。

🔑
區別程序(procedure)與處理程序(process)

這是 SICP 最重要的一個早期洞見:程序是靜態的文字描述,處理程序是動態的執行行為。 兩個在語法上相似的程序(都「呼叫自己」)可以產生完全不同的處理程序——線性遞迴 vs 線性迭代。 學 Scheme 的第一個技能:看到一段程序,能在腦中「演化」出它的處理程序形狀。

✏️ 練習 74.2 實作

以下程序計算一個整數清單的總和,屬於線性遞迴:

(define (sum-list lst)
  (if (null? lst)
      0
      (+ (car lst) (sum-list (cdr lst)))))

請把它改寫成線性迭代(尾遞迴)版本。提示:需要一個累積器(accumulator)參數。

看解答 
; 迭代版:用 acc 累積結果,遞迴呼叫是最後一步
(define (sum-list lst)
  (define (iter l acc)
    (if (null? l)
        acc                          ; 清單空了,回傳累積值
        (iter (cdr l) (+ acc (car l)))))  ; 把 car 加入累積,繼續
  (iter lst 0))    ; 從累積值 0 開始

; 驗證:
(sum-list '(1 2 3 4 5))  ; → 15

關鍵改變:原版的 (+ (car lst) (sum-list ...)) 在遞迴回來後「還要做加法」,所以不是尾遞迴。 改版把加法移到「進去之前」:(+ acc (car l)) 作為新的 acc 傳下去,遞迴呼叫是最後一步。

用高階程序建立抽象

SICP 第 1.3 節是整本書最具代表性的思維躍升之一。在第 1.1、1.2 節,我們用程序來抽象數值計算; 現在我們發現,「計算模式本身」也可以被抽象——用程序來描述程序。 能接收程序作為引數、或回傳程序的程序叫做高階程序(higher-order procedure)。

sum:把求和模式抽象化

看三個看似不同的程序: 

; 計算 a + (a+1) + ... + b
(define (sum-integers a b)
  (if (> a b)
      0
      (+ a (sum-integers (+ a 1) b))))

; 計算 a³ + (a+1)³ + ... + b³
(define (sum-cubes a b)
  (if (> a b)
      0
      (+ (cube a) (sum-cubes (+ a 1) b))))

; 計算 π/8 的級數近似(Leibniz 交錯級數的兩兩配對形式)
; 1/(1·3) + 1/(5·7) + 1/(9·11) + ...
(define (pi-sum a b)
  (if (> a b)
      0
      (+ (/ 1.0 (* a (+ a 2)))
         (pi-sum (+ a 4) b))))

這三個程序共享同樣的骨架:如果超過 b 就回傳 0,否則把「這項」加到「剩下的和」。 唯一不同的是「這項怎麼算」和「下一項的 a 是什麼」。我們可以把骨架抽出來: 

; 通用求和:term 計算每項,next 計算下一個 a
(define (sum term a next b)
  (if (> a b)
      0
      (+ (term a)
         (sum term (next a) next b))))

; 現在原來三個程序都是 sum 的特例:
(define (sum-integers a b)
  (sum (lambda (x) x)        ; term:x 本身
       a
       (lambda (x) (+ x 1))  ; next:加 1
       b))

(define (sum-cubes a b)
  (sum cube a (lambda (x) (+ x 1)) b))

(define (pi-sum a b)
  (sum (lambda (x) (/ 1.0 (* x (+ x 2))))
       a
       (lambda (x) (+ x 4))
       b))

; 用 pi-sum 計算 π 的近似值
(* 8 (pi-sum 1 1000))   ; → 3.139592655...

; 用 sum 計算積分(數值近似)
(define (integral f a b dx)
  (sum f
       (+ a (/ dx 2.0))
       (lambda (x) (+ x dx))
       b))

(integral (lambda (x) (* x x x)) 0 1 0.01)  ; ≈ 0.25  (精確值是 1/4)

lambda:給無名函式一個位置

上面大量出現的 lambda 是 Scheme 建立匿名程序的語法: (lambda (參數...) 主體)。它和 Python 的 lambda 是同一個概念—— 事實上 Python 就是從 Lisp 借鑒這個名字的。 

; lambda 產生一個程序值
((lambda (x y) (+ x y)) 3 4)   ; → 7  (建立後立即呼叫)

; lambda 可以指派給名字——這正是 define 的另一種形式
(define square (lambda (x) (* x x)))
; 等同於: (define (square x) (* x x))

; 使用 let 建立區域變數(let 是 lambda 的語法糖)
(define (f x)
  (let ((a (+ x 1))   ; a = x + 1
        (b (* x 2)))  ; b = x * 2
    (+ (* a a) (* b b))))
; (let ((var val) ...) body) 等同於 ((lambda (var ...) body) val ...)

fixed-point:不動點搜尋

如果一個函數 $f$ 滿足 $f(x) = x$,那麼 $x$ 就是 $f$ 的不動點(fixed point)。 許多計算問題都可以表達成「找某個函數的不動點」——包括求平方根。 我們可以寫一個通用的不動點搜尋程序: 

(define tolerance 0.00001)

(define (fixed-point f first-guess)
  (define (close-enough? v1 v2)
    (< (abs (- v1 v2)) tolerance))
  (define (try guess)
    (let ((next (f guess)))
      (if (close-enough? guess next)
          next
          (try next))))
  (try first-guess))

; 測試:cos 的不動點(cos(x) = x 的解)
(fixed-point cos 1.0)   ; → 0.7390822985...  (驗算:cos(0.739...) ≈ 0.739...)

; 用不動點求 √2:我們要找 y 使得 y = 2/y
; 直接用 (lambda (y) (/ 2 y)) 會震盪,不收斂!
; 解法:「平均阻尼(average damping)」
(define (sqrt x)
  (fixed-point (lambda (y) (average y (/ x y)))  ; 取平均,防震盪
               1.0))

(sqrt 2.0)    ; → 1.41421356...
(sqrt 9.0)    ; → 3.0
(sqrt 144.0)  ; → 12.0

注意:如果直接用 (lambda (y) (/ x y)),從 y=1 開始會得到 2, 1, 2, 1, ... 不斷震盪。加上平均阻尼後才能收斂。 這個「平均阻尼」本身也可以被抽象成高階程序(SICP 1.3.4 節),讓你組合各種數值方法。

ℹ️
高階程序與函數式程式設計

你在第 6 章「函數式程式設計」學過的 map、filter、reduce 都是高階函式的例子。 SICP 的 sum、fixed-point 展示了一個更深的洞見: 高階程序不只是「方便的工具」,而是一種建立語言層次(language levels)的方式—— 每次你把一個計算模式抽象成高階程序,你就在為自己的問題域建立一個更豐富的「詞彙表」。

✏️ 練習 74.3 實作

用 sum 高階程序計算 $1^2 + 2^2 + 3^2 + \cdots + n^2$。 答案應等於 $\frac{n(n+1)(2n+1)}{6}$。

看解答 
; 使用 sum 高階程序:term = x², next = x + 1
(define (sum-of-squares-to n)
  (sum (lambda (x) (* x x))
       1
       (lambda (x) (+ x 1))
       n))

; 驗算:
(sum-of-squares-to 10)   ; → 385
; 公式驗算: 10 * 11 * 21 / 6 = 385  ✓

(sum-of-squares-to 100)  ; → 338350
; 公式驗算: 100 * 101 * 201 / 6 = 338350  ✓
✏️ 練習 74.4 挑戰

SICP 1.3.3 節提到:平均阻尼(average damping)可以被抽象成高階程序。 請寫出 average-damp——它接收一個程序 f, 回傳一個「把 f(x) 和 x 取平均」的新程序。 然後用 average-damp 重新實作 sqrt 和 cube-root($\sqrt[3]{x}$)。

看解答 
; average-damp:回傳一個「平均阻尼版」的程序
(define (average-damp f)
  (lambda (x) (average x (f x))))

; 驗算 average-damp:
((average-damp square) 10)   ; → (average 10 100) → 55

; sqrt via fixed-point + average-damp
(define (sqrt x)
  (fixed-point (average-damp (lambda (y) (/ x y)))
               1.0))

(sqrt 4.0)   ; → 2.0
(sqrt 25.0)  ; → 5.0

; cube-root via fixed-point + average-damp
; 立方根 y 滿足 y = x / y²
(define (cube-root x)
  (fixed-point (average-damp (lambda (y) (/ x (* y y))))
               1.0))

(cube-root 8.0)    ; → 2.0
(cube-root 27.0)   ; → 3.0
(cube-root 125.0)  ; → 5.0

注意 average-damp 回傳的是一個 lambda——它是一個「回傳程序的程序」,這正是高階程序的威力:把「阻尼」本身抽象成一個可組合的模組。

Python 對照:同樣的抽象,不同的外衣

Scheme 和 Python 在思想上高度相通——畢竟 Python 大量借鑒了 Lisp 的概念。 把同樣的抽象用 Python 表達,有助於把 Scheme 的思維遷移到你更熟悉的語言。

sum 高階函式的 Python 版

# Scheme 的 sum → Python 版本
def sum_(term, a, next_, b):
    """把 term(a) + term(next_(a)) + ... + term(b) 加總"""
    if a > b:
        return 0
    return term(a) + sum_(term, next_(a), next_, b)

# sum_integers
sum_(lambda x: x, 1, lambda x: x + 1, 100)   # → 5050

# sum_cubes
sum_(lambda x: x**3, 1, lambda x: x + 1, 10)  # → 3025

# pi-sum:π/8 的級數近似(Leibniz 交錯級數的兩兩配對形式)
pi_approx = 8 * sum_(
    lambda x: 1.0 / (x * (x + 2)),
    1,
    lambda x: x + 4,
    1001
)
print(f"π ≈ {pi_approx:.6f}")   # π ≈ 3.139593

fixed-point 的 Python 版

def fixed_point(f, first_guess, tolerance=1e-5):
    """不動點搜尋:反覆套用 f 直到收斂"""
    def try_(guess):
        nxt = f(guess)
        if abs(nxt - guess) < tolerance:
            return nxt
        return try_(nxt)
    return try_(first_guess)

# cos 的不動點
import math
fixed_point(math.cos, 1.0)        # → 0.7390855...

# 用平均阻尼求 sqrt
def average_damp(f):
    return lambda x: (x + f(x)) / 2

def sqrt(x):
    return fixed_point(average_damp(lambda y: x / y), 1.0)

print(sqrt(2.0))    # → 1.4142135...
print(sqrt(144.0))  # → 12.0

語言差異小結

Python 和 Scheme 在高階函式上幾乎一一對應,但有幾個值得注意的差異:

  • 尾呼叫消除:Scheme 保證 TCO,Python 不保證(預設遞迴深度 ~1000)。上面的 fixed_point 在 Python 若要迭代千次以上需改成迴圈。
  • 精確算術:Scheme 的 (/ 1 3) 給 1/3(精確分數);Python 的 1/3 給 0.333...(浮點)。
  • 語法量:Python 的 lambda 只能是單一運算式;Scheme 的 lambda 可以有完整的多行主體。需要複雜邏輯時,Python 要先定義 def 再傳入。
  • 括號的意義:Scheme 的括號是「呼叫」;Python 的括號在不同語境有不同意義(元組、呼叫、分組)。
✏️ 練習 74.5 挑戰

快速冪的迭代版: 上面的 fast-expt 是線性遞迴版本(空間 $\Theta(\log n)$)。 請設計一個線性迭代版的快速冪,空間為 $\Theta(1)$。 提示:維護一個不變量(invariant): a * b^n 在整個計算過程中保持不變。 初始 a=1、b=base、n=exp;終止條件 n=0 時回傳 a。

看解答 
; 迭代版快速冪
; 不變量: a * b^n 在每步都相等
(define (fast-expt b n)
  (expt-iter 1 b n))

(define (expt-iter a b n)
  (cond ((= n 0) a)                    ; a * b^0 = a * 1 = a
        ((even? n)
         (expt-iter a (square b) (/ n 2)))   ; a * (b^2)^(n/2) = a * b^n
        (else
         (expt-iter (* a b) b (- n 1)))))    ; (a*b) * b^(n-1) = a * b^n

; 驗算:
(fast-expt 2 10)    ; → 1024
(fast-expt 3 20)    ; → 3486784401
(fast-expt 2 1000)  ; 大數也沒問題!

關鍵洞見:a * b^n 是不變量。偶數步把問題減半(改用 b^2 和 n/2,a 不變);奇數步把一個 b 「吸收」進 a(a *= b、n -= 1)。

把這一章串起來

你剛走過了 SICP 第一章的核心,這一章建立了整個「第十九部 · SICP」的地基。讓我們把主線整理清楚:

  • Scheme 語法:前綴記法、define、lambda—— 三條規則統治整門語言。這個極簡的語法不是偶然,而是刻意讓「語言的形式 = 語言能表達之最小形式」。
  • 代換模型:程序是文字描述;代換模型把它變成計算過程的執行。 應用序(Scheme 預設)先求值引數,正則序先展開再求值——理解這個差別有助於讀懂惰性語言。
  • 條件與牛頓法:cond/if 加上遞迴呼叫,就足以表達任何「迭代改進」算法。 不需要迴圈語句;遞迴就是迭代。
  • 處理程序的形狀:線性遞迴($\Theta(n)$ 空間)、線性迭代($\Theta(1)$ 空間)、樹狀遞迴($\Theta(\phi^n)$ 時間)。 同樣是「遞迴」,產生的處理程序形狀天差地別。尾遞迴是讓 Scheme 把遞迴當迴圈用的關鍵技術。
  • 高階程序:sum、fixed-point、average-damp—— 把「計算模式」本身抽象成程序。這一步讓抽象從「值的命名」提升到「行為的命名」,是整部 SICP 最重要的思維躍升。
