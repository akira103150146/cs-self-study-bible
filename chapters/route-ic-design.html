本路線的主線專題

這條路線的 Lab 串成 3 條主線專題(另外 2 條主線在別的路線,這裡也會用到)。一條主線是一份會長大的程式碼:前面 Lab 做好的零件,後面的 Lab 和專題直接拿來用。每條主線先定下最後的 Boss 戰,再拆成零件;每個零件的任務目標(含效能門檻)都說得出是哪一個 Boss 需要它。

🗺️
主線專題和地下城的對照

主線專題＝任務線;每個零件＝一個任務(有自己的資料夾);每組測試＝一個任務目標(打勾的格子);最後的整合測試＝Boss 戰。

〔公開〕的任務目標用 test(或 F5)自己跑;〔隱藏檢定〕在 submit 時才跑,只看得到名稱和一行說明;〔老師核可〕由老師人工看。零件過關之後,後面的專題一律用你自己的版本,規則見零件庫規則。

I1 自己的 RV32I CPU

任務線 rtl · 程度:大學
技能樹專題(依序是檢查點):🏆 8-bit ALU(Verilog)與 testbench、🏆 IC 畢業專題:自己的 RV32I CPU(Verilog)跑 C 程式

用 Verilog 把 Hack 的多工器與加法器重寫成可以調寬度的版本,組成 RV32I 的 ALU,再用 cocotb 寫自己的測試去抓突變版;最後做出單週期 RV32I CPU,參考模型是 rv32 任務線的指令集模擬器。

判題 runner 是新的 verilog-cocotb(Icarus Verilog 11＋cocotb 1.9.2,見 data/README 待決事項 12–15)。效能數字是 book-hwtools 映像在 i7-12700KF 上實測的 CPU 秒(user),含編譯與 cocotb 啟動(每次約 2.8 秒)。Verilog 任務不 consumes Hack 的 .hdl:觀念接 hack/gates、hack/alu(Mux16、Add16、ALU),但判題不會用到你的 Hack 晶片。檢查點 2(proj-ic-riscv)的 regfile、decode、cpu 還是 outline,它們的書(G36)還沒寫。

Boss 戰(最後專題的驗收):

檢查點 1:🏆 8-bit ALU(Verilog)與 testbench

  • ⚔️ ALU 窮舉〔隱藏檢定〕用你現在的 rtl/*.v 重跑閘與 ALU 兩個任務的全部隱藏檢定:Icarus 隱藏 testbench 把 8 位元版(W=8)的所有輸入與運算碼窮舉一遍,32 位元版用 cocotb 隨機向量對 Python 參考模型;每一層都要用你自己的 adder 與 full_adder。(效能:閘與 ALU 的全部隱藏檢定(含每次編譯)60 秒內)用到:任務「Verilog 閘與加法器」、任務「RV32I ALU」
  • ⚔️ ALU 與突變〔隱藏檢定〕你的 rtl/tests/test_alu.py 在參考 ALU 上全過,而且 3 個隱藏突變版每個都至少一項失敗(讀 cocotb 的 results.xml)。(效能:你的測試跑 4 個 ALU 版本(參考版＋3 個突變版),合計 60 秒內)用到:任務「cocotb 測試」

檢查點 2:🏆 IC 畢業專題:自己的 RV32I CPU(Verilog)跑 C 程式

  • ⚔️ RV32I 測試〔隱藏檢定〕rv32ui 測試＋一支 C 程式(排序＋CRC)經 MMIO 印字,對 rv32 指令集模擬器的輸出。用到:任務「單週期 CPU」

  1. 任務「Verilog 閘與加法器」(L1) rtl/gates · ~/零件庫/mux…adder.v(3)

    之後會用在:任務「RV32I ALU」、任務「單週期 CPU」
    • ☐ 多工器〔公開〕mux2、mux4(W=16)的公開向量:每個 sel 值都試,y 對參考模型。(← Boss「ALU 窮舉」、Boss「RV32I 測試」)
    • ☐ 加法器〔公開〕full_adder 的 8 列真值表;adder(W=16)的公開向量:sum、cout、ovf,含 cin=1。(← Boss「ALU 窮舉」、任務「RV32I ALU」的任務目標「十種運算」)
    • ☐ 窮舉〔隱藏檢定〕mux4 在 W=4 時 a、b、c、d、sel 的全部組合;adder 在 W=8 時 a、b、cin 的全部組合;W=1 的 adder。(← Boss「ALU 窮舉」、任務「RV32I ALU」的任務目標「8 位元窮舉」)
    • ☐ 寬的版本〔隱藏檢定〕W=16、32 的邊界值(0、1、全 1、只有最高位、交替位元)與每人 seed 決定的隨機向量;ovf 的四種情況(正＋正、負＋負、異號、剛好不溢位)。(← Boss「ALU 窮舉」、任務「RV32I ALU」的任務目標「32 位元隨機」)

    • ☐ 模擬時間〔隱藏檢定〕漣波進位在事件驅動的模擬器裡一級一級傳,電路不能大到讓上層的 ALU 測不完。(效能:W=4 mux4 窮舉 262,144 組＋W=8 adder 窮舉 131,072 組 2 秒內;W=32 adder 104 組隨機向量 3 秒內 ← 來自 Boss「ALU 窮舉」、任務「RV32I ALU」的任務目標「模擬時間」)
  2. 任務「RV32I ALU」(L2) rtl/alu · ~/零件庫/rtl/alu.v
    在第 50 章 Verilog:用文字描述硬體的 Lab
    先做:任務「Verilog 閘與加法器」
    之後會用在:任務「cocotb 測試」、任務「單週期 CPU」
    • ☐ 十種運算〔公開〕test 跑公開的 cocotb 測試:W=32 時 10 種運算各幾組向量,y 與 zero 對 alu_model.py。(← Boss「ALU 窮舉」)
    • ☐ 移位〔隱藏檢定〕移位量 0、1、W-1;b 的高位元有值(只看低 $clog2(W) 位元);sra 對負數補 1、srl 補 0。(← Boss「ALU 窮舉」、Boss「RV32I 測試」)
    • ☐ 有號與無號比較〔隱藏檢定〕slt 與 sltu:最小負數對 1、-1 對 0、相等、只差最高位元;a - b 溢位時 slt 也要對;結果只能是 0 或 1。(← Boss「ALU 窮舉」、Boss「RV32I 測試」)
    • ☐ 未定義的運算碼〔隱藏檢定〕6 個未定義的 op 一律 y = 0、zero = 1。(← Boss「ALU 窮舉」)
    • ☐ 8 位元窮舉〔隱藏檢定〕W=8:a、b 的 65,536 種組合 × 16 個 op,y 與 zero 全部對參考模型(Icarus 隱藏 testbench)。(← Boss「ALU 窮舉」)
    • ☐ 32 位元隨機〔隱藏檢定〕W=32 與 W=16:邊界值(0、1、-1、最大正數、最小負數、交替位元)＋每人 seed 決定的隨機向量,cocotb 對 Python 參考模型。(← Boss「ALU 窮舉」、Boss「RV32I 測試」)
    • ☐ 用自己的加法器〔隱藏檢定〕把 adder 換成故意弄壞的版本,add 與 sub 的結果都要跟著錯(證明加減法真的經過你的 adder)。(← Boss「ALU 窮舉」)
    • ☐ 模擬時間〔隱藏檢定〕ALU 是純組合電路,每組向量都要很快算完;檢查點 2 的 CPU 每個時脈週期都會用到它。(效能:W=8 窮舉 1,048,576 組向量(Icarus testbench)6 秒內;W=32 cocotb 隨機 4,000 組(含編譯與啟動)15 秒內 ← 來自 Boss「ALU 窮舉」、Boss「RV32I 測試」)
