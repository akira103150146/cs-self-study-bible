一則訊息值多少資訊？驚奇度與位元

假設你同時收到兩條新聞推播：

「太陽今天從東方升起。」
「台北101昨夜無預警倒塌。」

兩條都是「訊息」，但直覺告訴你第二條遠比第一條「有資訊量」。為什麼？ 因為第一條幾乎是確定的，它幾乎沒有告訴你任何新東西； 第二條極度出乎意料，收到的那一刻你的世界觀就被更新了一大塊。

1948 年，貝爾實驗室的 Claude Shannon 把這個直覺數學化。他定義一個事件 $x$ 的 驚奇度(surprisal)，又稱自資訊(self-information)，為：

$$I(x) = \log_2 \frac{1}{P(x)} = -\log_2 P(x) \quad \text{(位元)}$$

這個公式有三個美麗的性質：

  • $P(x) = 1$（確定事件）$\Rightarrow I(x) = 0$：確定的事沒有資訊量。
  • $P(x)$ 越小，$I(x)$ 越大：越罕見的事件，攜帶越多資訊。
  • 兩個獨立事件的驚奇度可相加：$I(x_1 x_2) = I(x_1) + I(x_2)$（源自對數的加法性質）。

為什麼用 $\log_2$？因為我們用「位元(bit)」計量——需要幾個是/否問題才能確定這件事。 一枚公平硬幣落正面的機率是 $1/2$，驚奇度 $= \log_2 2 = 1$ 位元； 擲一顆公平六面骰出現 6 點的機率是 $1/6$，驚奇度 $= \log_2 6 \approx 2.58$ 位元。

🔑
資訊量 = 驚奇度 = 需要幾個位元才能「傳達這件事」

$I(x) = -\log_2 P(x)$ 位元。確定的事 0 位元；機率 $1/2$ 的事 1 位元；機率 $1/1{,}000{,}000$ 的事約 20 位元。

夏農熵：衡量平均不確定性的量尺

單一事件的驚奇度很有用，但在壓縮或通訊裡，我們更在乎的是： 平均而言，從一個來源(source)取出一個符號，需要幾個位元？ 這就是夏農熵(Shannon entropy) $H(X)$ 的出發點。

如果來源 $X$ 有 $n$ 個符號，對應機率 $\{p_1, \dots, p_n\}$， 則驚奇度的期望值是：

$$H(X) = \mathbb{E}[I(X)] = -\sum_{i=1}^{n} p_i \log_2 p_i \quad \text{(位元/符號)}$$

慣例：$0 \cdot \log_2 0 \stackrel{\text{def}}{=} 0$（取極限 $p \to 0^+$ 可驗證）。

💡
熵的極值

最大值：所有 $n$ 個符號等機率 $p_i = 1/n$ 時，$H = \log_2 n$ 位元——完全均勻、最不可預測。
最小值 0：只有一個符號的機率為 1，其餘為 0——完全確定，不需要任何位元。

最能感受熵的場景是二元來源(binary source)：只有 0 和 1， 出現 1 的機率是 $p$，出現 0 的機率是 $1-p$。 此時熵就是二元熵函數(binary entropy function)：

$$H(p) = -p\log_2 p - (1-p)\log_2(1-p)$$

來感受一下熵的含義。英文文本的 26 個字母有不同頻率（'e' 約 12.7%，'z' 約 0.07%……）， 代入熵公式得到約 4.1 位元/字母。 然而 ASCII 用 8 位元存每個字母——表示英文文本至少有一半是「多餘的」，可以壓掉！ 

import math

def entropy(probs):
    """計算離散分佈的夏農熵（位元/符號）。"""
    return -sum(p * math.log2(p) for p in probs if p > 0)

# 公平硬幣：熵最大
print(f"公平硬幣熵    = {entropy([0.5, 0.5]):.4f} bits")    # 1.0000

# 偏硬幣（正面 90%）：熵低
print(f"偏硬幣熵      = {entropy([0.9, 0.1]):.4f} bits")    # 0.4690

# 四個等機率符號
print(f"四符號均勻熵  = {entropy([0.25]*4):.4f} bits")      # 2.0000

# 不均勻四符號（注意可壓縮性）
probs = [0.5, 0.25, 0.125, 0.125]
print(f"不均勻四符號熵= {entropy(probs):.4f} bits")         # 1.7500

最後那個例子很有啟發性：四個符號理論上需要 $\log_2 4 = 2$ 位元， 但因為分佈不均，實際熵只有 1.75 位元——這 0.25 位元的差距就是「可以壓縮的空間」。

💡
為什麼要學

熵是任務線「hzip 壓縮器」的量尺。任務「頻率與估計」（第 14 章的 Lab）要你寫 FreqTable.entropy()； 本章的任務「Huffman 編碼」用它檢查你的碼長：平均碼長 $L$ 一定要落在 $H \le L < H+1$。Boss 戰「機率期末：理論對實測」也用同一條不等式判分。 熵告訴你「這份資料最少要幾個位元」，你的壓縮器離它多遠，測試會量給你看。

⚠️
看起來對但其實錯：「單一字母的熵就是壓縮的極限」

把 "ab" 重複 500 次（1000 個字元）。a、b 各佔一半，單一字母的熵是 1 位元／字母， 所以「一個字母配一個碼」的方法（Huffman）最少要 1000 位元＝125 個位元組。 但這份資料完全可以預測。用本章 Lab 的 LZ77 規則（視窗 4096、預視 255，每個三元組存成 4 個位元組），只要 6 個三元組 (0,0,a) (0,0,b) (2,255,b) (2,255,b) (2,255,b) (2,229,b)，共 24 個位元組。

錯在哪裡：$-\sum p_i \log_2 p_i$ 是「每個符號彼此獨立」時的下限。真實資料前後相關（英文的 q 後面幾乎都是 u）， 把前文算進去，Shannon 在 1951 年估計英文每個字母只要約 0.6 到 1.3 位元。前面的「4.1 位元／字母」只對「字母互相獨立」的模型成立。 例子都對 ≠ 敘述為真：一定要先問「這個下限是對哪一種模型說的」。

源編碼定理：壓縮的理論下限

熵不只是一個數字，它告訴你一個根本事實。Shannon 在 1948 年的論文中證明了：

🔑
夏農源編碼定理(Source Coding Theorem)

設來源 $X$ 的熵為 $H(X)$ 位元/符號。則：
(1) 存在一個無損壓縮碼，使平均每符號的碼長任意接近 $H(X)$。
(2) 任何無損壓縮碼的平均碼長都不能低於 $H(X)$。

這是一個「存在性 + 下界」定理：它告訴你壓縮的理論極限在哪，但不告訴你怎麼建出最好的碼。 建出最好的碼，是 Huffman、算術編碼等演算法在做的事。

為什麼說「任意接近」而非「等於」？原因很微妙： 如果每個符號必須對應整數個位元，就沒辦法剛好達到熵（除非熵本身是整數）。 算術編碼突破這個限制，做到「非整數碼長」，從而真正逼近熵。

前綴碼與 Kraft 不等式

壓縮需要把每個符號對應到一個位元串，讓接收端能無歧義地還原原始序列。 最自然的方法是前綴碼(prefix-free code)，又稱即時碼(instantaneous code)： 沒有任何碼字是另一個碼字的前綴。

為什麼前綴碼能無歧義解碼？因為你從頭讀位元流，一旦讀到的位元串等於某個碼字， 就可以立刻輸出那個符號——不需要「等待」未來的位元確認邊界。 這就是「即時(instantaneous)」的含義，也是 Huffman 樹上「從根走到葉就確定符號」的原因。

前綴碼的存在有一個優雅的充要條件——Kraft 不等式(Kraft inequality)： 設 $n$ 個符號的碼長分別為 $\ell_1, \dots, \ell_n$（位元），則

$$\sum_{i=1}^{n} 2^{-\ell_i} \leq 1$$

等式成立時，稱為完整碼(complete code)——二元樹的每一片葉子都被用到， 沒有任何「浪費的分支」。最佳無損碼恰好滿足 Kraft 等式。

💡
Kraft 不等式的幾何直覺

想像一棵完全二元樹，根節點的「份額」是 1。每往下一層，左右各拿父節點一半份額。 一個碼長為 $\ell$ 的符號佔了 $2^{-\ell}$ 份額。Kraft 不等式說： 所有葉子佔的份額加起來不超過 1——你不能讓碼字互相搶佔空間。

以分佈 $\{0.5, 0.25, 0.125, 0.125\}$ 驗證：

Kraft 等於 1，是完整前綴碼。平均碼長 $L = 0.5\times1 + 0.25\times2 + 0.125\times3 + 0.125\times3 = 1.75$ 位元， 恰好等於熵 1.75 位元——這正是 Huffman 演算法對此分佈產生的最佳碼。

證明(參考):Kraft 不等式與前綴碼的檢查

💡
為什麼要學

任務「Huffman 編碼」的 kraft_sum 要用分數精確算出 $\sum 2^{-\ell_i}$；canonical_codes 碰到和大於 1 的碼長表要丟 ValueError。 任務「檔案格式與命令列」解壓時，碼長表是從檔案讀進來的，可能被改壞（隱藏檢定「CRC 對但內容壞」會故意塞一張超額的碼長表）。 Kraft 不等式就是那一行檢查：和大於 1，這張表配不出前綴碼，檔案一定是壞的。

證明(參考)。（前綴碼 ⇒ 不等式）設最長的碼長是 $\ell_{\max}$。看所有長度剛好 $\ell_{\max}$ 的位元串，一共 $2^{\ell_{\max}}$ 個。 長度 $\ell_i$ 的碼字是其中 $2^{\ell_{\max}-\ell_i}$ 個位元串的開頭（後面的 $\ell_{\max}-\ell_i$ 位隨便填）。 前綴碼裡沒有一個碼字是另一個的開頭，所以不同碼字「蓋住」的位元串互不重疊，加起來不超過全部： $\sum_i 2^{\ell_{\max}-\ell_i} \le 2^{\ell_{\max}}$。兩邊除以 $2^{\ell_{\max}}$ 就是 Kraft 不等式。

（不等式 ⇒ 前綴碼）反過來，碼長滿足 Kraft 不等式時，一定配得出前綴碼：把碼長由短到長排好，一個接一個連續配碼。 這正是本章後面「手算:canonical 碼」的做法，每配一個長度 $\ell$ 的碼字就用掉 $2^{-\ell}$ 的份額，和不超過 1 就不會用完。

證明的程式版本有兩個檢查：碼長的 Kraft 和（用 Fraction，不會有浮點誤差），和「一組碼字是不是前綴碼」。 後者有個省時的寫法：把碼字照字典順序排好，以 a 開頭的字串一定緊接在 a 後面，所以只要比相鄰的兩個。 

from fractions import Fraction

def kraft(lengths):
    """Σ 2^-ℓ,用分數精確計算(浮點數加很多個 2^-40 會有誤差)。"""
    return sum(Fraction(1, 2 ** l) for l in lengths)

def is_prefix_free(words):
    """排序後只比相鄰的兩個:以 a 開頭的字串,排序後一定緊接在 a 後面。"""
    words = sorted(words)
    return all(not b.startswith(a) for a, b in zip(words, words[1:]))

print(kraft([1, 2, 3, 3]), is_prefix_free(['0', '10', '110', '111']))   # 1 True
print(kraft([1, 2, 2]), is_prefix_free(['0', '01', '11']))              # 1 False
print(kraft([1, 2, 2, 3]))                                              # 9/8

第二行很重要：碼長 1、2、2 的 Kraft 和剛好是 1，但 {0, 01, 11} 不是前綴碼。 Kraft 不等式說的是「存在一組這種碼長的前綴碼」，不是「每一組這種碼長的碼都是前綴碼」。 第三行的和是 9/8，大於 1，任何人都配不出碼長 1、2、2、3 的前綴碼。

熵編碼：從 Huffman 到算術編碼

Huffman 編碼（連回第 30 章）

在第 30 章（貪婪演算法），我們詳細介紹了霍夫曼(Huffman)編碼的建樹演算法、 貪婪選擇性質與正確性證明。這裡只快速回顧結論：

  • Huffman 演算法每次從優先佇列取出兩個最小頻率的節點合併，$O(n \log n)$ 建出最佳前綴碼樹。
  • 在「每符號必須整數個位元」的前提下，保證平均碼長最小。
  • Huffman 的平均碼長 $L$ 滿足 $H(X) \leq L < H(X) + 1$ 位元/符號。

那最多差 1 位元的「缺口」，是每符號必須取整數位元所帶來的代價。 對 $k$ 個符號組成的「區塊」一次編碼，差距縮小到 $1/k$ 位元/符號； 但 $k$ 變大時需要 $n^k$ 個碼字，實用上代價極高——於是有了算術編碼。

手算:Huffman 建樹與優先佇列的狀態

用 "ABRACADABRA" 的次數 A:5、B:2、C:1、D:1、R:2 建樹。每一步從優先佇列取出最小的兩個節點，合併後放回。 同次數時要有固定的規則，這裡用「(次數, 建立順序)」排：葉子照符號順序 A、B、C、D、R 建立（編號 0–4），合併出來的新節點接著編號 5、6、7……。 「累計」欄是到目前為止所有合併的次數和：每合併一次，子樹裡每個符號的碼都多 1 位元，所以最後的累計就是編碼後的總位元數。

同次數的取法會改變碼長，但不會改變總位元數。如果第 2 步改成取 B:2 和 (CD):2（例如新節點排在同次數的葉子前面）， 碼長變成 A:1、R:2、B:3、C:4、D:4，總位元數 $5 + 4 + 6 + 4 + 4 = 23$，還是 23。兩組碼長的 Kraft 和都剛好是 1。 所以任務「Huffman 編碼」的公開測試「總位元數最少」只比 $\sum$ 次數 × 碼長，不比每個符號的碼長。

四個符號全是 2 位元，a 也是。1 位元的碼會用掉一半的碼空間（Kraft 份額 $\frac12$）， 可是 a 只佔 30%：把它和 c 合併，比讓它單獨佔一半更省。前面 ABRACADABRA 的 A 佔 5/11，夠重，才拿到 1 位元。 例子都對 ≠ 敘述為真：只看幾個「最常見的字母拿到最短的碼」的例子，會以為「最短」就是「1 位元」。

手算:canonical 碼，只靠碼長配出碼字

建樹得到的是碼長。如果解壓的一方也要知道每個碼字，最省的做法是只存碼長，兩邊用同一條規則把碼字配出來， 這叫 canonical Huffman 碼（DEFLATE 就是這樣做，見 RFC 1951 §3.2.2）。規則：

  1. 依 (碼長, 符號) 排序。
  2. 第一個符號的碼是 0（寫成它的碼長那麼多位）。
  3. 之後每一個：先把碼加 1；如果碼長比上一個長，再左移「長了幾位」位。

用手算 Huffman 得到的碼長 A:1、B:3、C:3、D:3、R:3：

把 ABRACADABRA 逐字換成碼字：0 100 111 0 101 0 110 0 100 111 0，共 23 位元。 從高位往低位填進位元組，最後一個位元組不滿 8 位就補 0： 01001110 10101100 10011100（最後一個 0 是補的）→ 4E AC 9C（3 個位元組）。

證明(參考):平均碼長夾在 H 和 H+1 之間

💡
為什麼要學

任務「Huffman 編碼」的隱藏檢定「對得上熵」，和 Boss 戰「機率期末：理論對實測」，都拿隱藏的隨機分布檢查 $H \le L < H+1$， 其中 $H$ 用你自己的 FreqTable.entropy() 算。這兩條不等式是源編碼定理落到整數碼長時的樣子；下面的程式版本就是測試在做的事。

記號：符號 $i$ 的機率 $p_i$、碼長 $\ell_i$，平均碼長 $L = \sum_i p_i \ell_i$，熵 $H = -\sum_i p_i \log_2 p_i$。

證明(參考)：$L < H+1$。取 Shannon 碼長 $\ell_i = \lceil -\log_2 p_i \rceil$。因為 $\ell_i \ge -\log_2 p_i$， $2^{-\ell_i} \le p_i$，所以 $\sum_i 2^{-\ell_i} \le \sum_i p_i = 1$：這組碼長滿足 Kraft 不等式，配得出前綴碼。 它的平均碼長 $\sum_i p_i \lceil -\log_2 p_i \rceil < \sum_i p_i (-\log_2 p_i + 1) = H + 1$。 Huffman 碼是最佳的，平均碼長不會比這組長，所以 $L_{\text{Huffman}} < H + 1$。

以 ABRACADABRA 為例：Shannon 碼長是 A:2、B:3、C:4、D:4、R:3，Kraft 和 $\frac58$，平均 $\frac{30}{11} \approx 2.727$； $H \approx 2.0404$，$H+1 \approx 3.0404$。Huffman 的 $L = \frac{23}{11} \approx 2.0909$，夾在 $H$ 和 $H+1$ 中間。

★深入(選讀)：$H \le L$。 $L - H = \sum_i p_i\left(\ell_i + \log_2 p_i\right) = -\sum_i p_i \log_2 \frac{2^{-\ell_i}}{p_i}$。 $\log_2$ 是凹函數，由 Jensen 不等式，$\sum_i p_i \log_2 \frac{2^{-\ell_i}}{p_i} \le \log_2 \sum_i 2^{-\ell_i} \le \log_2 1 = 0$（最後一步用 Kraft）。 所以 $L - H \ge 0$，等號成立剛好在每個 $p_i = 2^{-\ell_i}$ 時（例如前面的 $\{0.5, 0.25, 0.125, 0.125\}$）。 延伸閱讀：Cover & Thomas《Elements of Information Theory》講 Data Compression 的那一章。

程式版本：不需要知道證明，只檢查結論。前半段用上面手算 Huffman 的兩組碼長；後半段用證明裡的 Shannon 碼長在 1000 個隨機分布上試 （不是證明，是建立直覺，也是任務的隱藏檢定在做的事）。 

import math
import random
from fractions import Fraction

def entropy_of_counts(counts):
    n = sum(counts.values())
    return -sum(c / n * math.log2(c / n) for c in counts.values())

def avg_length(counts, lengths):
    n = sum(counts.values())
    return sum(counts[s] * lengths[s] for s in counts) / n

def kraft(lengths):
    return sum(Fraction(1, 2 ** l) for l in lengths.values())

# 手算 Huffman 的兩組碼長(同次數的取法不同),都是最佳的
counts = {'A': 5, 'B': 2, 'C': 1, 'D': 1, 'R': 2}
for lengths in [{'A': 1, 'B': 3, 'C': 3, 'D': 3, 'R': 3},
                {'A': 1, 'R': 2, 'B': 3, 'C': 4, 'D': 4}]:
    H, L = entropy_of_counts(counts), avg_length(counts, lengths)
    assert kraft(lengths) == 1          # Huffman 樹是滿二元樹 → Kraft 等式
    assert H <= L < H + 1               # 源編碼的上下界
    print(f"H = {H:.4f}  L = {L:.4f}  Kraft = {kraft(lengths)}")

# 證明裡的 Shannon 碼長 ⌈-log2 p⌉:Kraft ≤ 1,而且 H ≤ L < H+1
rng = random.Random(108)
for _ in range(1000):

    counts = {s: rng.randint(1, 1000) for s in range(k)}
    n = sum(counts.values())
    lengths = {s: math.ceil(-math.log2(c / n)) for s, c in counts.items()}
    H, L = entropy_of_counts(counts), avg_length(counts, lengths)
    assert kraft(lengths) <= 1
    assert H <= L < H + 1

算術編碼(Arithmetic Coding)

算術編碼的核心想法是：與其為每個符號分配整數長度的碼字， 不如把整個訊息序列對應到 $[0, 1)$ 區間上的一個實數—— 而表示這個實數需要的位元數，就恰好逼近整個序列的熵。

以分佈 $P(\text{A})=0.5,\ P(\text{B})=0.25,\ P(\text{C})=0.25$ 為例，編碼序列 "ABA"：

  1. 初始：整個 $[0,1)$ 是「目前的可能範圍」。
  2. 讀到 A（佔前 50%）：範圍縮到 $[0,\ 0.5)$。
  3. 讀到 B（在 $[0,0.5)$ 裡，B 佔 50%～75% 這一段）：縮到 $[0.25,\ 0.375)$。
  4. 讀到 A（在 $[0.25,0.375)$ 裡，A 佔前 50%）：縮到 $[0.25,\ 0.3125)$。
  5. 輸出區間內任何點的二進位表示，例如 $0.25 = 0.01_2$，至少需要 2 個位元（實際需加入序列終止符或長度資訊才能唯一解碼）。

區間越小，需要越多位元精確表示——這正對應「序列的熵」。 算術編碼可以達到任意接近熵的壓縮率，是理論最優的無損編碼族。 現代高效壓縮工具（zstd 的 ANS、HEVC/AV1 的 CABAC）都屬於算術編碼的變體。

ℹ️
ANS：現代算術編碼的繼承者

Asymmetric Numeral Systems（ANS）是 2009 年 Jarek Duda 提出的算術編碼變體， 用位移和查表取代乘除法，速度比傳統算術編碼快 10 倍以上。 你平常的 .zst 檔案（zstd）和 Apple 的 LZFSE 背後都有 ANS。

字典式壓縮：LZ77、LZ78 與 LZW

熵編碼的前提是「已知符號機率」——你需要事先統計或傳遞頻率表。 但如果資料是動態的，或重複出現的不是符號而是字串，該怎麼辦？

1977—1978 年，Abraham Lempel 和 Jacob Ziv 提出了字典式壓縮(dictionary compression)： 與其分析符號頻率，不如直接記錄「這一段字串，在前面什麼地方出現過」。

LZ77：滑動視窗

LZ77 維護一個滑動視窗(sliding window)：分成「歷史緩衝區」（已編碼的資料） 和「預視緩衝區」（待編碼的資料）。對每個位置，輸出一個三元組 $(\text{offset},\ \text{length},\ \text{next\_char})$：

  • offset：在歷史緩衝區往回多遠找到匹配
  • length：匹配了多長
  • next_char：匹配結束後的第一個新字元

LZ78 與 LZW：顯式字典

LZ78 不維護滑動視窗，而是動態建造一本字典(dictionary)： 每次讀到字典裡沒有的字串，就把它加入字典並輸出其索引加上新字元。

LZW（Lempel-Ziv-Welch，1984）是 LZ78 的改進版：預先填入所有單字元進字典（256 個 ASCII）， 編碼時只輸出索引、完全不需要傳遞「下一個字元」——使壓縮流更緊湊。 LZW 曾是 GIF 格式的壓縮演算法（因此引發著名的版權糾紛），也用於早期 Unix compress 與 TIFF。 

def lz77_encode(data, window=8, lookahead=4):
    """LZ77 簡易實作。回傳 (offset, length, next_char) 三元組列表。"""
    output = []
    i = 0
    while i < len(data):
        best_off, best_len = 0, 0
        start = max(0, i - window)
        for j in range(start, i):
            length = 0
            while (length < lookahead and
                   i + length < len(data) and
                   data[j + length] == data[i + length]):
                length += 1
            if length > best_len:
                best_len = length
                best_off = i - j
        next_c = data[i + best_len] if i + best_len < len(data) else ''
        output.append((best_off, best_len, next_c))
        i += best_len + 1
    return output

tokens = lz77_encode("abracadabra", window=8, lookahead=4)
for tok in tokens:
    print(tok)

  1. 在位置 $i$，匹配的起點最多往回 $W$ 個（offset 是 1 到 $W$）。匹配可以延伸過 $i$：一邊複製、一邊用剛複製出來的字元（重疊）。
  2. 取最長的匹配；一樣長時取最近的（offset 最小）。
  3. 長度最多是預視大小 $L$，而且一定要留一個字元當 next：長度 ≤ min($L$, 剩下的字元數 − 1)。
  4. 找不到匹配時輸出 (0, 0, 字元)。輸出一個三元組後，$i$ 往前跳「長度 + 1」。

和上面的 lz77_encode 不同的地方有兩個：它在一樣長時取最遠的（從視窗左邊掃起，> 只換更長的）， 而且最後一個三元組的 next 可以是空字串 ''。任務的版本處理位元組，next 一定是一個位元組（0..255 的整數），所以有規則 3。

有損壓縮一瞥：量化與感知編碼

前面談的都是無損壓縮(lossless compression)——解壓後和原始資料完全一樣。 但許多情況下你不需要完美還原：人眼對高頻細節不敏感、人耳對特定頻段有遮蔽效應， 讓有損壓縮(lossy compression)得以大幅縮小檔案而幾乎察覺不到差異。

量化(Quantization)

最直接的有損壓縮：把連續值「取整」。例如把 $[0, 255]$ 的像素值捨去最低 2 個位元， 位元數從 8 降到 6，代價是稍微模糊的色彩。 這種「以精度換空間」的操作就叫量化，它是所有有損壓縮的核心操作之一。

JPEG：頻域量化

JPEG 比「直接量化像素」聰明得多，其管線為：

  1. 色彩空間轉換：RGB → YCbCr（亮度 Y + 色差 Cb, Cr）。人眼對亮度敏感、對色差不太敏感，所以色差可先降採樣。
  2. 分塊 DCT（離散餘弦轉換）：把 8×8 像素塊轉換到頻域，得到 64 個頻率係數。低頻係數（整體明暗）重要，高頻係數（細節紋理）不重要。
  3. 量化：用量化矩陣把每個係數除以步長並取整。高頻係數的步長較大，很多係數直接變成 0。
  4. 熵編碼：用 Huffman（或 JPEG 2000 的算術碼）壓縮量化後的稀疏係數。

JPEG 的「品質」旋鈕直接控制量化步長：步長大 → 更多係數歸零 → 更小的檔案，但也更多「方塊感」。

MP3：感知遮蔽

MP3 的核心是感知編碼(perceptual coding)，利用聽覺心理學的現象： 一個強音調會「遮住」附近頻率的弱聲音。 MP3 用 MDCT 把音訊轉到頻域，根據感知遮蔽模型決定每個頻帶的量化精度， 再用 Huffman 壓縮——聽覺上幾乎無損，但檔案縮到 CD 原始大小的十分之一。

⚠️
重複有損壓縮會累積失真

每次 JPEG 重新存檔，量化誤差就累積一次。若需要反覆編輯圖片， 請以 PNG（無損）存中間檔，最後輸出才轉 JPEG。MP3 反覆重新編碼同理。

雜訊通道與糾錯碼

資訊不只要「壓縮」，還要「可靠地傳遞」。現實中的通道（無線電、光纖、硬碟磁面）都有雜訊， 傳出去的位元可能在途中被翻轉。資訊理論給了我們兩件利器： 通道容量告訴你通道最快能傳多少資訊； 糾錯碼告訴你如何在雜訊中恢復原始資料。

通道容量

Shannon 的通道編碼定理(channel coding theorem)指出： 每個通道都有一個最大資訊傳輸率 $C$（位元/使用），稱為通道容量(channel capacity)。 只要傳輸率低於 $C$，就存在一種編碼方案讓錯誤率任意小；超過 $C$ 則必然有無法消除的錯誤。

對加性高斯白雜訊(AWGN)通道，著名的夏農–哈特利定理給出：

$$C = W \log_2\!\left(1 + \frac{S}{N}\right) \quad \text{(位元/秒)}$$

其中 $W$ 是頻寬(Hz)，$S/N$ 是訊噪比。即使通道有雜訊，只要訊噪比夠大， 依然可以可靠地傳遞資訊——代價是用更複雜的編碼。

碼距與糾錯能力

糾錯的核心是漢明距離(Hamming distance)：兩個等長位元串之間不同位元的個數。 例如 1011101 和 1001001 在第 3、5 位不同，漢明距離 = 2。

一個糾錯碼的最小碼距(minimum distance) $d$ 決定其糾錯能力：

  • 能偵測 $d - 1$ 個錯誤
  • 能糾正 $\lfloor (d-1)/2 \rfloor$ 個錯誤

同位檢查(Parity Check)

最簡單的糾錯碼：在 $k$ 個資料位元後加一個同位位元(parity bit)， 使 1 的個數保持偶數（偶同位）。最小碼距 $d=2$， 能偵測 1 個錯誤，但不能糾正——知道出錯了，不知道哪一位。

Hamming(7,4) 碼：糾一位

1950 年，Richard Hamming 在貝爾實驗室發明了能糾正一個位元錯誤的碼， 現稱 Hamming(7,4)：4 個資料位元 + 3 個同位位元 = 共 7 位元，最小碼距 $d=3$。

7 個位元位置編號 1–7：位置 1, 2, 4（2 的冪次）是同位位元 $p_1, p_2, p_4$； 位置 3, 5, 6, 7 是資料位元 $d_1, d_2, d_3, d_4$。

三個同位位元的計算規則（偶同位，以 XOR $\oplus$ 表示）：

$$p_1 = d_1 \oplus d_2 \oplus d_4 \quad p_2 = d_1 \oplus d_3 \oplus d_4 \quad p_4 = d_2 \oplus d_3 \oplus d_4$$

接收端重新計算三個群組，得到症候碼 $(s_4, s_2, s_1)$： 若全為 0，無錯；否則以二進位讀出的數值直接是出錯的位置，翻轉它即可糾正。 

def hamming74_encode(d):
    """輸入 4 個資料位元 [d1,d2,d3,d4]，輸出 7 位元碼字。"""
    d1, d2, d3, d4 = d
    p1 = d1 ^ d2 ^ d4          # 覆蓋位置 1,3,5,7
    p2 = d1 ^ d3 ^ d4          # 覆蓋位置 2,3,6,7
    p4 = d2 ^ d3 ^ d4          # 覆蓋位置 4,5,6,7
    return [p1, p2, d1, p4, d2, d3, d4]   # 位置 1..7

def hamming74_decode(b):
    """輸入 7 位元碼字，自動糾正至多 1 位元錯誤，回傳 4 個資料位元。"""
    s1 = b[0] ^ b[2] ^ b[4] ^ b[6]
    s2 = b[1] ^ b[2] ^ b[5] ^ b[6]
    s4 = b[3] ^ b[4] ^ b[5] ^ b[6]
    syndrome = s4 * 4 + s2 * 2 + s1
    if syndrome:
        print(f"  偵測到錯誤，位置 {syndrome}，自動糾正")
        b = b[:]
        b[syndrome - 1] ^= 1
    return [b[2], b[4], b[5], b[6]]   # d1, d2, d3, d4

cw = hamming74_encode([1, 0, 1, 1])
print(f"原始碼字: {cw}")             # [0, 1, 1, 0, 0, 1, 1]

cw_err = cw[:]
cw_err[4] ^= 1                        # 翻轉位元 5
print(f"出錯碼字: {cw_err}")
recovered = hamming74_decode(cw_err)
print(f"還原資料: {recovered}")       # [1, 0, 1, 1] ✓

為什麼要學

「重新算一次檢查值，和收到的比」這個想法，在任務線「hzip 壓縮器」裡變成任務「CRC」（第 15 章的 Lab）： hzip 的檔案最後 4 個位元組是 CRC-32，Boss 戰「壞檔偵測」會翻任何一個位元、隨機改壞連續 4 個位元組以內的一段，你的解壓器都要抓到。 hzip 只偵測不糾正；下面這題說明為什麼「看到錯就修」很危險。

✏️ 手算 108.9 手算

看起來對但其實錯。「Hamming(7,4) 的症候碼不是 0，就把它指的那一位翻回來，資料一定修好了。」 資料 $[1, 0, 1, 1]$ 編成碼字後，位置 1 和位置 2 同時翻轉。算出症候碼，照規則「修正」，看還原的資料對不對。

看解答

碼字（位置 1–7）是 $[0, 1, 1, 0, 0, 1, 1]$（本章程式的範例）。翻轉位置 1、2 後收到 $[1, 0, 1, 0, 0, 1, 1]$。

$s_1 = b_1 \oplus b_3 \oplus b_5 \oplus b_7 = 1\oplus1\oplus0\oplus1 = 1$
$s_2 = b_2 \oplus b_3 \oplus b_6 \oplus b_7 = 0\oplus1\oplus1\oplus1 = 1$
$s_4 = b_4 \oplus b_5 \oplus b_6 \oplus b_7 = 0\oplus0\oplus1\oplus1 = 0$
症候碼 $(s_4 s_2 s_1)_2 = (011)_2 = 3$。

解碼器翻轉位置 3，得到 $[1, 0, 0, 0, 0, 1, 1]$，取出資料 $[0, 0, 1, 1]$，錯了（應該是 $[1, 0, 1, 1]$）。 現在有 3 個位元和原本的碼字不同，比修之前還糟。原因：最小碼距 $d = 3$ 只能「糾正 1 個」或「偵測 2 個」，不能兩件事同時做； 兩個錯誤會讓收到的字落在另一個碼字旁邊。實務上會加一個總同位位元變成 (8,4) 碼（$d = 4$，糾正 1 個、同時偵測 2 個）。

Reed-Solomon 碼與 CRC

Reed-Solomon 碼（1960 年）在有限域上操作，能糾正多個連續錯誤(burst error)， 廣泛用於光碟(CD/DVD/Blu-ray)的刮傷修復、QR Code 的容錯掃描，以及太空探測器的通訊。

CRC（Cyclic Redundancy Check，迴圈冗餘檢查）嚴格說是「偵錯」而非「糾錯」： 它附加多項式除法的餘數，接收端重新計算後若不符就丟棄封包。 在第 33 章（計算機網路）中，你見過以太網路幀、USB 和硬碟存取都使用 CRC。

互資訊、KL 散度與機器學習

資訊理論的語言在機器學習裡無所不在。理解三個核心概念， 你就能看懂大多數損失函數和模型評估方法的深層意義。

互資訊(Mutual Information)

互資訊 $I(X; Y)$ 衡量兩個隨機變數之間「共享了多少資訊」：

$$I(X; Y) = H(X) - H(X \mid Y) = H(Y) - H(Y \mid X)$$

直覺：$H(X)$ 是「知道 $Y$ 之前對 $X$ 的不確定性」，$H(X \mid Y)$ 是「知道 $Y$ 之後對 $X$ 的不確定性」， 差值就是 $Y$ 帶給你多少關於 $X$ 的資訊。$I(X; Y) = 0$ 表示 $X$ 和 $Y$ 完全獨立。

KL 散度(Kullback-Leibler Divergence)

KL 散度衡量「用分佈 $Q$ 來近似真實分佈 $P$ 要付出多少代價」：

$$D_{\mathrm{KL}}(P \| Q) = \sum_i p_i \log_2 \frac{p_i}{q_i} \geq 0$$

注意它不對稱：$D_{\mathrm{KL}}(P \| Q) \neq D_{\mathrm{KL}}(Q \| P)$， 因此嚴格說不是「距離」。$D_{\mathrm{KL}} = 0$ 當且僅當 $P = Q$。

壓縮含義：如果真實分佈是 $P$，但你用 $Q$ 設計了碼本， 平均每符號比最優多花 $D_{\mathrm{KL}}(P \| Q)$ 個位元。

交叉熵損失(Cross-Entropy Loss)

交叉熵(cross-entropy) 定義為：

$$H(P, Q) = -\sum_i p_i \log_2 q_i = H(P) + D_{\mathrm{KL}}(P \| Q)$$

在分類任務裡，$P$ 是真實標籤（one-hot 分佈），$Q$ 是模型輸出的 softmax 機率。 此時 $H(P) = 0$（真實標籤是確定的），所以：

$$\mathcal{L}_{\text{CE}} = H(P, Q) = D_{\mathrm{KL}}(P \| Q) = -\log_2 q_{y}$$

其中 $y$ 是正確類別。最小化交叉熵損失，等價於最小化模型預測分佈與真實分佈之間的 KL 散度， 也等價於最大化對數似然——三個視角說的是同一件事！

🔑
交叉熵損失的資訊理論意義

訓練分類器時最小化交叉熵，本質上是讓模型預測分佈 $Q$ 盡量「靠近」真實分佈 $P$—— 以資訊理論的角度看，就是縮短「用模型來描述真實標籤所需的平均位元數」。 這也是為什麼分類任務不用 MSE：MSE 沒有這個清晰的資訊理論根基。

$L = 0.4 + 0.5 + 0.6 + 0.4 + 0.2 = 2.1$；$H \approx 2.0414$；$2.0414 \le 2.1 < 3.0414$ ✓；效率 $H/L \approx 97.2\%$。

✏️ 練習 108.13 計算

接手算 108.5：二元來源 $P(\text{b}) = p = 0.05$、$P(\text{a}) = 0.95$。把兩個符號綁成一塊（aa、ab、ba、bb）做 Huffman，平均每個原始符號幾位元？三個一塊呢？

看解答

兩個一塊：機率 aa $0.9025$、ab $0.0475$、ba $0.0475$、bb $0.0025$（一般式：$(1-p)^2$、$p(1-p)$、$p(1-p)$、$p^2$）。 Huffman 碼長 aa:1、ba:2、ab:3、bb:3（ab、ba 對調也一樣），每塊平均 $0.9025 + 2(0.0475) + 3(0.0475) + 3(0.0025) = 1.1475$ 位元，每個符號 $0.57375$ 位元。

三個一塊：每塊平均 $1.29975$ 位元，每個符號約 $0.4333$ 位元。熵是 $0.2864$：一塊 $k$ 個符號時，每個符號的平均碼長 $< H + \frac1k$，越綁越接近，但碼表大小是 $2^k$。

✏️ 練習 108.15 計算

"abcdefghabc"（11 個字元），$L = 4$。分別用 $W = 4$ 和 $W = 8$ 編碼，各有幾個三元組？

看解答

$W = 4$：位置 8 的 abc 在 8 個位置以前，視窗看不到，11 個字元全是 (0, 0, 字元)，11 個三元組。

$W = 8$：前 8 個是 (0, 0, 字元)；位置 8 往回 8 個找到 abc，但只剩 3 個字元，要留 1 個 → (8, 2, c)。共 9 個三元組。 這就是視窗大小的取捨：視窗越大，找得到越遠的重複，但每個位置要找的候選越多（任務「LZ77」的效能門檻逼你用雜湊表找候選）。

✏️ 練習 108.16 計算

(a) 解碼 (0,0,a) (0,0,b) (2,3,c) (1,4,d)。(b) 把 (2, 3, c) 打包成 4 個位元組（offset 2 個位元組大端、length、next），寫成十六進位。

看解答

(a) ab → (2,3,c)：來源位置 0、1、2，寫出 a、b、a（第 3 個是剛寫出的），接 c → ababac； (1,4,d)：來源位置 5、6、7、8，寫出 4 個 c，接 d → ababacccccd。

(b) offset 2 → 00 02，length 3 → 03，c 的 ASCII 是 99 → 63：00 02 03 63。

✏️ 練習 108.17 計算

(a) 用 Hamming(7,4) 編碼資料 $[0, 1, 1, 0]$。(b) 收到 $[1, 0, 1, 1, 0, 1, 1]$，算症候碼、修正，取出資料。

看解答

(a) $p_1 = 0\oplus1\oplus0 = 1$，$p_2 = 0\oplus1\oplus0 = 1$，$p_4 = 1\oplus1\oplus0 = 0$ → $[1, 1, 0, 0, 1, 1, 0]$。

(b) $s_1 = 1\oplus1\oplus0\oplus1 = 1$，$s_2 = 0\oplus1\oplus1\oplus1 = 1$，$s_4 = 1\oplus0\oplus1\oplus1 = 1$，症候碼 $(111)_2 = 7$。 翻轉位置 7 → $[1, 0, 1, 1, 0, 1, 0]$，資料（位置 3、5、6、7）是 $[1, 0, 1, 0]$。驗算：重新編碼 $[1, 0, 1, 0]$ 正好得到 $[1, 0, 1, 1, 0, 1, 0]$。

✏️ 練習 108.18 計算

重複碼：把 1 個位元重複 $r$ 次（$r = 5$：0 → 00000、1 → 11111）。(a) 最小碼距、能偵測幾個錯、能糾正幾個錯？ (b) 收到 11010，用「離哪個碼字最近」解碼。(c) 一般的 $r$ 呢？

看解答

(a) $d = 5$：偵測 $d - 1 = 4$ 個，糾正 $\lfloor (d-1)/2 \rfloor = 2$ 個。 (b) 和 11111 差 2 位、和 00000 差 3 位，解成 1。(c) $d = r$，糾正 $\lfloor (r-1)/2 \rfloor$ 個；代價是傳輸率只有 $1/r$。

✏️ 練習 108.19 計算

hzip 的格式：標頭 14 個位元組（magic 4、版本 1、方法 1、原始長度 4、原始 CRC-32 4）＋本體＋最後的 CRC-32 4 個位元組。 方法 0 的本體是原始資料；方法 1 的本體是 256 個位元組的碼長表＋nbits（4 個位元組）＋位元流（$\lceil \text{nbits}/8 \rceil$ 個位元組）。 (a) "ABRACADABRA"（nbits ＝ 23）用兩種方法各幾個位元組？自動選擇會選哪個？ (b) 假設 Huffman 平均每個位元組 4 位元，原始資料至少要多長，方法 1 才會比方法 0 小？

看解答

(a) 方法 0：$14 + 11 + 4 = 29$（一般是 $n + 18$）。方法 1：$14 + 256 + 4 + \lceil 23/8 \rceil + 4 = 281$（一般是 $278 + \lceil \text{nbits}/8 \rceil$）。選方法 0。

(b) 要 $278 + \lceil 4n/8 \rceil < n + 18$，也就是 $\lceil n/2 \rceil < n - 260$。$n = 521$ 時兩邊都是 261（一樣大時選編號小的，還是方法 0），$n = 522$ 才贏：至少 522 個位元組。 短檔案的碼長表是固定成本，這也是為什麼真正的 DEFLATE 會再壓縮碼長表。

把這一章串起來

我們從「一則訊息值多少資訊」這個問題出發，走過了資訊理論的核心疆域：

  • 驚奇度 $I(x) = -\log_2 P(x)$：稀有事件攜帶更多資訊，位元是衡量單位。
  • 夏農熵 $H = -\sum p_i \log_2 p_i$：來源的「平均不確定性」，也是壓縮的理論下限。均勻分佈時最大；確定分佈時為 0。
  • 源編碼定理：無損壓縮不可能突破熵，但可以任意逼近它。
  • Kraft 不等式 $\sum 2^{-\ell_i} \leq 1$：前綴碼存在的充要條件；等號成立為完整碼。
  • Huffman（整數碼長最優，見第 30 章）、算術編碼 / ANS（突破整數限制，真正逼近熵）。
  • LZ77 / LZW + Huffman = DEFLATE：字典式壓縮找重複，熵編碼去冗餘，兩個階段的增益相乘。
  • 有損壓縮：JPEG 用 DCT 頻域量化，MP3 用感知遮蔽，犧牲人眼 / 人耳察覺不到的精度換取極高壓縮率。
  • 通道編碼定理 $C = W\log_2(1+S/N)$：雜訊通道的資訊傳輸極限。
  • Hamming(7,4)：3 個同位位元 + 4 個資料位元，症候碼直接指出 1 位元的出錯位置。
  • 交叉熵損失 = KL 散度（真實熵為 0 時）：深度學習分類任務的損失函數，有清晰的資訊理論根基。

Shannon 1948：資訊時代的原點

Claude Shannon 在 1948 年發表的 A Mathematical Theory of Communication（Bell System Technical Journal） 是計算機科學史上最重要的論文之一。他在一篇論文裡同時定義了「位元(bit)」這個詞、建立了熵的理論、 證明了源編碼定理與通道編碼定理——幾乎憑一己之力奠定了整個資訊理論的基礎。 這篇論文距今超過 75 年，每一段推導至今仍然成立。
