一則訊息值多少資訊？驚奇度與位元

假設你同時收到兩條新聞推播：

「太陽今天從東方升起。」
「台北101昨夜無預警倒塌。」

兩條都是「訊息」，但直覺告訴你第二條遠比第一條「有資訊量」。為什麼？ 因為第一條幾乎是確定的，它幾乎沒有告訴你任何新東西； 第二條極度出乎意料，收到的那一刻你的世界觀就被更新了一大塊。

1948 年，貝爾實驗室的 Claude Shannon 把這個直覺數學化。他定義一個事件 $x$ 的 驚奇度(surprisal)，又稱自資訊(self-information)，為：

$$I(x) = \log_2 \frac{1}{P(x)} = -\log_2 P(x) \quad \text{(位元)}$$

這個公式有三個美麗的性質：

  • $P(x) = 1$（確定事件）$\Rightarrow I(x) = 0$：確定的事沒有資訊量。
  • $P(x)$ 越小，$I(x)$ 越大：越罕見的事件，攜帶越多資訊。
  • 兩個獨立事件的驚奇度可相加：$I(x_1 x_2) = I(x_1) + I(x_2)$（源自對數的加法性質）。

為什麼用 $\log_2$？因為我們用「位元(bit)」計量——需要幾個是/否問題才能確定這件事。 一枚公平硬幣落正面的機率是 $1/2$，驚奇度 $= \log_2 2 = 1$ 位元； 擲一顆公平六面骰出現 6 點的機率是 $1/6$，驚奇度 $= \log_2 6 \approx 2.58$ 位元。

🔑
資訊量 = 驚奇度 = 需要幾個位元才能「傳達這件事」

$I(x) = -\log_2 P(x)$ 位元。確定的事 0 位元；機率 $1/2$ 的事 1 位元；機率 $1/1{,}000{,}000$ 的事約 20 位元。

夏農熵：衡量平均不確定性的量尺

單一事件的驚奇度很有用，但在壓縮或通訊裡，我們更在乎的是： 平均而言，從一個來源(source)取出一個符號，需要幾個位元？ 這就是夏農熵(Shannon entropy) $H(X)$ 的出發點。

如果來源 $X$ 有 $n$ 個符號，對應機率 $\{p_1, \dots, p_n\}$， 則驚奇度的期望值是：

$$H(X) = \mathbb{E}[I(X)] = -\sum_{i=1}^{n} p_i \log_2 p_i \quad \text{(位元/符號)}$$

慣例：$0 \cdot \log_2 0 \stackrel{\text{def}}{=} 0$（取極限 $p \to 0^+$ 可驗證）。

💡
熵的極值

最大值：所有 $n$ 個符號等機率 $p_i = 1/n$ 時，$H = \log_2 n$ 位元——完全均勻、最不可預測。
最小值 0：只有一個符號的機率為 1，其餘為 0——完全確定，不需要任何位元。

最能感受熵的場景是二元來源(binary source)：只有 0 和 1， 出現 1 的機率是 $p$，出現 0 的機率是 $1-p$。 此時熵就是二元熵函數(binary entropy function)：

$$H(p) = -p\log_2 p - (1-p)\log_2(1-p)$$

來感受一下熵的含義。英文文本的 26 個字母有不同頻率（'e' 約 12.7%，'z' 約 0.07%……）， 代入熵公式得到約 4.1 位元/字母。 然而 ASCII 用 8 位元存每個字母——表示英文文本至少有一半是「多餘的」，可以壓掉！ 

import math

def entropy(probs):
    """計算離散分佈的夏農熵（位元/符號）。"""
    return -sum(p * math.log2(p) for p in probs if p > 0)

# 公平硬幣：熵最大
print(f"公平硬幣熵    = {entropy([0.5, 0.5]):.4f} bits")    # 1.0000

# 偏硬幣（正面 90%）：熵低
print(f"偏硬幣熵      = {entropy([0.9, 0.1]):.4f} bits")    # 0.4690

# 四個等機率符號
print(f"四符號均勻熵  = {entropy([0.25]*4):.4f} bits")      # 2.0000

# 不均勻四符號（注意可壓縮性）
probs = [0.5, 0.25, 0.125, 0.125]
print(f"不均勻四符號熵= {entropy(probs):.4f} bits")         # 1.7500

最後那個例子很有啟發性：四個符號理論上需要 $\log_2 4 = 2$ 位元， 但因為分佈不均，實際熵只有 1.75 位元——這 0.25 位元的差距就是「可以壓縮的空間」。

源編碼定理：壓縮的理論下限

熵不只是一個數字，它告訴你一個根本事實。Shannon 在 1948 年的論文中證明了：

🔑
夏農源編碼定理(Source Coding Theorem)

設來源 $X$ 的熵為 $H(X)$ 位元/符號。則：
(1) 存在一個無損壓縮碼，使平均每符號的碼長任意接近 $H(X)$。
(2) 任何無損壓縮碼的平均碼長都不能低於 $H(X)$。

這是一個「存在性 + 下界」定理：它告訴你壓縮的理論極限在哪，但不告訴你怎麼建出最好的碼。 建出最好的碼，是 Huffman、算術編碼等演算法在做的事。

為什麼說「任意接近」而非「等於」？原因很微妙： 如果每個符號必須對應整數個位元，就沒辦法剛好達到熵（除非熵本身是整數）。 算術編碼突破這個限制，做到「非整數碼長」，從而真正逼近熵。

前綴碼與 Kraft 不等式

壓縮需要把每個符號對應到一個位元串，讓接收端能無歧義地還原原始序列。 最自然的方法是前綴碼(prefix-free code)，又稱即時碼(instantaneous code)： 沒有任何碼字是另一個碼字的前綴。

為什麼前綴碼能無歧義解碼？因為你從頭讀位元流，一旦讀到的位元串等於某個碼字， 就可以立刻輸出那個符號——不需要「等待」未來的位元確認邊界。 這就是「即時(instantaneous)」的含義，也是 Huffman 樹上「從根走到葉就確定符號」的原因。

前綴碼的存在有一個優雅的充要條件——Kraft 不等式(Kraft inequality)： 設 $n$ 個符號的碼長分別為 $\ell_1, \dots, \ell_n$（位元），則

$$\sum_{i=1}^{n} 2^{-\ell_i} \leq 1$$

等式成立時，稱為完整碼(complete code)——二元樹的每一片葉子都被用到， 沒有任何「浪費的分支」。最佳無損碼恰好滿足 Kraft 等式。

💡
Kraft 不等式的幾何直覺

想像一棵完全二元樹，根節點的「份額」是 1。每往下一層，左右各拿父節點一半份額。 一個碼長為 $\ell$ 的符號佔了 $2^{-\ell}$ 份額。Kraft 不等式說： 所有葉子佔的份額加起來不超過 1——你不能讓碼字互相搶佔空間。

以分佈 $\{0.5, 0.25, 0.125, 0.125\}$ 驗證：

符號機率碼字碼長 $\ell_i$$2^{-\ell_i}$
A0.500010.500
B0.2501020.250
C0.12511030.125
D0.12511130.125
總和1.000 ✓

Kraft 等於 1，是完整前綴碼。平均碼長 $L = 0.5\times1 + 0.25\times2 + 0.125\times3 + 0.125\times3 = 1.75$ 位元， 恰好等於熵 1.75 位元——這正是 Huffman 演算法對此分佈產生的最佳碼。

熵編碼：從 Huffman 到算術編碼

Huffman 編碼（連回第 31 章）

在第 31 章（貪婪演算法），我們詳細介紹了霍夫曼(Huffman)編碼的建樹演算法、 貪婪選擇性質與正確性證明。這裡只快速回顧結論：

  • Huffman 演算法每次從優先佇列取出兩個最小頻率的節點合併，$O(n \log n)$ 建出最佳前綴碼樹。
  • 在「每符號必須整數個位元」的前提下，保證平均碼長最小。
  • Huffman 的平均碼長 $L$ 滿足 $H(X) \leq L < H(X) + 1$ 位元/符號。

那最多差 1 位元的「缺口」，是每符號必須取整數位元所帶來的代價。 對 $k$ 個符號組成的「區塊」一次編碼，差距縮小到 $1/k$ 位元/符號； 但 $k$ 變大時需要 $n^k$ 個碼字，實用上代價極高——於是有了算術編碼。

算術編碼(Arithmetic Coding)

算術編碼的核心想法是：與其為每個符號分配整數長度的碼字， 不如把整個訊息序列對應到 $[0, 1)$ 區間上的一個實數—— 而表示這個實數需要的位元數，就恰好逼近整個序列的熵。

以分佈 $P(\text{A})=0.5,\ P(\text{B})=0.25,\ P(\text{C})=0.25$ 為例，編碼序列 "ABA"：

  1. 初始：整個 $[0,1)$ 是「目前的可能範圍」。
  2. 讀到 A（佔前 50%）：範圍縮到 $[0,\ 0.5)$。
  3. 讀到 B（在 $[0,0.5)$ 裡，B 佔 50%～75% 這一段）：縮到 $[0.25,\ 0.375)$。
  4. 讀到 A（在 $[0.25,0.375)$ 裡，A 佔前 50%）：縮到 $[0.25,\ 0.3125)$。
  5. 輸出區間內任何點的二進位表示，例如 $0.25 = 0.01_2$，至少需要 2 個位元（實際需加入序列終止符或長度資訊才能唯一解碼）。

區間越小，需要越多位元精確表示——這正對應「序列的熵」。 算術編碼可以達到任意接近熵的壓縮率，是理論最優的無損編碼族。 現代高效壓縮工具（zstd 的 ANS、HEVC/AV1 的 CABAC）都屬於算術編碼的變體。

ℹ️
ANS：現代算術編碼的繼承者

Asymmetric Numeral Systems（ANS）是 2009 年 Jarek Duda 提出的算術編碼變體， 用位移和查表取代乘除法，速度比傳統算術編碼快 10 倍以上。 你平常的 .zst 檔案（zstd）和 Apple 的 LZFSE 背後都有 ANS。

字典式壓縮：LZ77、LZ78 與 LZW

熵編碼的前提是「已知符號機率」——你需要事先統計或傳遞頻率表。 但如果資料是動態的，或重複出現的不是符號而是字串，該怎麼辦？

1977—1978 年，Abraham Lempel 和 Jacob Ziv 提出了字典式壓縮(dictionary compression)： 與其分析符號頻率，不如直接記錄「這一段字串，在前面什麼地方出現過」。

LZ77：滑動視窗

LZ77 維護一個滑動視窗(sliding window)：分成「歷史緩衝區」（已編碼的資料） 和「預視緩衝區」（待編碼的資料）。對每個位置，輸出一個三元組 $(\text{offset},\ \text{length},\ \text{next\_char})$：

  • offset：在歷史緩衝區往回多遠找到匹配
  • length：匹配了多長
  • next_char：匹配結束後的第一個新字元

LZ78 與 LZW：顯式字典

LZ78 不維護滑動視窗，而是動態建造一本字典(dictionary)： 每次讀到字典裡沒有的字串，就把它加入字典並輸出其索引加上新字元。

LZW（Lempel-Ziv-Welch，1984）是 LZ78 的改進版：預先填入所有單字元進字典（256 個 ASCII）， 編碼時只輸出索引、完全不需要傳遞「下一個字元」——使壓縮流更緊湊。 LZW 曾是 GIF 格式的壓縮演算法（因此引發著名的版權糾紛），也用於早期 Unix compress 與 TIFF。 

def lz77_encode(data, window=8, lookahead=4):
    """LZ77 簡易實作。回傳 (offset, length, next_char) 三元組列表。"""
    output = []
    i = 0
    while i < len(data):
        best_off, best_len = 0, 0
        start = max(0, i - window)
        for j in range(start, i):
            length = 0
            while (length < lookahead and
                   i + length < len(data) and
                   data[j + length] == data[i + length]):
                length += 1
            if length > best_len:
                best_len = length
                best_off = i - j
        next_c = data[i + best_len] if i + best_len < len(data) else ''
        output.append((best_off, best_len, next_c))
        i += best_len + 1
    return output

tokens = lz77_encode("abracadabra", window=8, lookahead=4)
for tok in tokens:
    print(tok)
# (0, 0, 'a')  →「沒匹配，直接輸出 a」
# (0, 0, 'b')
# (0, 0, 'r')
# (3, 1, 'c')  →「往回 3 位找到 'a'，複製 1 字元，接 c」
# (5, 1, 'd')  →「往回 5 位(到 data[0])找到 'a'，複製 1 字元，接 d」
# (7, 4, '')   →「往回 7 位找到 'abra'，複製 4 字元」

兩個世界的結合：DEFLATE 與現代壓縮

字典式壓縮（LZ77）和熵編碼（Huffman）各有強項： LZ77 把重複字串壓成短小的三元組；Huffman 再把三元組裡的符號頻率進一步壓縮。 把兩者串起來，就是廣泛使用的 DEFLATE 演算法，也是 gzip、zlib 和 PNG 的壓縮核心。

現代壓縮工具沿這條軸線不斷演進：

格式 / 工具字典部分熵編碼部分特點
gzip / zlibLZ77（32 KB 視窗）HuffmanDEFLATE，最通用
bzip2BWT + MTFHuffman壓縮率較高，速度較慢

🔑
壓縮率的本質：兩階段增益相乘

壓縮效果取決於 (1) 能找到多長的重複字串（字典式）和 (2) 剩下「新」符號能壓多緊（熵編碼）。 兩個階段的增益相乘而非相加——這就是為什麼 LZ + Huffman 的組合遠勝單獨使用任何一個。

有損壓縮一瞥：量化與感知編碼

前面談的都是無損壓縮(lossless compression)——解壓後和原始資料完全一樣。 但許多情況下你不需要完美還原：人眼對高頻細節不敏感、人耳對特定頻段有遮蔽效應， 讓有損壓縮(lossy compression)得以大幅縮小檔案而幾乎察覺不到差異。

量化(Quantization)

最直接的有損壓縮：把連續值「取整」。例如把 $[0, 255]$ 的像素值捨去最低 2 個位元， 位元數從 8 降到 6，代價是稍微模糊的色彩。 這種「以精度換空間」的操作就叫量化，它是所有有損壓縮的核心操作之一。

JPEG：頻域量化

JPEG 比「直接量化像素」聰明得多，其管線為：

  1. 色彩空間轉換：RGB → YCbCr（亮度 Y + 色差 Cb, Cr）。人眼對亮度敏感、對色差不太敏感，所以色差可先降採樣。
  2. 分塊 DCT（離散餘弦轉換）：把 8×8 像素塊轉換到頻域，得到 64 個頻率係數。低頻係數（整體明暗）重要，高頻係數（細節紋理）不重要。
  3. 量化：用量化矩陣把每個係數除以步長並取整。高頻係數的步長較大，很多係數直接變成 0。
  4. 熵編碼：用 Huffman（或 JPEG 2000 的算術碼）壓縮量化後的稀疏係數。

JPEG 的「品質」旋鈕直接控制量化步長：步長大 → 更多係數歸零 → 更小的檔案，但也更多「方塊感」。

MP3：感知遮蔽

MP3 的核心是感知編碼(perceptual coding)，利用聽覺心理學的現象： 一個強音調會「遮住」附近頻率的弱聲音。 MP3 用 MDCT 把音訊轉到頻域，根據感知遮蔽模型決定每個頻帶的量化精度， 再用 Huffman 壓縮——聽覺上幾乎無損，但檔案縮到 CD 原始大小的十分之一。

⚠️
重複有損壓縮會累積失真

每次 JPEG 重新存檔，量化誤差就累積一次。若需要反覆編輯圖片， 請以 PNG（無損）存中間檔，最後輸出才轉 JPEG。MP3 反覆重新編碼同理。

雜訊通道與糾錯碼

資訊不只要「壓縮」，還要「可靠地傳遞」。現實中的通道（無線電、光纖、硬碟磁面）都有雜訊， 傳出去的位元可能在途中被翻轉。資訊理論給了我們兩件利器： 通道容量告訴你通道最快能傳多少資訊； 糾錯碼告訴你如何在雜訊中恢復原始資料。

通道容量

Shannon 的通道編碼定理(channel coding theorem)指出： 每個通道都有一個最大資訊傳輸率 $C$（位元/使用），稱為通道容量(channel capacity)。 只要傳輸率低於 $C$，就存在一種編碼方案讓錯誤率任意小；超過 $C$ 則必然有無法消除的錯誤。

對加性高斯白雜訊(AWGN)通道，著名的夏農–哈特利定理給出：

$$C = W \log_2\!\left(1 + \frac{S}{N}\right) \quad \text{(位元/秒)}$$

其中 $W$ 是頻寬(Hz)，$S/N$ 是訊噪比。即使通道有雜訊，只要訊噪比夠大， 依然可以可靠地傳遞資訊——代價是用更複雜的編碼。

碼距與糾錯能力

糾錯的核心是漢明距離(Hamming distance)：兩個等長位元串之間不同位元的個數。 例如 1011101 和 1001001 在第 3、5 位不同，漢明距離 = 2。

一個糾錯碼的最小碼距(minimum distance) $d$ 決定其糾錯能力：

  • 能偵測 $d - 1$ 個錯誤
  • 能糾正 $\lfloor (d-1)/2 \rfloor$ 個錯誤

同位檢查(Parity Check)

最簡單的糾錯碼：在 $k$ 個資料位元後加一個同位位元(parity bit)， 使 1 的個數保持偶數（偶同位）。最小碼距 $d=2$， 能偵測 1 個錯誤，但不能糾正——知道出錯了，不知道哪一位。

Hamming(7,4) 碼：糾一位

1950 年，Richard Hamming 在貝爾實驗室發明了能糾正一個位元錯誤的碼， 現稱 Hamming(7,4)：4 個資料位元 + 3 個同位位元 = 共 7 位元，最小碼距 $d=3$。

7 個位元位置編號 1–7：位置 1, 2, 4（2 的冪次）是同位位元 $p_1, p_2, p_4$； 位置 3, 5, 6, 7 是資料位元 $d_1, d_2, d_3, d_4$。

三個同位位元的計算規則（偶同位，以 XOR $\oplus$ 表示）：

$$p_1 = d_1 \oplus d_2 \oplus d_4 \quad p_2 = d_1 \oplus d_3 \oplus d_4 \quad p_4 = d_2 \oplus d_3 \oplus d_4$$

接收端重新計算三個群組，得到症候碼 $(s_4, s_2, s_1)$： 若全為 0，無錯；否則以二進位讀出的數值直接是出錯的位置，翻轉它即可糾正。 

def hamming74_encode(d):
    """輸入 4 個資料位元 [d1,d2,d3,d4]，輸出 7 位元碼字。"""
    d1, d2, d3, d4 = d
    p1 = d1 ^ d2 ^ d4          # 覆蓋位置 1,3,5,7
    p2 = d1 ^ d3 ^ d4          # 覆蓋位置 2,3,6,7
    p4 = d2 ^ d3 ^ d4          # 覆蓋位置 4,5,6,7
    return [p1, p2, d1, p4, d2, d3, d4]   # 位置 1..7

def hamming74_decode(b):
    """輸入 7 位元碼字，自動糾正至多 1 位元錯誤，回傳 4 個資料位元。"""
    s1 = b[0] ^ b[2] ^ b[4] ^ b[6]
    s2 = b[1] ^ b[2] ^ b[5] ^ b[6]
    s4 = b[3] ^ b[4] ^ b[5] ^ b[6]
    syndrome = s4 * 4 + s2 * 2 + s1
    if syndrome:
        print(f"  偵測到錯誤，位置 {syndrome}，自動糾正")
        b = b[:]
        b[syndrome - 1] ^= 1
    return [b[2], b[4], b[5], b[6]]   # d1, d2, d3, d4

cw = hamming74_encode([1, 0, 1, 1])
print(f"原始碼字: {cw}")             # [0, 1, 1, 0, 0, 1, 1]

cw_err = cw[:]
cw_err[4] ^= 1                        # 翻轉位元 5
print(f"出錯碼字: {cw_err}")
recovered = hamming74_decode(cw_err)
print(f"還原資料: {recovered}")       # [1, 0, 1, 1] ✓

Reed-Solomon 碼與 CRC

Reed-Solomon 碼（1960 年）在有限域上操作，能糾正多個連續錯誤(burst error)， 廣泛用於光碟(CD/DVD/Blu-ray)的刮傷修復、QR Code 的容錯掃描，以及太空探測器的通訊。

CRC（Cyclic Redundancy Check，迴圈冗餘檢查）嚴格說是「偵錯」而非「糾錯」： 它附加多項式除法的餘數，接收端重新計算後若不符就丟棄封包。 在第 25 章（計算機網路）中，你見過以太網路幀、USB 和硬碟存取都使用 CRC。

互資訊、KL 散度與機器學習

資訊理論的語言在機器學習裡無所不在。理解三個核心概念， 你就能看懂大多數損失函數和模型評估方法的深層意義。

互資訊(Mutual Information)

互資訊 $I(X; Y)$ 衡量兩個隨機變數之間「共享了多少資訊」：

$$I(X; Y) = H(X) - H(X \mid Y) = H(Y) - H(Y \mid X)$$

直覺：$H(X)$ 是「知道 $Y$ 之前對 $X$ 的不確定性」，$H(X \mid Y)$ 是「知道 $Y$ 之後對 $X$ 的不確定性」， 差值就是 $Y$ 帶給你多少關於 $X$ 的資訊。$I(X; Y) = 0$ 表示 $X$ 和 $Y$ 完全獨立。

KL 散度(Kullback-Leibler Divergence)

KL 散度衡量「用分佈 $Q$ 來近似真實分佈 $P$ 要付出多少代價」：

$$D_{\mathrm{KL}}(P \| Q) = \sum_i p_i \log_2 \frac{p_i}{q_i} \geq 0$$

注意它不對稱：$D_{\mathrm{KL}}(P \| Q) \neq D_{\mathrm{KL}}(Q \| P)$， 因此嚴格說不是「距離」。$D_{\mathrm{KL}} = 0$ 當且僅當 $P = Q$。

壓縮含義：如果真實分佈是 $P$，但你用 $Q$ 設計了碼本， 平均每符號比最優多花 $D_{\mathrm{KL}}(P \| Q)$ 個位元。

交叉熵損失(Cross-Entropy Loss)

交叉熵(cross-entropy) 定義為：

$$H(P, Q) = -\sum_i p_i \log_2 q_i = H(P) + D_{\mathrm{KL}}(P \| Q)$$

在分類任務裡，$P$ 是真實標籤（one-hot 分佈），$Q$ 是模型輸出的 softmax 機率。 此時 $H(P) = 0$（真實標籤是確定的），所以：

$$\mathcal{L}_{\text{CE}} = H(P, Q) = D_{\mathrm{KL}}(P \| Q) = -\log_2 q_{y}$$

其中 $y$ 是正確類別。最小化交叉熵損失，等價於最小化模型預測分佈與真實分佈之間的 KL 散度， 也等價於最大化對數似然——三個視角說的是同一件事！

🔑
交叉熵損失的資訊理論意義

訓練分類器時最小化交叉熵，本質上是讓模型預測分佈 $Q$ 盡量「靠近」真實分佈 $P$—— 以資訊理論的角度看，就是縮短「用模型來描述真實標籤所需的平均位元數」。 這也是為什麼分類任務不用 MSE：MSE 沒有這個清晰的資訊理論根基。

更多資訊理論在深度學習中的應用（VAE 的 ELBO、InfoNCE 對比學習、互資訊最大化等） 將在第 105 章（深度學習的數學）深入展開。

✏️ 練習 102.1 思考

考慮一個來源，有四個符號 A, B, C, D，機率分別為 $0.4, 0.3, 0.2, 0.1$。

  1. 計算這個來源的夏農熵 $H$（保留 4 位小數）。
  2. 為四個符號設計一個前綴碼，驗證 Kraft 不等式成立。
  3. 計算你設計的碼的平均碼長 $L$，並確認 $L \geq H$。
看解答

(a) 計算熵：

$$H = -(0.4\log_2 0.4 + 0.3\log_2 0.3 + 0.2\log_2 0.2 + 0.1\log_2 0.1)$$

逐項：$0.4\times(-1.3219)=-0.5288$；$0.3\times(-1.7370)=-0.5211$； $0.2\times(-2.3219)=-0.4644$；$0.1\times(-3.3219)=-0.3322$。

$$H = 0.5288+0.5211+0.4644+0.3322 = \mathbf{1.8464} \text{ 位元}$$

(b) 一個合理的前綴碼：

A → 0（長度 1），B → 10（長度 2），C → 110（長度 3），D → 111（長度 3）。

Kraft：$2^{-1}+2^{-2}+2^{-3}+2^{-3} = 0.5+0.25+0.125+0.125 = 1.0 \leq 1$ ✓（完整碼）

(c) 平均碼長：

$$L = 0.4\times1+0.3\times2+0.2\times3+0.1\times3 = 0.4+0.6+0.6+0.3 = \mathbf{1.9} \text{ 位元}$$

$L = 1.9 \geq H = 1.8464$ ✓，差距 0.054 位元來自取整代價。

import math
probs = [0.4, 0.3, 0.2, 0.1]
H = -sum(p * math.log2(p) for p in probs)
print(f"H = {H:.4f}")   # 1.8464
lens = [1, 2, 3, 3]
L = sum(p * l for p, l in zip(probs, lens))
print(f"L = {L:.4f}")   # 1.9000

✏️ 練習 102.3 挑戰

用 Hamming(7,4) 對資料位元 $[1, 1, 0, 1]$（$d_1=1, d_2=1, d_3=0, d_4=1$）進行編碼， 然後模擬位元 2（$p_2$ 的位置）發生翻轉，執行糾錯並驗證還原正確。

  1. 手算求出 $p_1, p_2, p_4$ 的值，寫出 7 位元碼字。
  2. 翻轉位元 2 後，計算症候碼(syndrome)，指出出錯位置。
  3. 用 Python 程式驗算。
看解答

(a) 編碼： $d_1=1, d_2=1, d_3=0, d_4=1$

$p_1 = d_1 \oplus d_2 \oplus d_4 = 1 \oplus 1 \oplus 1 = 1$
$p_2 = d_1 \oplus d_3 \oplus d_4 = 1 \oplus 0 \oplus 1 = 0$
$p_4 = d_2 \oplus d_3 \oplus d_4 = 1 \oplus 0 \oplus 1 = 0$

碼字（位置 1–7：$p_1, p_2, d_1, p_4, d_2, d_3, d_4$）$= [1, 0, 1, 0, 1, 0, 1]$

(b) 翻轉位元 2（$p_2$ 從 0 變 1）： 收到 $[1, 1, 1, 0, 1, 0, 1]$

$s_1 = b_1 \oplus b_3 \oplus b_5 \oplus b_7 = 1\oplus1\oplus1\oplus1 = 0$
$s_2 = b_2 \oplus b_3 \oplus b_6 \oplus b_7 = 1\oplus1\oplus0\oplus1 = 1$
$s_4 = b_4 \oplus b_5 \oplus b_6 \oplus b_7 = 0\oplus1\oplus0\oplus1 = 0$
症候碼 $= (s_4,s_2,s_1)_2 = (0,1,0)_2 = \mathbf{2}$，指出位置 2 出錯。

翻轉位置 2 後恢復 $[1,0,1,0,1,0,1]$，取出資料位元（位置 3,5,6,7）$=[1,1,0,1]$ ✓

把這一章串起來

我們從「一則訊息值多少資訊」這個問題出發，走過了資訊理論的核心疆域：

  • 驚奇度 $I(x) = -\log_2 P(x)$：稀有事件攜帶更多資訊，位元是衡量單位。
  • 夏農熵 $H = -\sum p_i \log_2 p_i$：來源的「平均不確定性」，也是壓縮的理論下限。均勻分佈時最大；確定分佈時為 0。
  • 源編碼定理：無損壓縮不可能突破熵，但可以任意逼近它。
  • Kraft 不等式 $\sum 2^{-\ell_i} \leq 1$：前綴碼存在的充要條件；等號成立為完整碼。
  • Huffman（整數碼長最優，見第 31 章）、算術編碼 / ANS（突破整數限制，真正逼近熵）。
  • LZ77 / LZW + Huffman = DEFLATE：字典式壓縮找重複，熵編碼去冗餘，兩個階段的增益相乘。
  • 有損壓縮：JPEG 用 DCT 頻域量化，MP3 用感知遮蔽，犧牲人眼 / 人耳察覺不到的精度換取極高壓縮率。
  • 通道編碼定理 $C = W\log_2(1+S/N)$：雜訊通道的資訊傳輸極限。
  • Hamming(7,4)：3 個同位位元 + 4 個資料位元，症候碼直接指出 1 位元的出錯位置。
  • 交叉熵損失 = KL 散度（真實熵為 0 時）：深度學習分類任務的損失函數，有清晰的資訊理論根基。

Shannon 1948：資訊時代的原點

Claude Shannon 在 1948 年發表的 A Mathematical Theory of Communication（Bell System Technical Journal） 是計算機科學史上最重要的論文之一。他在一篇論文裡同時定義了「位元(bit)」這個詞、建立了熵的理論、 證明了源編碼定理與通道編碼定理——幾乎憑一己之力奠定了整個資訊理論的基礎。 這篇論文距今超過 75 年，每一段推導至今仍然成立。
