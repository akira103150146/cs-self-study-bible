CPU 畫一像素 vs GPU 同時畫百萬像素

想像你被要求把一張 1920×1080 的畫面填上顏色,每個像素都要執行一段光照計算——大約兩百萬次。 如果用 CPU,你的 8 核處理器一次只能跑 8 個執行緒;就算每個執行緒每奈秒完成一次計算, 填完一幀也要數十毫秒,遠遠達不到遊戲要求的每秒 60 幀(每幀 16.7 ms)。

GPU 用一個截然不同的思路解決這個問題。一塊現代 GPU 可能有 3000–20000 個著色器核心(shader core), 每個核心都能獨立執行一小段程式。當你渲染 1080p 畫面時,GPU 把這兩百萬個像素 分配給幾千個核心同時處理——每個核心負責幾百個像素,並行執行同一段著色器程式碼, 只有輸入資料(像素座標、插值後的頂點屬性)不同。

🔑
SIMT 模型

GPU 採用 SIMT(Single Instruction, Multiple Threads) 架構:所有執行緒執行同一段程式, 但對不同的資料操作。你寫的著色器函式就是那段「每個執行緒都跑一遍」的程式——GPU 負責決定有多少執行緒同時跑它。

早期 GPU 的管線是固定功能(fixed-function)的:你能設定參數(光源位置、材質顏色), 但光照計算的邏輯是寫死在硬體裡的。2001 年前後,GPU 開始支援可程式化著色器(programmable shader), 讓開發者自己決定每個頂點和每個像素「該怎麼計算」。這扇門一打開,整個即時繪圖的世界就爆炸了: 卡通渲染、水彩效果、物理正確的光照、程序生成的地形——全都變成可能。

📜
著色器語言的演進

2001 年 NVIDIA 推出 GeForce 3,首次支援可程式化頂點著色器。2004 年 OpenGL 2.0 引入 GLSL(OpenGL Shading Language), 把著色器語言標準化為類 C 語法。同期 DirectX 9 引入 HLSL,Cg(NVIDIA)也短暫流行。 今天 WebGL 使用 GLSL ES(嵌入式版本),WebGPU 則改用 WGSL 這套新語言。

圖形管線全貌回顧:哪些階段可程式化?

在第 39 章我們學過圖形管線的原理——從 3D 座標到螢幕像素的整個流程。 這裡快速重溫一遍,重點標出哪些階段是「你可以用 GLSL 控制的」,哪些是 GPU 硬體自動完成的。

用一句話描述這條管線:CPU 把頂點資料塞給 GPU; 頂點著色器把每個頂點從 3D 模型空間變換到螢幕空間; 光柵化把三角形填成像素格子; 片段著色器為每個像素決定顏色; 最後輸出合併做深度測試(z-buffer)與透明度混合,把結果寫入 framebuffer。

在現代 OpenGL(3.3+)與 WebGL 2 中,頂點著色器和片段著色器是必填的; 幾何著色器(geometry shader)與曲面細分著色器(tessellation shader)是選填的進階功能; compute shader 則完全脫離這條管線、作為獨立的 GPGPU 計算單元——我們後面會單獨討論。

GLSL 基礎:著色器的語言

GLSL(OpenGL Shading Language)的語法很像 C,但它沒有指標、沒有動態記憶體分配、 不能遞迴——因為 GPU 執行模型要求每個執行緒獨立、固定大小地執行。 它的核心是一套為向量/矩陣量身打造的型別系統。

型別系統

// ── 純量 ──
float f = 0.5;
int   i = 3;
bool  b = true;

// ── 向量(最常用!) ──
vec2  uv   = vec2(0.5, 0.5);       // UV 座標、2D 位置
vec3  pos  = vec3(1.0, 0.0, 0.0);  // 3D 位置、顏色(RGB)
vec4  clip = vec4(pos, 1.0);       // 齊次座標、RGBA

// 向量分量可用 .xyzw 或 .rgba 或 .stpq 存取(語意相同)
vec3 col = vec3(1.0, 0.5, 0.0);
float r   = col.r;          // == col.x == col.s
vec2  rg  = col.rg;         // swizzle:取前兩個分量
vec3  bgr = col.bgr;        // swizzle 可換順序

// ── 矩陣 ──
mat4 mvp;                   // 4×4 矩陣(column-major)
mat3 normalMat;             // 3×3,用於法向量變換

// ── 取樣器(紋理) ──
uniform sampler2D tex;       // 2D 紋理
uniform samplerCube cubemap; // 立方體貼圖
⚠️
float 字面值必須帶小數點

GLSL 嚴格區分 float 與 int。寫 vec3(1, 0, 0) 在 WebGL ES 2.0 裡會報錯;正確寫法是 vec3(1.0, 0.0, 0.0)。這是初學者最常踩的第一個雷。

限定詞(Qualifiers)

GLSL 靠限定詞區分不同「來源」的資料:

限定詞使用位置意義
attribute (ES 2.0) / in (ES 3.0+)頂點著色器輸入每個頂點不同:位置、法向量、UV
varying (ES 2.0) / out/in (ES 3.0+)頂點→片段傳遞由 GPU 在三角形面上做插值
uniform兩種著色器均可整個 draw call 期間固定:矩陣、光源位置、時間
out片段著色器輸出這個片段的顏色(寫入 framebuffer)

內建變數與函式

// ── 頂點著色器內建 ──
gl_Position  // vec4:必須賦值,裁剪空間座標
gl_PointSize // float:點的大小(以像素為單位)

// ── 片段著色器內建(ES 2.0) ──
gl_FragCoord    // vec4:片段在螢幕上的座標(唯讀)
gl_FragColor    // vec4:輸出顏色(ES 2.0 舊式寫法)
gl_FrontFacing  // bool:是否為正面多邊形

// ── 常用內建函式 ──
dot(a, b)         // 點積
cross(a, b)       // 叉積(vec3)
normalize(v)      // 單位向量
length(v)         // 向量長度
reflect(I, N)     // 反射向量
clamp(x, 0.0, 1.0)  // 夾值
mix(a, b, t)      // 線性插值: a*(1-t)+b*t
smoothstep(e0, e1, x) // 平滑步階函式
texture(sampler, uv)  // 紋理採樣(ES 3.0)
ℹ️
WebGL ES 2.0 vs 3.0

WebGL 1 對應 GLSL ES 1.00(用 attribute/varying/gl_FragColor); WebGL 2 對應 GLSL ES 3.00(用 in/out,加上 #version 300 es 宣告)。 本章範例以 WebGL 2 / GLSL ES 3.00 為主,並在需要時標注差異。

頂點著色器:把幾何搬到螢幕上

頂點著色器的職責只有一件事:把每個頂點從模型空間(model space) 變換到裁剪空間(clip space),寫入 gl_Position。 其餘的(法向量、UV、顏色)則打包傳給片段著色器做後續計算。

MVP 矩陣變換

在第 39 章我們推導過 MVP 矩陣: Model(把物體放到世界)→ View(把世界移到相機前)→ Projection(把 3D 投影到 2D 裁剪立方體)。 在 GPU 上,這三個矩陣通常合併成一個 mat4 傳入著色器: 

#version 300 es
// ── 頂點著色器 ──
layout(location = 0) in vec3 aPosition;  // 模型空間頂點座標
layout(location = 1) in vec3 aNormal;    // 法向量
layout(location = 2) in vec2 aTexCoord;  // UV 座標

uniform mat4 uMVP;        // Model * View * Projection
uniform mat4 uModel;      // 僅 Model 矩陣(用於世界空間法向量)
uniform mat3 uNormalMat;  // transpose(inverse(mat3(uModel)))

out vec3 vWorldPos;   // 傳給片段著色器:世界空間位置
out vec3 vNormal;     // 傳給片段著色器:世界空間法向量
out vec2 vTexCoord;   // 傳給片段著色器:UV

void main() {
    // 齊次座標:把 vec3 變成 vec4(w=1 表示「點」)
    vec4 worldPos4 = uModel * vec4(aPosition, 1.0);
    vWorldPos  = worldPos4.xyz;

    // 法向量需用法線矩陣變換(不能直接乘 Model,否則非均勻縮放會出錯)
    vNormal    = normalize(uNormalMat * aNormal);

    vTexCoord  = aTexCoord;

    // 最終裁剪空間座標
    gl_Position = uMVP * vec4(aPosition, 1.0);
}
💡
為什麼法向量需要特殊矩陣?

如果物體被不均勻縮放(x 方向拉長兩倍、y 方向不變),直接用 Model 矩陣乘法向量會讓法向量偏斜, 破壞光照計算。正確做法是用 法線矩陣(normal matrix)= transpose(inverse(mat3(Model)))。這個矩陣在 CPU 端計算好再當 uniform 傳進來, 避免在著色器裡做昂貴的逆矩陣計算。

Varying 插值

頂點著色器輸出的 out 變數(vWorldPos、vNormal、vTexCoord) 不是直接傳給片段著色器的——GPU 會在光柵化階段對三角形的三個頂點值做重心插值(barycentric interpolation): 三角形內部每個像素,都會拿到這三個頂點值依距離加權的插值結果。 這就是為什麼你給三個頂點各塗一個顏色,整個三角形就會自動出現漸層。

片段著色器:逐像素實作光照

片段著色器是整個圖學最「有趣」的地方——因為你在這裡決定每個像素的顏色, 可以實作任何你想要的視覺效果。我們從最經典的 Phong 光照開始。

Phong 光照模型

Phong 把物體表面的反射分成三個分量的疊加:

  • 環境光(ambient):模擬漫反射的全域底色——沒有這個,背陰面會全黑。
  • 漫反射(diffuse):符合 Lambert 餘弦定律——光線越正面照,越亮;斜射則暗。
  • 鏡面反射(specular):高光點——光線的反射方向接近視線方向時,出現亮斑。
#version 300 es
precision mediump float;

// 從頂點著色器插值傳來
in vec3 vWorldPos;
in vec3 vNormal;
in vec2 vTexCoord;

// uniform:每個 draw call 固定
uniform vec3  uLightPos;    // 光源世界座標
uniform vec3  uViewPos;     // 相機世界座標
uniform vec3  uLightColor;  // 光源顏色
uniform vec3  uObjectColor; // 物體基底色

out vec4 fragColor;

void main() {
    // --- 準備向量(全部單位化) ---
    vec3 N = normalize(vNormal);
    vec3 L = normalize(uLightPos - vWorldPos);   // 指向光源
    vec3 V = normalize(uViewPos  - vWorldPos);   // 指向相機
    vec3 R = reflect(-L, N);                     // L 對 N 的反射

    // --- 三分量 ---
    // 1. 環境光:常數比例
    float ka = 0.15;
    vec3 ambient = ka * uLightColor;

    // 2. 漫反射:Lambert 餘弦定律
    float kd = max(dot(N, L), 0.0);
    vec3 diffuse = kd * uLightColor;

    // 3. 鏡面反射:Blinn-Phong 用 half vector 更自然
    vec3 H = normalize(L + V);          // 半程向量(Blinn-Phong)
    float shininess = 64.0;             // 光澤度:越大越銳利
    float ks = pow(max(dot(N, H), 0.0), shininess);
    vec3 specular = ks * uLightColor;

    // --- 合併 ---
    vec3 result = (ambient + diffuse + specular) * uObjectColor;
    fragColor = vec4(result, 1.0);
}
💡
Blinn-Phong vs 原版 Phong

原版 Phong 用 dot(R, V)(反射向量對視線);Blinn-Phong 改用 dot(N, H)(法向量對半程向量 H=(L+V)/|L+V|)。 Blinn-Phong 效果更接近真實高光,且在光線從背後來時不會出現數值問題, 因此成為工業標準。大多數你看到的「Phong 著色器」其實是 Blinn-Phong。

PBR:基於物理的渲染核心公式

Phong 是近似值;PBR(Physically Based Rendering,基於物理的渲染)試圖更精確地模擬光與材質的交互。 (本書第 110 章 PBR 詳細推導將在進階電腦圖學部分呈現。)PBR 的反射率方程核心:

$$L_o(p, \omega_o) = \int_\Omega (k_d \frac{c}{\pi} + k_s \frac{DFG}{4(\omega_o \cdot n)(\omega_i \cdot n)}) L_i(p, \omega_i)(\omega_i \cdot n)\, d\omega_i$$

實作上,PBR 片段著色器用金屬度(metallic)和粗糙度(roughness)兩個參數, 搭配 Cook-Torrance BRDF(雙向反射率分佈函式)的三個項目: 

// PBR 片段著色器的核心計算(簡化版,完整實作見 LearnOpenGL PBR 章節)
// D:法線分佈函式(GGX/Trowbridge-Reitz)
float D_GGX(float NdotH, float roughness) {
    float a  = roughness * roughness;
    float a2 = a * a;
    float denom = (NdotH * NdotH * (a2 - 1.0) + 1.0);
    return a2 / (3.14159265 * denom * denom);
}

// F:Fresnel 項(Schlick 近似)
vec3 F_Schlick(float cosTheta, vec3 F0) {
    return F0 + (1.0 - F0) * pow(clamp(1.0 - cosTheta, 0.0, 1.0), 5.0);
}

// G:幾何遮蔽函式(Smith-GGX)
float G_Smith(float NdotV, float NdotL, float roughness) {
    float r  = roughness + 1.0;
    float k  = (r * r) / 8.0;
    float gv = NdotV / (NdotV * (1.0 - k) + k);
    float gl = NdotL / (NdotL * (1.0 - k) + k);
    return gv * gl;
}

紋理與取樣

光用顏色 uniform 無法表達磚牆或木紋的細節——這時候需要紋理貼圖(texture mapping): 把一張圖的顏色「貼」到 3D 物體表面。

UV 座標與 texture() 函式

每個頂點都帶有一對 UV 座標(又稱紋理座標,範圍通常是 [0,1]×[0,1]): 告訴 GPU 這個頂點對應到紋理的哪個位置。光柵化插值之後,片段著色器就能用插值後的 UV 採樣紋理: 

#version 300 es
precision mediump float;

in vec2 vTexCoord;        // 插值後的 UV
uniform sampler2D uTex;   // 2D 紋理物件

out vec4 fragColor;

void main() {
    // texture() 函式:傳入採樣器 + UV,回傳 vec4 RGBA
    vec4 texColor = texture(uTex, vTexCoord);
    fragColor = texColor;
}

Mipmap 與過濾

當紋理在螢幕上顯示得很小(遠處的地板磚)時,GPU 從一張高解析度紋理只採樣一個像素, 可能造成閃爍的摩爾紋(aliasing)。Mipmap 是預先計算的紋理金字塔: 原始尺寸 → 1/2 → 1/4 → ...,GPU 根據物體在螢幕上的大小自動挑選合適的層級。 搭配三線性過濾(trilinear filtering),可在層級之間平滑插值,消除閃爍。 

// WebGL 2 設定 mipmap 與三線性過濾
const tex = gl.createTexture();
gl.bindTexture(gl.TEXTURE_2D, tex);
gl.texImage2D(gl.TEXTURE_2D, 0, gl.RGBA, gl.RGBA, gl.UNSIGNED_BYTE, img);
gl.generateMipmap(gl.TEXTURE_2D);  // 自動產生 mipmap 金字塔
gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_MIN_FILTER, gl.LINEAR_MIPMAP_LINEAR); // 三線性
gl.texParameteri(gl.TEXTURE_2D, gl.TEXTURE_MAG_FILTER, gl.LINEAR); // 放大用雙線性

法線貼圖(Normal Mapping)

法線貼圖是一種不增加幾何細節、卻能讓光照「感覺」有細節的技巧: 把每個像素的法向量偏移量存進一張 RGB 紋理(R→X, G→Y, B→Z), 片段著色器讀取後替換掉插值法向量再做光照計算。 遠遠看去,平坦的牆面就好像凹凸不平一樣——但三角形數量一個都沒增加。 

// 法線貼圖採樣(切線空間 → 世界空間,需要 TBN 矩陣)
uniform sampler2D uNormalMap;

// 從法線貼圖讀取並解碼到 [-1, 1]
vec3 normalMapSample = texture(uNormalMap, vTexCoord).rgb;
vec3 tangentNormal   = normalMapSample * 2.0 - 1.0; // [0,1] → [-1,1]

// 用 TBN 矩陣把切線空間轉到世界空間
// (TBN 由頂點的 Tangent/Bitangent/Normal 組成,需從頂點著色器傳入)
vec3 N = normalize(vTBN * tangentNormal);

即時技術:陰影、延遲著色與後處理

Shadow Mapping:兩趟渲染

陰影貼圖(shadow mapping)是即時渲染中最廣泛使用的陰影技術,核心思路只有一句話: 從光源的視角先渲染一次場景,把每個點的深度存下來;第二次從相機視角渲染時, 檢查每個像素「光源是否看得到它」——如果看不到,它就在陰影裡。

第一趟(深度貼圖生成):

  • 把相機改到光源位置,用光源的投影矩陣(方向光用正投影,點光用透視投影)渲染整個場景。
  • 只需要深度值,不需要顏色——輸出寫到一個深度紋理(DEPTH_COMPONENT 格式)。

第二趟(場景渲染 + 陰影判斷):

// 片段著色器:shadow mapping 陰影判斷
uniform sampler2D uShadowMap;  // 第一趟渲染出的深度紋理
uniform mat4 uLightSpaceMat;   // 光源的 View*Projection 矩陣

float shadowTest(vec3 worldPos) {
    // 把世界座標變換到光源裁剪空間
    vec4 lightSpacePos = uLightSpaceMat * vec4(worldPos, 1.0);
    // 透視除法,轉到 NDC [-1,1]
    vec3 projCoords = lightSpacePos.xyz / lightSpacePos.w;
    // 從 [-1,1] 轉到 [0,1](UV 空間)
    projCoords = projCoords * 0.5 + 0.5;

    // 讀取光源深度貼圖中記錄的最近深度
    float closestDepth = texture(uShadowMap, projCoords.xy).r;
    // 當前片段在光源空間的深度
    float currentDepth = projCoords.z;

    // 稍微偏移以避免自遮擋(shadow acne)
    float bias = 0.005;
    return currentDepth - bias > closestDepth ? 1.0 : 0.0; // 1=在陰影中
}

void main() {
    float shadow = shadowTest(vWorldPos);
    // 在陰影中只保留環境光,其餘光照乘以 (1-shadow)
    vec3 lighting = ambient + (1.0 - shadow) * (diffuse + specular);
    fragColor = vec4(lighting * uObjectColor, 1.0);
}
⚠️
Shadow Acne 與 Peter Panning

不加 bias(偏移),自遮擋問題(shadow acne)會讓物體表面出現條紋雜訊。 bias 加太大則會造成物體「浮空」(peter panning)。 進階解法是PCF(Percentage Closer Filtering):對周圍多個紋素採樣並平均, 既能消除 acne 又能軟化陰影邊緣。

延遲著色(Deferred Shading)

傳統的前向渲染(forward rendering)對每個幾何體執行一次完整的光照片段著色器——若場景有 200 個光源、 10000 個三角形,每個三角形都要對 200 個光源各計算一次,大量浪費。

延遲著色把渲染分成兩趟:

  1. 幾何趟(Geometry Pass / G-Buffer):把每個像素的 位置(position)、法向量(normal)、漫反射顏色(albedo)、材質參數等 寫入多張離屏紋理——這組紋理合稱 G-Buffer(幾何緩衝)。
  2. 光照趟(Lighting Pass):畫一個全螢幕的四邊形, 片段著色器從 G-Buffer 讀取每個像素的資料,對所有光源各計算一次光照並累加。 由於此時每個「像素」的幾何已確定(沒有被遮擋的問題),計算量大幅減少。

後處理(Post-Processing)

後處理是在主場景渲染完成後,對整張 framebuffer 再做一次全螢幕的片段著色器處理: Bloom(亮部光暈)、景深(Depth of Field)、色調映射(Tone Mapping from HDR)、SSAO(環境遮蔽)等。 實作方式:把主渲染的輸出寫到一個紋理,再畫一個全螢幕四邊形並對該紋理做效果處理。

Compute Shader 與 WebGL / WebGPU 生態

Compute Shader:脫離圖形管線的 GPGPU

Compute shader 不屬於頂點→片段的渲染管線——它是一個獨立的 GPU 計算單元, 讓你直接在 GPU 上做任意並行計算:布料模擬、粒子系統、影像後處理、機器學習推論。 與第 118 章介紹的 CUDA 最大的差別在於:compute shader 在圖形 API(OpenGL/WebGPU)內執行, 能直接存取已綁定的紋理與緩衝,無需跨 API 拷貝資料。 

// OpenGL Compute Shader 範例:反轉圖像顏色
#version 430
layout(local_size_x = 16, local_size_y = 16) in; // 工作群組大小

layout(rgba8, binding = 0) uniform image2D uImage;

void main() {
    ivec2 texCoord = ivec2(gl_GlobalInvocationID.xy);
    vec4 color = imageLoad(uImage, texCoord);
    imageStore(uImage, texCoord, vec4(1.0 - color.rgb, color.a)); // 反色
}

gl_GlobalInvocationID 是 compute shader 的「自我定位」變數——類似 CUDA 的 threadIdx + blockIdx。 local_size_x/y 定義每個工作群組的大小(通常取 16×16=256 個執行緒)。

練習:自己動手寫著色器

✏️ 練習 111.1 實作

在 Shadertoy 新建一個 shader, 只修改 mainImage 函式,實現以下效果:

  1. 畫面顯示一個從左(紅)到右(藍)的橫向漸層背景。
  2. 在畫面正中央額外疊加一個半徑 0.3(以畫面高度為 1)的白色實心圓。

提示:Shadertoy 的 fragCoord 原點在左下,iResolution.y 是畫面高度。

看解答 
void mainImage(out vec4 fragColor, in vec2 fragCoord) {
    // 歸一化 UV:x 在 [0,1],y 在 [0,aspect]
    vec2 uv = fragCoord / iResolution.xy;

    // 1. 漸層:用 uv.x 插值紅→藍
    vec3 col = mix(vec3(1.0, 0.0, 0.0), vec3(0.0, 0.0, 1.0), uv.x);

    // 2. 圓形判斷:以畫面高度為單位,計算到中心的距離
    vec2 center = vec2(0.5, 0.5);          // 歸一化中心
    float dist = length(uv - center);      // 到中心距離
    if (dist < 0.3) col = vec3(1.0);      // 圓內塗白

    fragColor = vec4(col, 1.0);
}

關鍵概念: mix(a, b, t) 是 GLSL 的線性插值函式(a*(1-t)+b*t); length() 計算向量長度,是判斷是否在圓內的最直觀方式。 注意 if (dist < 0.3) 在程式碼中要把 < 寫成 &lt;, 但在著色器字串本身(非 HTML)中直接寫 < 即可。

✏️ 練習 111.2 實作

在本章「動手實作」的 WebGL 範例基礎上,修改片段著色器,把 Blinn-Phong 鏡面反射的 shininess 從 32.0 改為 256.0,並加入第二個固定光源(方向 (-1, 1, 2),顏色偏藍)。 觀察高光形狀與顏色的變化。

看解答

在片段著色器中新增第二光源計算,然後將兩者相加:

void main(){
  vec3 N = normalize(vNorm);

  // 光源 1(暖白)
  vec3 L1 = normalize(vec3(1.0, 2.0, 3.0));
  float diff1 = max(dot(N, L1), 0.0);
  vec3 H1 = normalize(L1 + vec3(0.0, 0.0, 1.0));
  float spec1 = pow(max(dot(N, H1), 0.0), 256.0); // 高 shininess → 小而銳的高光

  // 光源 2(冷藍)
  vec3 L2 = normalize(vec3(-1.0, 1.0, 2.0));
  float diff2 = max(dot(N, L2), 0.0);
  vec3 H2 = normalize(L2 + vec3(0.0, 0.0, 1.0));
  float spec2 = pow(max(dot(N, H2), 0.0), 256.0);

  vec3 lightCol1 = vec3(1.0, 0.95, 0.8);  // 暖白
  vec3 lightCol2 = vec3(0.4, 0.6, 1.0);   // 冷藍

  vec3 col = 0.05 * vColor
           + (0.6 * diff1 * lightCol1 + 0.3 * spec1 * lightCol1) * vColor
           + (0.4 * diff2 * lightCol2 + 0.2 * spec2 * lightCol2) * vColor;
  fragColor = vec4(col, 1.0);
}

觀察重點:shininess=256 時高光點極小且銳利(像拋光金屬); 32 時高光範圍大而柔和(像橡膠或亞光塑料)。 兩個光源相加時,注意要確保總亮度不超過 1.0,否則顏色會溢出(clamp 到白色)。

✏️ 練習 111.3 思考

用自己的話解釋 shadow mapping 的「兩趟渲染」:

  1. 第一趟渲染了什麼?從哪個視角渲染?輸出是什麼格式?
  2. 第二趟如何用第一趟的輸出判斷某個片段是否在陰影中?
  3. 為什麼需要 bias(深度偏移)?若 bias 設得太大會出現什麼問題?
看解答

1. 第一趟:從光源的視角渲染整個場景,只記錄每個像素的深度值(不計算顏色)。 輸出是一張深度貼圖(depth map / shadow map),格式通常是 DEPTH_COMPONENT—— 每個紋素存一個 float,代表「從光源看去,這個方向上最近的物體有多遠」。

2. 第二趟:對每個要著色的片段,先把它的世界座標用光源的 VP 矩陣 變換到光源裁剪空間,換算成 UV 後查詢深度貼圖,得到光源看到的最近深度 closestDepth。 再計算當前片段在光源方向上的深度 currentDepth。 若 currentDepth > closestDepth(當前片段比最近物體更遠), 代表有東西擋在中間→該片段在陰影裡。

3. Bias 的必要性:深度貼圖的解析度有限(例如 1024×1024), 一個紋素對應場景中的一個區域。物體的「自身深度」在計算精度上略大於深度貼圖中存的值, 會誤判自己遮蔽自己→表面出現條紋(shadow acne)。 加一個小偏移 bias(如 0.005)讓比較有一點寬容。 但 bias 過大會讓物體看起來「浮在空中」(peter panning), 陰影脫離物體底部。

✏️ 練習 111.4 挑戰

試在 Shadertoy 實作一個 2D ray marching SDF(有號距離場)場景:在片段著色器裡定義一個 圓(length(uv) - 0.3)和一個矩形的 SDF,用 min() 合併兩個形狀, 並依距離場的梯度估算法向量,套用簡單的漫反射光照。

看解答 
// 2D SDF ray marching 示範(Shadertoy)
float sdCircle(vec2 p, float r) { return length(p) - r; }
float sdBox(vec2 p, vec2 b) {
    vec2 d = abs(p) - b;
    return length(max(d, 0.0)) + min(max(d.x, d.y), 0.0);
}
float scene(vec2 p) {
    float c = sdCircle(p - vec2(-0.2, 0.0), 0.25);
    float b = sdBox(p - vec2(0.3, 0.0), vec2(0.15, 0.2));
    return min(c, b); // union
}
// 數值梯度估算法向量
vec2 calcNorm(vec2 p) {
    float e = 0.001;
    return normalize(vec2(
        scene(p + vec2(e,0.0)) - scene(p - vec2(e,0.0)),
        scene(p + vec2(0.0,e)) - scene(p - vec2(0.0,e))
    ));
}
void mainImage(out vec4 fragColor, in vec2 fragCoord) {
    vec2 uv = (fragCoord - iResolution.xy * 0.5) / iResolution.y;
    float d = scene(uv);
    vec3 col = vec3(0.05); // 背景
    if (d < 0.0) {         // 在形狀內
        vec2 N = calcNorm(uv);
        vec2 L = normalize(vec2(1.0, 1.5));
        float diff = max(dot(N, L), 0.0);
        col = vec3(0.2 + 0.8 * diff);
    }
    // 邊緣柔化
    col *= 1.0 - smoothstep(0.0, 0.005, d);
    fragColor = vec4(col, 1.0);
}

SDF(有號距離場)讓複雜形狀的布林運算變得極為簡單: min() = 聯集,max() = 交集,- = 差集。 3D 延伸後就是 ray marching 渲染的基礎,shadertoy 上大量精彩效果都用這個技術。

把這一章串起來

從 CPU 的序列思維跳到 GPU 的 SIMT 平行模型,是學習著色器最重要的第一步: 你寫的不是「一個程式跑一次」,而是「一個函式同時被幾千個執行緒套用到不同的資料上」。

本章的知識脈絡:

  • 第 39 章講了圖形管線的數學原理(齊次座標、MVP、Phong 模型、光柵化);本章把那些原理「實作」進 GLSL 著色器,讓你真的能在 GPU 上跑起來。
  • GLSL 語言:型別系統(vec/mat/sampler)、限定詞(in/out/uniform)、內建函式(normalize/dot/reflect/texture)是寫所有著色器的基礎詞彙。
  • 頂點著色器負責把幾何搬到螢幕上(MVP 矩陣),並把插值資料(法向量、UV)傳給片段著色器。
  • 片段著色器是視覺效果的核心:Phong/Blinn-Phong 光照、PBR、紋理採樣、法線貼圖都在這裡實作。
  • 即時技術:shadow mapping(兩趟渲染+深度比較)、deferred shading(G-Buffer 解耦幾何與光照)、後處理(全螢幕 quad + 效果 shader)是現代遊戲引擎的標配。
  • Compute shader 讓 GPU 脫離圖形管線做通用並行計算,與第 118 章 GPU/CUDA 的差別在於它在圖形 API 內原生運作,共享紋理資源。

著色器的本質

著色器就是一個純函式:輸入是幾何資料(位置、法向量、UV),輸出是位置或顏色。 GPU 把這個函式並行套用到每個頂點或每個像素上。 理解這個心智模型之後,你能寫的效果就只受限於你的數學想像力。
