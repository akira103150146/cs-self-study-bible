一百萬個數字:為什麼需要 NumPy

假設你有一百萬個數字:可能是一百萬個像素的亮度,也可能是一百萬筆成績。你想把每一個都乘 2 再加 1。 用第 2 章學的 Python,最自然的寫法是一個 list comprehension。 用 NumPy(Numerical Python),寫法是 a * 2 + 1,整個陣列一次算完。兩種寫法都量一下時間: 

import timeit
import numpy as np

n = 1_000_000
xs = list(range(n))            # Python 列表:一百萬個 int 物件
a = np.arange(n)               # NumPy 陣列:同樣的一百萬個整數

ys = [x * 2 + 1 for x in xs]   # Python 迴圈:一次算一個
b = a * 2 + 1                  # 向量化:整個陣列一次算
print(ys[:5], b[:5])

# 各跑 5 次取最快的一次(第一次常會比較慢)
t_loop = min(timeit.repeat(lambda: [x * 2 + 1 for x in xs], number=1, repeat=5))
t_vec = min(timeit.repeat(lambda: a * 2 + 1, number=1, repeat=5))
print(f"迴圈 {t_loop * 1000:.1f} ms,向量化 {t_vec * 1000:.2f} ms,快 {t_loop / t_vec:.0f} 倍")
[1, 3, 5, 7, 9] [1 3 5 7 9]
迴圈 31.9 ms,向量化 0.68 ms,快 47 倍

結果一樣,速度差了四、五十倍(你的電腦上數字會不一樣,倍數通常在幾十倍)。差在哪裡?

  • Python 列表裡放的是一百萬個「指向 int 物件的指標」。每算一個 x * 2 + 1,直譯器都要查型別、找加法函式、配置一個新的 int 物件。真正的乘法只占一小部分時間。
  • NumPy 陣列是一塊連續的記憶體,裡面直接放一百萬個 8 位元組的整數,而且大家的型別都一樣。 a * 2 + 1 只查一次型別,然後交給一個用 C 寫好的迴圈,一口氣算完。CPU 的快取和 SIMD 指令(一個指令同時算好幾個數)都派得上用場。

ndarray:一塊有形狀的記憶體

NumPy 的核心是 ndarray(n-dimensional array,n 維陣列)。它有三樣最重要的屬性: 形狀(shape)是每一維有多長;維度數(ndim)是有幾維,每一維也叫一個軸(axis); dtype(data type)是每一個元素的型別。 

import numpy as np

a = np.array([[1, 2, 3],
              [4, 5, 6]])      # 從巢狀列表建立:2 列 3 欄
print(a)
print("shape:", a.shape, " ndim:", a.ndim, " size:", a.size)
print("dtype:", a.dtype, " itemsize:", a.itemsize, " nbytes:", a.nbytes)

print(np.zeros((2, 3)))             # 全 0,預設 float64

print(np.arange(0, 10, 3))          # 像 range:不含 10

dtype:每個元素都是同一種型別

建立陣列時,NumPy 會找一個「裝得下全部元素」的型別。之後存進去的值,一律轉成這個型別,不會自動升級:

print(np.array([True, False]).dtype)

print(np.array([7, -7]) // 2)           # // 向下取整,和 Python 一樣
print(np.array([1.9, -1.9]).astype(np.int64))   # 轉整數:直接砍掉小數(往 0)

a = np.array([1, 2, 3])

print(a)

uint8 的陷阱:200 + 100 = 44

uint8 是「無號 8 位元整數」,只能放 0 到 255。灰階影像的每一個像素通常就是一個 uint8(見第 69 章)。 它很省記憶體,但算術結果超過範圍時,會繞回來:結果是「真正的答案 mod 256」,而且不會有任何警告。 

import numpy as np

p = np.array([200, 100, 30], dtype=np.uint8)   # 三個像素的亮度(0–255)
q = np.array([100, 200, 40], dtype=np.uint8)

print(p + q)            # 200+100=300 → 繞回 44
print(p - q)            # 100-200=-100 → 繞回 156
print(p * 2)            # 200*2=400 → 繞回 144
print(p.sum(), p.sum().dtype)        # 加總會自動換成大的整數型別
print(p.astype(np.int16) + q)        # 先換成放得下的型別再算
[44 44 70]
[100 156 246]
[144 200  60]
330 uint64
[300 300  70]

300 − 256 = 44;−100 + 256 = 156;30 − 40 = −10,−10 + 256 = 246;400 − 256 = 144。 注意 p.sum() 沒有出事:NumPy 的加總會把小整數換成 64 位元再加。出事的是逐元素的 +、-、*、**。 所以兩張影像相減、求差的平方之前,一定要先用 astype 換成放得下的型別。 本章 Lab 的隱藏檢定也會拿 uint8 的像素來試你的距離函式。

Python 的 int 確實不會溢位,2 ** 100 也算得出來。很多小例子在 NumPy 裡也算得對,因為數字還沒大到超出範圍。 但 NumPy 的 int64 是固定 64 位元的機器整數:

形狀與 reshape

同一塊資料,可以用不同的形狀來「看」。reshape 不搬動任何數字,只改變「怎麼把一排數字切成列與欄」: 

import numpy as np

a = np.arange(12)              # [0 1 2 ... 11]
b = a.reshape(3, 4)            # 3 列 4 欄:一列一列填
print(b)
print(a.reshape(2, -1).shape)  # -1:這一維由 NumPy 自己算
print(b.T.shape)               # 轉置:(3, 4) → (4, 3)
print(b.ravel())               # 攤平回一維

# reshape 只是換一種「看法」,資料還是同一塊
b[0, 0] = 100
print(a[:3])

幾個重點:

  • 列優先(row-major,也叫 C order):NumPy 預設先填滿第 0 列,再填第 1 列。所以 b[i, j] 對應攤平後的第 i*4 + j 個。上面的 assert 就是這句話的程式版。
  • -1 讓 NumPy 自己算那一維:12 個元素分成 2 列,每列就是 6 個。一次只能有一個 -1。
  • reshape 通常回傳視圖(view):和原陣列共用同一塊記憶體。改 b[0, 0],a[0] 也跟著變。
  • 機器學習常見的形狀:一張 8×8 的灰階圖是 (8, 8);攤平成特徵向量是 (64,);4,000 張疊起來是 (4000, 64),一列一筆資料。

多維也是一樣的規則。形狀 (2, 3, 4) 的陣列,最後一軸變化最快:c[i, j, k] 在攤平後的位置是 $i \cdot (3 \cdot 4) + j \cdot 4 + k$。NumPy 把「每一軸往前一格要跳幾個位元組」記在 strides 裡, np.arange(24).reshape(2, 3, 4).strides 是 (96, 32, 8):12 × 8、4 × 8、1 × 8。

向量化:把迴圈交給 C

開頭的例子是「每個元素乘 2 加 1」。再看一個機器學習天天在做的計算:平方和 $\sum_i x_i^2$。四種寫法:

計時請在單執行緒下跑:先在終端機設 OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1,例如 OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 python3 vec.py。 多核的機器上,內積用的 BLAS 函式庫預設會開好幾個執行緒;一百萬個元素的內積太小,開執行緒的成本比省下的時間還多。 在一台 20 個執行緒的桌上型電腦上實測,預設設定下 vec_dot 要 2.4–2.6 ms,反而比 vec_sum(1.3–1.8 ms)慢。 

# 先在終端機設 OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 再執行(見上面的說明)
import timeit
import numpy as np

n = 1_000_000
xs = [i * 0.001 for i in range(n)]   # Python 列表
a = np.array(xs)                     # 同樣的資料,float64 陣列

def loop_list():                     # 1. 純 Python
    s = 0.0
    for x in xs:
        s += x * x
    return s

def loop_array():                    # 2. 用 Python 迴圈走過 ndarray
    s = 0.0
    for x in a:
        s += x * x
    return s

def vec_sum():                       # 3. 向量化:先平方、再加總
    return np.sum(a * a)

def vec_dot():                       # 4. 內積:一步完成
    return a @ a

for f in (loop_list, loop_array, vec_sum, vec_dot):
    t = min(timeit.repeat(f, number=1, repeat=5))
    print(f"{f.__name__:10s} {f():.6e}  {t * 1000:8.2f} ms")

(時間是一台桌上型電腦單執行緒的一次執行。你的數字會不一樣,但只要也是單執行緒,快慢的順序和大概的倍數應該差不多。)

  • 第 2 種最慢,比純 Python 還慢約 5 倍。用 for 迴圈走過 ndarray,每拿一個元素,NumPy 都要把那 8 個位元組包成一個新的 Python 物件(np.float64)。把資料放進 NumPy、卻還是一個一個算,兩邊的缺點都拿到了。
  • 第 3 種比純 Python 快約 18 倍。a * a 先建出一個一百萬個元素的新陣列,np.sum 再加總。
  • 第 4 種單執行緒時又快約 4 倍:a @ a 是內積,交給高度最佳化的 BLAS 函式庫,不必建中間陣列。
  • 四個答案印到 6 位有效數字都一樣,但最後幾位可能不同:NumPy 的加總用「兩兩相加」的順序,浮點數的捨入和一個一個加不一樣(見第 59 章)。比較浮點結果要用 np.allclose,不要用 ==。

NumPy 的數學函式都是逐元素的,叫 ufunc(universal function):np.sqrt、np.exp、np.log、np.abs、np.maximum…… 比較運算子也是,結果是布林陣列。有 if 的迴圈,常常可以改用 np.where:

print(np.where(x > 0, x, 0.1 * x))    # 條件成立取 x,不成立取 0.1x
print(np.sqrt(np.abs(x)).round(3))    # 函式一個接一個套,每一步都是整個陣列
print(x > 0)                          # 比較也是逐元素:得到布林陣列

小技巧:什麼時候不必硬要向量化

如果第 i 步要用到第 i−1 步的結果(例如模擬一個會互相影響的系統),就不一定能向量化。先找有沒有現成的函式(累積和 np.cumsum、累積乘積 np.cumprod); 真的沒有,迴圈也沒關係。另外,資料只有幾十筆時,可讀性比速度重要。

廣播:形狀不一樣也能算

💡
為什麼要學

機器學習的公式幾乎都靠廣播:第 39 章的線性模型 X @ w + b,是 (n,) 加上一個純量; 每一欄減掉自己的平均,是 (n, d) 減 (d,);一次算出所有點兩兩之間的距離,是三維的廣播。 本章 Lab nn/arrays 的第一個任務目標「廣播規則」,要你自己寫出「兩個形狀廣播之後是什麼形狀」;Boss 戰「向量化 kNN」也是靠它才跑得夠快。

a + 10 其實已經是廣播了:一個陣列加一個純量,純量被「拉長」成和陣列一樣的形狀。 廣播(broadcasting)把這個想法推廣到兩個陣列: 

import numpy as np

a = np.array([[0], [10], [20]])   # 形狀 (3, 1):一欄
b = np.array([0, 1, 2, 3])        # 形狀 (4,):一列
c = a + b                         # (3, 1) 和 (4,) → (3, 4)
print(c)
print(c.shape)

# 廣播的意思:把長度 1 的軸「假裝複製」到需要的長度
a_big = np.tile(a, (1, 4))        # 真的複製成 (3, 4)
b_big = np.tile(b, (3, 1))        # 真的複製成 (3, 4)
assert np.array_equal(c, a_big + b_big)
# 逐格的不變式:c[i, j] = a[i, 0] + b[j]
for i in range(3):
    for j in range(4):
        assert c[i, j] == a[i, 0] + b[j]
print("不變式成立")

axis 與 keepdims

💡
為什麼要學

資料表一列一筆資料、一欄一個特徵。「每個特徵的平均」是沿 axis 0;「每筆資料的機率分布」(softmax,第 39 章的多類別分類)是沿 axis 1; 一批影像 (批次, 高, 寬) 又多一軸。Lab nn/arrays 的 standardize 與 softmax 都要能沿任何一軸算,隱藏檢定「任何軸」會拿 axis=0、1、-1 與三維陣列來試。

sum、mean、max 這類「把很多數字變成一個」的運算叫聚合(reduction)。給它 axis=k, 意思是「沿著第 k 軸把數字聚合起來」,第 k 軸就消失了。

圖 132-2 的文字版:X = [[1, 2, 3], [4, 5, 6]],形狀 (2, 3)。 X.sum(axis=0) 是 [1+4, 2+5, 3+6] = [5, 7, 9],形狀 (3,); X.sum(axis=1) 是 [1+2+3, 4+5+6] = [6, 15],形狀 (2,); X.sum(axis=1, keepdims=True) 是 [[6], [15]],形狀 (2, 1)。

import numpy as np

X = np.array([[1., 2., 3.],
              [4., 5., 6.]])          # 2 筆資料(列)× 3 個特徵(欄)
print(X.sum())                        # 全部加起來
print(X.sum(axis=0))                  # 沿著 axis 0(往下)加:每一欄的和
print(X.sum(axis=1))                  # 沿著 axis 1(往右)加:每一列的和
print(X.sum(axis=1, keepdims=True))   # 保留被加掉的那一維:形狀 (2, 1)
print(X / X.sum(axis=1, keepdims=True))   # 每一列除以自己的和 → 每列加起來是 1

「每一列除以自己的和」是機器學習最常見的動作之一:把每筆資料的分數變成機率。keepdims=True 讓列和保持 (2, 1), 靠右對齊後是「一欄」,剛好往右複製到每一欄。沒有 keepdims 時是 (2,),被拿去對「欄」,形狀對不上就報錯。

同樣的道理,「每一欄減掉自己的平均、除以自己的標準差」叫標準化(standardization)。沿 axis 0 時,剛好不需要 keepdims:

softmax 把一列分數 $z_1, \dots, z_K$ 變成機率:$\mathrm{softmax}(z)_i = e^{z_i} / \sum_j e^{z_j}$。 它也是「沿一軸先取 exp、再除以那一軸的和」,和上面的「每一列除以自己的和」是同一種形狀問題。 但直接照公式算,分數大一點就出事: 

import numpy as np

z = np.array([1000., 1001., 1002.])
e = np.exp(z)          # e 的 1000 次方超過 float64 的上限(約 1.8e308)
print(e)
print(e / e.sum())     # inf / inf = nan
[inf inf inf]
[nan nan nan]

(stderr 另外有 overflow encountered in exp 與 invalid value encountered in divide 兩行警告。)解法來自一個等式:對任何常數 $c$,

$$\frac{e^{z_i - c}}{\sum_j e^{z_j - c}} = \frac{e^{z_i} e^{-c}}{e^{-c} \sum_j e^{z_j}} = \frac{e^{z_i}}{\sum_j e^{z_j}}.$$

分子分母同乘 $e^{-c}$,約掉了。取 $c = \max_j z_j$,每一個 $z_j - c \le 0$,$e^{z_j - c}$ 最大是 1,不會溢位; 而且最大的那一項是 $e^0 = 1$,分母至少是 1,不會變成 0 / 0。上面的例子減掉 1002 之後是 $[-2, -1, 0]$,答案約是 [0.090, 0.245, 0.665]。 Lab 的 softmax(Z, axis) 要你沿著任何一軸做這件事:每一列(或每一欄)減掉自己那一軸的最大值。想想看,要用到這一節的哪一個參數?

距離矩陣與 kNN:從三層迴圈到廣播

第 39 章介紹的 k-近鄰(k-nearest neighbors,kNN)是最樸素的分類法: 要分類一個新的點,就找訓練資料裡離它最近的 k 個點,看它們多數是哪一類。不用訓練,但每一個查詢點都要和全部訓練點算距離。 n 個查詢點、m 個訓練點,就是一個 n × m 的距離矩陣:D[i, j] 是第 i 個查詢點到第 j 個訓練點的距離。 比大小時,用平方距離 $\|a - b\|^2 = \sum_k (a_k - b_k)^2$ 就夠了(開根號不改變誰比較近),還省掉 n × m 次開根號。

同一個距離矩陣,三種寫法:

import time
import numpy as np

def sq_dists_python(A, B):
    """純 Python:A、B 是列表的列表。三層迴圈。"""
    return [[sum((a - b) ** 2 for a, b in zip(p, q)) for q in B] for p in A]

def sq_dists_loop(A, B):
    """兩層 Python 迴圈,最裡面那一層(d 個維度)交給 NumPy。"""
    n, m = len(A), len(B)
    D = np.empty((n, m))
    for i in range(n):
        for j in range(m):
            diff = A[i] - B[j]
            D[i, j] = diff @ diff
    return D

def sq_dists_3d(A, B):
    """沒有 Python 迴圈:先廣播出 (n, m, d) 的差,再沿最後一軸加總。"""
    diff = A[:, None, :] - B[None, :, :]   # (n, 1, d) − (1, m, d) → (n, m, d)
    return (diff ** 2).sum(axis=-1)        # (n, m)

rng = np.random.default_rng(1)
A = rng.random((200, 64))     # 200 個查詢點,每個 64 維
B = rng.random((1000, 64))    # 1000 個訓練點

for f, args in [(sq_dists_python, (A.tolist(), B.tolist())),
                (sq_dists_loop, (A, B)),
                (sq_dists_3d, (A, B))]:
    t = time.perf_counter()
    D = np.array(f(*args))
    print(f"{f.__name__:16s} {time.perf_counter() - t:6.3f} 秒  {D.shape}")

D1, D2 = sq_dists_loop(A, B), sq_dists_3d(A, B)
# 不變式:兩種寫法一樣;平方距離不會是負的;自己到自己是 0
assert np.allclose(D1, D2)
assert (D2 >= 0).all()
assert np.allclose(np.diag(sq_dists_3d(A, A)), 0)

  • A[:, None, :] 的 None(也可以寫 np.newaxis)在那個位置插入一個長度 1 的軸:(200, 64) 變成 (200, 1, 64)。和 (1, 1000, 64) 廣播,得到 (200, 1000, 64):每一對 (i, j) 的差向量都在裡面。
  • 三維廣播版沒有任何 Python 迴圈,卻只比兩層迴圈版快 2 倍左右。因為它先寫出一個 102 MB 的中間陣列,平方時再寫一個 102 MB 的,最後再讀一遍來加總。 瓶頸變成記憶體頻寬,不是計算。
  • 把規模放大到 nn 任務線 Boss 戰「向量化 kNN」的大小(1,620 個查詢點、4,000 個訓練點、64 維),中間陣列要 3.32 GB。很多電腦會直接記憶體不足;就算放得下,也很慢。

「程式開頭寫了 np.random.seed(0),後面所有的亂數就都固定了。」寫一段程式證明這句話不對。正確的寫法是什麼?

import numpy as np

np.random.seed(0)                          # 只會固定舊的全域亂數(np.random.rand 那一套)
print(np.random.rand())                    # 每次都一樣
print(np.random.default_rng().integers(1000))   # 新的 Generator 沒給種子:每次都不同
print(np.random.default_rng(0).integers(1000))  # 種子要直接交給 default_rng

np.random.seed 只管舊的全域產生器。default_rng() 沒給種子時,會向作業系統要一個新的亂數種子,和全域種子無關。正確的寫法:rng = np.random.default_rng(0),之後所有亂數都從這個 rng 要。

把這一章串起來

  • ndarray:一塊連續的記憶體,加上形狀與 dtype。全部同一個型別,所以可以交給 C 一口氣算。dtype 不會自動升級:uint8 的 200 + 100 = 44,int64 也會溢位,存進整數陣列的小數會被砍掉。
  • 形狀:reshape 只換看法、不搬資料(列優先,c[i, j, k] 在 12i + 4j + k);整數索引拿掉一軸、切片保留一軸;切片是視圖,遮罩與花式索引是副本。
  • 向量化:把迴圈搬到 C,通常快幾十倍;但用 for 迴圈走過 ndarray 比純 Python 還慢。沒有迴圈之後,還要算一下中間陣列有多大。
  • 廣播:靠右對齊、左邊補 1,每一維相等或有一邊是 1。維度數不同也可以廣播;(n,) 和 (n, 1) 混用會默默變成 (n, n)。
  • axis 與 keepdims:axis=k 就是第 k 軸消失;keepdims 讓它變成 1,才能再廣播回去。方陣忘了 keepdims 不會報錯,只會算錯。softmax 減掉每一列的最大值,結果不變、也不溢位。
  • 亂數:rng = np.random.default_rng(seed) 建立一次、一路用下去;同一組索引同時切 X 和 y。
  • 線性代數:矩陣乘法用 @,(n, d) @ (d, k) → (n, k);* 是逐元素。解方程組用 solve。
  • 距離矩陣與 kNN:三維廣播沒有迴圈,但 1,620 × 4,000 × 64 要 3.32 GB;Lab 要你找出不建這個中間陣列的寫法。kNN 的規則:距離相同索引小的先、同票取最小的類別。
  • pandas:Series 是有標籤的一欄,DataFrame 是共用索引的很多欄。loc 看標籤、iloc 看位置;改資料用一個 loc。先看 shape、dtypes、isna().sum()、describe();補值是一個要寫下來的決定;pandas 跳過 NaN、std 除以 n − 1。
  • groupby 與 merge:分組、套用、合併;平均的平均不是全體平均。merge 之後一定比列數:inner 會悄悄變少,重複的鍵會悄悄變多,用 validate 擋住。
