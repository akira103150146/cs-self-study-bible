里程碑 1 — REPL 與 meta 指令

所有互動式程式的起點都是 REPL——讀取一行輸入、求值(evaluate)、印出結果、重複(loop)。 把 DB 的 REPL 先建好,其他所有功能都插進去這個框架。 

# db.py — 里程碑 1：REPL 框架
import sys

def main():
    db_file = sys.argv[1] if len(sys.argv) > 1 else ":memory:"
    print(f"MiniDB v0.1  (file: {db_file})")

    while True:
        try:
            line = input("minidb> ").strip()
        except (EOFError, KeyboardInterrupt):
            print("\nBye.")
            break

        if not line:
            continue

        if line.startswith("."):
            result = handle_meta(line)
            if result == "EXIT":
                break
        else:
            handle_sql(line, db_file)   # 里程碑 2 以後才真正實作

def handle_meta(cmd: str) -> str:
    """處理 meta 指令 (.exit, .help, .tables ...)"""
    if cmd == ".exit":
        print("Bye.")
        return "EXIT"
    elif cmd == ".help":
        print("  .exit    離開 MiniDB")
        print("  .tables  列出所有資料表")
        print("  .stats   顯示 pager 統計")
    elif cmd == ".tables":
        print("(尚未實作:里程碑 4 之後可列出資料表)")
    else:
        print(f"未知 meta 指令: {cmd}")
    return "OK"

def handle_sql(sql: str, db_file: str):
    print(f"[TODO] 執行 SQL: {sql}")

if __name__ == "__main__":
    main()

執行 python db.py mydb.db,就能看到提示符 minidb>。 輸入 .exit 離開,輸入任何 SQL 都印出「TODO」。 這個框架是所有後續里程碑的插槽(socket)——每個里程碑只需要替換對應的函式。

里程碑 2 — SQL 前端:Tokenizer 與解析器

SQL 是一種領域專用語言(domain-specific language,DSL)。 把 INSERT INTO users VALUES (1, 'Alice', 'alice@example.com') 這串字符 變成程式能操作的結構,需要兩個步驟: 詞法分析(tokenization) 把字串切成有意義的最小單元(token), 語法分析(parsing) 則把 token 串組合成代表「語句意圖」的抽象語法樹(AST,abstract syntax tree)。

Tokenizer

# tokenizer.py — 里程碑 2 前半部
from dataclasses import dataclass
from enum import Enum, auto
from typing import List

class TT(Enum):    # TokenType 縮寫
    KW   = auto()  # 關鍵字 INSERT / SELECT / FROM / INTO / VALUES / WHERE
    ID   = auto()  # 識別子(資料表名稱、欄位名稱)
    INT  = auto()  # 整數字面值
    STR  = auto()  # 字串字面值 'Alice'
    COMMA   = auto()
    LPAREN  = auto()
    RPAREN  = auto()
    STAR    = auto()
    EQ      = auto()
    EOF     = auto()

KEYWORDS = {"INSERT","INTO","VALUES","SELECT","FROM","WHERE","CREATE","TABLE"}

@dataclass
class Token:
    type: TT
    value: str

def tokenize(sql: str) -> List[Token]:
    """把 SQL 字串切成 Token 串列。遇到無法識別的字元拋 SyntaxError。"""
    tokens, i, n = [], 0, len(sql.strip())
    sql = sql.strip()
    while i < n:
        c = sql[i]
        if c.isspace():
            i += 1
        elif c in ",()":
            t = {",": TT.COMMA, "(": TT.LPAREN, ")": TT.RPAREN}[c]
            tokens.append(Token(t, c)); i += 1
        elif c == "*":
            tokens.append(Token(TT.STAR, "*")); i += 1
        elif c == "=":
            tokens.append(Token(TT.EQ, "=")); i += 1
        elif c == "'":               # 單引號字串
            j = sql.index("'", i + 1)
            tokens.append(Token(TT.STR, sql[i+1:j])); i = j + 1
        elif c.isdigit():
            j = i
            while j < n and sql[j].isdigit(): j += 1
            tokens.append(Token(TT.INT, sql[i:j])); i = j
        elif c.isalpha() or c == "_":
            j = i
            while j < n and (sql[j].isalnum() or sql[j] == "_"): j += 1
            word = sql[i:j].upper()
            tokens.append(Token(TT.KW if word in KEYWORDS else TT.ID, word)); i = j
        else:
            raise SyntaxError(f"未知字元 '{c}' at pos {i}")
    tokens.append(Token(TT.EOF, ""))
    return tokens

極簡 Parser

我們只支援兩種語句: INSERT INTO <table> VALUES (<id>, <name>, <email>) 與 SELECT * FROM <table>(里程碑 6 加 WHERE)。 Parser 用遞迴下降(recursive descent)手法——每個語法規則對應一個函式。 

# parser.py — 極簡遞迴下降解析器
from tokenizer import tokenize, TT, Token
from dataclasses import dataclass
from typing import Optional, List

@dataclass
class InsertStmt:
    table: str
    row_id: int
    name: str
    email: str

@dataclass
class SelectStmt:
    table: str
    where_id: Optional[int] = None   # 里程碑 6 才使用

class Parser:
    def __init__(self, sql: str):
        self.tokens = tokenize(sql)
        self.pos = 0

    def peek(self) -> Token:
        return self.tokens[self.pos]

    def consume(self, expected_type: TT = None, expected_val: str = None) -> Token:
        tok = self.tokens[self.pos]
        if expected_type and tok.type != expected_type:
            raise SyntaxError(f"期望 {expected_type},得到 {tok}")
        if expected_val and tok.value != expected_val:
            raise SyntaxError(f"期望 '{expected_val}',得到 '{tok.value}'")
        self.pos += 1
        return tok

    def parse(self):
        tok = self.peek()
        if tok.type == TT.KW and tok.value == "INSERT":
            return self.parse_insert()
        elif tok.type == TT.KW and tok.value == "SELECT":
            return self.parse_select()
        else:
            raise SyntaxError(f"不支援的語句開頭: {tok.value}")

    def parse_insert(self):
        self.consume(TT.KW, "INSERT")
        self.consume(TT.KW, "INTO")
        table = self.consume(TT.ID).value
        self.consume(TT.KW, "VALUES")
        self.consume(TT.LPAREN)
        row_id = int(self.consume(TT.INT).value)
        self.consume(TT.COMMA)
        name  = self.consume(TT.STR).value
        self.consume(TT.COMMA)
        email = self.consume(TT.STR).value
        self.consume(TT.RPAREN)
        return InsertStmt(table=table, row_id=row_id, name=name, email=email)

    def parse_select(self):
        self.consume(TT.KW, "SELECT")
        self.consume(TT.STAR)
        self.consume(TT.KW, "FROM")
        table = self.consume(TT.ID).value
        # 可選的 WHERE id = N
        if self.peek().type == TT.KW and self.peek().value == "WHERE":
            self.consume()   # WHERE
            self.consume(TT.ID)   # 欄位名稱(我們只支援 id)
            self.consume(TT.EQ)
            where_id = int(self.consume(TT.INT).value)
            return SelectStmt(table=table, where_id=where_id)
        return SelectStmt(table=table)

里程碑 3 — 記憶體中的資料表:列結構與頁

SQL 前端把輸入轉成了 InsertStmt / SelectStmt。 現在要真的存放資料。我們先做「純記憶體版本」——像 SQLite 的早期實作一樣, 用固定大小的頁(page)在記憶體中管理列(row),為後面的持久化做準備。

列的二進位格式

每筆列佔固定的位元組數,讓「列 N 在哪裡」能用乘法直接算出來,無需遍歷: 

# row.py — 列的序列化
import struct

# schema: (id: u32, name: 32-byte str, email: 255-byte str) = 291 bytes/row
ROW_FORMAT = "I 32s 255s"          # struct format string
ROW_SIZE   = struct.calcsize(ROW_FORMAT)   # 291 bytes

def serialize_row(row_id: int, name: str, email: str) -> bytes:
    """把一筆列封裝成固定大小的位元組串。"""
    return struct.pack(
        ROW_FORMAT,
        row_id,
        name.encode("utf-8")[:32],
        email.encode("utf-8")[:255],
    )

def deserialize_row(data: bytes) -> dict:
    """從位元組串還原一筆列。"""
    row_id, raw_name, raw_email = struct.unpack(ROW_FORMAT, data)
    return {
        "id":    row_id,
        "name":  raw_name.rstrip(b"\x00").decode("utf-8"),
        "email": raw_email.rstrip(b"\x00").decode("utf-8"),
    }

頁結構

頁(page)是儲存引擎最小的 I/O 單位——磁碟讀寫永遠以整頁為單位, 即使你只需要一個位元組。這和作業系統的分頁(paging)同一個道理 (見 第 24 章)。 我們使用 4 096 位元組(4 KiB)頁,與 SQLite 預設一致: 

# page.py — 頁常數
PAGE_SIZE        = 4096            # 4 KiB
ROWS_PER_PAGE    = PAGE_SIZE // ROW_SIZE   # ≈ 14 rows/page

class Table:
    """純記憶體版本:把每一頁存成一個 bytes 物件的陣列。"""
    def __init__(self):
        self.pages: list[bytes | None] = [None] * 100   # 最多 100 頁
        self.num_rows = 0

    def row_slot(self, row_num: int):
        """計算第 row_num 筆列所在的(page_idx, byte_offset)。"""
        page_idx = row_num // ROWS_PER_PAGE
        row_offset = row_num % ROWS_PER_PAGE
        byte_offset = row_offset * ROW_SIZE
        return page_idx, byte_offset

    def insert(self, row_id: int, name: str, email: str):
        page_idx, byte_offset = self.row_slot(self.num_rows)
        if self.pages[page_idx] is None:
            self.pages[page_idx] = bytearray(PAGE_SIZE)
        data = serialize_row(row_id, name, email)
        self.pages[page_idx][byte_offset:byte_offset + ROW_SIZE] = data
        self.num_rows += 1

    def select_all(self):
        for i in range(self.num_rows):
            page_idx, byte_offset = self.row_slot(i)
            chunk = self.pages[page_idx][byte_offset:byte_offset + ROW_SIZE]
            yield deserialize_row(bytes(chunk))
🔑
核心觀念:固定大小是 O(1) 定址的關鍵

因為每筆列大小固定(ROW_SIZE 位元組),第 N 筆的位元組位置 = N × ROW_SIZE, 一個乘法直接算出,不需要遍歷。這是「固定欄位長度」設計的根本優勢, 也是為何傳統 RDBMS 對 VARCHAR 儲存格外謹慎。

✏️ 里程碑 3 檢查點 實作

實作 往返驗證(round-trip test):把一筆列序列化後立刻反序列化, 斷言結果與原始資料相同。 

# 測試目標:以下所有斷言必須通過
row_in = (1, "Alice", "alice@example.com")
blob   = serialize_row(*row_in)
row_out = deserialize_row(blob)

assert len(blob) == ROW_SIZE, f"期望 {ROW_SIZE} bytes,實際 {len(blob)}"
assert row_out["id"]    == 1
assert row_out["name"]  == "Alice"
assert row_out["email"] == "alice@example.com"
print("往返驗證通過 ✓")
看解答與常見陷阱

直接把上方程式碼加到 row.py 末尾,用 if __name__ == "__main__": 包起來,執行即可。

里程碑 4 — 持久化與 pager

里程碑 3 的 Table 是純記憶體的:程式一結束,資料就消失。 這一步要把頁持久化(persist)到磁碟上——程式重啟後資料還在。 這正是 第 24 章檔案 I/O 知識的實戰。

Pager 是儲存引擎的門衛:它維護一個「頁快取(page cache)」, 讓上層的 B-tree 或執行器以頁號(page number)讀寫資料,不需要關心磁碟細節。

資料庫檔案格式

我們的 .db 檔案結構極簡:

  • 第 0 頁:根頁(root page)——B-tree 的根節點從這裡開始。
  • 第 1、2、3 … 頁:B-tree 節點依序儲存。
  • 所有頁等長(4 096 bytes),「頁 N 的位元組位置 = N × PAGE_SIZE」——O(1) 定址。
# pager.py — 磁碟頁管理器
import os
from page import PAGE_SIZE

class Pager:
    """Pager:把頁號對應到磁碟位置,並維護記憶體快取。"""

    def __init__(self, filename: str):
        if filename == ":memory:":
            self._file = None          # 純記憶體模式
            self._next_page_num = 0
        else:
            # "a+b" 在 Linux O_APPEND 下 seek()+write() 位置不可靠;
            # 改用 "r+b"(需先建空檔)確保隨機讀寫正確
            if not os.path.exists(filename):
                open(filename, "wb").close()
            self._file = open(filename, "r+b")
            # _next_page_num 初始化為磁碟現有頁數,避免新頁號與根頁(0)衝突
            self._next_page_num = os.path.getsize(filename) // PAGE_SIZE
        self._cache: dict[int, bytearray] = {}
        self.reads  = 0
        self.writes = 0
        self.cache_hits = 0

    def allocate_page(self) -> int:
        """分配下一個新頁號:取 _next_page_num 與快取現有最大頁號+1 的較大值,
        確保新頁號不與任何現有頁(磁碟或快取)重疊。首次分裂時 old_page 已在快取,
        故 max(cache)+1 >= 1,安全地避開根頁(0)。"""
        num = max(self._next_page_num,
                  max(self._cache.keys()) + 1 if self._cache else 0)
        self._next_page_num = num + 1
        return num

    @property
    def num_pages(self) -> int:
        if self._file is None:
            return 0
        size = os.path.getsize(self._file.name)
        return size // PAGE_SIZE

    def get_page(self, page_num: int) -> bytearray:
        """讀取頁 page_num,優先從快取取,否則從磁碟讀。"""
        if page_num in self._cache:
            self.cache_hits += 1
            return self._cache[page_num]

        # 快取 miss:從磁碟讀取(或新建空頁)
        self.reads += 1
        page = bytearray(PAGE_SIZE)
        if self._file and page_num < self.num_pages:
            self._file.seek(page_num * PAGE_SIZE)
            data = self._file.read(PAGE_SIZE)
            page[:len(data)] = data
        self._cache[page_num] = page
        return page

    def flush(self, page_num: int):
        """把快取中的頁 page_num 寫回磁碟。"""
        if self._file is None or page_num not in self._cache:
            return
        self._file.seek(page_num * PAGE_SIZE)
        self._file.write(self._cache[page_num])
        self._file.flush()
        self.writes += 1

    def flush_all(self):
        """程式結束前,把所有「髒頁」寫回磁碟。"""
        for page_num in list(self._cache.keys()):
            self.flush(page_num)

    def close(self):
        self.flush_all()
        if self._file:
            self._file.close()

注意 get_page 先查快取(cache lookup),只有 miss 才真正做磁碟 I/O—— 這就是緩衝池(buffer pool)的最基本形式,也是資料庫能在大多數情況下省去磁碟讀寫的關鍵。

💡
開檔模式:為何改用 "r+b"?

Linux 的 O_APPEND flag 讓所有 write() 都強制跳到檔末, 無論先前 seek() 到哪裡,因此 "a+b" 模式下 seek()+write() 的寫入位置不可靠。 正確做法:若檔案不存在先以 "wb" 建立空檔,再以 "r+b" 開啟, 才能真正支援隨機讀寫且不截斷——等同於 C 語言的 fopen(path, "r+b")。

里程碑 5 — B-tree 索引:從葉節點到分裂

有了 pager,我們可以把第 29 章的 B-tree 理論真正實作出來。 為什麼 SQLite 用 B-tree 而不是陣列?答案和 第 28 章的搜尋分析完全一致:

  • 陣列:查找 O(log n)(二分搜),但插入 O(n)(要搬移元素)。
  • B-tree:查找 和 插入都是 O(log n),且每個節點恰好佔一頁——讀一個節點 = 一次磁碟 I/O。
🔑
B-tree 是為磁碟而生的資料結構

B-tree 的「矮胖」形狀(高分支因子 b、樹高 $O(\log_b n)$)恰好讓每次查找的磁碟 I/O 次數最小化。 SQLite 預設 b ≈ 481(每個內部節點可放 480 個子指標),一棵高度 3 的 B-tree 能索引超過一億筆記錄!

節點格式

我們實作 B+ tree(B-plus tree)——所有資料存在葉節點(leaf node), 內部節點(internal node)只存鍵(key)和子指標。每個節點 = 一個磁碟頁: 

# btree.py — 節點格式常數
import struct
from pager import Pager
from page import PAGE_SIZE

# ─── 通用標頭 (header) ─── 每個節點前 6 bytes
NODE_TYPE_OFFSET   = 0   # 1 byte: 0=leaf, 1=internal
IS_ROOT_OFFSET     = 1   # 1 byte: 1=root
PARENT_PTR_OFFSET  = 2   # 4 bytes: 父節點頁號(root 時為 0)
COMMON_HEADER_SIZE = 6

# ─── 葉節點標頭 ───
LEAF_NUM_CELLS_OFFSET = COMMON_HEADER_SIZE      # 4 bytes
LEAF_HEADER_SIZE      = COMMON_HEADER_SIZE + 4  # 10 bytes

# ─── 葉節點 cell 格式 ─── (key u32 + row bytes)
LEAF_KEY_SIZE    = 4          # u32
LEAF_VALUE_SIZE  = 291        # ROW_SIZE(與 row.py 一致)
LEAF_CELL_SIZE   = LEAF_KEY_SIZE + LEAF_VALUE_SIZE  # 295 bytes
LEAF_SPACE       = PAGE_SIZE - LEAF_HEADER_SIZE     # 4086 bytes
LEAF_MAX_CELLS   = LEAF_SPACE // LEAF_CELL_SIZE     # 13 cells/page

# ─── 內部節點標頭 ───
INTERNAL_NUM_KEYS_OFFSET   = COMMON_HEADER_SIZE
INTERNAL_RIGHT_CHILD_OFFSET= COMMON_HEADER_SIZE + 4
INTERNAL_HEADER_SIZE       = COMMON_HEADER_SIZE + 8

INTERNAL_KEY_SIZE          = 4
INTERNAL_CHILD_SIZE        = 4
INTERNAL_CELL_SIZE         = INTERNAL_KEY_SIZE + INTERNAL_CHILD_SIZE
INTERNAL_MAX_CELLS         = 3   # 學習用:設小,方便觀察分裂

NODE_LEAF     = 0
NODE_INTERNAL = 1

葉節點的讀寫

def leaf_num_cells(page: bytearray) -> int:
    return struct.unpack_from("I", page, LEAF_NUM_CELLS_OFFSET)[0]

def set_leaf_num_cells(page: bytearray, n: int):
    struct.pack_into("I", page, LEAF_NUM_CELLS_OFFSET, n)

def leaf_cell_offset(cell_num: int) -> int:
    return LEAF_HEADER_SIZE + cell_num * LEAF_CELL_SIZE

def leaf_key(page: bytearray, cell_num: int) -> int:
    off = leaf_cell_offset(cell_num)
    return struct.unpack_from("I", page, off)[0]

def leaf_value(page: bytearray, cell_num: int) -> bytes:
    off = leaf_cell_offset(cell_num) + LEAF_KEY_SIZE
    return bytes(page[off: off + LEAF_VALUE_SIZE])

def leaf_insert_cell(page: bytearray, cell_num: int, key: int, value: bytes):
    """在 cell_num 位置插入 (key, value),並將後面的 cell 往右移一格。"""
    n = leaf_num_cells(page)
    if n >= LEAF_MAX_CELLS:
        raise OverflowError("葉節點已滿,需要分裂")
    # 把 cell_num 之後的 cells 向右搬移一格
    for i in range(n, cell_num, -1):
        src = leaf_cell_offset(i - 1)
        dst = leaf_cell_offset(i)
        page[dst: dst + LEAF_CELL_SIZE] = page[src: src + LEAF_CELL_SIZE]
    # 寫入新 cell
    off = leaf_cell_offset(cell_num)
    struct.pack_into("I", page, off, key)
    page[off + LEAF_KEY_SIZE: off + LEAF_CELL_SIZE] = value
    set_leaf_num_cells(page, n + 1)

Cursor 抽象

Cursor(游標)代表「B-tree 中的一個位置」。它讓查詢執行器不需要知道 B-tree 細節, 只需要 cursor.advance() 和 cursor.value() 就能遍歷所有列。 

class Cursor:
    """游標:指向 B-tree 中某個葉節點的某個 cell。"""
    def __init__(self, pager: Pager, page_num: int, cell_num: int):
        self.pager    = pager
        self.page_num = page_num
        self.cell_num = cell_num

    @property
    def end_of_table(self) -> bool:
        page = self.pager.get_page(self.page_num)
        return self.cell_num >= leaf_num_cells(page)

    def value(self) -> bytes:
        """回傳當前 cell 的 value(序列化後的 row)。"""
        page = self.pager.get_page(self.page_num)
        return leaf_value(page, self.cell_num)

    def advance(self):
        """把游標移到下一個 cell(本章暫不處理跨頁的 next-leaf 指標)。"""
        self.cell_num += 1

節點分裂(Node Split)——最關鍵的步驟

當葉節點滿了(leaf_num_cells == LEAF_MAX_CELLS),插入新 cell 前必須先分裂(split)。 分裂把一個滿的葉節點拆成左、右兩個葉節點,並將「分裂點鍵值」上升到父節點。

ℹ️
B+ tree 的分裂規則

分裂點選在 ⌈(N+1)/2⌉(向上取整):若葉節點溢位後有 5 cells,分裂點在索引 3—— 左葉得到前 3 個 cells(含分裂鍵),右葉得到後 2 個。分裂鍵(分裂點的 key)複製到父節點作為分隔鍵(separator key)。 注意 B+ tree 的葉節點保留分裂鍵(資料在葉層不丟失),而傳統 B-tree 則是上升後從葉層移走。

def leaf_split_and_insert(pager: Pager, old_page_num: int,
                          cell_num: int, key: int, value: bytes) -> tuple[int, int]:
    """
    葉節點分裂:
      1. 把 old_page 上的 cells + 新 cell 排序後分成左、右兩半。
      2. 左半留在 old_page,右半放進 new_page(pager 分配下一個空頁)。
      3. 回傳 (split_key, new_page_num) tuple(分裂鍵 + 新頁號)。
    """
    old_page = pager.get_page(old_page_num)
    new_page_num = pager.allocate_page()    # 用計數器確保新頁號 ≠ old_page_num
    new_page = pager.get_page(new_page_num) # 會在 cache 中建立空頁

    # 把 old_page 所有 cells + 新 cell 收集到臨時陣列
    total = LEAF_MAX_CELLS + 1
    all_cells = []
    j = 0
    for i in range(total):
        if i == cell_num:
            all_cells.append((key, value))
        else:
            k = leaf_key(old_page, j)
            v = leaf_value(old_page, j)
            all_cells.append((k, v))
            j += 1

    # 計算分裂點
    left_count  = (total + 1) // 2    # ⌈total/2⌉ 給左葉
    right_count = total - left_count

    # 清空 old_page 並填入左半
    set_leaf_num_cells(old_page, 0)
    for i, (k, v) in enumerate(all_cells[:left_count]):
        off = leaf_cell_offset(i)
        struct.pack_into("I", old_page, off, k)
        old_page[off + LEAF_KEY_SIZE: off + LEAF_CELL_SIZE] = v
    set_leaf_num_cells(old_page, left_count)

    # 填入右半到 new_page
    set_leaf_num_cells(new_page, 0)
    for i, (k, v) in enumerate(all_cells[left_count:]):
        off = leaf_cell_offset(i)
        struct.pack_into("I", new_page, off, k)
        new_page[off + LEAF_KEY_SIZE: off + LEAF_CELL_SIZE] = v
    set_leaf_num_cells(new_page, right_count)

    # 分裂鍵 = 右葉第一個 key(上升到父節點)
    split_key = all_cells[left_count][0]

    # 標記節點類型為葉節點
    old_page[NODE_TYPE_OFFSET] = NODE_LEAF
    new_page[NODE_TYPE_OFFSET] = NODE_LEAF

    return split_key, new_page_num

里程碑 6 — 查詢:SELECT 與 WHERE 過濾

有了 B-tree 和 Cursor,執行 SELECT 就是「把 Cursor 從最左葉節點出發, 逐 cell 讀取直到 end_of_table」。加上 WHERE id = N 則可以走 B-tree 查找直接定位, 不需要掃全表——這就是索引的意義。

全表掃描(Table Scan)

# executor.py — 查詢執行器(局部)
from row import deserialize_row
from btree import Cursor, leaf_num_cells, leaf_value, NODE_TYPE_OFFSET, NODE_LEAF
from pager import Pager

def table_start(pager: Pager) -> Cursor:
    """回傳指向最左葉節點第一個 cell 的 cursor(目前僅單根葉節點)。"""
    return Cursor(pager, page_num=0, cell_num=0)

def execute_select(pager: Pager, where_id: int | None = None):
    """走訪 B-tree 並印出符合條件的列。"""
    cur = table_start(pager)
    while not cur.end_of_table:
        row = deserialize_row(cur.value())
        if where_id is None or row["id"] == where_id:
            print(f"  ({row['id']}, {row['name']!r}, {row['email']!r})")
        cur.advance()

B-tree 查找(B-tree Search)

對有索引的 WHERE id = N,可以做二分搜直接定位到目標 leaf cell: 

def leaf_find(pager: Pager, page_num: int, target_key: int) -> Cursor:
    """
    在葉節點中二分搜 target_key,回傳指向對應 cell(或應插入位置)的 Cursor。
    時間複雜度 O(log M),M = 葉節點 cell 數。
    """
    page = pager.get_page(page_num)
    n = leaf_num_cells(page)
    lo, hi = 0, n
    while lo < hi:
        mid = (lo + hi) // 2
        k = leaf_key(page, mid)
        if k == target_key:
            return Cursor(pager, page_num, mid)
        elif k < target_key:
            lo = mid + 1
        else:
            hi = mid
    return Cursor(pager, page_num, lo)   # lo = 應插入的位置
🔑
全表掃描 vs. 索引查找

SELECT * FROM users(無 WHERE)= 全表掃描,時間 $O(n)$。 SELECT * FROM users WHERE id = 42(主鍵查找)= B-tree 二分搜,時間 $O(\log n)$。 這就是加索引能快千倍的原因——從 第 28 章的理論,在這裡真正落地。

def handle_sql(sql: str, pager: Pager):
    try:
        stmt = Parser(sql).parse()
    except SyntaxError as e:
        print(f"語法錯誤: {e}"); return

    if isinstance(stmt, InsertStmt):

里程碑 7 — 交易與一致性:WAL 與 ACID 一瞥

你的 MiniDB 現在能讀寫磁碟了。但有一個殺手級問題: 如果在 pager.flush() 執行到一半時電源突然斷了,怎麼辦? 你可能把一個 B-tree 頁寫到一半——磁碟上的資料永遠壞掉了。

這就是為什麼所有嚴肅的資料庫系統都需要交易(transaction)保證—— 也就是大名鼎鼎的 ACID 四個性質:

ACID 四個性質

  • 原子性(Atomicity):一個交易要麼完全成功,要麼完全沒發生。不存在「做了一半」的狀態。
  • 一致性(Consistency):交易完成後,資料庫仍滿足所有定義的約束條件(如主鍵唯一性、外鍵參照)。
  • 隔離性(Isolation):並行執行的多個交易,彼此互不干擾——好像每個交易都是獨自在執行。
  • 持久性(Durability):一旦交易提交成功,即使系統立刻崩潰,資料也不會遺失。
📜
ACID 的起源

ACID 由 Jim Gray 在 1970–1980 年代的研究中逐步定義。Gray 後來因資料庫交易研究榮獲 1998 年圖靈獎(Turing Award)。他在 2007 年神秘失蹤——當時他一個人開著帆船出海,至今下落不明。

WAL:預寫日誌

如何在磁碟上實現原子性?最廣泛使用的技術是 WAL(write-ahead log,預寫日誌)——SQLite、PostgreSQL 都用它。 基本思路:

  1. 修改資料之前,先把「打算做的修改」寫進一個獨立的 WAL 日誌檔。
  2. WAL 寫完並 fsync()(確保落磁碟)之後,才把修改套用到正式的資料頁。
  3. 如果步驟 2 中途崩潰:
    - WAL 完整 → 重啟時重播(replay) WAL 來恢復。
    - WAL 不完整(步驟 1 中途崩潰)→ 丟掉 WAL,等同於交易未提交,不影響原始資料。 
# wal.py — 極簡 WAL 骨架(僅示意)
import struct, os

WAL_MAGIC   = b"MWDB"    # 4 bytes: magic number
WAL_FRAME_HDR = 12       # page_num(4) + page_size(4) + checksum(4)

class WAL:
    def __init__(self, wal_path: str):
        self._path = wal_path
        self._frames: list[tuple[int, bytes]] = []  # (page_num, page_data)

    def append(self, page_num: int, page_data: bytes):
        """把一個「將要寫入的頁」追加到 WAL 記憶體緩衝區。"""
        self._frames.append((page_num, bytes(page_data)))

    def commit(self):
        """
        提交:把所有 frame 寫進 WAL 檔,最後呼叫 fsync 確保落磁碟。
        此後才能把修改套用到主資料庫檔案。
        """
        with open(self._path, "ab") as f:
            for page_num, data in self._frames:
                checksum = sum(data) & 0xFFFFFFFF  # 簡化 checksum
                f.write(struct.pack("III", page_num, len(data), checksum))
                f.write(data)
            f.flush()
            os.fsync(f.fileno())   # 強制落磁碟
        self._frames.clear()

    def rollback(self):
        """回滾:直接丟棄記憶體中的 frames,不寫檔。"""
        self._frames.clear()

    def replay(self, pager):
        """重啟時:把 WAL 中所有已提交的 frames 套用到 pager。"""
        if not os.path.exists(self._path):
            return
        with open(self._path, "rb") as f:
            while True:
                hdr = f.read(WAL_FRAME_HDR)
                if len(hdr) < WAL_FRAME_HDR: break
                page_num, size, _ = struct.unpack("III", hdr)
                data = f.read(size)
                if len(data) < size: break   # 不完整的 frame,忽略
                page = pager.get_page(page_num)
                page[:] = data
        os.remove(self._path)   # replay 後刪除 WAL 檔
⚠️
fsync 不可省略

Python 的 f.flush() 只把資料送進作業系統的頁快取(OS page cache), 不保證真正寫到磁碟。只有 os.fsync(fd) 才能保證持久性。 省略 fsync 的「資料庫」在斷電後可能丟失剛剛「已提交」的交易—— 這是許多「土炮資料庫」的致命缺陷。

並行控制(Concurrency Control)概覽

ACID 的隔離性是最複雜的一塊。生產資料庫通常有兩種主流做法:

  • 鎖(locking):讀鎖(shared lock)允許多個讀者並行; 寫鎖(exclusive lock)獨佔資源。SQLite 預設使用檔案鎖實現資料庫級別的鎖定—— 任意時刻只允許一個寫者。
  • MVCC(multi-version concurrency control,多版本並行控制): PostgreSQL 的做法——每次修改不蓋掉原始版本,而是建立新版本, 讓讀者「看到修改前的快照」,讀寫不互相阻塞。 詳見 第 37 章的並行控制小節。
ℹ️
SQLite WAL 模式

SQLite 3.7.0 起支援 WAL 模式(PRAGMA journal_mode=WAL), 讓讀取和一個寫入可以並行發生,大幅提升並發效能。 預設的 DELETE 日誌模式則是每次提交前把修改的頁複製到 .db-journal 檔, 思路略有不同但目標相同。

驗收與延伸:整合七個里程碑

  • 接受 INSERT INTO users VALUES (id, 'name', 'email') 並寫入 B-tree 葉節點。
  • 接受 SELECT * FROM users 並全表掃描印出所有列。
  • 接受 SELECT * FROM users WHERE id = N 並走 B-tree 二分搜直接定位。
  • 程式重啟後,資料仍然存在(pager 的持久化)。
  • 葉節點滿時自動分裂,分裂鍵上升至父節點(里程碑 5 的核心)。

把這一章串起來

你剛剛從零打造了一個能在磁碟上持久化、用 B-tree 索引、 支援 SQL 解析的關聯式資料庫。讓我們把七個里程碑的收穫梳理一遍:

  • 里程碑 1(REPL):所有互動式程式的骨架——讀取、求值、印出、迴圈。 .exit 等 meta 指令和 SQL 走不同路徑。
  • 里程碑 2(SQL 前端):Tokenizer 把字串切成 token, 遞迴下降 Parser 把 token 組合成 InsertStmt/SelectStmt。 固定 schema 讓解析器保持簡單。
  • 里程碑 3(記憶體資料表):struct.pack/unpack 做二進位序列化。 固定大小的列讓「列 N 的位置 = N × ROW_SIZE」——O(1) 定址。
  • 里程碑 4(Pager):頁快取讓 B-tree 以頁號讀寫,實際 I/O 盡量延遲到 flush_all。 頁 N 在檔案中的位置 = N × PAGE_SIZE——同樣是 O(1)。
  • 里程碑 5(B-tree):葉節點儲存資料,內部節點儲存分隔鍵。 節點分裂是最關鍵步驟:把滿的葉節點拆為左右兩半,分裂鍵上升到父節點。 整棵樹的高度 $O(\log_b n)$,保證查找和插入都是 $O(\log n)$ 次磁碟 I/O。
  • 里程碑 6(查詢):Cursor 抽象隔離了 B-tree 細節。 全表掃描 O(n),主鍵查找 O(log n)——索引的威力在這裡真正體現。
  • 里程碑 7(交易):WAL 保障原子性——先寫日誌,再改資料頁, 崩潰後重播恢復。fsync 是持久性的最後一道防線。 MVCC 讓讀寫不互相阻塞。

這一章整合了本書四個大方向的知識: 第 37 章的 SQL 語義與關聯代數、 第 29 章的 B-tree 理論、 第 28 章的二分搜與搜尋分析、 第 24 章的檔案 I/O 與持久化。 一個從零打造的資料庫,是同時驗證這四塊知識的最佳戰場。

「如果你不能簡單地解釋它,你就還沒有真正理解它。」——理查・費曼(Richard Feynman)

能親手寫出 B-tree 分裂,你就真的理解了 B-tree——不只是「知道它是 O(log n)」, 而是「知道每個 case 會怎麼跑、每個 off-by-one 在哪裡」。這就是 capstone 的意義。
