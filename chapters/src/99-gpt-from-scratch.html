🔑
這一章的一條主線

如果這章你只記得一件事,請記得:LLM 是一台「預測下一個 token」的機率機器。 它不「理解」、不「思考」、不查資料庫,它只是反覆地問同一個問題:「給定目前看到的這串 token,下一個最可能是什麼?」 ——然後從機率分佈裡挑一個、接上去、再問一次。整個 ChatGPT,就是這個動作快速重複了上千次的結果。 後面所有的機制(embedding、注意力、Transformer),都只是為了把這個「預測下一個 token」做得夠準。

語言模型在做什麼:預測下一個 token

我們先把「語言模型」這個詞拆開。它的工作,可以用一句你早就會的事情來描述:文字接龍。 給你「今天天氣很」,你大概會接「好」「熱」「冷」,而不會接「香蕉」。你心裡其實對「下一個字」有個機率感: 「好」很可能、「香蕉」幾乎不可能。語言模型做的,就是把這個「機率感」變成一個精確的數學物件。

正式地說:語言模型(language model)是一個函數,給定前面的一串 token $t_1, t_2, \dots, t_{n}$, 它輸出「下一個 token」在整個詞彙表上的機率分佈:

$$P(t_{n+1} \mid t_1, t_2, \dots, t_n)$$

注意這不是只猜一個答案,而是給詞彙表裡每一個可能的 token 各一個機率。 假設詞彙表有 5 萬個 token,模型輸出的就是一個長度 5 萬、加起來等於 1 的機率向量。 生成文字時,我們從這個分佈裡挑一個 token(可以挑機率最大的,也可以帶點隨機性地抽樣), 把它接到句子尾巴,然後把加長後的句子再餵回去,預測再下一個 token——如此反覆。 這種「一次生一個、把輸出接回輸入」的方式,叫自迴歸(autoregressive)生成。

這也立刻解釋了幾個你可能困惑過的現象。模型會幻覺(hallucination),是因為它本來就不是在「查事實」, 而是在「接最像樣的下一個 token」——聽起來通順、統計上合理的句子,不保證為真。它有上下文長度上限, 是因為每次預測能「看」的前文 token 數量有限(這個窗口大小我們等一下會在注意力裡看到)。 而它怎麼學會這套「機率感」的?答案是:讀了海量的文字,反覆做這個「遮住下一個字、猜猜看、對答案、調參數」的練習—— 這正是第 38 章講的監督式學習與梯度下降,只是「標籤」就是「下一個真正出現的 token」, 資料多到不需要人標(這叫自監督 self-supervised)。訓練機制我們複用第 38 章,稍後只補上 LLM 特有的部分。

tokenization:文字怎麼被切開

模型只懂數字,不懂文字。所以餵字進模型前的第一步,是把文字切成一個個單位,再把每個單位對應到一個整數編號。 這個切法叫 tokenization(分詞 / 斷詞),切出來的單位叫 token。

你直覺可能會想:那就一個字一個 token、或一個英文單字一個 token 嘛?兩種都不好。逐字元切, 序列會長到爆炸,而且單一字元「c」幾乎不帶語意;逐單字切,詞彙表會大到無法收拾(英文光是各種變形、拼錯、新詞就無窮多), 遇到沒見過的詞還會直接卡住。現代 LLM 走的是中間路線:子詞(subword)切法,最常見的是 BPE(Byte Pair Encoding,位元組對編碼)。

BPE 的直覺很可愛:先把所有文字拆成最小單位(字元或位元組),然後反覆把「最常一起出現的相鄰一對」合併成一個新 token, 合併個幾萬次,就長出一套詞彙表。結果是:常見的詞(like、the)會變成單一 token;罕見或複合的詞會被切成幾塊 (例如「tokenization」可能被切成 token + ization)。這樣既控制了詞彙表大小,又能用「拼湊」的方式表示任何沒見過的字串。

ℹ️
token 不是字,也不是詞

一個重要的直覺校正:token 是統計切出來的碎片,不對應任何語言學單位。 英文裡 1 個 token 平均約 0.75 個單字;中文一個常用字常是 1 個 token,但生僻字可能被拆成好幾個位元組 token。 這也是為什麼模型「數不清一個單字裡有幾個字母」(它根本沒看到字母,只看到 token), 以及為什麼 API 是按 token 計費、而不是按字數——你之後在第 94 章串接 API 時,會親自和 token 計數打交道。

用 Python 看一眼這個「文字 ↔ 整數」的轉換最直接(這裡用最小的字元級示意,真實 LLM 用的是上面說的 BPE):

# 字元級 tokenizer 示意:真實 LLM 用 BPE(如 tiktoken),原理一樣只是切法更聰明
text = "hello"
chars = sorted(set("helo "))            # 這個小語料的「詞彙表」
stoi = {c: i for i, c in enumerate(chars)}   # token(字元) -> 整數 id
itos = {i: c for c, i in stoi.items()}       # 整數 id -> token

ids = [stoi[c] for c in text]           # 編碼:文字 -> 一串 token id
print(ids)                              # 例如 [1, 2, 3, 3, 4]
print("".join(itos[i] for i in ids))    # 解碼:token id -> 文字 -> "hello"

記住這一步的產出:一段文字,進來之後變成了一串整數 token id,例如 [1, 2, 3, 3, 4]。 模型從頭到尾看到的,就只是這種整數序列。下一個問題是:整數本身沒有意義(id=3 並不比 id=2「大」或「更接近」), 那要怎麼讓模型理解「token 之間的關係」?這就輪到 embedding 上場。

embedding:把 token 變成有意義的向量

把 token id 直接當數字餵進神經網路是行不通的——id=300 和 id=301 在編號上相鄰,語意上卻可能毫無關係。 我們需要的,是讓語意相近的 token,在某個空間裡也靠得近。這個空間,就是第 54 章的主角:向量空間。

embedding(詞嵌入 / 嵌入向量)做的事是:給詞彙表裡每個 token 配一個可學習的向量(例如 768 維)。 這些向量一開始是隨機的,但在訓練過程中會被慢慢調整,最後神奇地排出了結構:意思相近的詞,向量也相近。 最經典的例子,是向量之間竟然能做「語意算術」:

$$\vec{v}_{\text{國王}} - \vec{v}_{\text{男人}} + \vec{v}_{\text{女人}} \approx \vec{v}_{\text{皇后}}$$

這正是第 54 章「向量是空間裡的點、方向有意義」的活生生體現:在這個語意空間裡,「性別」竟然對應到一個固定的方向。 embedding 在程式裡就是一張查表:輸入 token id,查出對應那一列向量。 

import torch
import torch.nn as nn

vocab_size, n_embd = 5000, 768          # 詞彙表大小、每個 token 的向量維度
token_emb = nn.Embedding(vocab_size, n_embd)   # 一張 (5000 x 768) 的可學習查表

ids = torch.tensor([1, 2, 3, 3, 4])     # 上一節得到的 token id 序列(長度 5)
vecs = token_emb(ids)                   # 查表:每個 id 換成一條 768 維向量
print(vecs.shape)                       # torch.Size([5, 768]) ← 5 個 token、各 768 維

位置編碼:把「順序」也告訴模型

這裡藏著一個微妙又關鍵的問題。我們等一下要用的注意力機制,本身是「看不出順序」的—— 對它來說,「狗咬人」和「人咬狗」裡的 token 集合一模一樣,它分不出誰先誰後。但順序顯然攸關意義! 所以我們必須主動把位置資訊注入向量。這就是位置編碼(positional encoding)。

做法直觀:再準備一張「位置」的 embedding 表——第 0 個位置一條向量、第 1 個位置一條向量…… 然後把「token 向量」和「該位置的向量」相加。這樣同一個 token 出現在不同位置, 進入模型的向量就不同,模型於是「感覺得到」順序。 

block_size = 128                              # 模型一次能看的最大 token 數(上下文窗口)
pos_emb = nn.Embedding(block_size, n_embd)    # 位置 0,1,2,... 各配一條向量

T = ids.shape[0]                              # 目前序列長度 = 5
pos = pos_emb(torch.arange(T))                # (5, 768):第 0~4 個位置的向量
x = vecs + pos                                # 逐元素相加:token 含義 + 它在哪裡
print(x.shape)                                # torch.Size([5, 768])

現在 x 裡的每一列,都同時編碼了「這是什麼 token」與「它在第幾個位置」。 這就是真正送進 Transformer 主體的東西。注意這裡的 block_size——它就是模型的上下文長度上限由來: 位置表只準備了這麼多列,超過就沒有位置向量可查了。

注意力機制:讓每個 token 去「看」其他 token

終於來到整個 Transformer 的心臟。前面我們讓每個 token 變成了一條含位置的向量,但這些向量目前還是各自獨立的—— 「它」這個 token 的向量,還不知道前文的「它」指的是「那隻貓」還是「那台車」。語言充滿這種脈絡依賴: 一個詞的意思,取決於它周圍的詞。我們需要一個機制,讓每個 token 能去「看」其他 token、按相關程度蒐集資訊, 來更新自己。這個機制就是注意力(attention)。

Q、K、V:一個圖書館的比喻

想像每個 token 要去一座圖書館找資料。注意力給每個 token 算出三樣東西,都是用它的向量乘上一個可學習的權重矩陣得到的:

  • Query(查詢,$Q$):我「想找什麼」?——像你心裡的搜尋關鍵字。
  • Key(鍵,$K$):我「能提供什麼」?——像每本書背上的標籤。
  • Value(值,$V$):我「實際的內容」是什麼?——像書裡真正的資訊。

流程是:某個 token 拿自己的 Query,去和所有 token 的 Key 比對相似度(用點積), 相似度高的代表「這本書跟我要找的很相關」;把這些相似度經過 softmax 變成一組加起來為 1 的權重; 最後用這組權重,去對所有 token 的 Value 做加權平均。 結果就是:每個 token 都「讀」了一遍全場、按相關度把別人的資訊揉進了自己——它的向量,從此帶上了脈絡。

公式與維度:$\text{softmax}(QK^\top/\sqrt{d_k})\,V$

把上面那段話寫成數學,就是 Transformer 原始論文〈Attention Is All You Need〉(2017)裡那條著名的式子:

$$\text{Attention}(Q, K, V) = \text{softmax}\!\left(\frac{Q K^\top}{\sqrt{d_k}}\right) V$$

這條式子第一次看會發暈,但只要盯著維度看,它就會變得清澈。假設我們有 $n$ 個 token, 每個 token 的 Query/Key 維度是 $d_k$、Value 維度是 $d_v$(常常 $d_k = d_v$)。把它們疊成矩陣:

符號形狀意思
$Q$$n \times d_k$每個 token 各一條 Query(每列一個)
$K$$n \times d_k$每個 token 各一條 Key
$V$$n \times d_v$每個 token 各一條 Value
$K^\top$$d_k \times n$把 $K$ 轉置,好和 $Q$ 相乘
$Q K^\top$$n \times n$注意力分數:第 $i$ 列第 $j$ 行 = token $i$ 的 Query 和 token $j$ 的 Key 的點積
$\text{softmax}(\cdot)$$n \times n$對每一列做 softmax,使每列權重加起來為 1
$\text{softmax}(\cdot)\,V$$n \times d_v$輸出:每個 token 一條「揉進脈絡後」的新向量

關鍵的維度檢查:$Q$ 是 $n \times d_k$、$K^\top$ 是 $d_k \times n$,相乘得到 $n \times n$ 的分數矩陣—— 裡頭裝著「每個 token 對每個 token」的相關度,共 $n^2$ 個數字(這就是為什麼上下文越長、計算量是平方成長,長文本特別吃資源)。 softmax 不改變形狀,還是 $n \times n$;再乘上 $V$($n \times d_v$),維度上 $(n \times n)(n \times d_v) = n \times d_v$—— 輸出 token 數不變、每個 token 一條新向量。進去 $n$ 個 token,出來還是 $n$ 個 token,只是每個都更新過了。

為什麼要除以 $\sqrt{d_k}$?

這個 $\sqrt{d_k}$ 的縮放,常被當成「不知道為什麼但照抄」的細節,其實它的理由很扎實。 $Q$ 和 $K$ 的點積,是 $d_k$ 個乘積的加總。假設 $Q$、$K$ 的每個分量大致是均值 0、變異數 1 的獨立隨機數, 那麼它們點積的變異數會正比於 $d_k$(把 $d_k$ 個變異數 1 的東西加起來),標準差就是 $\sqrt{d_k}$。

當 $d_k$ 很大(例如 64、128),點積的數值就會被放得很大很大。而 softmax 一旦吃到「某個值遠大於其他值」, 會把幾乎全部機率壓到那一個上,輸出趨近一個 one-hot 向量——這時 softmax 進入飽和區、梯度趨近 0, 模型就「學不動」了(這正是第 38 章 sigmoid 飽和、梯度消失的老問題)。 除以 $\sqrt{d_k}$,恰好把點積的標準差拉回到 1 附近,讓 softmax 待在「斜率健康、梯度充足」的區間。 一句話:$\sqrt{d_k}$ 是為了穩住 softmax,不讓它因為維度一大就梯度消失。

自注意力 vs 因果遮罩:不准偷看未來

當 $Q$、$K$、$V$ 全都來自同一串 token 自己(每個 token 既是查詢者、也是被查的對象),這叫自注意力(self-attention)—— 這也是 GPT 用的。但這裡有個致命問題:GPT 的任務是預測下一個 token。如果在預測第 3 個 token 時, 注意力允許第 3 個位置去「看」第 4、第 5 個 token,那不就偷看到答案了嗎?訓練出來的模型一上線(沒有未來可看)就會廢掉。

解法是因果遮罩(causal mask):在做 softmax 之前,把分數矩陣裡所有「未來位置」(第 $i$ 列中 $j > i$ 的那些格子) 強制設成 $-\infty$。因為 $e^{-\infty} = 0$,softmax 之後這些位置的權重剛好變成 0——等於每個 token 只被允許看「自己和前面」、看不到後面。 因為遮掉的恰好是分數矩陣的上三角,所以你也會聽到「下三角遮罩」這個說法。

🔑
因果遮罩 = GPT 的「不准偷看未來」

GPT 屬於 decoder-only 架構,每個位置只能注意到它左邊(含自己)的 token。 這保證了「預測下一個 token」這個任務在訓練與推論時行為一致。(相對地,BERT 那類雙向模型沒有這個遮罩, 每個 token 能看左右兩邊,因為它的任務不是生成、而是理解——這是兩種模型的根本分歧。)

Softmax:把一排分數變成機率分佈

我們在注意力裡用了兩次 softmax,在語言模型的最後輸出也要用它。它是整個 LLM 反覆出現的關鍵零件, 卻是第 38 章(只做到二元的 sigmoid)沒講透的一塊。現在補上。

Softmax 解決的問題是:我手上有一排任意實數分數(可正可負、大小不一), 想把它們變成一個合法的機率分佈(每個都在 0 到 1 之間、全部加起來等於 1)。公式是:

$$\text{softmax}(z)_i = \frac{e^{z_i}}{\sum_{j} e^{z_j}}$$

拆開看就三步:(1) 每個分數取 $e$ 的次方,把它變成正數,而且「大的變得更突出」(指數放大差距); (2) 把所有指數值加起來當分母;(3) 各自除以這個總和來歸一化。 sigmoid 其實就是只有兩類時的 softmax 特例——所以你早在第 38 章就見過它的弟弟了。 

import torch
import torch.nn.functional as F

scores = torch.tensor([1.0, 3.0, 2.0])   # 三個任意分數(例如對 3 個 token 的注意力分數)
probs = F.softmax(scores, dim=-1)         # dim=-1:沿最後一維歸一化
print(probs)                              # tensor([0.0900, 0.6652, 0.2447])
print(probs.sum())                        # tensor(1.0000) ← 是合法機率分佈

# 手算驗證:e^1=2.718, e^3=20.086, e^2=7.389,總和 30.193
# 2.718/30.193=0.090,  20.086/30.193=0.665,  7.389/30.193=0.245 ✓

在語言模型的最後一步,模型對詞彙表裡每個 token 算出一個分數(叫 logits), 再用 softmax 把這 5 萬個分數變成 5 萬個機率——這就是本章一開始那個 $P(t_{n+1} \mid \dots)$。 順帶一提,你在 API 裡調的 temperature(溫度) 參數,做的就是在 softmax 前把 logits 除以一個溫度值: 溫度越高、分佈越平、輸出越隨機有創意;溫度越低、分佈越尖、輸出越保守確定。

Transformer block:把注意力堆成一座塔

單一個注意力層還不夠強。真正的 GPT,是把注意力和幾個夥伴打包成一個Transformer block(區塊), 再把這個 block 疊很多層(GPT-3 疊了 96 層)。一個標準的 block 裡有四個元件:

  • 多頭注意力(multi-head attention):與其做一次注意力,不如並行做好幾次(好幾個「頭」), 每個頭用自己的一組 Q/K/V 權重,各自學會關注不同面向(有的頭管文法、有的頭管指代、有的頭管長距離關係),最後把各頭的輸出拼接起來。
  • 前饋網路(feed-forward network,FFN):注意力之後,每個 token 各自過一個小型的兩層全連接網路(中間夾一個非線性激活,如 ReLU/GELU), 負責「消化」剛剛蒐集來的脈絡資訊。這裡用的就是第 38 章的全連接層與激活函數。
  • 殘差連接(residual connection):把「子層的輸入」直接加到「子層的輸出」上($x + \text{sublayer}(x)$)。 這條「捷徑」讓梯度能順暢地流過很深的網路,是能堆到上百層而不會訓練崩掉的關鍵(和第 67 章 ResNet 的殘差是同一招)。
  • 層正規化(LayerNorm):把每個 token 向量的數值重新縮放到穩定範圍,讓訓練更平順、更快收斂。

關鍵在於:block 的輸入與輸出維度完全相同($n$ 個 token、各 $d$ 維),所以它能像樂高一樣一層疊一層。 token 向量每經過一層,就「揉進」更多脈絡、變得更懂自己在這句話裡的角色。疊得夠深,模型就能捕捉極其細緻的語言結構。

預訓練 vs 微調:模型是怎麼「煉」出來的

架構講完了,但一個隨機初始化的 Transformer 什麼都不會。它怎麼變成會聊天的 ChatGPT?經過三個階段—— 訓練機制全是第 38 章的梯度下降 + 反向傳播,差別只在「資料」和「目標」:

  1. 預訓練(pre-training):餵進海量文字(整個網路等級的資料), 讓模型反覆做「遮住下一個 token、預測它、和真正的 token 比、用交叉熵當損失、反向傳播調參數」。 因為「答案」就是文字裡本來的下一個 token,不需要人工標註,所以叫自監督學習。 這一步最貴(動輒上千萬美元的算力),煉出的是一個「博學但不聽話」的基礎模型(base model)—— 它很會接話,但你問它問題,它可能回你「更多類似的問題」,因為網路上的文字就長那樣。
  2. 指令微調(instruction fine-tuning / SFT):用一批「人寫的(指令 → 理想回答)」高品質範例繼續訓練, 教模型「當別人問你問題時,要回答,而不是接話」。這一步讓基礎模型變成一個聽得懂指令的助理。
  3. RLHF(基於人類回饋的強化學習):讓模型對同一問題生成多個回答,由人(或一個學人偏好的「獎勵模型」)排序好壞, 再用強化學習(第 38 章的第三類學習)把模型朝「人更喜歡的回答」推。這一步雕琢的是語氣、安全性、有用程度—— 讓模型不只「會答」,還「答得體貼、不亂來」。
ℹ️
這解釋了你 agent 裡的兩件事

第一,為什麼模型「不知道最新消息」——它的知識凍結在預訓練資料的截止日;要補,得靠你在第 96 章學的 RAG(檢索增強)把外部資料塞進上下文。 第二,為什麼「prompt 寫得好不好」影響這麼大——模型本質是條件機率 $P(\text{下一個 token} \mid \text{上下文})$, 你給的 prompt 就是那個「條件」,條件一變、整個分佈就變。prompt engineering 不是玄學,是在調整機率的條件。

概念性手刻 mini-GPT(教學最小版)

現在把所有零件組起來,寫一個能跑、但刻意極簡的 mini-GPT。把前面所有概念串成程式碼, 你會發現它短得驚人。先看單頭因果自注意力——這是整段最核心的部分,把注意力公式逐行翻成 PyTorch: 

import torch
import torch.nn as nn
import torch.nn.functional as F

class CausalSelfAttention(nn.Module):
    """單頭因果自注意力(教學最小版;真實 GPT 用多頭)。"""
    def __init__(self, n_embd, head_size, block_size):
        super().__init__()
        self.key   = nn.Linear(n_embd, head_size, bias=False)   # 產生 K
        self.query = nn.Linear(n_embd, head_size, bias=False)   # 產生 Q
        self.value = nn.Linear(n_embd, head_size, bias=False)   # 產生 V
        # 下三角遮罩(buffer,不是可學參數):位置 i 只允許看 j ≤ i
        self.register_buffer("tril", torch.tril(torch.ones(block_size, block_size)))

    def forward(self, x):
        B, T, C = x.shape           # batch、序列長度、embedding 維度
        q = self.query(x)           # (B, T, head_size)
        k = self.key(x)             # (B, T, head_size)
        v = self.value(x)           # (B, T, head_size)
        d_k = k.shape[-1]
        # 注意力分數 QKᵀ / √d_k → (B, T, T)
        wei = q @ k.transpose(-2, -1) * d_k ** -0.5
        # 因果遮罩:把「未來」位置設成 -∞,softmax 後權重恰好變 0
        wei = wei.masked_fill(self.tril[:T, :T] == 0, float("-inf"))
        wei = F.softmax(wei, dim=-1)   # 每一列變成機率分佈 (B, T, T)
        out = wei @ v                  # 加權平均 Value → (B, T, head_size)
        return out

對照前面的公式:q @ k.transpose(-2, -1) 就是 $QK^\top$、* d_k ** -0.5 就是除以 $\sqrt{d_k}$、 masked_fill(..., float("-inf")) 就是因果遮罩、F.softmax(..., dim=-1) 就是 softmax、最後 wei @ v 就是乘上 $V$。 一行一行,正是那條式子。接著把它包進一個 Transformer block:

class TransformerBlock(nn.Module):
    def __init__(self, n_embd, head_size, block_size):
        super().__init__()
        self.ln1  = nn.LayerNorm(n_embd)
        self.attn = CausalSelfAttention(n_embd, head_size, block_size)
        self.ln2  = nn.LayerNorm(n_embd)
        self.ff   = nn.Sequential(                  # 前饋網路:放大 4 倍再壓回
            nn.Linear(n_embd, 4 * n_embd),
            nn.ReLU(),
            nn.Linear(4 * n_embd, n_embd),
        )

    def forward(self, x):
        x = x + self.attn(self.ln1(x))   # 殘差 + 注意力(先 LayerNorm)
        x = x + self.ff(self.ln2(x))     # 殘差 + 前饋網路
        return x

最後把 embedding、位置編碼、block、輸出頭組成完整 mini-GPT:

class MiniGPT(nn.Module):
    def __init__(self, vocab_size, n_embd, block_size, head_size):
        super().__init__()
        self.token_emb = nn.Embedding(vocab_size, n_embd)   # token id → 向量
        self.pos_emb   = nn.Embedding(block_size, n_embd)   # 位置 → 向量
        self.block     = TransformerBlock(n_embd, head_size, block_size)
        self.ln_f      = nn.LayerNorm(n_embd)
        self.head      = nn.Linear(n_embd, vocab_size)      # 輸出頭:向量 → 每個 token 的分數(logits)

    def forward(self, idx):
        B, T = idx.shape
        tok = self.token_emb(idx)              # (B, T, n_embd)
        pos = self.pos_emb(torch.arange(T))    # (T, n_embd)
        x = tok + pos                          # 把位置資訊加進去
        x = self.block(x)                      # 一層 Transformer block(真實 GPT 疊很多層)
        x = self.ln_f(x)
        logits = self.head(x)                  # (B, T, vocab_size)
        return logits

# 推論:取「最後一個位置」的 logits,過 softmax 得下一個 token 的機率分佈
model = MiniGPT(vocab_size=5000, n_embd=64, block_size=128, head_size=64)
idx = torch.randint(0, 5000, (1, 10))          # 假裝有一段 10 個 token 的輸入
logits = model(idx)                            # (1, 10, 5000)
next_token_logits = logits[:, -1, :]           # 只看最後一格 → (1, 5000)
probs = F.softmax(next_token_logits, dim=-1)   # → 下一個 token 的機率分佈
print(probs.shape)                             # torch.Size([1, 5000])
⚠️
誠實聲明:這是「教學最小版」,不是真的 GPT

上面的程式碼是為了看懂原理而刻意極簡的:單頭(真實 GPT 是多頭並行)、只疊一層(GPT-3 疊 96 層)、 沒有 dropout、沒有訓練迴圈、沒有真正的 BPE tokenizer、沒有任何效能最佳化。它能讓你看清資料怎麼流動, 但離一個能用的模型還很遠。想看「麻雀雖小、五臟俱全、真的能訓練出會講話的模型」的完整版,業界公認的兩個最佳起點是: Andrej Karpathy 的 nanoGPT(約 300 行、能在莎士比亞文本上訓練), 以及 Sebastian Raschka 的 LLMs-from-scratch(一本書的篇幅,從零帶你寫出並訓練一個 GPT)。 強烈建議跟著敲一遍——你會對這章的每個概念有脫胎換骨的理解。

Transformer 與 CNN:別把兩種「深度學習」搞混

你在第 67 章看過另一種紅透半邊天的深度網路:卷積神經網路(CNN)。它和這章的 Transformer 都叫「深度學習」、 都會「學特徵」、都用反向傳播訓練——但它們是為完全不同的資料設計的,核心機制南轅北轍。別把它們混為一談。

CNN(第 67 章)Transformer(本章)
擅長的資料影像(有空間結構的網格)文本 / 序列(有順序的 token 串)
核心機制卷積:用小的核掃過鄰近像素,抓局部紋理注意力:每個 token 直接和全場任意 token 互動
關係的距離靠堆疊層數,才能慢慢看到較大範圍一層之內,任意兩個 token 就能直接連上
位置觀念卷積天生帶有空間位置(像素鄰接)注意力看不出順序,要額外加位置編碼
典型輸出類別、框、分割遮罩下一個 token 的機率分佈
🔑
face embedding ≠ text embedding

兩章都出現了「embedding」這個詞,但別被同名騙了。第 67 章的人臉 embedding, 是 CNN 把一張臉的影像壓成的向量,用來比對「兩張臉像不像」;本章的文本 embedding, 是把一個文字 token 對應到的向量,捕捉的是語意。兩者都是「把東西變成向量,好比較距離」的同一思想 (都根植於第 54 章的向量空間),但產生它的網路、輸入的資料、捕捉的意義完全不同。 看到「embedding」要先問一句:是誰、為什麼東西算的?

練習

✏️ 練習 93.1 計算

某個 query token 對 3 個 key 算出的已縮放注意力分數是 $\mathbf{s} = [1,\ 3,\ 2]$, 三個 token 的 Value 向量分別是 $\mathbf{v}_1=[1,0]$、$\mathbf{v}_2=[0,1]$、$\mathbf{v}_3=[1,1]$。 (a) 手算 softmax 後的三個注意力權重。(b) 算出注意力輸出向量(權重對 Value 的加權平均)。

看解答

(a) 套 $\text{softmax}(z)_i = e^{z_i}/\sum_j e^{z_j}$:

$e^1 = 2.718$,$e^3 = 20.086$,$e^2 = 7.389$,總和 $= 30.193$。

權重 $= [\,2.718/30.193,\ 20.086/30.193,\ 7.389/30.193\,] \approx [0.090,\ 0.665,\ 0.245]$(加起來 = 1 ✓)。

(b) 輸出 $= 0.090\,[1,0] + 0.665\,[0,1] + 0.245\,[1,1]$。

第一維:$0.090 + 0 + 0.245 = 0.335$;第二維:$0 + 0.665 + 0.245 = 0.910$。所以輸出 $\approx [0.335,\ 0.910]$。

直覺:第二個 token 分數最高($s=3$)、權重最大(0.665),所以輸出最靠近 $\mathbf{v}_2=[0,1]$—— 注意力「最關注」誰,輸出就最像誰的 Value。用程式驗證:

import torch, torch.nn.functional as F
s = torch.tensor([1., 3., 2.])
w = F.softmax(s, dim=-1)                 # tensor([0.0900, 0.6652, 0.2447])
V = torch.tensor([[1.,0.], [0.,1.], [1.,1.]])
print(w @ V)                             # tensor([0.3347, 0.9100])
✏️ 練習 93.2 思考

注意力公式裡為什麼要除以 $\sqrt{d_k}$?如果不除、而且 $d_k$ 很大(例如 256), softmax 的輸出與梯度會發生什麼事?這和第 38 章的哪個老問題是同一回事?

看解答

$Q$ 與 $K$ 的點積是 $d_k$ 個分量乘積的加總。若各分量大致是均值 0、變異數 1 的獨立隨機數, 則點積的變異數正比於 $d_k$、標準差約為 $\sqrt{d_k}$。$d_k$ 一大,點積數值就會被放得很大。

把很大的數丟進 softmax,會讓某一格的機率趨近 1、其餘趨近 0(分佈變得極尖、近乎 one-hot)。 這時 softmax 落入飽和區:對輸入的變化幾乎不反應,梯度趨近 0,模型學不動。

這正是第 38 章 sigmoid 飽和導致梯度消失的同一個毛病。除以 $\sqrt{d_k}$ 把點積的標準差拉回 1 附近, 讓 softmax 待在斜率健康、梯度充足的區間,訓練才穩。一句話:$\sqrt{d_k}$ 是穩定 softmax 梯度的縮放。

✏️ 練習 93.3 思考

(a) 因果遮罩(causal mask)具體怎麼做、為什麼能「防止 token 偷看未來」? (b) 對一個 4-token 的序列,寫出注意力分數矩陣($4\times4$)裡哪些位置會被遮成 $-\infty$。 (c) 如果拿掉因果遮罩,拿這種模型去做「預測下一個 token」的訓練,上線後會出什麼問題?

看解答

(a) 在 softmax 之前,把分數矩陣第 $i$ 列中所有「未來位置」($j > i$)設成 $-\infty$。 因為 $e^{-\infty}=0$,softmax 後這些位置的權重恰好為 0,等於 token $i$ 對未來 token 的注意力是 0——看不到後面。

(b) 被遮的是嚴格上三角(行號 $j$ 大於列號 $i$)。以 ✗ 表示被遮、✓ 表示保留(列 = query 位置 0~3):

        j=0  j=1  j=2  j=3
i=0      ✓    ✗    ✗    ✗      (位置 0 只看得到自己)
i=1      ✓    ✓    ✗    ✗
i=2      ✓    ✓    ✓    ✗
i=3      ✓    ✓    ✓    ✓      (位置 3 看得到全部前文)

保留的恰好是下三角(含對角線),所以也叫「下三角遮罩」。

(c) 訓練時若不遮,預測第 $i$ 個 token 時模型能看到第 $i{+}1, i{+}2, \dots$ 也就是答案本身, 損失會低得不真實(模型只是把答案抄過來)。但上線生成時未來根本還不存在,模型一旦少了偷看的答案就完全不會預測—— 訓練與推論行為不一致,模型實際上沒學到東西。

✏️ 練習 93.4 挑戰

承本章的 mini-GPT。設 batch 大小 $B=2$、序列長度 $T=10$、embedding 維度 $n\_embd=64$、head_size $=64$、詞彙表 $vocab=5000$。 請寫出資料流經以下各點時的張量形狀:(a) token_emb(idx) 之後;(b) 注意力分數 wei(softmax 前); (c) 注意力輸出 out;(d) 最終 logits;(e) 取最後一格、過 softmax 後的「下一個 token 機率」。

看解答
  • (a) token_emb(idx):輸入 idx 是 $(B, T) = (2, 10)$,查表後每個 token 變 64 維 → $(2, 10, 64)$。加上位置編碼後形狀不變。
  • (b) wei = q @ k.transpose(-2,-1):$q,k$ 各 $(2,10,64)$,$k^\top$ 為 $(2,64,10)$,相乘 → $(2, 10, 10)$。這就是每個 token 對每個 token 的分數($T\times T$)。
  • (c) out = wei @ v:$(2,10,10)$ 乘 $v\,(2,10,64)$ → $(2, 10, 64)$。注意 token 數 10 不變、每個 token 一條新向量。
  • (d) logits = head(x):輸出頭把 64 維映到 vocab → $(2, 10, 5000)$。
  • (e) logits[:, -1, :] 取最後一格 → $(2, 5000)$;過 softmax 形狀不變,仍是 $(2, 5000)$,且每一列加起來為 1。

核心心得:注意力不改變 token 數量($T$ 進、$T$ 出),只更新每個 token 的向量內容; 真正把「向量」翻譯成「詞彙表上機率」的,是最後的輸出頭 + softmax。

把這一章串起來

我們把那個你天天在 agent 裡呼叫、卻看不清的黑箱,從外到內拆了一遍。回顧這趟旅程的路標:

  • 本質:LLM 是一台「預測下一個 token 機率分佈」的機器,靠自迴歸一個接一個生成。幻覺、上下文上限、prompt 敏感,全是這個本質的直接後果。
  • tokenization:文字被 BPE 切成子詞 token、再變成整數 id;token 不是字也不是詞,API 按它計費。
  • embedding + 位置編碼:token id 查表成向量,語意近則向量近(第 54 章的向量空間);注意力看不出順序,所以要把位置向量加進去。
  • 注意力:$\text{softmax}(QK^\top/\sqrt{d_k})V$。Q 查、K 比、V 取;$QK^\top$ 是 $n\times n$ 的分數、softmax 成權重、加權平均 V。除以 $\sqrt{d_k}$ 是為了穩住 softmax 梯度;因果遮罩讓 GPT 不能偷看未來。
  • Softmax:把一排任意分數變成合法機率分佈(補上第 38 章的拼圖),temperature 就是在它之前縮放 logits。
  • Transformer block:多頭注意力 + 前饋網路 + 殘差 + LayerNorm,輸入輸出同維、可無限堆疊,就是 GPT 的主體。
  • 訓練三階段:自監督預訓練 → 指令微調 → RLHF,機制全是第 38 章的梯度下降 + 反向傳播 + 強化學習。
  • mini-GPT:我們用幾十行 PyTorch 把這些零件串了起來——但它是教學最小版,真正能訓練的完整版請看 nanoGPT 與 LLMs-from-scratch。
  • CNN vs Transformer:卷積抓影像局部、注意力連文本全場;face embedding 與 text embedding 同思想、不同網路。別搞混。

現在,當你的 agent 呼叫那個 chat(),你不再面對一團魔法。你知道對面是一台 Transformer, 它正把你的 prompt 切成 token、嵌成向量、用注意力反覆揉進脈絡,最後在詞彙表上算出一個機率分佈、抽一個 token 接上去—— 週而復始。你看得見它為什麼會忘、為什麼會掰、為什麼吃 prompt。這份「看得見」,就是你做好 agent 工程的底氣。 接下來在第 94 章《手刻你的 LLM client》,我們就把這台機器當成一個服務,親手寫程式去呼叫它—— 從這一章的「裡面怎麼運作」,正式走向「外面怎麼使用」。
