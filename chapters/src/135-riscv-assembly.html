為什麼在 Hack 之後還要學 RISC-V

你在{{ch:21-cpu-machine-language}}學過 Hack:16 位元的指令,只有 A 指令和 C 指令,只有 A、D 兩個暫存器。 它小到可以從 NAND 閘一路蓋出來。這是它最大的優點。

但是 Hack 少了很多真實 CPU 一定有的東西。它沒有「呼叫函式」的指令,也沒有堆疊;記憶體一格就是 16 位元,沒有位元組; 常數最多 15 位元;它也沒有一套「大家都遵守的約定」,讓 A 寫的函式可以被 B 呼叫。 這些東西,在你讀編譯器的輸出、寫模擬器、設計 CPU、做逆向工程的時候,每天都會碰到。

RISC-V(唸作 risk-five)是 2010 年從加州大學柏克萊分校開始的開放指令集。任何人都可以免費實作它,不用付授權費。 它的基本整數指令集 RV32I 只有 40 條指令(37 條運算、載入儲存與分支跳躍,加上 fence、ecall、ebreak), 小到一個學期就能做出一顆 CPU,但它又是真的:ESP32-C3 這類微控制器用的就是 RISC-V 核心,很多晶片裡負責管理工作的小核心也是。

32 個暫存器與它們的 ABI 名稱

RV32I 有 32 個整數暫存器,硬體上的名字是 x0 到 x31,每個 32 位元。對硬體來說,除了 x0,它們完全一樣: 任何指令都可以讀寫任何暫存器。x0 很特別:讀它永遠得到 0,寫它的值直接丟掉。

既然硬體不在乎,為什麼還要分工?因為程式不是一個人寫的。你的函式會呼叫別人寫的函式,編譯器產生的程式要和手寫的組合語言接在一起。 大家要先說好「引數放在哪個暫存器」「誰可以隨便改哪個暫存器」。這份約定叫做 ABI(application binary interface,應用程式二進位介面)。 為了方便記,每個暫存器都有一個照用途取的 ABI 名稱。寫組合語言時大家都用 ABI 名稱,反組譯器(像 objdump)也預設印 ABI 名稱。

🔑
核心觀念

硬體只有 x0–x31,而且除了 x0 都一樣。a0、sp、s0 這些名字和它們的分工全部是軟體的約定。約定不會自己執行:遵不遵守,是寫程式的人(和編譯器)的責任。

第一支程式:組譯、連結、反組譯

先看一支完整的程式。它印出一段字串、一個整數和一個換行,然後結束:

    .text
    .globl _start
_start:
    la   a0, msg        # a0 = 字串的位址
    li   a7, 4          # 4 = print_string
    ecall
    li   a0, 42
    li   a7, 1          # 1 = print_int
    ecall
    li   a0, 10         # 10 = '\n'
    li   a7, 11         # 11 = print_char
    ecall
    li   a0, 0
    li   a7, 93         # 93 = exit(a0)
    ecall

    .data
msg:
    .string "answer = "

一行一行看:

  • .text、.data:組譯器指引(assembler directive),以點開頭,不是指令。它們告訴組譯器「接下來的東西放在程式區」或「放在資料區」。
  • .globl _start:把 _start 這個標籤匯出,連結器要知道程式從哪裡開始。
  • _start:、msg::標籤(label),代表一個位址。和 Hack 的 (LOOP) 一樣。
  • la、li:假指令(pseudo-instruction),組譯器會把它們換成一到兩條真指令。後面有一節專門講。
  • ecall:環境呼叫(environment call)。照 a7 的編號請執行環境(模擬器或作業系統)做事。這裡用到 4(印字串)、1(印整數)、11(印字元)、93(結束)。
  • .string "answer = ":在資料區放一串位元組,最後自動補一個 0(NUL)。
  • # 後面是註解。

要把它變成機器碼,需要 RISC-V 的交叉工具鏈(cross toolchain)。在 Debian 或 Ubuntu 上可以用 sudo apt install gcc-riscv64-unknown-elf 安裝(會一起裝 binutils)。 名字裡雖然有 64,加上 -march=rv32i -mabi=ilp32 就會產生 32 位元的 RV32I 程式。ilp32 的意思是 int、long、指標(pointer)都是 32 位元。 另外準備一個連結腳本(linker script),讓程式從位址 0 開始放: 

ENTRY(_start)
SECTIONS
{
  . = 0x0;                 /* 程式從位址 0 開始放 */
  .text : { *(.text*) }
  .data : { *(.data*) *(.rodata*) *(.sdata*) }
  .bss  : { *(.bss*) *(.sbss*) }
}
riscv64-unknown-elf-as -march=rv32i -mabi=ilp32 hello.s -o hello.o          # 組譯
riscv64-unknown-elf-ld -m elf32lriscv -T link.ld --no-relax hello.o -o hello.elf   # 連結
riscv64-unknown-elf-objdump -d -M no-aliases hello.elf                      # 反組譯
riscv64-unknown-elf-objcopy -O binary hello.elf hello.bin                   # 只留下位元組
od -An -tx4 -w4 -v hello.bin | tr -d ' '                                    # 每行印一個 32 位元字

連結器的「放鬆」(relaxation)

上面的連結指令加了 --no-relax。如果不加,連結器發現 msg 的位址很小(0x30),會把 la a0, msg 的兩條指令縮成一條 addi a0, zero, 48, call 也常被縮成一條 jal。這叫連結器放鬆,能讓程式變小變快,但會讓「原始碼的第幾行對到第幾個字」變得不好追。本章為了方便手算,一律加 --no-relax; 用 gcc 編出來的程式通常會放鬆,讀反組譯時看到的指令可能比原始碼少。

六種指令格式:R、I、S、B、U、J

每一條 RV32I 指令都是 32 位元。最低 7 位元是 opcode,決定大類(運算、載入、儲存、分支…)。剩下的 25 位元怎麼切,共有六種切法,叫做指令格式:

先看幾個一眼就能看出的設計:

  • rd、rs1、rs2 永遠在同一個位置(有的話)。rd 在 11–7、rs1 在 19–15、rs2 在 24–20。硬體可以在還不知道是哪條指令之前,就先去讀暫存器。
  • 暫存器編號都是 5 位元,剛好表示 0–31。
  • 立即值(immediate)的最高位(符號位)永遠在位元 31。不管哪種格式,符號延伸都看同一個位元。
  • S 型沒有 rd(儲存不寫暫存器),所以把原本 rd 的位置拿來放立即值的低 5 位元;B 型同理。

立即值:符號延伸與 B、J 型的「打散」位元

💡
為什麼要學

立即值是解碼器最容易寫錯、測試最容易漏掉的地方。本章 Lab 的模擬器有一組隱藏檢定專門測每種格式立即值的極端值(I/S 型 −2048 與 2047、B 型 ±4 KiB、J 型 ±1 MiB); IC 路線設計 CPU 時,立即值產生器(immediate generator)是單獨的一個零件,要和你的模擬器的解碼結果逐一比對。

立即值在指令裡只有 12 或 20 位元,但暫存器是 32 位元。要把短的數字變長,就要做符號延伸(sign extension): 把最高位(符號位)複製到所有新增的位元。這樣 12 位元的 111111110000(−16)延伸成 32 位元的 0xFFFFFFF0,還是 −16; 000000001100(12)延伸成 0x0000000C,還是 12。二補數的細節見{{ch:20-combinational-sequential}}。

RV32I 的規則很簡單:所有立即值都做符號延伸,而且符號位一律是指令的位元 31。 (唯一的例外是移位量 shamt,它只有 5 位元,不延伸。sltiu 也是先符號延伸,再當成無號數比較。)

B 型與 J 型為什麼要打散位元

看圖 135-1 的 B 型:立即值的第 12 位放在指令位元 31,第 10–5 位放在 30–25,第 4–1 位放在 11–8,第 11 位卻跑到位元 7。 J 型更亂:位元 31 是 imm[20],30–21 是 imm[10:1],20 是 imm[11],19–12 是 imm[19:12]。為什麼不照順序放?

把散開的位元撿回來,寫成程式就是下面四個函式(它們等一下會用在迷你模擬器裡):

def sext(value, bits):
    """把 bits 位元寬的值做符號延伸,回傳 Python 的有號 int。"""
    value &= (1 << bits) - 1
    return value - (1 << bits) if value >> (bits - 1) else value

def imm_i(w): return sext(w >> 20, 12)
def imm_s(w): return sext((w >> 25) << 5 | (w >> 7) & 0x1F, 12)
def imm_b(w): return sext((w >> 31) << 12 | (w >> 7 & 1) << 11
                          | (w >> 25 & 0x3F) << 5 | (w >> 8 & 0xF) << 1, 13)
def imm_j(w): return sext((w >> 31) << 20 | (w >> 12 & 0xFF) << 12
                          | (w >> 20 & 1) << 11 | (w >> 21 & 0x3FF) << 1, 21)

大常數與位址:lui、auipc 與 li、la 假指令

addi 的立即值只有 12 位元。那要怎麼把 0x12345678 放進暫存器?答案是兩步: lui(load upper immediate)把 20 位元放進暫存器的高 20 位、低 12 位清成 0;再用 addi 加上低 12 位元。 

lui  a0, 0x12345        # a0 = 0x12345000
addi a0, a0, 0x678      # a0 = 0x12345000 + 0x678 = 0x12345678

auipc(add upper immediate to pc)和 lui 很像,只是把結果再加上這條指令自己的 pc。 它是「和位置無關的程式」(position-independent code)的基礎:auipc 加 addi 可以算出「離我這條指令多遠的位址」, 不管程式被放到記憶體的哪裡都對。auipc t1, 0xfffff 的意思是 t1 = pc + 0xFFFFF000 = pc − 4096。

每次都手算 hi 和 lo 很煩,所以組譯器提供假指令:li rd, 常數(load immediate)與 la rd, 標籤(load address)。 組譯器會自動選一到兩條真指令。下面是 riscv64-unknown-elf-as 實際的展開結果:

拆法本身可以寫成程式,而且「lui 再 addi 一定回到原來的數」可以直接寫成 assert: 

import random

def split_li(v):
    """把 32 位元常數 v 拆成 lui 的 20 位元 hi 與 addi 的 12 位元有號 lo。"""
    v &= 0xFFFFFFFF
    lo = v & 0xFFF
    if lo >= 0x800:              # addi 會把這 12 位元當成負數
        lo -= 0x1000
    hi = ((v - lo) >> 12) & 0xFFFFF   # 等於 ((v + 0x800) >> 12) & 0xFFFFF
    assert -2048 <= lo <= 2047
    assert ((hi << 12) + lo) & 0xFFFFFFFF == v   # 不變式:lui hi 再 addi lo 一定回到 v
    return hi, lo

for v in [0x12345678, 0x12345FFF, 0x800, 0x10000004, 0x7FFFFFFF, 0xDEADBEEF, -1]:
    hi, lo = split_li(v)
    print(f'{v & 0xFFFFFFFF:#010x} → lui {hi:#07x}, addi {lo}')

for _ in range(100_000):         # 隨機抽查:不是證明,是建立信心
    split_li(random.getrandbits(32))
print('10 萬個隨機常數都通過')

證明(參考):為什麼 lui hi 再 addi lo 一定得到 v

設 $v$ 是 0 到 $2^{32}-1$ 的整數,$r = v \bmod 4096$。若 $r < 2048$,取 lo = $r$;否則取 lo = $r - 4096$。兩種情況都有 $-2048 \le \text{lo} \le 2047$(addi 放得下),而且 $v - \text{lo}$ 是 4096 的倍數。 令 hi = $(v - \text{lo})/4096 \bmod 2^{20}$。lui 得到 $\text{hi} \cdot 4096 \bmod 2^{32} = (v - \text{lo}) \bmod 2^{32}$,再加 lo 得到 $v \bmod 2^{32} = v$。 上面程式的兩個 assert 就是這兩件事:lo 的範圍,與「加回去等於 v」。隨機抽查 10 萬個數不是證明,只是讓你對程式更有信心;證明才保證 $2^{32}$ 個數全部成立。

算術、邏輯與比較:沒有 mul 的整數運算

RV32I 的運算指令分兩組:R 型(兩個暫存器)與 I 型(暫存器加 12 位元常數)。I 型沒有 subi,因為 addi 加負數就是減法。 幾個和 Python 不一樣、要特別記住的地方:

  • 沒有旗標(flags)。x86 和 ARM 的加法會設定進位、溢位旗標;RISC-V 沒有。加法溢位就照二補數繞回(0x7FFFFFFF + 1 = 0x80000000),不會有任何通知。要比較,就用 slt 或分支指令直接比兩個暫存器。
  • slt 和 sltu(set less than):rd = (rs1 < rs2) ? 1 : 0。slt 把兩邊當有號數,sltu 當無號數。−1 的位元是 0xFFFFFFFF,所以 slt 認為 −1 < 1,sltu 認為 0xFFFFFFFF > 1。
  • 三種移位:sll 左移補 0;srl 邏輯右移,左邊補 0;sra 算術右移,左邊補符號位。0x80000000 用 srl 右移 4 位得 0x08000000,用 sra 得 0xF8000000。
  • 移位量只看低 5 位元。sll 的 rs2 是 33 的時候,只移 1 位(33 = 0b100001)。32 位元的數移 32 位以上沒有意義,硬體乾脆只接 5 條線。
  • 沒有乘法和除法。那是 M 擴充(RV32M)的指令。只有 RV32I 的時候,C 編譯器會把 x * 10 改成移位加法,把 x * y 改成呼叫函式庫的 __mulsi3(後面「從 C 到 RV32I」一節有實例)。

載入與儲存:位元組、半字、字

RISC-V 是載入/儲存架構(load/store architecture):運算指令只碰暫存器,只有載入和儲存指令會碰記憶體。 記憶體以位元組為單位編址,一次可以讀寫 1 個位元組(byte)、2 個位元組(半字,halfword)或 4 個位元組(字,word)。 位址一律是「基底暫存器 + 12 位元位移」,寫成 lw rd, 位移(rs1)。

指令讀寫幾個位元組放進 32 位元暫存器時
lb / lbu1lb 符號延伸;lbu 補 0(u = unsigned)
lh / lhu2lh 符號延伸;lhu 補 0
lw4(剛好 32 位元,不必延伸)
sb / sh / sw1 / 2 / 4只寫 rs2 的低 8 / 16 / 32 位元,記憶體的其他位元組不動

多位元組的值用小端序放:低位元組放在低位址。sw 把 0x8001FF7F 存到 0x100,記憶體會變成 0x100 = 7F、0x101 = FF、0x102 = 01、0x103 = 80。

對齊(alignment):半字的位址要是 2 的倍數,字的位址要是 4 的倍數。規格允許硬體自己處理沒對齊的存取,也允許它丟出例外; 本章 Lab 的模擬器採用比較嚴格的做法:沒對齊就是錯誤。寫組合語言時,自己保證對齊最安全。

分支與跳躍:把 if 與迴圈翻成組合語言

Hack 的跳躍是「ALU 算出來的結果大於 0 就跳」。RISC-V 的條件分支直接比較兩個暫存器:beq(相等)、bne(不等)、 blt/bge(有號的小於、大於等於)、bltu/bgeu(無號)。 沒有 bgt、ble,因為把兩個運算元對調就有了(見假指令表)。

無條件跳躍有兩條:jal rd, 標籤 把 pc + 4 存進 rd,再跳到 pc + imm;jalr rd, imm(rs1) 把 pc + 4 存進 rd,再跳到 rs1 + imm(最低位清成 0)。 rd 寫 zero 就是單純的跳躍,寫 ra 就是呼叫函式。

常見的翻譯樣板(a、b 已經在暫存器裡):

# if (a < b) { 甲 } else { 乙 }       —— 條件反過來寫:不成立就跳去 else
    bge  a, b, else_part
    (甲)
    j    end_if
else_part:
    (乙)
end_if:

# while (i != 0) { 身體 }
loop:
    beqz i, done
    (身體)
    j    loop
done:

條件反過來寫是因為分支「成立就跳走」:C 的 if (a < b) 要在 a ≥ b 時跳過「甲」。 另外,有號和無號要分清楚:C 的 int 比較用 blt/bge,unsigned 與指標用 bltu/bgeu。

⚠️
看起來對但其實錯:「beq 的位移量以指令為單位,而且從下一條指令算起」

Hack 的跳躍目標是指令編號;有些教科書的 MIPS 分支也是「下一條指令 + 位移 × 4」。所以很多人以為 RISC-V 也一樣。 不對:RISC-V 的 B 型與 J 型立即值是位元組位移,而且從分支指令自己的位址算起。 上面「手算:立即值與分支目標」那張表的 00028e63(beq t0, zero, 0x120)在 0x104,立即值是 28,目標是 0x104 + 28 = 0x120,中間隔了 7 條指令。 如果把 28 當成指令數,會跳到 0x104 + 112;如果從 pc + 4 算起,會差一條。寫模擬器和組譯器時,這兩個錯都會讓「跳 0 步」「跳下一條」這種小例子看起來還可以,大一點的程式就全亂了。

呼叫約定:誰負責保存哪個暫存器

💡
為什麼要學

本章 Lab 的組合語言函式會被我們的測試框架呼叫:框架先在 s0–s11、gp、tp 放檢查值,呼叫之後檢查它們沒變、sp 回到原處、用 ra 回去。 你自己的模擬器之後要跑 gcc 編出來的程式,它們全都遵守這套約定。讀反組譯做逆向時,知道「a0 是第一個引數、回傳值也在 a0」,一段函式就讀懂了一半。

呼叫約定(calling convention)是 ABI 的一部分,規定函式之間怎麼交接。RISC-V 的版本(ilp32,整數部分)可以濃縮成五條:

  1. 引數放在 a0–a7(前 8 個),多的放在堆疊上。回傳值放在 a0(64 位元的值用 a0、a1)。
  2. 用 jal ra, f(或 call f)呼叫,返回位址存在 ra;函式用 ret(jalr zero, 0(ra))回去。
  3. 被呼叫者保存(callee-saved):s0–s11 和 sp。函式如果要用它們,必須先把舊值存起來,回去之前還原。呼叫者可以相信它們在呼叫前後不變。
  4. 呼叫者保存(caller-saved):t0–t6、a0–a7、ra。被呼叫的函式可以隨便改。呼叫者如果在呼叫之後還需要它們的值,要自己先存起來。
  5. sp 隨時保持 16 位元組對齊,堆疊往低位址長。gp、tp 一般程式不要動。

為什麼要分兩種?想像兩個極端。如果全部都是「被呼叫者保存」,每個小函式都要把用到的暫存器存起來再還原,很多根本沒必要; 如果全部都是「呼叫者保存」,呼叫者每次呼叫前都要把所有還要用的值存起來。分成兩半,讓兩邊都能挑便宜的用: 不會呼叫別人的函式(葉函式,leaf function)只用 t 和 a,完全不必碰堆疊;要跨過呼叫保留的值,放進 s 暫存器,存一次、還原一次就好。

🔑
核心觀念

呼叫約定是一份雙方的契約:被呼叫者保證 s 暫存器與 sp 不變;呼叫者不能假設 t、a、ra 不變。只要有一方不守,錯誤會出現在另一方的程式裡,而且常常要很久以後才發作。

下面這支程式呼叫一個把引數乘 2 的函式。呼叫之前,呼叫者把 100 放在 t0,呼叫之後拿來用:

    .text
    .globl _start
_start:
    li   t0, 100        # 呼叫前放進 t0,以為呼叫之後還在
    li   a0, 5
    jal  ra, twice      # a0 = twice(5)
    add  a0, a0, t0     # 期望 10 + 100 = 110
    li   a7, 1
    ecall               # 印出 a0
    li   a7, 10
    ecall

twice:                  # 版本 A:只用 a0
    slli a0, a0, 1
    ret

執行結果是 110。現在把 twice 換成另一個寫法。它完全合法:t0 本來就是函式可以隨便用的暫存器。

twice:                  # 版本 B:用 t0 當暫存(完全合法)
    slli t0, a0, 1
    mv   a0, t0
    ret

同一個呼叫者,印出來變成 20:twice 把 t0 改成 10,呼叫者再加 10。

⚠️
看起來對但其實錯:「t 暫存器呼叫之後還在,我測過了」

用版本 A 測試,結果是對的,因為這個 twice 剛好沒碰 t0。但約定說 t 是呼叫者保存:被呼叫的函式隨時可以改它。 哪天 twice 換了寫法(版本 B)、換了編譯器的最佳化等級、或者呼叫的是函式庫,錯誤就出現了,而且出現在呼叫者這邊,不在真正「改了 t0」的函式裡。 這次的測試通過,不代表程式守了約定。本章 Lab 的測試框架就是故意在 t 暫存器放亂數、在 s 暫存器放檢查值來抓這種錯。 要跨過呼叫保留的值,放進 s 暫存器(並在你的函式裡保存它),或自己存到堆疊上。

呼叫框:跟著遞迴的 fib 走一趟

函式需要記憶體來放「跨過呼叫要保留的東西」:返回位址 ra、要用的 s 暫存器的舊值、放不進暫存器的區域變數。 這塊記憶體叫呼叫框(stack frame,也有人叫堆疊框)。函式一進來就把 sp 往下減,開出自己的框(序言,prologue); 回去之前從框裡還原,再把 sp 加回去(尾聲,epilogue)。{{ch:03-functions-recursion}}的「呼叫堆疊」,在機器層就是這個。

用遞迴的費氏數列來看:fib(0) = 0、fib(1) = 1、fib(n) = fib(n−1) + fib(n−2)。它會呼叫自己兩次,第一次呼叫的結果要跨過第二次呼叫保留下來,很適合練習: 

    .text
    .globl _start
_start:
    li   sp, 0x00100000     # 堆疊頂(模擬器一開始也是這個值)
    li   a0, 6
    jal  ra, fib            # a0 = fib(6)
    li   a7, 1              # print_int
    ecall
    li   a0, 0
    li   a7, 93             # exit(0)
    ecall

# fib(n):a0 = n,回傳 a0 = 第 n 個費氏數(fib(0)=0、fib(1)=1)
fib:
    addi sp, sp, -16        # 開一個 16 位元組的框
    sw   ra, 12(sp)         # 存返回位址(等一下 jal 會蓋掉 ra)
    sw   s0, 8(sp)          # 要用 s0、s1,先存起它們的舊值
    sw   s1, 4(sp)
    mv   s0, a0             # s0 = n(跨過呼叫還要用,所以放 s 暫存器)
    li   t0, 2
    blt  a0, t0, fib_base   # n < 2 → 答案就是 n
    addi a0, s0, -1
    jal  ra, fib            # a0 = fib(n-1)
    mv   s1, a0             # s1 = fib(n-1),跨過下一次呼叫
    addi a0, s0, -2
    jal  ra, fib            # a0 = fib(n-2)
    add  a0, s1, a0         # a0 = fib(n-1) + fib(n-2)
    j    fib_done
fib_base:
    mv   a0, s0
fib_done:
    lw   s1, 4(sp)          # 照相反順序還原
    lw   s0, 8(sp)
    lw   ra, 12(sp)
    addi sp, sp, 16         # 收掉框
    ret

重點:

  • 框的大小是 16 位元組。只需要存 3 個字(12 位元組),但 sp 要保持 16 對齊,所以開 16,0(sp) 空著。
  • ra 一定要存。fib 裡面還有 jal ra, fib,會把 ra 蓋掉;不存的話,就回不到呼叫者了。
  • n 放在 s0、fib(n−1) 放在 s1,因為它們要跨過呼叫。用 s 暫存器就要先存舊值(呼叫者的 s0、s1 也要保證不變)。
  • 就算是 n < 2 的情況,也走同一個尾聲,把框收掉。每一條路徑上,開框和收框都要剛好配對。

# mul32_trace.py:移位加法乘法的 Python 模型,逐輪印出並檢查迴圈不變式
MASK = 0xFFFFFFFF

def mul32_trace(a, b):
    a, b = a & MASK, b & MASK
    goal = (a * b) & MASK                    # 正確答案,只拿來檢查不變式
    result, rnd = 0, 0
    while b != 0:                            # beqz:b 是 0 就結束
        bit = b & 1                          # andi:取 b 的最低位
        if bit:                              # beqz:最低位是 0 就跳過加法
            result = (result + a) & MASK     # add
        a = (a << 1) & MASK                  # slli:a 左移一位
        b = b >> 1                           # srli:b 邏輯右移一位(左邊補 0)
        rnd += 1
        assert (result + a * b) & MASK == goal, '不變式壞了'
        print(f'第 {rnd} 輪:最低位 {bit},結果 {result},a {a},b {b}')
    return result

ecall:請執行環境幫忙

ecall 會讓 CPU 把控制權交給「執行環境」:真實的機器上是作業系統的核心,模擬器裡是模擬器自己。要做什麼,照約定放在暫存器裡: a7 放編號,a0 放引數。下表是 Ripes 模擬器的編號,本書(包括本章 Lab 的模擬器)也照這一套:

a7a0名稱做什麼

4字串的位址print_string印出 a0 指到的、以 NUL 結尾的字串

第一支程式 hello.s 就是用 4、1、11、93 印出 answer = 42。 在 RISC-V 的 Linux 上,ecall 是真正的系統呼叫(system call,見{{ch:24-operating-system}}),編號是另一套: 64 是 write、93 是 exit。93 剛好相同,其他編號都不一樣,同一支程式不能直接拿到 Linux 上跑。

記憶體映射 I/O:寫到某個位址就是印字

真實的嵌入式系統常常沒有作業系統可以 ecall。周邊裝置(序列埠、LED、計時器)直接「掛」在某段位址上,讀寫那些位址就是在操作裝置。 這叫記憶體映射 I/O(memory-mapped I/O,MMIO),和 Hack 的 SCREEN、KBD 是同一個想法。本書的 RV32I 環境約定兩個位址:

位址名稱寫入讀取
0x10000000CONSOLEsb/sh/sw:把寫入值的低 8 位元當成一個字元輸出得到 0
0x10000004EXITsw:結束程式,結束狀態碼是寫入的值(有號)得到 0
 
    .text
    .globl _start

    li   t0, 0x10000000 # CONSOLE 的位址
    li   t1, 'H'

    li   t1, 'i'

li t0, 0x10000000 低 12 位元是 0,只要一條 lui t0, 0x10000;EXIT 用 sw t1, 4(t0),位移 4 就到了 0x10000004。 在完整的 RV32I 模擬器上執行,console 印出 Hi 加換行,結束狀態碼 3,共執行 9 條指令。 IC 路線之後自己設計 CPU 時,CPU 的測試也用同樣的兩個位址輸出,這樣同一支程式在模擬器和硬體上都能跑。

ℹ️
C 程式怎麼寫 MMIO

C 裡面要用 volatile 指標:*(volatile unsigned char *)0x10000000 = 'H';。volatile 告訴編譯器「每次寫入都有作用,不能省、不能合併」; 少了它,編譯器可能覺得連續寫同一個位址三次沒有意義,只留最後一次。

用 Python 寫一個迷你指令集模擬器

指令集模擬器(instruction set simulator,ISS)用軟體照著規格一條一條執行機器碼。它不管管線、快取這些硬體細節,只管「每條指令執行完之後,暫存器、記憶體和 pc 應該是什麼」。 它是 CPU 設計的參考答案,也是學指令集最好的方法:寫完一個,你就再也不會忘記 B 型的立即值怎麼排。

下面是一個只認 13 條指令的迷你版:lui、addi、slli、add、sub、lw、sw、 beq、bne、blt、jal、jalr、ecall(只有 1、11、93 三個編號)。 它剛好夠跑本章的 fib 程式。它不是本章 Lab 要的模擬器:Lab 要全部 40 條指令、各種錯誤(非法指令、沒對齊、超出範圍)、MMIO、反組譯、存取紀錄與效能要求,介面也不一樣。 這裡只讓你看到骨架。 

# mini_rv.py:只認 13 條 RV32I 指令的迷你模擬器(示範骨架,不是本章 Lab 要的完整 ISS)
MASK = 0xFFFFFFFF

def sext(value, bits):
    """把 bits 位元寬的值做符號延伸,回傳 Python 的有號 int。"""
    value &= (1 << bits) - 1
    return value - (1 << bits) if value >> (bits - 1) else value

# 立即值:照六種格式把散開的位元撿回來
def imm_i(w): return sext(w >> 20, 12)
def imm_s(w): return sext((w >> 25) << 5 | (w >> 7) & 0x1F, 12)
def imm_b(w): return sext((w >> 31) << 12 | (w >> 7 & 1) << 11
                          | (w >> 25 & 0x3F) << 5 | (w >> 8 & 0xF) << 1, 13)
def imm_j(w): return sext((w >> 31) << 20 | (w >> 12 & 0xFF) << 12
                          | (w >> 20 & 1) << 11 | (w >> 21 & 0x3FF) << 1, 21)

class MiniRV:
    def __init__(self, words, mem_size=1 << 20):
        self.mem = bytearray(mem_size)
        for i, w in enumerate(words):                 # 程式從位址 0 開始放,小端序
            self.mem[4 * i:4 * i + 4] = w.to_bytes(4, 'little')
        self.x = [0] * 32                             # x0..x31
        self.x[2] = mem_size                          # sp 指向記憶體頂端
        self.pc = 0
        self.out = ''
        self.halted = False

    def word(self, addr):
        return int.from_bytes(self.mem[addr:addr + 4], 'little')

    def step(self):
        w = self.word(self.pc)
        op, rd, f3 = w & 0x7F, w >> 7 & 0x1F, w >> 12 & 7
        rs1, rs2, f7 = w >> 15 & 0x1F, w >> 20 & 0x1F, w >> 25
        a, b = self.x[rs1], self.x[rs2]
        next_pc, val = self.pc + 4, None              # val:要寫進 rd 的值
        if op == 0x37:                   val = w & 0xFFFFF000               # lui
        elif op == 0x13 and f3 == 0:     val = a + imm_i(w)                 # addi
        elif op == 0x13 and f3 == 1:     val = a << rs2                     # slli(shamt 放在 rs2 的位置)
        elif op == 0x33 and f3 == 0:     val = a - b if f7 == 0x20 else a + b   # sub / add
        elif op == 0x03 and f3 == 2:     val = self.word((a + imm_i(w)) & MASK)  # lw
        elif op == 0x23 and f3 == 2:                                        # sw
            addr = (a + imm_s(w)) & MASK
            self.mem[addr:addr + 4] = b.to_bytes(4, 'little')
        elif op == 0x63 and f3 in (0, 1, 4):                                # beq / bne / blt
            taken = {0: a == b, 1: a != b, 4: sext(a, 32) < sext(b, 32)}[f3]
            if taken:
                next_pc = self.pc + imm_b(w)
        elif op == 0x6F:                 val, next_pc = next_pc, self.pc + imm_j(w)       # jal
        elif op == 0x67:                 val, next_pc = next_pc, (a + imm_i(w)) & ~1      # jalr
        elif w == 0x00000073:            self.ecall()                                     # ecall
        else:
            raise ValueError(f'不認得的指令 {w:08x}(pc = {self.pc:#x})')
        if val is not None and rd != 0:               # 寫 x0 沒有作用
            self.x[rd] = val & MASK
        self.pc = next_pc & MASK

    def ecall(self):
        num, a0 = self.x[17], self.x[10]              # a7 = 編號,a0 = 引數
        if num == 1:    self.out += str(sext(a0, 32))  # print_int
        elif num == 11: self.out += chr(a0 & 0xFF)     # print_char
        elif num == 93: self.halted = True             # exit
        else:
            raise ValueError(f'不支援的 ecall {num}')

    def run(self, limit=100_000):
        steps = 0
        while not self.halted and steps < limit:
            self.step()
            steps += 1
        return steps

結構就是{{ch:21-cpu-machine-language}}的指令週期:

  1. 取指令:從 mem[pc] 讀 4 個位元組(小端序)。
  2. 解碼:用移位和遮罩切出 opcode、rd、funct3、rs1、rs2、funct7,立即值用前面的 imm_* 撿回來。
  3. 執行:一長串 if/elif,每條指令一行。
  4. 寫回:有結果就寫進 rd(rd 是 x0 時丟掉),最後更新 pc。所有值都 & MASK 保持在 32 位元,這就是 Python 版的「繞回」。

把呼叫約定寫成 assert

呼叫約定是一組不變式(invariant):函式回來的時候,sp、s0–s11 要和進去時一樣;執行的每一刻,sp 都要 16 對齊。 有了模擬器,這些可以直接寫成程式來檢查。下面的 call() 模仿測試框架:在 s 暫存器放檢查值,把 ra 設成一個假的返回位址,跑到 pc 回到那裡為止。 每一步只做 O(1) 的檢查(sp 對齊),整體性質(s 暫存器沒變)回來之後才查。 

from mini_rv import MiniRV
from run_fib import FIB

SAVED = [2, 8, 9] + list(range(18, 28))     # sp、s0、s1、s2..s11
RET = 0x000FFF00                            # 假的返回位址:pc 走到這裡就算函式回來了

def call(words, entry, a0):
    """像測試框架一樣呼叫一個函式,並檢查呼叫約定的不變式。"""
    m = MiniRV(words)
    for r in SAVED[1:]:
        m.x[r] = 0x5EED0000 + r             # 在 s 暫存器放檢查值
    m.x[1], m.x[10], m.pc = RET, a0, entry  # ra、a0、pc
    before = {r: m.x[r] for r in SAVED}
    steps = 0
    while m.pc != RET:
        m.step()
        steps += 1
        assert m.x[2] % 16 == 0, f'sp 沒有 16 位元組對齊:{m.x[2]:#x}'   # O(1),每一步都查
        assert steps < 100_000, '跑太久,可能沒有回到 ra'
    for r in SAVED:                         # 整體性質:回來之後才查
        assert m.x[r] == before[r], f'x{r} 被改了:{before[r]:#x} → {m.x[r]:#x}'
    return m.x[10], steps

  • 對齊與範圍:lh/lhu/sh 要 2 對齊、lw/sw 要 4 對齊,否則 Trap('misaligned');跳到不是 4 對齊的位址(分支成立、jal、jalr 清掉最低位之後)也是 Trap('misaligned');RAM 與 MMIO 以外 → Trap('access')。

(a) 一條 jal 最遠能跳多遠?(b) 如果要呼叫一個距離 100 MiB 的函式,要怎麼辦?(c) jalr 為什麼要把目標的最低位清成 0?

看解答

(a) J 型立即值 21 位元有號、最低位是 0:往前 1048574 位元組,往回 1048576 位元組,約 ±1 MiB。

(b) 用 auipc 加 jalr(就是假指令 call):auipc ra, hi 算出 pc + hi·4096,jalr ra, lo(ra) 再加上 12 位元的 lo 並跳過去,範圍 ±2 GiB。hi/lo 的拆法和 li 一樣要處理「lo 是負數時 hi 加 1」。

(c) 讓 jalr 的目標計算和 jal、分支一樣:位移都是偶數。有了 C 擴充(16 位元的壓縮指令)後,指令只要 2 對齊;清掉最低位也讓軟體可以把最低位拿來做標記。只有 RV32I 時,目標還要 4 對齊,否則是「指令位址沒對齊」的例外。

from mini_rv import MiniRV, imm_i

class MiniRV2(MiniRV):
    def step(self):
        w = self.word(self.pc)
        op, rd, f3 = w & 0x7F, w >> 7 & 0x1F, w >> 12 & 7
        rs1, f7 = w >> 15 & 0x1F, w >> 25
        a = self.x[rs1]
        if op == 0x13 and f3 == 7:                    # andi
            val = a & (imm_i(w) & 0xFFFFFFFF)
        elif op == 0x13 and f3 == 5 and f7 == 0:      # srli
            val = a >> (w >> 20 & 0x1F)
        else:
            return super().step()                     # 其他交給原本的 13 條
        if rd != 0:
            self.x[rd] = val
        self.pc += 4

✏️ 練習 135.10 挑戰

本章的 fib 程式:n < 2 的呼叫執行 13 條指令(序言 4 條、mv、li、blt、fib_base 的 mv、尾聲 5 條), n ≥ 2 的呼叫本身執行 19 條(不含它呼叫的子問題),_start 執行 8 條。 (a) 證明計算 fib(n) 時,n < 2 的呼叫有 F(n+1) 次,n ≥ 2 的呼叫有 F(n+1) − 1 次(F 是費氏數,F(1) = F(2) = 1)。 (b) 由此寫出總指令數的公式,並和實測的 fib(3) = 85、fib(4) = 149、fib(6) = 405 條對照。(c) 預測 fib(10)、fib(20) 的指令數。

看解答

(a) 設 L(n) 是計算 fib(n) 時 n < 2 的呼叫次數(葉),I(n) 是 n ≥ 2 的呼叫次數。L(0) = L(1) = 1,I(0) = I(1) = 0;n ≥ 2 時 L(n) = L(n−1) + L(n−2),I(n) = 1 + I(n−1) + I(n−2)。 L 的遞迴式和初值與 F(n+1) 相同,所以 L(n) = F(n+1)。令 J(n) = I(n) + 1,得 J(n) = J(n−1) + J(n−2)、J(0) = J(1) = 1,所以 J(n) = F(n+1),I(n) = F(n+1) − 1。(這是歸納法;換個說法:呼叫樹是一棵滿二元樹,每個內部節點都有兩個子節點,所以內部節點永遠比葉子少 1 個。)

(b) 總數 = 13·F(n+1) + 19·(F(n+1) − 1) + 8 = 32·F(n+1) − 11。fib(3):F(4) = 3,32·3 − 11 = 85;fib(4):F(5) = 5,149;fib(6):F(7) = 13,405。全部吻合。

(c) fib(10):F(11) = 89,32·89 − 11 = 2,837;fib(20):F(21) = 10946,350,261。實際在模擬器上跑,分別是 2,837 與 350,261 條,印出 55 與 6765。 指令數和 fib(n) 本身一樣是指數成長,約 1.618n:遞迴版 fib 很適合拿來測模擬器的速度,不適合拿來算費氏數。

把這一章串起來

  • 32 個暫存器,硬體上一樣,軟體上分工:x0 永遠是 0;ra、sp、a0–a7、s0–s11、t0–t6 的角色全部來自 ABI 約定。
  • 六種格式:R(兩個暫存器)、I(暫存器加常數、載入、jalr)、S(儲存)、B(分支)、U(lui、auipc)、J(jal)。rd、rs1、rs2 位置固定,符號位永遠在位元 31。
  • 立即值都做符號延伸;B、J 型的位元打散是為了讓硬體簡單,位移以位元組計、從分支指令自己算起。
  • 大常數 = lui + addi,lo ≥ 0x800 時 hi 要加 1;位址用 auipc + addi。li、la、call、ret 都是假指令。
  • 載入儲存分 1、2、4 位元組,lb/lh 符號延伸、lbu/lhu 補 0;小端序;要對齊。
  • 呼叫約定:引數 a0–a7,回傳 a0;s 與 sp 被呼叫者保存,t、a、ra 呼叫者保存;sp 16 對齊。呼叫框存 ra 與要用的 s 暫存器,序言與尾聲必須配對。
  • 和外界說話:ecall(a7 = 1、4、10、11、93)或 MMIO(0x10000000 印字、0x10000004 結束)。
  • 模擬器就是取指 → 解碼 → 執行 → 寫回的迴圈;呼叫約定可以寫成 assert 自動檢查。
