從 Hack HDL 到 Verilog:同一件事,換一種寫法

在{{ch:19-boolean-logic}}和{{ch:20-combinational-sequential}}, 你用 Hack HDL 從 Nand 一路接出 Mux、加法器、ALU 和暫存器。Hack HDL 很單純:只有「零件」和「線」,沒有運算子、沒有 if、也沒有參數。 這種單純是好事,它逼你看清每一顆閘。但真的設計晶片時,沒有人一顆一顆接 32 位元的加法器。

業界用的硬體描述語言(hardware description language,HDL)主要是 Verilog(和它的後繼者 SystemVerilog)與 VHDL。 Verilog 讓你寫 assign y = a + b;,再交給合成工具(synthesis tool)把它變成閘; 也讓你寫 testbench、在模擬器裡一拍一拍看訊號怎麼變。 {{ch:47-digital-circuits}}講的卡諾圖、關鍵路徑、正反器和有限狀態機,在這一章都會變成幾行 Verilog。

🔑
核心觀念

Verilog 看起來像 C,但它不是在描述「先做什麼、再做什麼」。它描述的是一堆同時存在、同時運作的電路。 每一行 assign 是一塊一直在算的組合邏輯;每一個 always @(posedge clk) 是一排在時脈邊緣同時更新的正反器。 用寫軟體的直覺讀 Verilog,是本章大部分陷阱的來源。

本章的工具是 Icarus Verilog(指令是 iverilog 和 vvp),一套開源的 Verilog 模擬器。 書裡每一段程式都用 Icarus Verilog 11 實際跑過,下面印出的輸出就是它的輸出。 你在 Linux 上可以 sudo apt install iverilog;macOS 用 brew install icarus-verilog。 版本不同時,訊息的字句可能略有不同(例如較新的版本在 $finish 時會多印一行),但數值應該一樣。

第一個模組:module、埠與實例化

先寫一顆 1 位元的 2 選 1 多工器(multiplexer)。sel 是 0 時輸出 a,是 1 時輸出 b:

// 1 位元 2 選 1 多工器:sel=0 選 a,sel=1 選 b
module mux2 (
    input  a,
    input  b,
    input  sel,
    output y
);
    assign y = sel ? b : a;
endmodule
  • module mux2 ( … ); 到 endmodule:一個模組(module),相當於 Hack 的 CHIP Mux { … }。
  • 括號裡是埠(port):input 是輸入腳,output 是輸出腳。沒寫寬度就是 1 位元。
  • assign y = sel ? b : a;:連續指定(continuous assignment)。右邊任何一個訊號變了,左邊就重新算。 ? : 和 C 的條件運算子一樣,在硬體裡就是一顆多工器。
  • // 是註解,和 C 一樣;也可以用 /* … */。

模組本身不會動。要看它的行為,得寫一個測試平台(testbench):另一個模組,裡面放一顆 mux2,再餵它輸入、印出輸出。

module tb_mux2;
    reg a, b, sel;          // testbench 自己驅動的訊號用 reg
    wire y;                 // 被模組輸出驅動的訊號用 wire
    integer i;

    mux2 dut (.a(a), .b(b), .sel(sel), .y(y));   // 用名字接腳

    initial begin
        $display("sel a b | y");
        for (i = 0; i < 8; i = i + 1) begin
            {sel, a, b} = i[2:0];   // 一次指定三個位元
            #1;                     // 等 1 個時間單位,讓 assign 算完
            $display(" %b  %b %b | %b", sel, a, b, y);
        end
        $finish;
    end
endmodule

編譯再執行。-g2012 打開 SystemVerilog 2012 的語法,-Wall 打開大部分警告:

iverilog -g2012 -Wall -o sim tb_mux2.v mux2.v   # 編譯:兩個檔案 → 模擬檔 sim
vvp sim                                       # 執行模擬

和真值表一致。這個 testbench 裡有幾個新東西:

  • mux2 dut (.a(a), .b(b), .sel(sel), .y(y));:實例化(instantiation)一顆 mux2,名字叫 dut(device under test,待測元件)。 .a(a) 的意思是「mux2 的 a 腳接到我的 a 訊號」。這和 Hack 的 Mux(a=a, …) 完全一樣:左邊是零件的腳,右邊是我的線。
  • initial begin … end:模擬一開始就執行一次的區塊。begin/end 相當於 C 的大括號。
  • #1:等 1 個時間單位。testbench 改了輸入之後要等一下,讓電路算完再讀輸出。
  • {sel, a, b} = i[2:0];:大括號是拼接(concatenation),把三個 1 位元訊號當成一個 3 位元的值一次指定。
  • $display 像 C 的 printf(會自動換行);%b 印二進位、%h 十六進位、%d 十進位(%0d 不補空白)。$finish 結束模擬。

結構式寫法:把 Hack 的晶片一顆一顆翻過來

附錄 G用三輸入的 And3 示範 Hack HDL 的語法。同一顆晶片用 Verilog 的結構式(structural)寫法,幾乎是逐行對應:

Hack HDL(And3.hdl)Verilog(and3.v)
 
CHIP And3 {
    IN a, b, c;
    OUT out;
    PARTS:
    And(a=a, b=b, out=ab);
    And(a=ab, b=c, out=out);
}
 
module and2 (input a, b, output out);
    assign out = a & b;
endmodule

module and3 (input a, b, c, output out);
    wire ab;                                // 內部線要先宣告
    and2 g1 (.a(a),  .b(b), .out(ab));      // .腳(訊號):左邊是零件的腳,右邊是我的線
    and2 g2 (.a(ab), .b(c), .out(out));
endmodule

兩個差別:Verilog 沒有內建的 And 零件可以直接叫(其實有內建的閘,後面練習 136.10 會用到),所以先寫一顆 and2; 而且內部線 ab 要先用 wire 宣告。忘了宣告會怎樣?Verilog 會自己幫你生一條 1 位元的線,叫隱含線(implicit net)。 拼錯字也一樣不會報錯,只會多一條沒人驅動的線: 

module and2 (input a, b, output out);
    assign out = a & b;
endmodule
module and3_typo (input a, b, c, output out);
    and2 g1 (.a(a),  .b(b), .out(ab));      // 忘了宣告 ab
    and2 g2 (.a(abb), .b(c), .out(out));    // 又拼錯成 abb
endmodule
typo.v:5: warning: implicit definition of wire 'ab'.
typo.v:6: warning: implicit definition of wire 'abb'.

只是警告,程式照樣編得過,and3_typo 的 out 卻永遠算錯。這就是要一直開 -Wall 的理由。 更嚴格的做法是在檔案開頭寫 `default_nettype none,讓「沒宣告就用」直接變成錯誤(埠也要寫明 input wire):

    assign out = a & b;
endmodule

    and2 g1 (.a(a),  .b(b), .out(ab));
    and2 g2 (.a(abb), .b(c), .out(out));
endmodule

訊號與數值:wire、reg 與 logic

Verilog 的訊號有兩大類,差別在「誰可以驅動它」:

型別誰可以寫它沒人寫時的值常見用途
wireassign、模組實例的輸出腳z(高阻抗,沒接)接線、組合邏輯的輸出
regalways、initial 區塊裡的指定x(未知)always 區塊算出來的值;testbench 驅動的輸入
logic(SystemVerilog)兩種都可以,但不能有好幾個連續指定(或連續指定和 always 混用)驅動它x新的程式碼大多用它取代 wire 與 reg
⚠️
reg 不等於暫存器

reg 這個名字是歷史包袱。它只表示「這個訊號在 always 或 initial 裡被指定」,不表示會合成出正反器。 always @* 裡的 reg 是組合邏輯;只有 always @(posedge clk) 裡的 reg 才是暫存器。 SystemVerilog 改用 logic,就是為了不再讓人誤會。

寫錯型別會怎樣?下面兩段都是錯的:

module err1 (input a, output reg y);
    assign y = a;      // 錯:用 assign 驅動 reg
endmodule
module err2 (input a, output y);   // y 沒寫型別,預設是 wire
    always @* y = a;   // 錯:在 always 裡對 wire 賦值
endmodule

用 -g2012 編譯,err2.v 是錯誤:

err2.v:2: error: y is not a valid l-value in err2.
err2.v:1:      : y is declared here as wire.
Elaboration failed

err1.v 在 -g2012 下反而編得過,因為 SystemVerilog 放寬了規則,准許用 assign 驅動變數。 改用舊標準 -g2005 才會看到錯誤: 

err1.v:2: error: reg y; cannot be driven by primitives or continuous assignment.
1 error(s) during elaboration.

logic 兩種寫法都接受,但它管另一件事:不能被好幾個連續指定驅動(連續指定和 always 混用也不行)。同一條 wire 被兩個 assign 驅動, Verilog 不會擋,兩邊打架的位元就變成 x(這個例子先送 a=1、b=0,再送 a=1、b=1): 

module err4 (input a, b, output y);
    assign y = a & b;
    assign y = a | b;   // 同一條線兩個驅動者
endmodule
module tb;
    reg a, b; wire y;
    err4 d(.a(a), .b(b), .y(y));
    initial begin
        a = 1; b = 0; #1 $display("y = %b", y);
        a = 1; b = 1; #1 $display("y = %b", y);
    end
endmodule
y = x
y = 1

第一列 a & b 是 0、a | b 是 1,兩個驅動者不同意,結果是 x;第二列兩邊都是 1,才看起來「正常」。同樣的事改用 logic,編譯就會擋下來:

err5.v:3: error: Unresolved net/uwire y cannot have multiple drivers.
1 error(s) during elaboration.

四值邏輯、向量與常數

Hack 的線只有 0 和 1。Verilog 的每個位元有四個值:0、1、x(未知:還沒初始化,或兩個驅動者打架)、 z(高阻抗:沒有人驅動)。多位元的訊號叫向量(vector),寬度寫在名字前面:reg [7:0] a 是 8 位元,a[7] 是最高位元。 常數寫成「位元數 ' 進位 值」:8'b1011_0110、4'hA、32'd100。 

module tb_vec;
    reg  [7:0] a;
    reg  [3:0] n;
    wire [7:0] u;          // 沒有人驅動的線
    reg        r;          // 還沒指定過的 reg

    initial begin
        a = 8'b1011_0110;                   // 底線只是給人看的分隔
        n = 4'hA;                           // 4 位元、十六進位 A = 1010
        $display("a        = %b (%0d, 0x%h)", a, a, a);
        $display("a[7:4]   = %b", a[7:4]);           // 取高 4 位元
        $display("a[0]     = %b", a[0]);
        $display("{n, n}   = %b", {n, n});           // 拼接
        $display("{4{2'b10}} = %b", {4{2'b10}});     // 重複 4 次
        $display("sign-ext = %b", {{4{n[3]}}, n});   // 符號延伸成 8 位元
        $display("zero-ext = %b", {4'b0000, n});     // 補 0 延伸
        $display("u = %b, r = %b", u, r);            // z 與 x
        $display("r & 0 = %b, r | 1 = %b, r + 1 = %b", r & 1'b0, r | 1'b1, r + 1'b1);
    end
endmodule

看最後一列:x & 0 是 0(不管 x 是什麼,AND 0 都是 0),x | 1 是 1,但 x + 1 整個變成 x。 x 會一路往下傳。模擬時看到一片 x,通常是忘了重置、忘了接線,或兩個驅動者打架。

位元寬度:多出來的位元去哪了

Verilog 很少因為寬度不合而報錯,它會默默截掉或補 0。這是加法器最常見的 bug:

module tb_width;
    reg  [3:0] a = 4'd12, b = 4'd7;
    wire [3:0] s4  = a + b;          // 結果只留 4 位元:進位丟了
    wire [4:0] s5  = a + b;          // 左邊 5 位元:運算也用 5 位元做
    wire [4:0] s5b = {1'b0, a + b};  // 拼接裡的 a + b 是「自己決定寬度」:4 位元
    wire [3:0] s;  wire co;
    assign {co, s} = a + b;          // 拼接當左邊:進位落到 co
    initial #1 $display("s4=%0d s5=%0d s5b=%0d co=%b s=%0d", s4, s5, s5b, co, s);
endmodule
s4=3 s5=19 s5b=3 co=1 s=3

12 + 7 = 19 = 1_0011。s4 只有 4 位元,進位被截掉,剩 3。s5 是 5 位元,Verilog 會把運算放大到左邊的寬度再算,所以得到 19。 但 s5b 也是 5 位元,卻得到 3:拼接 {…} 裡的每一項都用自己的寬度算,a + b 在拼接裡只有 4 位元。 要拿到進位,最清楚的寫法是讓左邊變成拼接:assign {co, s} = a + b;。

三種寫法:assign、always @* 與 always @(posedge clk)

同一個函式 $y = (a \cdot b) + c$,可以用三種方式寫。前兩種是組合邏輯,第三種多了一個正反器:

module styles (
    input            clk,
    input            a, b, c,
    output           y1,        // assign 驅動:wire
    output reg       y2,        // always @* 驅動:reg(但不是暫存器)
    output reg       q          // always @(posedge clk) 驅動:真的暫存器
);
    // ① 連續指定:右邊任何一個訊號變了,左邊立刻重算
    assign y1 = (a & b) | c;

    // ② 組合 always:@* 讓模擬器自己找出「讀了哪些訊號」
    always @* begin
        y2 = (a & b) | c;
    end

    // ③ 時脈 always:只有 clk 從 0 變 1 的那一刻才更新
    always @(posedge clk) begin
        q <= (a & b) | c;
    end
endmodule
寫法左邊的型別什麼時候重算變成什麼電路
assignwire右邊任何一個訊號變了組合邏輯
always @*reg區塊裡讀到的任何訊號變了組合邏輯(每條路徑都有指定時)
always @(posedge clk)reg只在 clk 從 0 變 1 的瞬間正反器(加上前面的組合邏輯)

用一個 testbench 同時看三個輸出。always #5 clk = ~clk; 讓時脈每 5 個時間單位翻一次,上升邊緣在 t = 5、15、25:

module tb_styles;
    reg clk = 0, a = 0, b = 0, c = 0;
    wire y1, y2, q;
    styles dut (.clk(clk), .a(a), .b(b), .c(c), .y1(y1), .y2(y2), .q(q));

    always #5 clk = ~clk;              // 每 5 個時間單位翻一次:週期 10

    initial begin
        $display(" t  clk a b c | y1 y2 q");
        $monitor("%2t   %b  %b %b %b |  %b  %b %b", $time, clk, a, b, c, y1, y2, q);
        #2  c = 1;                     // t=2:c 變 1
        #10 c = 0; a = 1;              // t=12
        #6  b = 1;                     // t=18
        #10 $finish;                   // t=28
    end
endmodule

還有一個細節:t = 0 時 y1 是 0,y2 卻是 x。assign 在模擬一開始就算一次; always @* 要等到它讀的訊號變化才會第一次執行,這裡的輸入在宣告時就是 0,沒有「變化」,所以 y2 一直是 x,直到 t = 2 c 變了才算。 SystemVerilog 的 always_comb 會在 0 時刻自己先跑一次,沒有這個問題: 

module tb_comb;
    reg a = 0;
    reg y_star; logic y_comb;
    always @* y_star = ~a;
    always_comb y_comb = ~a;
    initial begin
        #1 $display("t=1: y_star=%b y_comb=%b", y_star, y_comb);
        a = 1;
        #1 $display("t=2: y_star=%b y_comb=%b", y_star, y_comb);
    end
endmodule
t=1: y_star=x y_comb=1
t=2: y_star=0 y_comb=0

阻塞與非阻塞:= 和 <=

always 區塊裡有兩種指定。阻塞指定(blocking assignment)a = b; 和寫程式一樣:這一行做完,a 就是新值,下一行讀到的是新的 a。 非阻塞指定(nonblocking assignment)a <= b; 不一樣:右邊現在就算好,但左邊要等到這個時間點的所有區塊都跑完,才一起更新。

為什麼要有第二種?因為正反器就是這樣運作的。時脈邊緣一到,所有正反器同時取樣自己的輸入、同時更新輸出; 沒有哪一顆「先更新」,讓別顆讀到新值。<= 正好模擬這件事:大家都讀邊緣之前的值。

💡
為什麼要學:每一個有時脈的零件都靠它

暫存器檔、PC、計數器、FSM 的狀態暫存器,在硬體上都是「同時更新」。本章的循序邏輯、之後 rtl 任務線的暫存器檔與單週期 CPU、 UART 的鮑率產生器,全部都用 <=。{{ch:137-verification-cocotb}}的 cocotb 也會碰到同一件事: 在時脈邊緣讀訊號,讀到的是更新之前還是之後的值。

交換兩個暫存器

a 是 1、b 是 2,想在每個時脈邊緣交換它們。同一件事寫兩次,一次用 =,一次用 <=:

module tb_swap;
    reg clk = 0;
    reg [3:0] a1 = 1, b1 = 2;    // 用阻塞 = 交換
    reg [3:0] a2 = 1, b2 = 2;    // 用非阻塞 <= 交換

        a1 = b1;
        b1 = a1;

        a2 <= b2;
        b2 <= a2;

兩條規則,照著寫就不會出事

① 有時脈的 always(always @(posedge clk))一律用 <=。

看起來對但其實錯:「阻塞只要把順序倒過來就好」

有人發現:把阻塞版的三行倒過來寫(q3 = q2; q2 = q1; q1 = d;),每一行都先讀舊值再被覆蓋,結果和非阻塞一樣。這在一個區塊裡確實成立。 但真實的設計會拆成很多個 always 區塊、很多個模組。把移位暫存器拆成三個區塊看看:

generate:把 4 個全加器串起來

{{ch:20-combinational-sequential}}的漣波進位加法器(ripple-carry adder)是一排全加器(full adder), 每一級的進位輸出接到下一級的進位輸入。先寫一顆 1 位元全加器 fa: 

// 1 位元全加器:s = a ^ b ^ ci;co = 「至少兩個是 1」
module fa (
    input  a, b, ci,
    output s, co
);
    assign s  = a ^ b ^ ci;
    assign co = (a & b) | (a & ci) | (b & ci);
endmodule

再用 generate 迴圈放 4 顆,串成 4 位元的 add4:

// 4 位元漣波進位加法器:用 generate 串 4 個 fa
module add4 (
    input  [3:0] a, b,
    output [3:0] s,
    output       co
);
    wire [4:0] c;              // c[i] 是第 i 級的進位輸入
    assign c[0] = 1'b0;        // 最低位沒有進位輸入

    genvar i;
    generate
        for (i = 0; i < 4; i = i + 1) begin : stage
            fa u (.a(a[i]), .b(b[i]), .ci(c[i]), .s(s[i]), .co(c[i+1]));
        end
    endgenerate

    assign co = c[4];
endmodule
  • genvar i:generate 迴圈專用的變數。迴圈在編譯時展開,產生 4 顆 fa,名字是 stage[0].u 到 stage[3].u(begin : stage 替每一份取名)。
  • wire [4:0] c:5 條進位線。c[0] 接常數 0,c[i+1] 是第 i 級的進位輸出,c[4] 就是 co。
  • 這個 add4 寬度固定 4 位元、沒有進位輸入、也沒有溢位旗標。把它改成寬度可調的版本,是本章 Lab 的工作。

證明(參考):漣波進位加法器為什麼是對的

記號:$A_k = a[k{-}1{:}0]$ 是 a 的低 k 位元代表的數,$B_k$、$S_k$ 同理。要證明的是 對每個 k = 0, 1, …, 4,$2^k \cdot c[k] + S_k = A_k + B_k$(k = 0 時兩邊都是 0,因為 c[0] = 0)。 k = 4 就是 $16 \cdot co + s = a + b$,也就是 {co, s} == a + b。

歸納步驟:假設對 k 成立。全加器的真值表保證 $a[k] + b[k] + c[k] = 2 \cdot c[k{+}1] + s[k]$(三個位元相加,結果最多是 3,剛好用兩個位元 $c[k{+}1]\,s[k]$ 表示)。 兩邊乘 $2^k$ 再加上歸納假設: $$A_{k+1} + B_{k+1} = A_k + B_k + 2^k(a[k] + b[k]) = S_k + 2^k(a[k] + b[k] + c[k]) = S_k + 2^k s[k] + 2^{k+1} c[k{+}1] = S_{k+1} + 2^{k+1} c[k{+}1]$$ 所以對 k+1 也成立。同一個論證對任何寬度 W 都成立,只要把 4 換成 W。

這個歸納法的「每一步都成立的式子」,就是程式裡的不變式(invariant)。把它寫進 testbench,每一組輸入、每一級都檢查一次: 

module tb_add4_inv;
    reg  [3:0] a, b;
    wire [3:0] s;
    wire       co;
    integer i, j, k, m, lhs, rhs, bad;

    add4 dut (.a(a), .b(b), .s(s), .co(co));

    initial begin
        bad = 0;
        for (i = 0; i < 16; i = i + 1)
            for (j = 0; j < 16; j = j + 1) begin
                a = i; b = j; #1;
                // 不變式:做完第 k 級,{c[k+1], s[k:0]} == a[k:0] + b[k:0]
                for (k = 0; k < 4; k = k + 1) begin
                    m   = (1 << (k + 1)) - 1;                 // 低 k+1 位元的遮罩
                    lhs = dut.c[k+1] * (m + 1) + (s & m);     // {c[k+1], s[k:0]}
                    rhs = (i & m) + (j & m);
                    if (lhs != rhs) bad = bad + 1;
                end
            end
        $display("不變式檢查 256 x 4 = %0d 次,失敗 %0d 次", 256 * 4, bad);
    end
endmodule

cin 與 ovf:進位輸入、有號溢位與減法

本章 Lab 的 adder 比 add4 多了進位輸入 cin、進位輸出 cout 和有號溢位旗標 ovf。這三個都只是接線,不用多加全加器:

  • c[0] = cin:最低位那條原本接常數 0 的進位線,改接 cin。上面的證明照樣成立:左邊的 c[0] 本來就是 cin,只是 k = 0 時右邊多加一個 cin,最後變成 {cout, sum} == a + b + cin。
  • cout = c[W]:最高一級送出的進位,也就是無號加法結果的第 W+1 個位元(add4 的 co = c[4])。
  • ovf:把 a、b、sum 當二補數時的溢位。溢位的意思是「兩個同號的數相加,結果卻是另一個號」。它也只用到進位鏈上已經有的線,不用另外做一個加法器。

怎麼判斷溢位?最高一級(第 W−1 級)吃的是兩個符號位元 a[W−1]、b[W−1] 和進位 c[W−1]。照兩個符號位元分三種情況:

a[W−1] b[W−1]意思sum[W−1]c[W]什麼時候溢位
0 0正 + 正= c[W−1]0sum 變成負的,也就是 c[W−1] = 1
1 1負 + 負= c[W−1]1sum 變成非負,也就是 c[W−1] = 0
0 1 或 1 0異號= 1 − c[W−1]= c[W−1]永遠不會溢位

把 c[W] 那一欄和「什麼時候溢位」那一欄並排看,就找得到一條只用最高兩級進位 c[W]、c[W−1] 判斷溢位的規則;手算 136.2 的第 (3) 小題請你自己找出來。 例:上面 testbench 印的 1011 + 0110,當有號讀是 −5 + 6 = 1:異號相加,照表永遠不會溢位(cout = 1 只是無號的進位)。

減法用同一個 adder:二補數的 −b = ~b + 1,所以 a − b = a + ~b + 1。把 b 每個位元取反(~b)送進 b 腳、cin 接 1,不用另外做減法器。 這時 cout = 1 表示「沒有借位」(當無號看 a ≥ b),ovf 照樣是有號溢位。例:W = 4,3 − 5,送進去的是 0011 + 1010 + 1:

  • ☐ 真的用 full_adder〔隱藏檢定〕把 full_adder 換成故意弄壞的版本,你的 adder 結果要跟著錯(證明 adder 真的由 full_adder 串成,不是直接寫 a + b)。
  • ☐ 模擬時間〔隱藏檢定〕漣波進位在事件驅動的模擬器裡一級一級傳,電路不能大到讓上層的 ALU 測不完。門檻:W=4 mux4 窮舉 262,144 組＋W=8 adder 窮舉 131,072 組 2 秒內;W=32 adder 104 組隨機向量 3 秒內。這個門檻來自任務「RV32I ALU」的「模擬時間」(ALU 用你的 adder),以及 Boss 戰「ALU 窮舉」:閘與 ALU 的全部隱藏檢定要在 60 秒內跑完。

規則:adder.v 必須 instantiate full_adder(檢定會把 full_adder 換成壞掉的版本,你的 adder 要跟著錯)。判題接受的 Verilog 照本章的「判題接受的 Verilog」:只編譯你的檔案時 iverilog -g2012 -Wall 零警告;不准 `include、`timescale、階層參照、initial 區塊與宣告時給初值;系統函式只准 $signed、$unsigned、$clog2、$display。

這個零件過關之後,後面的專題一律用你自己的版本。規則見零件庫規則。

組合邏輯的陷阱:意外長出閂鎖

always @* 寫的是組合邏輯:輸出只由「現在的輸入」決定。但如果某一條路徑沒有指定輸出, Verilog 的語意是「那就保持原來的值」。要保持舊值,電路就得記住東西,合成工具只好替你放一顆閂鎖(latch)。 這幾乎都是 bug:閂鎖是準位觸發的({{ch:47-digital-circuits}}講過它和正反器的差別),時序難分析,而且你根本沒打算要它。

💡
為什麼要學:簽核時不准有閂鎖

組合電路長出閂鎖,模擬時常常看不出來(下面的例子在你測的輸入上全對)。任務線「UART 收發器」最後的 Boss 戰「合成與時序簽核」會用合成工具 Yosys 檢查「沒有 latch」; RV32I ALU 的隱藏檢定也會送未定義的運算碼,檢查輸出是不是規定的 0,而不是「上一次的值」。

看起來對但其實錯:測過的輸入都對

想做一個 3 選 1:sel = 00 選 a、01 選 b、10 選 c。11「不會用到」,所以沒寫:

// 想做的是:sel=00 選 a、01 選 b、10 選 c;11 不會用到(所以沒寫)
module pick_bad (input [1:0] sel, input a, b, c, output reg y);
    always @* begin
        case (sel)
            2'b00: y = a;
            2'b01: y = b;
            2'b10: y = c;
        endcase              // sel=11 時沒有指定 y → y 要「記住」舊值 → 閂鎖
    end
endmodule

// 修法:一開頭先給預設值(或補 default)
module pick_good (input [1:0] sel, input a, b, c, output reg y);
    always @* begin
        y = 1'b0;            // 每條路徑都有值
        case (sel)
            2'b00: y = a;
            2'b01: y = b;
            2'b10: y = c;
            default: ;       // 11:維持上面的預設值 0
        endcase
    end
endmodule
module tb_latch;
    reg [1:0] sel; reg a, b, c;
    wire y_bad, y_good;
    pick_bad  u1 (.sel(sel), .a(a), .b(b), .c(c), .y(y_bad));
    pick_good u2 (.sel(sel), .a(a), .b(b), .c(c), .y(y_good));
    task show(input integer k);
        #1 $display("%0d  %b  %b %b %b |  %b   %b", k, sel, a, b, c, y_bad, y_good);
    endtask
    initial begin
        $display("步 sel a b c | bad good");
        sel = 2'b00; a = 1; b = 0; c = 0;  show(1);
        sel = 2'b11;                       show(2);
        a = 0;                             show(3);
        sel = 2'b01;                       show(4);
        sel = 2'b11; a = 1; b = 1; c = 1;  show(5);
        sel = 2'b10;                       show(6);
    end
endmodule

⚠️
iverilog -Wall 不會警告閂鎖

上面兩個模組用 iverilog -g2012 -Wall 編譯,都沒有任何警告。Icarus 是模擬器,不做合成,它只照語意模擬「保持舊值」。 要抓閂鎖,得靠合成工具的報告(例如 Yosys 會列出它推論出的 latch),或從寫法上避免。

避免閂鎖的三個習慣:

  1. 區塊一開頭先給每個輸出一個預設值(像 pick_good 的 y = 1'b0;)。後面的 if、case 只需要寫「不一樣」的情況。
  2. case 一律寫 default,if 一律配 else。
  3. 一個 always 區塊指定好幾個輸出時,每一條路徑都要指定到每一個輸出。最容易漏的是「這條路徑只改了 y1,忘了 y2」。

反過來,在 always @(posedge clk) 裡「沒寫就保持」是正確的:那本來就是正反器,保持舊值正是它的工作。 後面帶致能的暫存器就是這樣寫的。

另外兩個組合邏輯陷阱

敏感列表不完整。舊式的寫法是把會觸發區塊的訊號列在 @( ) 裡。漏了一個,模擬就不會在它變化時重算:

合成工具通常不管敏感列表,照「a AND b」做出電路;於是模擬和合成出來的電路行為不一樣,這是最難查的一種 bug。 解法很簡單:組合邏輯一律寫 always @*(或 SystemVerilog 的 always_comb),讓工具自己找。

同一個訊號被兩個地方驅動。前面已經看過:兩個 assign 打架會變成 x;兩個 always 區塊指定同一個 reg,則是誰最後執行誰贏,又是一種競賽。 規則是:每個訊號只在一個地方指定。用 logic 宣告的話,兩個連續指定會直接編譯失敗。

組合電路實例:8 位元 ALU 與 RV32I 的運算

{{ch:20-combinational-sequential}}的 Hack ALU 用 6 個控制位元(zx、nx、zy、ny、f、no)拼出 18 種函式。 Verilog 有現成的運算子,一個小 ALU 寫成 case 就好。下面是 8 位元、4 種運算的範例,加減法直接用 + 和 -: 

// 8 位元、4 種運算的小 ALU(範例用:直接寫 + 與 -)
module alu8 (
    input      [7:0] a, b,
    input      [1:0] op,      // 00 add、01 sub、10 and、11 or
    output reg [7:0] y,
    output           zero
);
    always @* begin
        case (op)
            2'b00:   y = a + b;
            2'b01:   y = a - b;
            2'b10:   y = a & b;
            2'b11:   y = a | b;
            default: y = 8'h00;   // op 有 x 或 z 時也有值:不會長出閂鎖
        endcase
    end
    assign zero = (y == 8'h00);
endmodule
module tb_alu8;
    reg  [7:0] a, b;
    reg  [1:0] op;
    wire [7:0] y;
    wire       zero;
    alu8 dut (.a(a), .b(b), .op(op), .y(y), .zero(zero));

    task show(input [7:0] xa, input [7:0] xb, input [1:0] xop);
        begin
            a = xa; b = xb; op = xop; #1;
            $display("op=%b a=%h b=%h -> y=%h (%0d) zero=%b", op, a, b, y, y, zero);
        end
    endtask

    initial begin
        show(8'h7F, 8'h01, 2'b00);   // 127 + 1:8 位元裝得下,但有號溢位
        show(8'hFF, 8'h01, 2'b00);   // 255 + 1:進位丟掉,結果 0
        show(8'h05, 8'h07, 2'b01);   // 5 - 7 = -2 → FE
        show(8'h3C, 8'h0F, 2'b10);   // and
        show(8'h3C, 8'h0F, 2'b11);   // or
        show(8'h3C, 8'h3C, 2'b01);   // 相等相減 → zero=1
    end
endmodule

  • 7F + 01 = 80:8 位元裝得下,但把它們當二補數看是 127 + 1 = −128,有號溢位。這顆 ALU 沒有溢位旗標,所以看不出來。
  • FF + 01 的進位被截掉,結果 0,zero 變 1。
  • 2 位元的 op 四種值都寫了,default 看起來多餘;但 op 是 x 或 z 時(例如還沒接好),default 讓 y 有確定的值,寫法上也保證不會長出閂鎖。

        $display("or   %h", a | b);
        $display("and  %h", a & b);

Verilog 的規則是:一個運算式裡只要有一個運算元是無號的,整個運算式就用無號算。這會產生兩個看起來很對的 bug:

{{ch:20-combinational-sequential}}用 Hack 內建的 DFF 一層一層蓋出 Bit、Register 和 PC。 Verilog 沒有內建的 DFF 零件,always @(posedge clk) 加上 <= 就是正反器。下面四個模組放在同一個檔案 seq.v: 

// D 正反器:同步重置(只在時脈邊緣看 rst)
module dff_sync (input clk, rst, d, output reg q);
    always @(posedge clk) begin
        if (rst) q <= 1'b0;
        else     q <= d;
    end
endmodule

// D 正反器:非同步重置(rst 一變 1 就立刻清 0,不等時脈)
module dff_async (input clk, rst, d, output reg q);
    always @(posedge clk or posedge rst) begin
        if (rst) q <= 1'b0;
        else     q <= d;
    end
endmodule

// 帶致能的暫存器:寬度用參數 W 決定(預設 8)
module reg_en #(parameter W = 8) (
    input              clk, rst, en,
    input      [W-1:0] d,
    output reg [W-1:0] q
);
    always @(posedge clk) begin
        if (rst)     q <= {W{1'b0}};
        else if (en) q <= d;
        // en=0:什麼都不寫 → q 保持。這在時脈 always 裡是正確的「記住」,不是閂鎖
    end
endmodule

// 0..MAX 反覆計數的計數器(預設 MAX=9:十進位一位數)
module counter #(
    parameter MAX = 9,
    parameter N   = $clog2(MAX + 1)   // 裝得下 MAX 要幾個位元:MAX=9 → 4
) (
    input              clk, rst, en,
    output reg [N-1:0] count,
    output             wrap           // count==MAX 而且 en=1:下一拍要繞回 0
);
    assign wrap = en && (count == MAX);
    always @(posedge clk) begin
        if (rst)       count <= {N{1'b0}};
        else if (wrap) count <= {N{1'b0}};
        else if (en)   count <= count + 1'b1;
    end
endmodule
  • 同步重置(synchronous reset):rst 只在時脈邊緣被看見。非同步重置(asynchronous reset):rst 也寫進敏感列表(or posedge rst),一拉高就立刻清 0。兩種都常見,一個設計裡選一種用到底。
  • reg_en 的 en = 0 時什麼都不寫,q 保持。在時脈 always 裡這是正確的「記住」,合成出來是正反器前面加一顆多工器(選 d 或選 q 自己),和 Hack 的 Bit 一樣。
  • counter 的寬度 N 由參數 MAX 推出:$clog2(MAX + 1)。MAX = 9 要 4 位元,MAX = 3 只要 2 位元。wrap 是組合輸出,在「這一拍數到 MAX 而且 en = 1」時是 1,告訴外面「下一個邊緣要繞回 0」。很多計數器串接(秒、分、時)就是靠這種訊號。
  • {W{1'b0}} 是「W 個 0」:用重複拼接寫出和參數一樣寬的常數。

用 Verilog 寫有限狀態機

{{ch:47-digital-circuits}}把有限狀態機(FSM)拆成三塊:狀態暫存器、次態邏輯、輸出邏輯,並設計了偵測 "101" 的 Moore 機(S0–S3,可重疊)。 Verilog 的標準寫法就是照這三塊各寫一段,叫三段式(three-block)寫法: 

// Moore 版 "101" 偵測器(可重疊):輸出只看現態
module det101_moore (input clk, rst, x, output y);
    localparam S0 = 2'd0,   // 還沒有有用的前綴
               S1 = 2'd1,   // 看到 "1"
               S2 = 2'd2,   // 看到 "10"
               S3 = 2'd3;   // 看到 "101":輸出 1
    reg [1:0] state, next;

    // ① 狀態暫存器:唯一一個用時脈的區塊,用 <=
    always @(posedge clk) begin
        if (rst) state <= S0;
        else     state <= next;
    end

    // ② 次態邏輯:純組合,用 =,每條路徑都要給 next 一個值
    always @* begin
        next = S0;
        case (state)
            S0: next = x ? S1 : S0;
            S1: next = x ? S1 : S2;
            S2: next = x ? S3 : S0;
            S3: next = x ? S1 : S2;
            default: next = S0;
        endcase
    end

    // ③ 輸出邏輯:Moore 只看 state
    assign y = (state == S3);
endmodule

// Mealy 版:輸出看「現態 + 現在的輸入」,只要 3 個狀態
module det101_mealy (input clk, rst, x, output y);
    localparam M0 = 2'd0, M1 = 2'd1, M2 = 2'd2;   // 前綴長度 0、"1"、"10"
    reg [1:0] state, next;

    always @(posedge clk) begin
        if (rst) state <= M0;
        else     state <= next;
    end

    always @* begin
        next = M0;
        case (state)
            M0: next = x ? M1 : M0;
            M1: next = x ? M1 : M2;
            M2: next = x ? M1 : M0;    // "101" 的最後一個 1 也是下一個 "1"
            default: next = M0;
        endcase
    end

    assign y = (state == M2) && x;     // 在 "10" 之後看到 1:當拍就喊
endmodule
  • ① 狀態暫存器:唯一用時脈的區塊,只有一行 state <= next(加上重置)。
  • ② 次態邏輯:always @*,先給 next = S0 的預設值,再用 case 照{{ch:47-digital-circuits}}的狀態轉移表填。表上的每一格就是一行。
  • ③ 輸出邏輯:Moore 只看 state;Mealy 看 state 和 x。
  • localparam 替狀態取名字,編碼和{{ch:47-digital-circuits}}一樣(S0 = 00 … S3 = 11)。Moore 輸出 state == S3 在這個編碼下就是 $Q_1 \cdot Q_0$。

★深入(選讀):模擬語意、事件佇列與 delta cycle

前面看過三件怪事:阻塞的移位暫存器拆成三個區塊會競賽;always @* 在 0 時刻不會先跑;<= 的新值要「等一下」才看得到。 它們都來自同一個機制:模擬器的事件佇列(event queue)。

💡
為什麼要學:testbench 讀錯一拍,是最常見的驗證 bug

{{ch:137-verification-cocotb}}的 cocotb 測試在 Python 裡等時脈邊緣、讀 DUT 的輸出;讀到的是邊緣「之前」還是「之後」的值,就取決於這一節的排程。 rtl/tb 任務要你寫測試抓突變版的 ALU,測試自己讀錯時間點,就會把正確的版本判成錯。

Verilog 的模擬時間是一格一格的整數(t = 0、1、2…)。同一個時間點裡,模擬器把要做的事分成幾個區(region),照順序處理 (這是 IEEE 1364 的四個區;SystemVerilog 為了 assertion 和 testbench 又多加了幾區,但順序的精神一樣):

圖 136-4 的文字版:

時間點 t:
  ① Active    阻塞指定、assign 重算、$display、算好 <= 的右邊(還不寫)
       │  空了
  ② Inactive  #0 之後的敘述          ── 喚醒了新事件 → 回到 ①
       │  空了
  ③ NBA       把排隊的 <= 一起寫進去  ── 有訊號變了 → 回到 ①(新的一輪 delta cycle)
       │  全部安靜
  ④ Monitor   $strobe、$monitor 印出這個時間點的最後結果
       │
  前進到下一個有事件的時間點

「回到 ①」的每一輪,叫一個 delta cycle:模擬時間沒有前進,但訊號又變了一次。 一個時脈邊緣通常要好幾輪 delta cycle 才會安靜:正反器的 <= 寫進去 → 後面的組合邏輯重算 → 再下一級的組合邏輯重算…… delta 是零時間,所以它只決定「順序」,不代表延遲。

這也解釋了前面的現象:

  • 非阻塞為什麼沒有競賽:所有正反器的 always 都在 ① 裡讀值、算右邊,寫入全部延到 ③。不管 ① 裡誰先執行,大家讀到的都是邊緣之前的值。
  • 阻塞為什麼有競賽:寫入在 ① 裡就發生了,而 ① 裡的事件順序標準沒規定。

用一個小例子看 $display、#0 和 $strobe 各自在哪一區印:

module tb_sched;
    reg  [3:0] q = 0;
    reg        clk = 0;
    wire [3:0] w1, w2;
    assign w1 = q + 1;          // q 變了 → w1 重算(一個 delta)
    assign w2 = w1 * 2;         // w1 變了 → w2 重算(再一個 delta)

        q <= 4'd5;
        $display("display: q=%0d w1=%0d w2=%0d", q, w1, w2);   // 現在就印

    initial begin

        #1  $display("t=11   : q=%0d w1=%0d w2=%0d", q, w1, w2);

可合成的子集:哪些寫法會變成電路

Verilog 一開始是為了模擬設計的語言,後來才拿來合成。所以它有一大塊語法只在模擬器裡有意義,合成工具不會(也沒辦法)把它變成閘。 能合成的那一部分叫可合成子集(synthesizable subset)。寫設計檔只用這一部分;testbench 才用其他的。

寫法能合成嗎變成什麼/說明
assign、模組實例、閘(and、or…)能組合邏輯與接線
always @*/always_comb,每條路徑都有指定能組合邏輯
always @*,有路徑沒指定能,但多半是 bug閂鎖
always @(posedge clk)能正反器(加上前面的組合邏輯)
always @(posedge clk or posedge rst)能有非同步重置的正反器
parameter、localparam、generate、次數固定的 for能編譯時展開成好幾份硬體
+、-、比較、移位、位元運算能加法器、比較器、多工器
*多半能乘法器,電路很大
/、%看情況除數是 2 的次方常數時就是移位;一般的除法很多工具不支援,或做出很大很慢的電路
指定成 x(例如 y = 8'bx;)能很多工具當成 don't-care,隨它化簡({{ch:47-digital-circuits}});模擬時則真的是 x
initial、宣告時給初值不能(ASIC)只有模擬裡有效。有些 FPGA 工具拿來當開機初值,但不要依賴;用重置
#延遲不能合成時直接忽略;真正的延遲由閘和連線決定
$display、$finish、$dumpvars、$random不能只給模擬
===、!==不能(或當成 ==)硬體裡沒有 x 和 z 可以比
while、次數由訊號決定的迴圈不能硬體的大小要在編譯時決定
real(浮點數)不能要浮點就自己做浮點運算單元
🔑
寫每一行之前,先想它是哪一塊硬體

可合成的 Verilog 裡,每一行都能指出它對應的電路:這個 ?: 是一顆多工器,這個 + 是一顆加法器,這個 always @(posedge clk) 是一排正反器。 說不出來的那一行,通常就是不能合成、或合成出你沒想到的東西(例如閂鎖)。for 迴圈也一樣:它不是「跑 8 次」,而是「做 8 份」。

本章已經寫了很多 testbench,它們都有同樣的骨架:產生時脈、重置、送輸入、檢查輸出、印結果、結束。 把它寫完整一點,就是一個會自己判斷對錯(self-checking)的 testbench。下面測 MAX = 9 的計數器 25 拍, 在 testbench 裡用一行 expect_cnt 當參考模型,每拍比對;同時把所有訊號存成波形檔: 

module tb_counter;
    reg clk = 0, rst = 1, en = 1;
    wire [3:0] count;
    wire wrap;
    integer errors = 0, expect_cnt = 0, cycle;

    counter #(.MAX(9)) dut (.clk(clk), .rst(rst), .en(en), .count(count), .wrap(wrap));

    always #5 clk = ~clk;                  // 10 個時間單位一個週期

    initial begin
        $dumpfile("counter.vcd");          // 波形檔的名字
        $dumpvars(0, tb_counter);          // 0 = 這一層和底下所有訊號都記
        @(posedge clk); #1 rst = 0;        // 重置一拍
        for (cycle = 0; cycle < 25; cycle = cycle + 1) begin
            @(posedge clk); #1;
            expect_cnt = (expect_cnt == 9) ? 0 : expect_cnt + 1;   // 參考模型
            if (count !== expect_cnt) begin
                errors = errors + 1;
                $display("FAIL cycle %0d: count=%0d expect=%0d", cycle, count, expect_cnt);
            end
        end
        if (errors == 0) $display("PASS: 25 拍全部正確");
        else             $display("FAIL: %0d 拍錯", errors);
        $finish;
    end
endmodule

Verilog 的來歷

Verilog 在 1984 年前後由 Gateway Design Automation 的 Phil Moorby 等人設計,原本是一套模擬器的語言;Cadence 在 1989 年買下 Gateway,1990 年把語言公開,1995 年成為 IEEE 1364 標準。 這段歷史解釋了為什麼它有那麼多「只能模擬」的語法。2005 年起,擴充版 SystemVerilog 成為 IEEE 1800 標準,加入 logic、always_comb、assertion 與大量驗證用的功能; 之後的 IEEE 1800 版本已經把 Verilog 併進去。

  • (甲)SystemVerilog 准許 assign 驅動變數;Verilog-2005 不准:reg y; cannot be driven by primitives or continuous assignment.
  • (丙)-g2012 下可以編譯。Icarus 在 -g2005 下把 logic 當成 reg,所以錯誤訊息和(甲)一模一樣。

結論:新程式用 logic,一個訊號只在一個地方指定,就不必背這些規則。

✏️ 練習 136.7 實作

用三段式寫法,寫一個偵測 "110" 的 Mealy 機(可重疊)。先畫狀態圖、列轉移表,再寫 Verilog。對輸入 1101110110 追出每一拍的現態與 y。

看解答

三個狀態:A(前綴長度 0)、B(看到 "1")、C(看到 "11")。轉移:A 讀 1 → B、讀 0 → A;B 讀 1 → C、讀 0 → A;C 讀 1 → C("111" 還是以 "11" 結尾)、讀 0 → A,而且這時輸出 1。

// Mealy 版 "110" 偵測器(可重疊)
module det110_mealy (input clk, rst, x, output y);
    localparam A = 2'd0,   // 前綴長度 0
               B = 2'd1,   // 看到 "1"
               C = 2'd2;   // 看到 "11"
    reg [1:0] state, next;

    always @(posedge clk) begin
        if (rst) state <= A;
        else     state <= next;
    end

    always @* begin
        next = A;
        case (state)
            A: next = x ? B : A;
            B: next = x ? C : A;
            C: next = x ? C : A;   // "111" 還是以 "11" 結尾;"110" 之後從頭來
            default: next = A;
        endcase
    end

    assign y = (state == C) && !x;
endmodule
module tb_det110;
    reg clk = 0, rst = 1, x = 0;
    wire y;
    det110_mealy dut (.clk(clk), .rst(rst), .x(x), .y(y));

        #1 clk = 1; #1 clk = 0; rst = 0;
        for (i = 0; i < 10; i = i + 1) begin
            x = bits[9 - i];
            #1 $display("%0d x=%b state=%0d y=%b", i, x, dut.state, y);
            clk = 1; #1 clk = 0;
        end
    end
endmodule

把這一章串起來

Verilog 是你在 Hack HDL 學過的同一件事:用文字描述「有哪些電路、線怎麼接」。它多給你的,是運算子、always、參數和 generate,讓 32 位元的加法器只要幾行; 它多要求你的,是時時記得自己在寫硬體:

  • 模組、埠、實例化和 Hack 的 CHIP、IN/OUT、零件一一對應:.a(x) 一樣是「左邊零件的腳,右邊我的線」。內部線要宣告,並且一直開著 -Wall。
  • wire 與 reg只差在「誰能寫它」;reg 不等於暫存器。新程式用 SystemVerilog 的 logic。訊號有 0、1、x、z 四個值,寬度不合時 Verilog 會默默截斷或延伸。
  • assign 和 always @* 是組合邏輯;always @(posedge clk) 是正反器。有時脈的區塊用 <=,組合的區塊用 =,不照規則寫就會競賽。
  • parameter 與 generate讓一個模組任意寬度;漣波加法器的正確性是一個歸納法,它的程式版本是逐級的不變式 testbench。
  • 組合邏輯的每一條路徑都要指定每一個輸出,否則長出閂鎖;先給預設值、case 寫 default。
  • RV32I 的 ALU 有十種運算;有號和無號只在 slt/sltu、sra/srl 與溢位上不同。Verilog 的有號運算會被無號的運算元「傳染」。
  • FSM 用三段式:狀態暫存器、次態邏輯、輸出邏輯。Moore 的輸出比 Mealy 晚一拍。
  • 模擬器的事件佇列決定同一個時間點裡誰先誰後:Active、Inactive、NBA、Monitor,每回到 Active 一次是一個 delta cycle。
  • 只有可合成子集會變成電路;initial、#延遲、$display 屬於 testbench。self-checking testbench 加上 VCD 波形,是驗證的第一步。

  • Icarus Verilog:本章用的模擬器,文件與原始碼在 steveicarus.github.io/iverilog。波形檢視器 GTKWave。
  • HDLBits(hdlbits.01xz.net):一百多題線上 Verilog 小題,從一條線寫到 FSM,送出就有模擬器判對錯,很適合配著本章練。
  • Sarah L. Harris、David Harris,Digital Design and Computer Architecture, RISC-V Edition:Chapter 4 是 HDL(SystemVerilog 與 VHDL 對照),後面的章節用它做出 RISC-V 處理器,正好是 rtl 任務線的路線。
  • Clifford E. Cummings,〈Nonblocking Assignments in Verilog Synthesis, Coding Styles That Kill!〉(SNUG 2000):阻塞與非阻塞的經典整理,本章的兩條規則就是它的結論。
  • Samir Palnitkar,Verilog HDL: A Guide to Digital Design and Synthesis:完整的 Verilog 語法參考。
  • 標準本身:IEEE 1800(SystemVerilog,已包含 Verilog)。第 4 節「Scheduling semantics」就是本章 ★深入 那一節的正式版本。
