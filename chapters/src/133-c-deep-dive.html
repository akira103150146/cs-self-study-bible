核心觀念

在 C 裡,一個變數就是「從某個位址開始的幾個位元組」,型別只是告訴編譯器怎麼解讀這幾個位元組。本章每一節都在回答同一個問題:這幾個位元組在哪裡、有幾個、什麼時候有效。

本章每一段完整的程式都可以直接編譯:gcc -std=c17 -Wall -Wextra 檔名.c -o 檔名;只有片段、沒有 main 的(例如 struct 的宣告與看組語的示範),用 -c 或 -S 編譯。 除了特別標明「錯誤示範」、要讓你看警告的那幾段,都不會有任何警告。 書上的輸出都是在 x86-64 Linux、gcc 13.3 上實際跑出來的;和機器有關的結果(例如位元組順序、long 的大小),會特別註明。

指標運算:加 1 是加幾個位元組

橋接章 A說過:*(q + 1) 就是 q[1]。現在要問得更精確:q + 1 的位址,比 q 大多少? 答案是一個元素的大小。q 指向 int32_t,q + 1 就比 q 大 4 個位元組;指向 uint8_t 就大 1;指向 double 就大 8。 這叫指標運算(pointer arithmetic):指標的加減,單位是「它指向的型別」。 

#include <stdio.h>
#include <stdint.h>

int main(void) {
    int32_t a[4] = {10, 20, 30, 40};
    int32_t *p = a;               // a 退化成 &a[0]
    uint8_t *b = (uint8_t *)a;    // 同一塊記憶體,用「一個位元組」的眼光看
    int16_t *h = (int16_t *)a;    // 用「兩個位元組」的眼光看

    // 印「離 a 的開頭幾個位元組」,不印位址本身(位址每次執行都不同)
    printf("p + 2      -> 位移 %td,值 %d\n", (char *)(p + 2) - (char *)a, (int)*(p + 2));
    printf("b + 2      -> 位移 %td\n", (char *)(b + 2) - (char *)a);
    printf("h + 3      -> 位移 %td\n", (char *)(h + 3) - (char *)a);
    printf("&a + 1     -> 位移 %td\n", (char *)(&a + 1) - (char *)a);
    printf("&a[3] - p  =  %td 個元素\n", &a[3] - p);
    printf("p[1] %d, *(p + 1) %d, 1[p] %d\n", (int)p[1], (int)*(p + 1), (int)1[p]);
    return 0;
}

輸出:

p + 2      -> 位移 8,值 30
b + 2      -> 位移 2
h + 3      -> 位移 6
&a + 1     -> 位移 16
&a[3] - p  =  3 個元素
p[1] 20, *(p + 1) 20, 1[p] 20
  • 同一塊記憶體,用三種眼光看:p + 2 走 2 × 4 = 8 個位元組,b + 2 走 2 × 1 = 2,h + 3 走 3 × 2 = 6。
  • &a 的型別是「指向整個陣列 int32_t[4] 的指標」,一個元素是 16 個位元組,所以 &a + 1 跳過整個陣列。
  • 兩個指標相減,得到的是「相差幾個元素」(型別是 ptrdiff_t,用 %td 印),不是相差幾個位元組。
  • p[i] 的定義就是 *(p + i)。加法可以交換,所以 1[p] 也合法。知道就好,不要這樣寫。

程式只印「離 a 開頭幾個位元組」,不印位址本身:Linux 每次執行都會把堆疊放在隨機的位置(位址空間配置隨機化,ASLR),位址每次都不同,位移才是固定的。 (char *) 轉型是為了讓兩個指標相減時,單位變成位元組。

⚠️
指標運算的界線

C 標準只保證:指標在同一個陣列裡移動,或剛好指到最後一個元素的「下一格」,都是合法的(下一格可以拿來比較,不能讀寫)。 超出這個範圍,光是算出那個指標就已經是未定義行為,不必等到讀寫。把不同陣列的指標相減,也是未定義行為。

陣列不是指標:退化與 sizeof 陷阱

橋接章 A說「陣列名稱在大多數式子裡會自動轉成第 0 格的位址」。這個自動轉換叫做退化(decay)。 退化之後,長度資訊就不見了。陣列本身不是指標,只是它很容易變成指標。 

#include <stdio.h>

void show(int arr[10]) {          // 看起來是陣列,其實是 int *arr
    printf("函式裡 sizeof(arr) = %zu\n", sizeof(arr));
}

int main(void) {
    int a[10] = {0};
    int *p = a;
    char s[] = "hi";              // 陣列:'h' 'i' '\0'
    const char *t = "hi";         // 指標:指向唯讀的字串常數

    printf("sizeof(a) = %zu, 元素數 = %zu\n", sizeof(a), sizeof(a) / sizeof(a[0]));
    printf("sizeof(p) = %zu\n", sizeof(p));
    printf("sizeof(s) = %zu, sizeof(t) = %zu\n", sizeof(s), sizeof(t));
    show(a);
    return 0;
}

這段程式是錯誤示範,gcc 會警告:

decay.c: In function ‘show’:
decay.c:4:48: warning: ‘sizeof’ on array function parameter ‘arr’ will return size of ‘int *’ [-Wsizeof-array-argument]
    4 |     printf("函式裡 sizeof(arr) = %zu\n", sizeof(arr));
      |                                                ^
decay.c:3:15: note: declared here
    3 | void show(int arr[10]) {          // 看起來是陣列,其實是 int *arr
      |           ~~~~^~~~~~~

輸出(x86-64,指標是 8 個位元組):

sizeof(a) = 40, 元素數 = 10
sizeof(p) = 8
sizeof(s) = 3, sizeof(t) = 8
函式裡 sizeof(arr) = 8
  • sizeof(a) 是整個陣列:10 × 4 = 40。sizeof 是三個「不退化」的例外之一,另外兩個是 &a,以及用字串常數初始化字元陣列(char s[] = "hi")。
  • sizeof(p) 是指標本身的大小:8。
  • s 是 3 個位元組的陣列(含 '\0');t 是一個指標,指向放在唯讀區的字串常數。透過 t 修改字串是未定義行為,所以 t 宣告成 const char *。
  • 參數寫成 int arr[10],編譯器會把它當成 int *arr,10 只是給人看的註解。函式裡的 sizeof(arr) 是 8,不是 40。
⚠️
看起來對但其實錯:在函式裡用 sizeof 算長度

sizeof(arr) / sizeof(arr[0]) 在宣告陣列的那個函式裡是對的,換到接收參數的函式裡就變成 8 ÷ 4 = 2。 測試時剛好用 2 個元素的陣列,就看不出錯。規則:陣列傳進函式時,一定另外傳長度,例如 f(const int *a, size_t n)。

二維陣列退化成什麼

int32_t m[3][4] 是「3 個元素的陣列,每個元素是 int32_t[4]」。它退化成指向第 0 個元素的指標,型別是 int32_t (*)[4]:一步走一整列。 

#include <stdio.h>
#include <stdint.h>

int main(void) {
    int32_t m[3][4] = {{0, 1, 2, 3}, {10, 11, 12, 13}, {20, 21, 22, 23}};
    int32_t (*row)[4] = m;        // m 退化成「指向 4 個 int32_t 的陣列」的指標
    int32_t *cell = &m[0][0];     // 指向單一元素

    printf("row + 1  -> 位移 %td\n", (char *)(row + 1) - (char *)m);
    printf("cell + 1 -> 位移 %td\n", (char *)(cell + 1) - (char *)m);
    printf("row[2][1] = %d, (*(row + 2))[1] = %d\n", (int)row[2][1], (int)(*(row + 2))[1]);
    return 0;
}

輸出:

row + 1  -> 位移 16
cell + 1 -> 位移 4
row[2][1] = 21, (*(row + 2))[1] = 21

row + 1 走一列(16 個位元組),cell + 1 走一格(4 個位元組)。 int32_t (*row)[4] 的括號不能省:int32_t *row[4] 是「4 個指標的陣列」,意思完全不同。

指向指標的指標

C 一律傳值。想讓函式改掉呼叫端的 int,要傳 int *;同樣的道理,想讓函式改掉呼叫端的指標,就要傳指標的位址,也就是 int **。 最常見的兩個用途:函式透過參數「交回」一個新配置的指標,以及修改鏈結串列。 

#include <stdio.h>
#include <stdlib.h>

struct node { int val; struct node *next; };

// 加到最前面:要改的是 head 本身,所以傳 head 的位址
static int push_front(struct node **head, int v) {
    struct node *n = malloc(sizeof *n);
    if (n == NULL) return -1;
    n->val = v;
    n->next = *head;
    *head = n;
    return 0;
}

// 刪掉第一個值等於 v 的節點。pp 指向「指到目前節點的那個指標」,
// 所以刪開頭和刪中間是同一段程式,不必特別處理 head
static void remove_first(struct node **head, int v) {
    for (struct node **pp = head; *pp != NULL; pp = &(*pp)->next) {
        if ((*pp)->val == v) {
            struct node *dead = *pp;
            *pp = dead->next;     // 讓前一個指標跳過它
            free(dead);
            return;
        }
    }
}

static void print_list(const struct node *n) {
    for (; n != NULL; n = n->next) printf("%d ", n->val);
    printf("\n");
}

int main(void) {
    struct node *head = NULL;
    for (int v = 1; v <= 4; v++) push_front(&head, v);
    print_list(head);             // 4 3 2 1
    remove_first(&head, 4);       // 刪開頭
    remove_first(&head, 2);       // 刪中間
    print_list(head);             // 3 1
    while (head != NULL) {        // 全部還回去
        struct node *next = head->next;
        free(head);
        head = next;
    }
    return 0;
}

輸出:

4 3 2 1 
3 1
  • push_front 要改 main 的 head,所以收 struct node **head,寫 *head = n。如果只收 struct node *head,改的是複本,main 的串列永遠是空的。
  • remove_first 的 pp 不是指向節點,而是指向「指到目前節點的那個指標」:一開始是 head 的位址,之後是前一個節點的 next 欄位的位址。 刪除時只要 *pp = dead->next,刪開頭和刪中間就是同一段程式。
  • (*pp)->next 的括號不能省:-> 比 * 先結合。

main(int argc, char **argv) 的 argv 也是指向指標的指標:它指向一個陣列,陣列裡每一格是一個指向字串的指標。

struct 的記憶體佈局:對齊與填補

把 char、int32_t、char 三個成員放進一個 struct,1 + 4 + 1 = 6 個位元組,對吧?在 x86-64 上,答案是 12。 多出來的 6 個位元組是填補(padding),原因是對齊(alignment): 大多數 CPU 讀一個 4 位元組的整數時,希望它的位址是 4 的倍數。有的 CPU 讀到沒對齊的位址會變慢,有的會直接觸發例外。 所以編譯器替每個型別規定一個對齊值,並在成員之間塞進空的位元組。

💡
為什麼要學

檔案格式、網路封包、硬體暫存器群組,都有「第幾個位元組是什麼欄位」的規格。 你要能一眼看出一個 struct 的佈局和規格對不對得上;對不上時(通常是因為填補),就要改成一個位元組一個位元組讀(本章練習 133.12)。 {{ch:134-chip8-emulator}}的 CPU 狀態、之後 Game Boy 的卡匣標頭,都會用到。

規則只有三條(x86-64 Linux 的 System V ABI;其他平台大致相同,但不保證):

  1. 每個基本型別的對齊值通常等於它的大小:char 1、int16_t 2、int32_t 4、double 與指標 8。
  2. 成員依宣告順序放。放之前,把目前的位移補到這個成員對齊值的倍數。第一個成員一定在位移 0。
  3. struct 本身的對齊值是成員裡最大的那個;總大小要補到它的倍數(這樣陣列裡每個元素才都對齊)。
#include <stdio.h>
#include <stddef.h>   // offsetof
#include <stdint.h>

struct A { char c; int32_t i; char d; };
struct B { int32_t i; char c; char d; };
struct C { char c; double x; int16_t s; };
struct D { uint8_t tag; uint16_t len; uint32_t crc; uint8_t flags; };

// 不變量:把手算的結果寫成編譯期檢查;佈局一變,編譯就失敗
_Static_assert(offsetof(struct D, crc) == 4, "crc 應該在位移 4");
_Static_assert(sizeof(struct D) == 12, "struct D 應該是 12 位元組");

#define SHOW(T, f) printf("  %-6s 位移 %2zu,大小 %zu\n", #f, offsetof(T, f), sizeof(((T *)0)->f))

int main(void) {
    printf("struct A:sizeof %zu,_Alignof %zu\n", sizeof(struct A), _Alignof(struct A));
    SHOW(struct A, c); SHOW(struct A, i); SHOW(struct A, d);
    printf("struct B:sizeof %zu,_Alignof %zu\n", sizeof(struct B), _Alignof(struct B));
    SHOW(struct B, i); SHOW(struct B, c); SHOW(struct B, d);
    printf("struct C:sizeof %zu,_Alignof %zu\n", sizeof(struct C), _Alignof(struct C));
    SHOW(struct C, c); SHOW(struct C, x); SHOW(struct C, s);
    printf("struct D:sizeof %zu,_Alignof %zu\n", sizeof(struct D), _Alignof(struct D));
    SHOW(struct D, tag); SHOW(struct D, len); SHOW(struct D, crc); SHOW(struct D, flags);
    return 0;
}

  • struct A 和 struct B 的成員一模一樣,只是順序不同,大小就差了 4。把大的成員排前面,通常比較省。
  • struct C:double 要對齊 8,所以 c 後面補 7 個;s 放完是 18,補到 8 的倍數,總共 24。
  • _Static_assert 是編譯期的斷言:條件不成立,程式就編譯不過。把你手算的佈局寫成 _Static_assert,哪天有人插了一個成員、換了編譯器,錯誤會在編譯時就出現,而不是在讀錯一個封包之後。

位元欄位:看起來方便,為什麼 MMIO 不用

硬體暫存器常常是「第 0 位是開關、第 1–2 位是模式、第 3–7 位是除頻值」這種格式。C 有一個看起來正好合用的語法:位元欄位(bit-field), 在成員後面寫 : 位元數。 

#include <stdio.h>
#include <stdint.h>
#include <string.h>

struct ctrl_bf {                  // 用位元欄位描述一個 8 位元的控制暫存器
    unsigned enable : 1;
    unsigned mode   : 2;
    unsigned div    : 5;
};

int main(void) {
    struct ctrl_bf r = {0};
    r.enable = 1;
    r.mode = 2;
    r.div = 9;

    uint32_t raw = 0;
    memcpy(&raw, &r, sizeof r < sizeof raw ? sizeof r : sizeof raw);
    printf("sizeof(struct ctrl_bf) = %zu\n", sizeof r);
    printf("位元欄位排出來的值 = 0x%02X\n", (unsigned)raw);

    // 同一個意思,用遮罩與移位自己排:位置寫在程式裡,不靠編譯器
    uint32_t m = (1u << 0) | (2u << 1) | (9u << 3);
    printf("遮罩版的值       = 0x%02X\n", (unsigned)m);

    r.div = 40;                   // 40 需要 6 位元,欄位只有 5 位元
    printf("div 存 40 之後讀回 %u\n", (unsigned)r.div);
    return 0;
}

最後一個指定是故意的錯誤示範,gcc 會警告:

bitfield.c: In function ‘main’:
bitfield.c:26:13: warning: unsigned conversion from ‘int’ to ‘unsigned char:5’ changes value from ‘40’ to ‘8’ [-Woverflow]
   26 |     r.div = 40;                   // 40 需要 6 位元,欄位只有 5 位元
      |             ^~

輸出(x86-64,gcc):

sizeof(struct ctrl_bf) = 4
位元欄位排出來的值 = 0x4D
遮罩版的值       = 0x4D
div 存 40 之後讀回 8

在這台機器上,位元欄位從最低位開始排:enable 在第 0 位、mode 在第 1–2 位、div 在第 3–7 位, 1 + 2 × 2 + 9 × 8 = 77 = 0x4D,和遮罩版一樣。存 40 進 5 位元的欄位,只留下低 5 位:40 = 0b101000,低 5 位是 0b01000 = 8。

那為什麼寫硬體暫存器的程式(MMIO,memory-mapped I/O,記憶體映射輸入輸出)幾乎都不用它?因為 C 標準把太多細節留給實作決定:

  • 從哪一頭開始排是實作定義的。同一份 struct,換一個編譯器或換一種 CPU,enable 可能跑到第 7 位。資料手冊寫的是「第 0 位」,不是「第一個欄位」。
  • 欄位裝在多大的單位裡、會不會跨過單位的邊界是實作定義的。上面的 struct 只用了 8 個位元,sizeof 卻是 4。
  • 改一個欄位時,實際讀寫多少位元組由編譯器決定。很多周邊只接受完整 32 位元的存取;有的暫存器是「寫 1 清除」(write-1-to-clear),編譯器順手把讀回來的其他位元寫回去,就會誤清旗標。
  • 沒有寫 signed 或 unsigned 的 int 位元欄位,有沒有號也是實作定義的。

公平地說:在 x86-64 的 gcc 13 上,對一個 volatile 的 32 位元位元欄位改 mode,和你自己用遮罩讀、改、寫,產生的指令一模一樣(都是一次 32 位元讀、and、or、一次 32 位元寫)。 問題不在這一次對不對,而在於標準沒有保證下一次、下一台機器也一樣。遮罩把位置寫在程式碼裡,讀的人和編譯器看到的都是同一件事。

核心觀念

位元欄位適合「只在自己程式裡用、不在乎實際位元位置」的旗標壓縮。只要位元位置是外面規定的(硬體、檔案、網路),就用定寬整數加遮罩。

定寬整數與整數提升

橋接章 A說 int「常見」是 4 個位元組。C 標準只保證 int 至少 16 位元、long 至少 32 位元。 寫硬體和檔案格式時,「大概」不夠,所以 C99 加了 <stdint.h>:int8_t、uint8_t、int16_t……uint64_t,名字裡的數字就是位元數。

#include <stdio.h>
#include <stdint.h>

int main(void) {
    uint8_t a = 0xF0;
    uint8_t b = ~a;                       // 存回 uint8_t 時截成 8 位元
    printf("b = 0x%02X\n", (unsigned)b);
    printf("~a == 0x0F ? %d\n", ~a == 0x0F);   // a 先被提升成 int
    printf("~a = 0x%X\n", (unsigned)~a);

    char c = (char)0xF6;                  // char 有沒有號是實作定義
    printf("c = %d\n", c);

    uint16_t x = 0xFFFF;
    uint32_t ok = (uint32_t)x * x;        // 先轉成 uint32_t 再乘
    printf("ok = %u\n", (unsigned)ok);
    return 0;
}

遮罩與移位:設、清、翻轉、取出欄位

{{ch:19-boolean-logic}}教過 AND、OR、XOR 的真值表。在 C 裡,&、|、^、~ 對每一個位元同時做這些運算, 再加上 <<、>> 兩個移位,就能操作任何一個位元或一段位元。用來挑出某些位元的那個數叫遮罩(mask)。

💡
為什麼要學

CHIP-8 的指令 0x8XY6 要切出 X(第 8–11 位)與 Y(第 4–7 位);Game Boy 的 F 暫存器裡,Z、N、H、C 四個旗標各佔一位;韌體裡每個周邊暫存器都是一堆欄位。 本章 Lab 的 emu/bits.h 就是一組這樣的位元函式,{{ch:134-chip8-emulator}}的 CPU 每一條指令都會用到。

想做的事寫法為什麼
第 n 位的遮罩1u << n只有第 n 位是 1
設成 1(set)x |= 1u << nx | 1 = 1,x | 0 = x
清成 0(clear)x &= ~(1u << n)x & 0 = 0,x & 1 = x
翻轉(toggle)x ^= 1u << nx ^ 1 = 非 x,x ^ 0 = x
檢查第 n 位(x >> n) & 1u移到第 0 位再挑出來
取出 [lo, lo+w) 這段(x >> lo) & ((1u << w) - 1u)(1u << w) - 1 是低 w 位全是 1
把這段換成 v(x & ~(M << lo)) | ((v & M) << lo),M 是低 w 位的遮罩先清掉那一段,再放進 v

下面的程式用一個全域變數 ctrl 假裝是 UART(序列埠)的控制暫存器,並把這些寫法包成巨集。巨集的名字都用大寫,提醒讀的人「這不是函式」。 

#include <stdio.h>
#include <stdint.h>
#include <assert.h>

#define BIT(n)            (1u << (n))
#define LOW_ONES(w)       (BIT(w) - 1u)                 // 低 w 位全是 1;w 只能是 0..31
#define FIELD_GET(x, lo, w)     (((x) >> (lo)) & LOW_ONES(w))
#define FIELD_PUT(x, lo, w, v)  (((x) & ~(LOW_ONES(w) << (lo))) | (((v) & LOW_ONES(w)) << (lo)))

// 假裝這是一個 UART 的控制暫存器:
//   bit 0 EN(開關)、bit 1 IRQ(中斷)、bits 4..7 BAUD(4 位元)、bits 8..15 DIV(8 位元)
uint32_t ctrl = 0;

int main(void) {
    ctrl |= BIT(0);                       // 設:EN = 1
    ctrl |= BIT(1);                       // 設:IRQ = 1
    ctrl &= ~BIT(1);                      // 清:IRQ = 0
    ctrl ^= BIT(3);                       // 翻轉:bit 3 由 0 變 1
    ctrl ^= BIT(3);                       // 再翻轉一次,變回 0
    ctrl = FIELD_PUT(ctrl, 4, 4, 0x9u);   // BAUD = 9
    ctrl = FIELD_PUT(ctrl, 8, 8, 0x1A3u); // DIV 只有 8 位元,0x1A3 只留下 0xA3
    printf("ctrl = 0x%08X\n", (unsigned)ctrl);
    printf("EN = %u, IRQ = %u, BAUD = %u, DIV = 0x%02X\n",
           (unsigned)FIELD_GET(ctrl, 0, 1), (unsigned)FIELD_GET(ctrl, 1, 1),
           (unsigned)FIELD_GET(ctrl, 4, 4), (unsigned)FIELD_GET(ctrl, 8, 8));

    // 不變量:換掉一段之後,這段以外的位元一個都不能變
    uint32_t before = ctrl;
    uint32_t after = FIELD_PUT(before, 4, 4, 0x3u);
    assert(((before ^ after) & ~(LOW_ONES(4) << 4)) == 0);
    assert(FIELD_GET(after, 4, 4) == 0x3u);
    printf("after = 0x%08X\n", (unsigned)after);
    return 0;
}

輸出:

ctrl = 0x0000A391
EN = 1, IRQ = 0, BAUD = 9, DIV = 0xA3
after = 0x0000A331

ctrl 最後是 0xA391:DIV(第 8–15 位)= 0xA3,BAUD(第 4–7 位)= 9,EN(第 0 位)= 1,IRQ 已經清掉。 0x1A3 放進 8 位元的 DIV,& LOW_ONES(8) 先把第 8 位(0x100)丟掉,不會溢出去改到別的欄位。

證明(參考):FIELD_PUT 只改那一段

令 M = LOW_ONES(w) << lo,也就是 [lo, lo+w) 這段是 1、其他是 0。對任何一個位元位置 i: 如果 i 不在那一段,~M 的第 i 位是 1,所以 x & ~M 保留 x 的第 i 位;而 (v & LOW_ONES(w)) << lo 的第 i 位一定是 0,OR 之後還是 x 的第 i 位。 如果 i 在那一段,x & ~M 的第 i 位是 0,OR 之後就是 v 的第 (i − lo) 位。所以結果「段外等於 x、段內等於 v 的低 w 位」。

程式最後兩個 assert 就是這個證明的程式版本:(before ^ after) & ~M == 0 說「段外沒有任何位元改變」,FIELD_GET(after, 4, 4) == 3 說「段內是新的值」。 證明保證所有輸入都對;assert 只檢查這一次,但它會在你改壞巨集的那一刻叫出來。

⚠️
看起來對但其實錯:LOW_ONES(32)

LOW_ONES(w) 對 w = 1 到 31 都對,測了一堆都過。但 w = 32 時,1u << 32 的移位量等於型別寬度,是未定義行為(下一小節)。 而 32 位元的欄位偏偏很常見(例如整個暫存器)。上面的 FIELD_GET、FIELD_PUT 只在 w ≤ 31、lo + w ≤ 32 時能用; 本章 Lab 要你寫的版本必須連寬度 0 和 32 都沒有未定義行為。巨集還有另一個問題:參數會被展開好幾次:FIELD_PUT(x, lo++, 4, v) 展開後有兩個 lo++,中間沒有序列點,是未定義行為(練習 133.5)。

移位的規則與未定義行為

移位看起來最簡單,規則卻最多。先看合法的情況:

#include <stdio.h>
#include <stdint.h>

int main(void) {
    int32_t s = -16;
    uint32_t u = (uint32_t)s;             // 同樣的 32 個位元:0xFFFFFFF0
    printf("u = 0x%08X\n", (unsigned)u);
    printf("u >> 2 = 0x%08X(邏輯右移,左邊補 0)\n", (unsigned)(u >> 2));
    printf("s >> 2 = %d(實作定義;gcc 用算術右移,左邊補符號位元)\n", (int)(s >> 2));
    printf("u << 4 = 0x%08X(左邊移出去的位元就丟掉)\n", (unsigned)(u << 4));
    printf("1u << 31 = 0x%08X\n", 1u << 31);
    uint8_t byte = 0x81;
    printf("byte << 1 = 0x%X(先提升成 int,所以第 8 位留下來了)\n", (unsigned)(byte << 1));
    printf("(uint8_t)(byte << 1) = 0x%02X\n", (unsigned)(uint8_t)(byte << 1));
    return 0;
}

「移位量等於寬度」為什麼是未定義行為?因為 CPU 的做法不一樣。x86 的移位指令只看移位量的低 5 位,所以「移 32 位」等於「移 0 位」;有的 CPU(例如 32 位元 ARM)會得到 0。 C 標準不想讓每次移位都多一道檢查,乾脆不規定。下面這段的移位量在執行時才知道,編譯器沒辦法警告: 

#include <stdio.h>

int main(int argc, char **argv) {
    (void)argv;
    unsigned n = 31u + (unsigned)argc;    // 不帶參數執行時 argc 是 1,所以 n = 32
    unsigned r = 1u << n;                 // 移位量等於寬度:未定義行為
    printf("n = %u, 1u << n = %u\n", n, r);
    return 0;
}

在 x86-64 上,用 -O0 或 -O2 編譯,這次都印出:

n = 32, 1u << n = 1

你可能以為 1u << 32 會是 0(1 被移出去了),實際上是 1。換一台機器、換一個最佳化等級,答案可能又不一樣。這就是未定義行為:不是「結果很怪」,是「沒有結果可以依靠」。 本章後面的消毒器會把這一行直接指出來。

旋轉:移出去的位元從另一邊回來

右旋 n 位(rotate right)和右移很像,差別是右邊移出去的 n 個位元不丟掉,而是從左邊補回來。所以 rotr32(0x12345678, 8) = 0x78123456:最低的位元組 78 轉到最上面。 直覺的寫法是 (x >> n) | (x << (32 - n)),但 n = 0 時後半的左移變成 x << 32,正好是上面表格裡「移位量等於寬度」的未定義行為;n ≥ 32 時前半的 x >> n 也一樣。 做法是先 n %= 32,再把左移量寫成 (32 - n) & 31(n = 0 時是 0),或是 n == 0 時直接回傳 x。 

#include <stdio.h>
#include <stdint.h>

// 右旋 n 位:右邊移出去的位元,從左邊補回來
static uint32_t rot_right(uint32_t x, unsigned n) {
    n %= 32u;                             // 旋轉 32 位等於沒轉
    return (x >> n) | (x << ((32u - n) & 31u));   // n = 0 時左移 0 位,不是 32 位
}

int main(void) {
    printf("0x%08X\n", (unsigned)rot_right(0x12345678u, 8));
    printf("0x%08X\n", (unsigned)rot_right(0x12345678u, 4));
    printf("0x%08X\n", (unsigned)rot_right(0x12345678u, 0));
    printf("0x%08X\n", (unsigned)rot_right(0x12345678u, 32));
    return 0;
}

符號延伸:把短的二補數變長

{{ch:19-boolean-logic}}的二補數(two's complement):w 位元的數,最高位的權重是 −2w−1。 0xF6 當 8 位元的二補數是 −128 + 64 + 32 + 16 + 4 + 2 = −10。把它放進 32 位元的變數時,要讓值還是 −10,左邊 24 位就要補上符號位元 1:0xFFFFFFF6。 這叫符號延伸(sign extension)。無號數變寬則是左邊補 0,叫零延伸(zero extension)。

💡
為什麼要學

Game Boy 的相對跳躍 JR e 用一個有號的 8 位元位移;GBA 的 ARM 分支指令有 24 位元的有號位移;RISC-V 的立即值是 12 位元有號數。 模擬器每次解碼這種指令,都要把一段位元符號延伸成 32 位元。本章 Lab 的 sign_extend 就是做這件事。

#include <stdio.h>
#include <stdint.h>

// 把 12 位元的欄位當二補數:先翻轉符號位元,再減掉它
static int32_t sext12(uint32_t x) {
    const uint32_t sign = 1u << 11;
    x &= (1u << 12) - 1u;                 // 只留低 12 位
    return (int32_t)(x ^ sign) - (int32_t)sign;
}

int main(void) {
    uint8_t raw = 0xF6;
    int8_t  s8  = (int8_t)raw;            // 轉成有號的 8 位元(gcc:照位元解讀)
    int32_t w1  = s8;                     // 有號變寬:補符號位元
    uint32_t w2 = raw;                    // 無號變寬:補 0
    printf("s8 = %d\n", s8);
    printf("w1 = %d = 0x%08X\n", (int)w1, (unsigned)w1);
    printf("w2 = %u = 0x%08X\n", (unsigned)w2, (unsigned)w2);

    printf("sext12(0xFF6) = %d\n", (int)sext12(0xFF6));
    printf("sext12(0x7F6) = %d\n", (int)sext12(0x7F6));
    printf("sext12(0x800) = %d\n", (int)sext12(0x800));

    uint16_t pc = 0x0150;                 // 相對跳躍:位移量是有號的 8 位元
    uint8_t offset = 0xFE;
    printf("跳到 0x%04X\n", (unsigned)(uint16_t)(pc + (int8_t)offset));
    return 0;
}

證明(參考):為什麼 (x ^ s) − s 是對的

x 是 w 位元(0 ≤ x < 2w),s = 2w−1。二補數的值是:最高位是 0 時等於 x,是 1 時等於 x − 2w。 最高位是 0:x ^ s 把那一位從 0 變 1,等於 x + s,減掉 s 還是 x。 最高位是 1:x ^ s 把那一位從 1 變 0,等於 x − s,再減 s 得到 x − 2s = x − 2w。兩種情況都對。 程式裡用有號的 int32_t 做減法,是為了讓結果可以是負數;w 是 32 時 s 本身就裝不進 int32_t,要另外處理(這是 Lab 的邊界之一)。

大小端:多位元組的值怎麼排

記憶體的每個位址放一個位元組。一個 32 位元的值 0x12345678 要佔 4 個位址,那麼 0x12 放在最小的位址,還是 0x78 放在最小的位址? 兩種都有人用:

  • 小端序(little-endian,LE):最低有效位元組(0x78)放在最小的位址。x86、x86-64、Game Boy、GBA、大部分 ARM 與 RISC-V 系統都是。
  • 大端序(big-endian,BE):最高有效位元組(0x12)放在最小的位址,和人寫數字的順序一樣。網路協定的「網路位元組順序」({{ch:25-networking}})、CHIP-8 的指令、很多檔案格式都是。

這個名詞叫位元組順序或端序(endianness)。它只管「位元組」的順序,一個位元組裡 8 個位元的順序不受影響。

為什麼要學

你的模擬器跑在 x86-64(小端序)上,模擬的 CHIP-8 卻要用大端序讀指令。如果直接把兩個位元組的記憶體當成 uint16_t 讀,每一條指令的兩個位元組都會反過來。 本章 Lab 的 load16_be、store32_le 這組函式,就是讓模擬器的結果和主機是哪一種端序無關。

和主機端序無關的讀寫函式

要讀「某個格式規定的端序」,不要問這台電腦是哪一種端序,直接用移位把位元組拼起來。移位是對「值」做運算,和值在記憶體裡怎麼放無關,所以同一份程式在任何機器上結果都一樣。 

#include <stdio.h>
#include <stdint.h>
#include <string.h>

// 從位元組陣列讀、寫 16 位元的值。只用移位,和這台電腦是哪一種端序無關
static uint16_t get_le16(const uint8_t *p) { return (uint16_t)(p[0] | (p[1] << 8)); }
static uint16_t get_be16(const uint8_t *p) { return (uint16_t)((p[0] << 8) | p[1]); }
static void put_le16(uint8_t *p, uint16_t v) { p[0] = (uint8_t)v; p[1] = (uint8_t)(v >> 8); }
static void put_be16(uint8_t *p, uint16_t v) { p[0] = (uint8_t)(v >> 8); p[1] = (uint8_t)v; }

int main(void) {
    uint32_t v = 0x11223344;
    const uint8_t *b = (const uint8_t *)&v;   // 用 unsigned char 看物件的位元組是合法的
    printf("0x11223344 在這台電腦的記憶體裡:%02X %02X %02X %02X\n",
           (unsigned)b[0], (unsigned)b[1], (unsigned)b[2], (unsigned)b[3]);

    uint8_t buf[4];
    put_be16(buf, 0xBEEF);                     // 網路封包、CHIP-8 的指令:大端序
    put_le16(buf + 2, 0xBEEF);                 // Game Boy、x86:小端序
    printf("buf = %02X %02X %02X %02X\n",
           (unsigned)buf[0], (unsigned)buf[1], (unsigned)buf[2], (unsigned)buf[3]);
    printf("get_be16(buf) = 0x%04X, get_le16(buf) = 0x%04X\n",
           (unsigned)get_be16(buf), (unsigned)get_le16(buf));
    printf("get_le16(buf + 1) = 0x%04X\n", (unsigned)get_le16(buf + 1));

    uint16_t host;
    memcpy(&host, buf, 2);                     // 照這台電腦的端序解讀:結果不可攜
    printf("memcpy 讀回 0x%04X\n", (unsigned)host);
    return 0;
}

buf = BE EF EF BE

  • memcpy 把位元組原封不動複製進 uint16_t,得到的是「照這台電腦的端序解讀」:在 x86-64 上是 0xEFBE,在大端序的機器上是 0xBEEF。不可攜。

const 正確性

const 的意思是「透過這個名字,不能改」。它不是讓資料變成唯讀的魔法,而是你和編譯器(還有讀程式的人)之間的約定: 函式參數寫成 const uint8_t *buf,就是在說「我只讀 buf,不會改它」。違反約定,編譯器直接報錯。 

#include <stdio.h>
#include <stddef.h>
#include <stdint.h>

// const 寫在參數上是一個承諾:這個函式只讀 buf,不會改它
static size_t count_byte(const uint8_t *buf, size_t n, uint8_t v) {
    size_t c = 0;
    for (size_t i = 0; i < n; i++) {
        if (buf[i] == v) c++;
        // buf[i] = 0;            // 編譯錯誤:assignment of read-only location
    }
    return c;
}

int main(void) {
    uint8_t data[6] = {7, 0, 7, 7, 1, 0};
    int x = 1, y = 2;

    const int *p1 = &x;           // 指向 const int:不能透過 p1 改值,但 p1 可以改指別人
    p1 = &y;
    // *p1 = 5;                   // 編譯錯誤:assignment of read-only location

    int *const p2 = &x;           // const 指標:p2 永遠指 x,但可以透過它改 x
    *p2 = 5;
    // p2 = &y;                   // 編譯錯誤:assignment of read-only variable

    const int *const p3 = &y;     // 兩個都不能改
    printf("%d %d %d\n", *p1, *p2, *p3);
    printf("7 出現 %zu 次\n", count_byte(data, sizeof data, 7));
    return 0;
}

const int *const pp 是 const 指標,指向 const int不能不能
const volatile uint32_t *const STATUSSTATUS 是 const 指標,指向 const volatile uint32_t程式不能寫,但硬體會改不能

最後一列是下一節的主角:一個唯讀的硬體狀態暫存器。const 說「我不准寫它」,volatile 說「它自己會變」。兩個並不矛盾。 const 還有一個實際的好處:韌體裡宣告成 static const 的大表格,連結器可以把它放進 Flash,不佔寶貴的 RAM。

ℹ️
const 是會傳染的

一個函式收了 const uint8_t *,它就不能把這個指標傳給一個收 uint8_t * 的函式(gcc 會警告「discards const qualifier」)。 所以要從最底層的函式開始加 const。只讀不寫的指標參數,一律加 const,這叫 const 正確性(const correctness)。

volatile:它做什麼、不做什麼

編譯器最佳化的前提是:記憶體裡的值,只有這個程式自己會改。所以它可以把同一個位址寫三次合併成一次,也可以把迴圈裡重複的讀取搬到迴圈外面。 對一般變數,這些都是對的。但硬體暫存器不是一般變數:寫三次 UART 的資料暫存器,是送出三個字元;讀一次狀態暫存器,下一次可能就不一樣了。

volatile 就是告訴編譯器:這個物件可能被這個程式以外的東西讀寫,每一次讀寫都要照原樣做出來,不能合併、不能刪掉、不能改變彼此的順序。

💡
為什麼要學

韌體的第一支程式通常就是「等狀態暫存器的某一位變成 1,再寫資料暫存器」。少了 volatile,開了最佳化就當機,沒開最佳化又正常,是最難查的那一種錯。 之後微控制器與中斷的章節,ISR 和主程式共用的旗標也一定要用它。

模擬的暫存器:看編譯器做了什麼

真的韌體會寫 #define UART_DATA (*(volatile uint32_t *)0x40011004),把固定的硬體位址當成一個變數。我們的電腦上沒有那個裝置, 所以用全域變數假裝是暫存器,然後看 gcc -O2 -S 產生的組合語言({{ch:21-cpu-machine-language}}): 

#include <stdint.h>

// 真的韌體裡,這會是一個固定的硬體位址,例如 (uintptr_t)0x40011004。
// 這裡用一個全域變數「假裝」是 UART 的資料暫存器與狀態暫存器,讓程式在電腦上也能編譯。
uint32_t fake_uart_data;
uint32_t fake_uart_status;

#define TX_READY (1u << 7)

#define DATA_PLAIN    (*(uint32_t *)&fake_uart_data)
#define STATUS_PLAIN  (*(uint32_t *)&fake_uart_status)
#define DATA_VOL      (*(volatile uint32_t *)&fake_uart_data)
#define STATUS_VOL    (*(const volatile uint32_t *)&fake_uart_status)

void send3_plain(void) {          // 送出 'H' 'i' '!' 三個字元
    DATA_PLAIN = 'H';
    DATA_PLAIN = 'i';
    DATA_PLAIN = '!';
}

void send3_volatile(void) {
    DATA_VOL = 'H';
    DATA_VOL = 'i';
    DATA_VOL = '!';
}

void wait_plain(void) {           // 等硬體把 TX_READY 設起來
    while ((STATUS_PLAIN & TX_READY) == 0) { }
}

void wait_volatile(void) {
    while ((STATUS_VOL & TX_READY) == 0) { }
}

用 gcc -std=c17 -Wall -Wextra -O2 -S uart_volatile.c 編譯,四個函式的本體是(x86-64 AT&T 語法,省略了對齊用的 .p2align):

send3_plain:
    endbr64
    movl $33, fake_uart_data(%rip)
    ret

send3_volatile:
    endbr64
    movl $72, fake_uart_data(%rip)
    movl $105, fake_uart_data(%rip)
    movl $33, fake_uart_data(%rip)
    ret

wait_plain:
    endbr64
    testb $-128, fake_uart_status(%rip)
    jne .L4
.L6:
    jmp .L6
.L4:
    ret

wait_volatile:
    endbr64
    leaq fake_uart_status(%rip), %rdx

    movl (%rdx), %eax
    testb $-128, %al
    je .L8

  • send3_plain 只剩一條 movl $33:33 是 '!'。編譯器認為前兩次寫入馬上被蓋掉,沒有人看得到,就刪了。真的 UART 只會送出一個 !。
  • send3_volatile 有三條寫入,72、105、33 就是 'H'、'i'、'!',順序也照原樣。
  • wait_plain 只讀狀態一次(testb)。如果那時還沒準備好,就跳到 .L6: jmp .L6:一個永遠不再讀暫存器的無窮迴圈。
  • wait_volatile 在迴圈 .L8 裡每一圈都重新 movl (%rdx), %eax 讀一次。

跑起來看:沒有 volatile 的輪詢永遠等不到

組合語言是證據,但我們也可以真的跑一次。下面用一個 POSIX 訊號模擬「硬體在背後改了暫存器」:alarm(1) 讓系統 1 秒後送 SIGALRM,處理函式把 ready 設成 1。 主程式從頭到尾都沒有改 ready,就像它從來沒有寫過硬體的狀態暫存器。 

#define _POSIX_C_SOURCE 200809L   // 要用 POSIX 的 alarm()
#include <stdio.h>
#include <signal.h>
#include <unistd.h>

// 「硬體」在 1 秒後把 ready 設成 1。這裡用 SIGALRM 訊號模擬:
// 處理函式會在主程式不知道的時候插進來執行,就像硬體在背後改暫存器。
#ifdef NO_VOLATILE
static sig_atomic_t ready = 0;            // 錯誤示範
#else
static volatile sig_atomic_t ready = 0;   // 最傳統、可攜的寫法:處理函式只「指定一個值」
#endif

static void on_alarm(int sig) {
    (void)sig;
    ready = 1;
}

int main(void) {
    signal(SIGALRM, on_alarm);
    alarm(1);
    unsigned long spins = 0;
    while (!ready) {
        spins++;                           // 一直輪詢(polling)
    }
    printf("等到了;輪詢了 %s 次\n", spins > 1000 ? "超過 1000" : "不到 1000");
    return 0;
}
gcc -std=c17 -Wall -Wextra -O2 fake_hw.c -o hw
./hw                       # 約 1 秒後印出:等到了;輪詢了 超過 1000 次
gcc -std=c17 -Wall -Wextra -O2 -DNO_VOLATILE fake_hw.c -o hw_bad
timeout 3 ./hw_bad; echo $?   # 印出 124:被 timeout 在 3 秒時強制結束,迴圈從沒停過

有 volatile 的版本 1 秒後結束;沒有 volatile 的版本,即使處理函式已經把 ready 設成 1,主迴圈也看不到,只能被 timeout 砍掉(結束狀態碼 124)。 -O0 編譯的話,兩個版本都會正常結束,所以這種錯常常在「改成發行版編譯」那天才出現。

ℹ️
為什麼是 volatile sig_atomic_t

C99 以前,C 標準只保證一種和訊號處理函式共用變數的寫法:volatile sig_atomic_t,而且處理函式裡對它只保證「指定一個值」(像 ready = 1)是安全的,ready++ 這種讀了再寫的就不保證。 sig_atomic_t 是一個「讀寫一次就完成、不會被訊號切成兩半」的整數型別。C11 起,lock-free 的 _Atomic 物件(可以用 atomic_is_lock_free 檢查)也可以在處理函式裡用;本章用最傳統、到處都能編的 volatile sig_atomic_t。 微控制器上的中斷服務程式(ISR)和主程式共用旗標,道理一樣。

volatile 不做的事

volatile 只管一件事:這個物件的每一次存取都要真的做出來。下面這些它都不管:

  • 不保證原子性。counter++ 就算 counter 是 volatile,還是「讀、加、寫」三個步驟,中間可以被中斷或另一個執行緒插進來: 
    volatile int counter;

void bump(void) {
    counter++;            // 看起來是一個動作
}
    bump:
    endbr64
    movl counter(%rip), %eax
    addl $1, %eax
    movl %eax, counter(%rip)
    ret
  • 不是執行緒之間的同步工具。多個執行緒共用變數,要用 C11 的 _Atomic(<stdatomic.h>)或互斥鎖({{ch:24-operating-system}}、{{ch:43-parallel}})。只靠 volatile 的共用變數在 C 標準裡仍然是資料競爭(data race),是未定義行為。
  • 不管其他非 volatile 變數的順序。先寫一般的緩衝區、再寫 volatile 的「開始傳送」暫存器,編譯器仍然可以把緩衝區的寫入挪到後面;CPU 本身也可能重新排序。需要順序時要用記憶體屏障(memory barrier)。
  • 不處理快取。{{ch:48-computer-architecture}}的快取不知道你寫了 volatile。和 DMA 共用的緩衝區,要靠硬體的一致性機制或手動清快取。
⚠️
看起來對但其實錯:「加了 volatile,多執行緒就安全了」

兩個執行緒各對 volatile int counter 做 100 萬次 counter++,結果常常小於 200 萬,而且每次跑都不同(我們用 -O2 -pthread 實測 5 次,每次都只有 101 萬左右)。 每一次讀寫都「真的做了」,但兩個執行緒的「讀、加、寫」交錯在一起,有些加法被蓋掉。在單核心、沒有中斷的情況下測不出這個錯,這正是它危險的地方。

🔑
核心觀念

volatile 用在「這個程式以外的東西會讀寫這塊記憶體」:記憶體映射的暫存器、和訊號處理函式或 ISR 共用的旗標。它解決的是編譯器最佳化的問題,不是並行的問題。

函式指標與分派表

函式也放在記憶體裡,也有位址。函式指標(function pointer)就是存函式位址的變數,透過它可以呼叫「執行時才決定的」函式。 Python 的函式本來就是值,可以放進 list 和 dict;C 用函式指標做同樣的事。

💡
為什麼要學

CPU 模擬器用 opcode 查表決定要執行哪個函式;中斷向量表是一個函式位址的陣列;模擬器的記憶體匯流排用「這段位址交給這個裝置的函式」來接上鍵盤、計時器和螢幕。 這三件事都是函式指標的陣列。本章 Lab 的 bus_map 就是「登錄一段位址的處理函式」。

#include <stdio.h>
#include <stdint.h>

static int add(int a, int b) { return a + b; }
static int sub(int a, int b) { return a - b; }
static int mul(int a, int b) { return a * b; }

typedef int (*binop)(int, int);           // binop:「吃兩個 int、回傳 int 的函式」的指標

// 一台只有 4 個指令的小機器:指令的高 4 位是 opcode,低 4 位是運算元
enum { OP_LOAD, OP_ADD, OP_SUB, OP_MUL };

int main(void) {
    int (*f)(int, int) = add;             // 不用 typedef 的寫法
    binop g = &mul;                       // & 可寫可不寫
    printf("f(2, 3) = %d, g(2, 3) = %d\n", f(2, 3), (*g)(2, 3));

    // 分派表(dispatch table):用 opcode 當索引,直接查到要呼叫的函式
    static const binop table[4] = { [OP_ADD] = add, [OP_SUB] = sub, [OP_MUL] = mul };
    const uint8_t prog[] = {0x05, 0x13, 0x32, 0x21, 0x14};   // LOAD 5; ADD 3; MUL 2; SUB 1; ADD 4
    int acc = 0;
    for (size_t pc = 0; pc < sizeof prog; pc++) {
        unsigned op = prog[pc] >> 4, arg = prog[pc] & 0x0F;
        if (op == OP_LOAD) acc = (int)arg;
        else acc = table[op](acc, (int)arg);
        printf("pc %zu:op %u arg %u -> acc %d\n", pc, op, arg, acc);
    }
    return 0;
}

輸出:

f(2, 3) = 5, g(2, 3) = 6
pc 0:op 0 arg 5 -> acc 5
pc 1:op 1 arg 3 -> acc 8
pc 2:op 3 arg 2 -> acc 16
pc 3:op 2 arg 1 -> acc 15
pc 4:op 1 arg 4 -> acc 19
  • int (*f)(int, int):f 是一個指標,指向「吃兩個 int、回傳 int 的函式」。括號不能省,int *f(int, int) 是「回傳 int * 的函式」。宣告很難讀,所以通常先 typedef。
  • 函式名稱會自動轉成函式指標,所以 add 和 &add 一樣;呼叫時 g(2, 3) 和 (*g)(2, 3) 也一樣。
  • 分派表(dispatch table):table[op](acc, arg) 用 opcode 當索引直接找到函式,取代一長串 switch。[OP_ADD] = add 是 C99 的指定初始化(designated initializer),沒列出的元素([OP_LOAD])是 NULL。
  • 指令 0x32 的高 4 位是 opcode 3(MUL)、低 4 位是運算元 2:這正是前面「遮罩與移位」一節的 FIELD_GET。
⚠️
分派表的邊界檢查

這個範例的 prog 裡只有合法的 opcode。真的模擬器讀到的是任意位元組:op 超出表的範圍、或剛好是表裡的 NULL,呼叫下去就是當機,甚至跳到攻擊者準備好的位址。 查表之前一定先檢查 op < 表的長度 而且 table[op] != NULL(練習 133.10)。

從分派表到記憶體映射

把「用 opcode 查函式」換成「用位址查函式」,就是記憶體映射的概念:大部分位址是 RAM,但有幾段位址屬於裝置。程式讀寫那些位址時,實際上是在呼叫裝置的函式。 下面是一台位址只有 8 位元的小機器:0xF0 是鍵盤、0xF1 是 LED,其他位址是 RAM。記憶體映射表寫死在程式裡,用全域陣列當 RAM。 

#include <stdio.h>
#include <stdint.h>

// 一台位址只有 8 位元(0x00..0xFF)的小機器。大部分位址是 RAM,
// 但 0xF0 是鍵盤、0xF1 是 LED:讀寫它們會呼叫「裝置」的函式,而不是碰 RAM。
typedef uint8_t (*read_fn)(uint8_t addr);
typedef void (*write_fn)(uint8_t addr, uint8_t value);

struct region {
    uint8_t lo, hi;          // 這一段涵蓋 [lo, hi]
    read_fn rd;              // NULL:這一段不能讀(本例讀回 0)
    write_fn wr;             // NULL:這一段不能寫(本例直接忽略)
    const char *name;
};

static uint8_t ram[256];
static uint8_t pending_key = 'A';         // 鍵盤緩衝區裡還沒被讀走的字

static uint8_t ram_rd(uint8_t a) { return ram[a]; }
static void ram_wr(uint8_t a, uint8_t v) { ram[a] = v; }
static uint8_t key_rd(uint8_t a) {        // 讀了就清掉:這個「讀」有副作用
    (void)a;
    uint8_t k = pending_key;
    pending_key = 0;
    return k;
}
static void led_wr(uint8_t a, uint8_t v) { (void)a; printf("  [LED] 0x%02X\n", (unsigned)v); }

// 記憶體映射表:從上往下找,先符合的那一段負責。最後一段 RAM 包住全部位址
static const struct region memory_map[] = {
    {0xF0, 0xF0, key_rd, NULL,   "KEY"},
    {0xF1, 0xF1, NULL,   led_wr, "LED"},
    {0x00, 0xFF, ram_rd, ram_wr, "RAM"},
};
#define NREGIONS (sizeof memory_map / sizeof memory_map[0])

static const struct region *find(uint8_t a) {
    for (size_t i = 0; i < NREGIONS; i++)
        if (a >= memory_map[i].lo && a <= memory_map[i].hi) return &memory_map[i];
    return NULL;                           // 本例不會發生:RAM 包住全部
}

static uint8_t mem_read(uint8_t a) {
    const struct region *r = find(a);
    return (r && r->rd) ? r->rd(a) : 0;
}

static void mem_write(uint8_t a, uint8_t v) {
    const struct region *r = find(a);
    if (r && r->wr) r->wr(a, v);
}

int main(void) {
    mem_write(0x10, 0x42);
    printf("read 0x10 -> 0x%02X(%s)\n", (unsigned)mem_read(0x10), find(0x10)->name);
    mem_write(0xF1, 0x07);                 // 寫 LED:呼叫 led_wr
    printf("read 0xF0 -> '%c'\n", mem_read(0xF0));
    printf("read 0xF0 -> 0x%02X(第二次讀,已經被清掉)\n", (unsigned)mem_read(0xF0));
    printf("read 0xF1 -> 0x%02X(LED 不能讀)\n", (unsigned)mem_read(0xF1));
    return 0;
}

輸出:

read 0x10 -> 0x42(RAM)
  [LED] 0x07
read 0xF0 -> 'A'
read 0xF0 -> 0x00(第二次讀,已經被清掉)
read 0xF1 -> 0x00(LED 不能讀)
  • CPU 只會說「讀 0xF0」,不知道那裡是鍵盤。find 查表,找到負責的那一段,再透過函式指標呼叫它。換一張表,同一顆 CPU 就接上了不同的裝置。
  • key_rd 讀了就把字清掉:讀取有副作用。所以第二次讀 0xF0 得到 0。這種暫存器在真的硬體上很常見(讀資料暫存器會清掉「有資料」旗標),也是 volatile 必須存在的理由。
  • 讀有副作用,就代表「讀幾次、照什麼順序讀」會改變結果。本章最後的手算 133.6 會追這件事。

這個範例故意寫得很簡單:表是寫死的、處理函式拿到的是完整位址、找不到的位址讀回 0、只處理單一位元組。本章 Lab 的匯流排要的比這多(執行時登錄、拒絕重疊、超出範圍的處理、多位元組存取的規則),細節見 Lab 的規格。

堆疊與堆積:變數住在哪裡、活多久

一支 C 程式執行時,它的變數分住在幾個區域,每個區域的生命週期(lifetime)不同:

區域放什麼什麼時候出現什麼時候消失
程式碼(.text)機器碼、字串常數(常放在旁邊的唯讀區)程式載入時程式結束
.data有初值的全域變數與 static 變數程式載入時程式結束
.bss沒有初值的全域與 static 變數(清成 0)程式載入時程式結束
堆積(heap)malloc 要來的記憶體malloc 成功時free 時
堆疊(stack)區域變數、參數、返回位址(呼叫堆疊)進入函式或區塊時離開那個函式或區塊時

文字版(由高位址到低位址):堆疊(往下長) → 還沒用到的空間 → 堆積(往上長) → .bss → .data → 程式碼 .text。

下面的程式驗證這個順序。它不印位址(每次執行都不同),只印比較的結果:

#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>

int g_init = 1;               // 有初值的全域變數:.data 區段
int g_zero;                   // 沒有初值的全域變數:.bss 區段(開機時清成 0)

static void depth(int n, uintptr_t prev) {
    int local = n;            // 每一層呼叫都有自己的 local,放在自己的呼叫框裡
    uintptr_t here = (uintptr_t)&local;
    if (prev != 0)
        printf("  第 %d 層的 local 比上一層%s\n", n, here < prev ? "低(堆疊往下長)" : "高");
    if (n < 3) depth(n + 1, here);
}

int main(void) {
    int local = 0;
    int *heap = malloc(sizeof *heap);
    if (heap == NULL) return 1;

    uintptr_t code = (uintptr_t)&main;    // 把函式位址轉成整數是常見的實作定義做法
    uintptr_t data = (uintptr_t)&g_init, bss = (uintptr_t)&g_zero;
    uintptr_t hp = (uintptr_t)heap, st = (uintptr_t)&local;
    printf("程式碼 < .data ? %d\n", code < data);
    printf(".data  < .bss  ? %d\n", data < bss);
    printf(".bss   < 堆積  ? %d\n", bss < hp);
    printf("堆積   < 堆疊  ? %d\n", hp < st);
    depth(1, 0);
    free(heap);
    return 0;
}

輸出(x86-64 Linux,用 -O0 編譯;-O2 會把遞迴最佳化掉,最後一行就不一定是「低」了。我們連跑 30 次,每次都一樣):

程式碼 < .data ? 1
.data  < .bss  ? 1
.bss   < 堆積  ? 1
堆積   < 堆疊  ? 1
  第 2 層的 local 比上一層低(堆疊往下長)
  第 3 層的 local 比上一層低(堆疊往下長)
  • 每次呼叫 depth 都在堆疊上開一個新的呼叫框(stack frame),裡面有自己的 local。越深的呼叫,位址越低。函式回傳,它的呼叫框就被下一次呼叫拿去用了。
  • 這些相對位置是 Linux x86-64 的慣例,不是 C 標準的規定。C 只規定生命週期:區域變數活到區塊結束、malloc 的記憶體活到 free、全域變數活到程式結束。
  • 堆疊不大:Linux 預設的堆疊上限通常是 8 MiB(ulimit -s 看得到),微控制器上常常只有幾 KiB。在函式裡宣告 int big[10000000]; 就會撞爆堆疊(stack overflow),要用 malloc。

生命週期錯誤與消毒器

生命週期結束之後,記憶體還在那裡,裡面的位元組通常也還沒變,只是你已經沒有權利用它了。 還指著它的指標叫懸空指標(dangling pointer)。透過懸空指標讀寫,是未定義行為,而且最麻煩的是:它常常「看起來正常」。

UBSan 抓未定義行為

-fsanitize=undefined 在每個可能出現未定義行為的運算旁邊加檢查:有號溢位、超過寬度的移位、除以 0、沒對齊的存取…… 回頭跑本章前面的兩個例子。先是整數提升造成的有號溢位:

核心觀念

C 的記憶體錯誤不會自己報錯。三層防線一起用:編譯時 -Wall -Wextra(看得到的抓)、測試時 -fsanitize=address,undefined(跑到的抓)、寫程式時養成習慣(傳長度、free 後設成 NULL、誰配置誰釋放)。

從 C 到記憶體安全

這一章的錯誤,在{{ch:36-secure-coding}}換了一個名字:漏洞。陣列越界寫入就是緩衝區溢位;釋放後使用可以讓攻擊者控制「那塊記憶體下次裝什麼」; 整數提升造成的溢位,會讓長度檢查失效,接著變成越界。它們的根源都是同一件事:C 不檢查你有沒有權利用一塊記憶體。

本章的規則違反時在{{ch:36-secure-coding}}叫做
指標只能在陣列範圍內移動讀寫到隔壁的資料緩衝區溢位、Off-by-one
陣列傳進函式要另外傳長度函式不知道邊界緩衝區溢位
小型別先提升成 int算出來的長度是負數或繞回整數溢位
生命週期結束就不能再用透過懸空指標讀寫Use-after-free、double free

業界的回應有三條路:在 C 裡加防線(本章的警告、消毒器,加上{{ch:36-secure-coding}}的堆疊保護、ASLR、模糊測試); 改用會在編譯時檢查生命週期的語言(Rust 的所有權與借用,見{{ch:85-rust-ownership}}); 或在硬體上替每個指標加上邊界(例如研究中的 CHERI 架構)。不管走哪一條,你都得先懂本章講的「位元組、位址、生命週期」,才知道它們在防什麼。 想從攻擊者的角度看這些錯誤,讀{{ch:72-ctf-pwn-reverse}}。

手算:多位元組存取經過記憶體映射

最後把本章的三件事放在一起:端序、記憶體映射、讀取的副作用。本章 Lab 的匯流排有這幾條規則,我們先用紙筆照規則追一遍:

  1. 16、32 位元的存取,一律拆成 2 或 4 次單一位元組存取,依位址由小到大:addr、addr + 1、……(位址是 uint32_t,0xFFFFFFFF + 1 繞回 0)。LE 和 BE 都一樣由小到大,差別只在組合:LE 第一個位元組放最低位,BE 第一個位元組放最高位。
  2. 落在 MMIO 區段裡的位元組,交給那一段的處理函式,並告訴它 offset = addr − base。
  3. 超出記憶體大小的位址:讀回 0xFF(open bus:這個位址沒有任何東西回應,規格規定讀到 0xFF)、寫入被忽略,而且錯誤計數(faults)加 1。

設定:記憶體大小 0x100(合法位址 0x00–0xFF)。RAM 裡 [0x7E] = 0x11、[0x7F] = 0x22、[0xFE] = 0xAA、[0xFF] = 0xBB。 0x80–0x81 是一個 MMIO 區段 SEQ:每次讀回計數器目前的值,然後計數器加 1(一開始是 0x01);每次寫入把 (offset, 值) 記進 LOG。faults 一開始是 0。

2read16be(0x7E)0x7E、0x7F11、220x1122不變

  • 第 3、4 步:讀 SEQ 會改變計數器,所以「讀幾次、照什麼順序」決定了答案。如果實作偷懶,BE 從高位址往低位址讀,第 4 步就會變成 0x0302。這就是規則 1 要把順序寫死的原因。
  • 第 5 步:16 位元讀取的後半超出範圍。前半照常讀到 0xBB,後半是 open bus 的 0xFF,而且只有後半算一次 fault。
  • 第 6、7 步:同一個值,BE 和 LE 寫進裝置的位元組順序相反,但位址順序一樣是 offset 0 再 offset 1。

typedef struct Bus Bus;            // 不透明:struct Bus 在你的 bus.c 裡定義
typedef uint8_t (*bus_read_fn)(void *ctx, uint32_t offset);               // offset = addr - base
typedef void (*bus_write_fn)(void *ctx, uint32_t offset, uint8_t value);

Bus *bus_new(uint32_t size);       // RAM 0..size-1 全是 0;size 是 0 或大於 BUS_MAX_SIZE → NULL
void bus_free(Bus *b);             // b 是 NULL 時什麼都不做
uint32_t bus_size(const Bus *b);

// 把 [base, base+len) 交給裝置:成功回 0。
// len 是 0、超出 [0, size)、和已經註冊的區段重疊、已經有 16 段 → 回 -1,什麼都不改。
// rd 是 NULL:讀回 BUS_OPEN;wr 是 NULL:寫入被忽略。
int bus_map(Bus *b, uint32_t base, uint32_t len, bus_read_fn rd, bus_write_fn wr, void *ctx);

// 落在區段裡 → 呼叫 rd/wr(ctx, addr - base);其他位址是 RAM。
// 超出 [0, size):讀回 BUS_OPEN、寫入被忽略,而且 bus_faults 加 1。
uint8_t bus_read8(Bus *b, uint32_t addr);
void bus_write8(Bus *b, uint32_t addr, uint8_t v);

// 多位元組存取一律拆成 read8/write8,依位址由小到大:addr、addr+1、…(uint32_t 自然進位)。
uint16_t bus_read16le(Bus *b, uint32_t addr);
uint16_t bus_read16be(Bus *b, uint32_t addr);
void bus_write16le(Bus *b, uint32_t addr, uint16_t v);
void bus_write16be(Bus *b, uint32_t addr, uint16_t v);
uint32_t bus_read32le(Bus *b, uint32_t addr);
void bus_write32le(Bus *b, uint32_t addr, uint32_t v);

// 直接寫進 RAM(不經過 MMIO 區段):成功回 0;超出範圍回 -1,一個位元組都不寫。
int bus_load(Bus *b, uint32_t addr, const uint8_t *data, uint32_t n);
uint32_t bus_faults(const Bus *b); // 到目前為止超出範圍的存取次數
#endif

三個容易漏掉的規定(上面兩個標頭的註解沒有寫完整的地方):

  • bits_get、bits_set 的 lo 是 0..31;lo + width 超過 32 時,超出第 31 位的部分當成不存在:bits_get 只取到第 31 位(上面補 0),bits_set 只改 [lo, 32) 這一段,v 多出來的位元丟掉。例如 bits_get(0xF0000000, 28, 8) = 0xF。這種情況也不能有未定義行為。
  • bus_load 失敗只回 -1,不算一次超出範圍的存取:bus_faults 只計 bus_read*／bus_write* 的存取。
  • bus_map 的 base + len 超過 uint32_t 的範圍(例如 base = 0xFFFFFFF0、len = 0x20)一律算「超出 [0, size)」,回 -1。判斷時不能先算 base + len:它會溢位繞回一個小的數,看起來就像在範圍裡。bus_load 的 addr + n 也一樣。

// 一個「計數器」裝置:每讀一次回傳目前的值再加 1;寫入記下最後一次的 offset 與值
struct counter { uint8_t next; uint32_t last_off; uint8_t last_val; };
static uint8_t ctr_read(void *ctx, uint32_t off) {
    struct counter *c = ctx;
    (void)off;
    return c->next++;
}
static void ctr_write(void *ctx, uint32_t off, uint8_t v) {
    struct counter *c = ctx;
    c->last_off = off;
    c->last_val = v;
}

int main(void) {
    printf("%08X %08X %08X\n", (unsigned)mask(0), (unsigned)mask(5), (unsigned)mask(32));
    printf("%u %08X %X\n", (unsigned)bit_get(0x80, 7), (unsigned)bit_set(0, 31, 1),

    printf("overlap=%d\n", bus_map(b, 0x80F, 4, ctr_read, NULL, &dev));
    bus_write16be(b, 0x100, 0xBEEF);

✏️ 練習 133.7 思考

有人這樣寫 16 位元有號數的符號延伸:int32_t v = (x & 0x8000) ? (int32_t)(x | 0xFFFF0000) : (int32_t)x;,x 是 uint32_t,只有低 16 位有值。這樣對嗎?有沒有和機器有關的地方?

看解答

位元的想法是對的:符號位元是 1 就把高 16 位補 1。例如 x = 0x8000,x | 0xFFFF0000 = 0xFFFF8000。 但最後一步把 0xFFFF8000(大於 INT32_MAX 的無號數)轉成 int32_t,在 C17 是實作定義的;gcc 規定照位元解讀,得到 −32768,所以在 gcc 上會對。 想完全不依賴實作,可以照本章 sext12 的寫法:先 x &= 0xFFFF 把 x 限定在 16 位,再算 (int32_t)(x ^ 0x8000) - (int32_t)0x8000。注意不能直接寫 (x ^ 0x8000) - 0x8000:x 是 uint32_t,這個減法是在 uint32_t 上算的,x = 0x8000 時得到 4294934528,轉回 int32_t 又是同一個實作定義的轉換。先限定 16 位,x ^ 0x8000 最大是 0xFFFF,轉成 int32_t 一定裝得下,減法就真的在 int32_t 裡算。另一個寫法是 (int32_t)(int16_t)x 搭配 gcc 的規定。

下面哪些變數該加 volatile?哪些加了也沒用,應該用別的東西?

  1. 計時器中斷服務程式每 1 毫秒把 ticks 加 1,主程式讀 ticks 來計算經過的時間。
  2. 兩個執行緒共用的計數器 hits,都會做 hits++。
  3. 指向 GPIO 輸入暫存器(按鈕的狀態)的指標。
  4. 一張只讀的查表 sine_table[256]。
  5. 拿來「空轉等待」的迴圈變數:for (int i = 0; i < 100000; i++) { }。
看解答
  1. 要 volatile(被 ISR 改)。如果 ticks 比 CPU 一次能讀寫的寬度還大(例如 8 位元 CPU 上的 32 位元變數),讀的時候還要暫時關中斷,因為 volatile 不保證一次讀完。
  2. volatile 沒用:hits++ 不是原子的。用 _Atomic(atomic_fetch_add)或互斥鎖。
  3. 要,而且是 const volatile:程式不寫它,但按鈕會改變它。
  4. 不要 volatile,要 static const:它不會變,讓編譯器盡量最佳化,還能放進 Flash。
  5. 不加 volatile,整個迴圈會被最佳化刪掉;加了雖然會留下來,但延遲的長短取決於時脈與編譯器,不可靠。要等一段時間,用硬體計時器。
✏️ 練習 133.9 思考

用「從名字往左讀」說出每個宣告的意思,並說出哪些東西可以改:(1)const char *msg;(2)char *const buf;(3)const uint8_t *const rom;(4)volatile uint32_t *const GPIO_OUT;(5)int (*handlers[4])(int)。

看解答
  1. msg 是指標,指向 const char:可以改指別的字串,不能透過它改字元。
  2. buf 是 const 指標,指向 char:永遠指同一塊,但可以改裡面的字元。
  3. rom 是 const 指標,指向 const uint8_t:兩個都不能改(適合模擬器裡的 ROM 映像)。
  4. GPIO_OUT 是 const 指標,指向 volatile uint32_t:位址固定,每次寫入都會真的做出來(寫韌體時的輸出暫存器)。
  5. handlers 是 4 個元素的陣列,每個元素是指標,指向「吃一個 int、回傳 int 的函式」:一張分派表。用 typedef int (*handler)(int); handler handlers[4]; 比較好讀。
✏️ 練習 133.10 實作

擴充本章的分派表小機器:加一個 opcode 4 是 SHL(acc 左移 arg 位),並讓它遇到表裡沒有的 opcode 時印出訊息、停下來,而不是當機。用程式 {0x03, 0x42, 0x11, 0x77} 測試。

看解答 
#include <stdio.h>
#include <stdint.h>

static int add(int a, int b) { return a + b; }
static int sub(int a, int b) { return a - b; }
static int mul(int a, int b) { return a * b; }
static int shl(int a, int b) { return (int)((unsigned)a << b); }   // 新增:左移

typedef int (*binop)(int, int);
enum { OP_LOAD, OP_ADD, OP_SUB, OP_MUL, OP_SHL, OP_COUNT };

int main(void) {
    static const binop table[OP_COUNT] = {
        [OP_ADD] = add, [OP_SUB] = sub, [OP_MUL] = mul, [OP_SHL] = shl,
    };
    const uint8_t prog[] = {0x03, 0x42, 0x11, 0x77};   // LOAD 3; SHL 2; ADD 1; 不存在的 opcode 7
    int acc = 0;
    for (size_t pc = 0; pc < sizeof prog; pc++) {
        unsigned op = prog[pc] >> 4, arg = prog[pc] & 0x0F;
        if (op == OP_LOAD) {
            acc = (int)arg;
        } else if (op < OP_COUNT && table[op] != NULL) {
            acc = table[op](acc, (int)arg);
        } else {
            printf("pc %zu:不認得的 opcode %u,停止\n", pc, op);
            break;
        }
        printf("pc %zu:acc %d\n", pc, acc);
    }
    return 0;
}

輸出:

pc 0:acc 3
pc 1:acc 12
pc 2:acc 13
pc 3:不認得的 opcode 7,停止

LOAD 3;SHL 2 得 12;ADD 1 得 13;0x77 的 opcode 是 7,超出表的範圍,停下來。shl 先轉成 unsigned 再移,避免有號數左移的未定義行為。OP_COUNT 放在 enum 最後,表的長度和檢查用同一個常數,加新 opcode 時不會忘了改。

✏️ 練習 133.12 挑戰

一個封包標頭的線上格式是:1 個位元組的 tag,接著 2 個位元組的 len,接著 4 個位元組的 crc,全部大端序、中間沒有空隙,共 7 個位元組。 有人寫 struct header *h = (struct header *)wire; 直接讀。說出這樣做的三個問題,並寫一個一個欄位讀出來的 parse_header。測資 01 00 2A DE AD BE EF。

看解答

三個問題:(1)填補:struct header 在記憶體裡 len 在位移 2、crc 在位移 4,總共 8 個位元組,和線上格式的位移 1、3 對不上; (2)端序:就算位移對了,x86-64 也會用小端序解讀;(3)對齊與嚴格別名:wire 是 uint8_t 陣列,不保證對齊 4,用 struct 型別讀它是未定義行為。

#include <stdio.h>
#include <stdint.h>
#include <stddef.h>

struct header { uint8_t tag; uint16_t len; uint32_t crc; };   // 記憶體裡:tag@0、len@2、crc@4

static uint16_t get_be16(const uint8_t *p) { return (uint16_t)((p[0] << 8) | p[1]); }

// 從線上格式(緊密排列、大端序)一個欄位一個欄位讀出來,不把 struct 直接蓋在緩衝區上
static struct header parse_header(const uint8_t *buf) {
    struct header h;
    h.tag = buf[0];
    h.len = get_be16(buf + 1);
    h.crc = ((uint32_t)get_be16(buf + 3) << 16) | get_be16(buf + 5);
    return h;
}

int main(void) {
    const uint8_t wire[7] = {0x01, 0x00, 0x2A, 0xDE, 0xAD, 0xBE, 0xEF};
    struct header h = parse_header(wire);
    printf("tag %u, len %u, crc 0x%08X\n", (unsigned)h.tag, (unsigned)h.len, (unsigned)h.crc);
    printf("sizeof(struct header) = %zu,線上格式只有 7 個位元組\n", sizeof(struct header));
    return 0;
}

輸出:

tag 1, len 42, crc 0xDEADBEEF
sizeof(struct header) = 8,線上格式只有 7 個位元組

32 位元的 crc 用兩次 get_be16 組起來:0xDEAD << 16 | 0xBEEF。注意要先轉成 uint32_t 再左移 16,否則 uint16_t 會提升成 int,0xDEAD << 16 超過 INT_MAX,又是有號溢位。

把這一章串起來

  • 指標運算以「指向的型別」為單位;&a 是指向整個陣列的指標;只能在陣列範圍內(含最後一格的下一格)移動。
  • 陣列會退化成指標,長度就不見了:sizeof 只在宣告陣列的地方有用,傳進函式要另外傳長度。要改呼叫端的指標,就傳指向指標的指標。
  • struct 佈局:每個成員補到自己的對齊值,總大小補到最大的對齊值;大的成員排前面比較省;用 offsetof 與 _Static_assert 把手算的佈局釘住。
  • 位元欄位的位置和存取寬度是實作定義的,外面規定位元位置時改用定寬整數加遮罩。
  • 定寬整數:<stdint.h> 給確定的大小,但比 int 小的型別運算時會先提升成有號的 int。
  • 遮罩與移位:|= 設、&= ~ 清、^= 翻轉、移位加遮罩取出與替換欄位。移位量不能等於或超過寬度;位元運算用無號數、加括號。
  • 符號延伸:變寬時補什麼看來源的型別;任意寬度用 (x ^ s) - s。「是不是負數」要先說好寬度。
  • 大小端:LE 最小的位址放最低的位元組;用移位拼位元組,結果就和主機無關。
  • const 是「透過這個名字不能改」的約定;volatile 讓每一次存取都真的做出來,但不保證原子性、不是執行緒同步工具。
  • 函式指標讓分派表與記憶體映射成為可能:用 opcode 或位址查到要呼叫的函式;讀取可能有副作用,所以存取的次數與順序是規格的一部分。
  • 生命週期:區域變數活到區塊結束,malloc 的活到 free。懸空指標「看起來正常」最危險;用 -Wall -Wextra 與 -fsanitize=address,undefined 把它們抓出來。
