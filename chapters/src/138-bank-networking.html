下面這組抽認卡收了五層共 64 條常考名詞解釋,從實體層的訊號與編碼,到應用層的 DNS、HTTP 都在裡面。先用上方的分層 chips 選你要練的範圍(或選全部),卡片正面只顯示名詞,按「🔄 翻卡」看背面的定義;翻開後標「會了」的卡會先移出這一輪的牌堆,標「不熟」的卡會留在牌堆裡稍後重新出現,直到整輪的卡都標成「會了」才算練完一輪。

計算題隨機驗算怎麼玩

下面這組題目涵蓋 CRC 驗證、CIDR 子網劃分、傳輸延遲、頻寬延遲乘積、TCP 視窗等八種期中考常見計算題型,每次出現的數字都是隨機生成的,所以背答案沒有用。算出自己的答案後按「檢查答案」核對對錯,不管對錯都可以展開「看詳解」,照著詳解逐步列出的算法回頭檢查自己哪一步算錯;按「換一題」會用新的隨機數字重新出一題同類型的題目,練到不看詳解也能算對為止。

路由演算法範例題

名詞解釋和計算題都可以隨機換數字反覆練,但路由演算法的手算追蹤不適合這樣做:隨機產生的網路圖很容易出現幾條路徑成本剛好相同、最短路徑不唯一的情況,等於同一題有好幾個「都對」的答案,反而讓你搞不清楚自己的手算邏輯到底哪裡出錯。因此底下四題固定用同一組網路拓樸,確保答案唯一又乾淨;練法跟本書其他章節的練習題一樣:先自己手算一次,再展開「看詳解」核對逐步過程。

範例一:Dijkstra(連結狀態)逐步追蹤

範例一 · 從 A 出發跑 Dijkstra 固定答案

這一題固定用同一張 6 個節點的無向圖,邊與權重如下:

邊權重
A-B2
A-C5
B-C1
B-D4
C-D2
C-E3
D-E2
D-F6
E-F2

以 A 為起點跑 Dijkstra:先把 A 加入已確定集合 N',把 A 直接相連的節點距離設成邊的權重,其他節點先設成 ∞;接下來每一輪,從還沒確定的節點裡挑 D(v) 最小的那個加入 N',再用它的邊去「放寬」(relax)還沒確定的鄰居——如果繞道這個新加入的節點比目前記錄的距離更短,就更新 D(v) 和前驅 p(v)。自己拿一張紙,照這個流程畫一次完整的 N' / D(v),p(v) 逐輪表,再展開核對。

看逐輪過程與最終答案

表中的「—」代表這個節點在更早的輪次就已經確定,之後不會再變動。

RoundN'D(B),p(B)D(C),p(C)D(D),p(D)D(E),p(E)D(F),p(F)
0A2,A5,A∞∞∞
1A,B—3,B6,B∞∞
2A,B,C——5,C6,C∞
3A,B,C,D———6,C11,D
4A,B,C,D,E————8,E

第 1 輪加入 B 之後,原本 D(C)=5(p(C)=A)可以改走 A-B-C,成本 2+1=3,比 5 短,所以更新成 D(C)=3,p(C)=B;同時 D(D) 第一次有值,走 A-B-D 是 2+4=6,p(D)=B。第 2 輪加入 C 之後,D(D) 又被 C 刷新:A-B-C-D 是 3+2=5,比原本經 B 的 6 短,所以 D(D)=5,p(D)=C;D(E) 第一次有值,走 ...-C-E 是 3+3=6,p(E)=C。第 3 輪加入 D 之後,經 D 去 E 要 5+2=7,比現有的 6 貴,所以 E 不變;但 D(F) 第一次有值,經 D 去 F 是 5+6=11,p(F)=D。第 4 輪加入 E 之後,經 E 去 F 只要 6+2=8,比經 D 的 11 短,所以 F 更新成 D(F)=8,p(F)=E。

最終每個節點到 A 的最短距離:A=0,B=2,C=3,D=5,E=6,F=8。沿著 p(v) 往回追——F←E←C←B←A——可以重建出到 F 的最短路徑是 A-B-C-E-F,成本 2+1+3+2=8,正好等於 D(F);D-F 這條邊雖然存在(權重 6),但走 D-F 總成本是 5+6=11,比走 C-E-F 的 6+2=8 貴,所以最短路徑不會經過它,這也是為什麼 D(F) 最後定案在 8 而不是 11。

範例二:Distance Vector(Bellman-Ford)鄰居交換

範例二 · X 收到鄰居的向量後重新計算 固定答案

這一題固定用 4 個節點 W、X、Y、Z 的網路,直接相連的邊與權重如下(注意 W 和 Z 之間沒有直接連線):

邊權重
W-X2
W-Y5
X-Y1
X-Z3
Y-Z1

Distance Vector 一開始,每個節點只知道「自己到直接鄰居的成本」,其他目的地一律當成 ∞。四個節點的初始向量:

節點到 W到 X到 Y到 Z
W025∞
X2013
Y5101
Z∞310

一般更新規則(每個節點 x,對每一個目的地 d,都套用同一條規則):$D_x(d) = \min_{v}\big(c(x,v) + D_v(d)\big)$,其中 v 取遍 x 的每一個鄰居;「v = x 自己」這一項——也就是 x 到 d 的直接連線成本——永遠是其中一個候選項。

練習:假設每個節點同時把自己目前的向量送給鄰居,X 收到 W 和 Y 送來的(上面列出的)初始向量後,請自己先算一次 X 的三個非自己項目(到 W、到 Y、到 Z)會不會變,再展開核對。

看 X 的三個重新計算

到 W: min(直接 = 2,經 Y:c(X,Y)+D_Y(W) = 1+5 = 6,經 Z:c(X,Z)+D_Z(W) = 3+∞ = ∞) = 2——不變。

到 Y: min(直接 = 1,經 W:c(X,W)+D_W(Y) = 2+5 = 7,經 Z:c(X,Z)+D_Z(Y) = 3+1 = 4) = 1——不變。

到 Z: min(直接 = 3,經 W:c(X,W)+D_W(Z) = 2+∞ = ∞,經 Y:c(X,Y)+D_Y(Z) = 1+1 = 2) = 2——改變,Z 的距離從 3 變成 2,現在改走 Y,不再走原本的直接邊。

只有「到 Z」這一項改變,因為繞道 Y(X-Y 的 1 加上 Y 原本到 Z 的 1,等於 2)比 X 原本直接連到 Z 的 3 更短。這也示範了 Distance Vector 的優點:節點不需要知道全圖,只要鄰居老實回報「我到各地要多遠」,x 自己就能用上面那條規則慢慢算出更短的路。但正因為 x 看到的只是鄰居給的「答案」,不是鄰居的「推導過程」,一旦某個鄰居的數字是過時或錯的,x 也會被牽連著跟著算錯——下一題的 count-to-infinity 就是這種情況的極端版本。

範例三:count-to-infinity 陷阱

範例三 · Y-Z 這條鏈路忽然變貴之後 固定答案

這一題固定用一條只有 3 個節點的鏈:X-Y:1,Y-Z:1(X 沒有直接連到 Z)。穩定狀態下,Y 到 Z 直接走那條邊,成本 1;X 到 Z 沒有直接邊,只能繞道 Y,成本是 X-Y 的 1 加上 Y 到 Z 的 1,等於 2。

現在假設 Y-Z 這條鏈路忽然壞到只剩很差的狀態,成本從 1 跳到 60。Distance Vector 沒有全局視野,每個節點只會跟直接鄰居交換「我現在到各地要多遠」,然後各自重新套用範例二的更新規則。自己想一想:Y 發現自己到 Z 的直接成本變成 60 之後,會不會乾脆改成繞道 X?如果會,X 之後又會怎麼反應?這樣一輪一輪交換下去,會發生什麼事?想清楚再展開看逐輪過程。

看逐輪過程與為什麼這麼慢
輪發生什麼事到 Z 的距離
變化前穩定狀態X = 2(經 Y),Y = 1(直接)
0Y-Z 鏈路成本從 1 跳到 60Y 的直接成本變成 60;X 還不知道,仍回報 2
1Y 比較「直接 60」vs「經 X:c(Y,X)+D_X(Z)=1+2=3」,改走 XY = 3(經 X,但其實是舊資料)
2X 收到 Y 回報的 3,重新算 c(X,Y)+D_Y(Z)=1+3=4X = 4(經 Y)
3Y 再收到 X 的 4,重新算 c(Y,X)+D_X(Z)=1+4=5Y = 5(經 X)
4X 再收到 Y 的 5,重新算 c(X,Y)+D_Y(Z)=1+5=6X = 6(經 Y)
⋮同樣的來回一直重複,每一輪只增加 1⋮
最終直到「經 X」的估計終於超過 Y 的直接成本 60,Y 才改回走直接邊;X 也跟著 Y 穩定下來Y = 60(直接),X = 61(經 Y)

問題出在哪裡:Y 在第 1 輪改走 X 的時候,用的是 X「舊的」回報值 2——但 X 的那個 2,本來就是繞道 Y 才算出來的!Y 等於是在用「繞一圈又繞回自己」的資料來更新自己,卻不知道這個迴圈存在。這就是 count-to-infinity:每一輪雙方都只把對方的估計值加上一個固定的邊成本再回傳,真正的壞消息(鏈路變貴了 59)要花很多輪、一輪只爬一點,才能慢慢「追上」。

這一題要帶走的重點:這麼慢是因為這個最簡單版本的 Distance Vector 沒有 split-horizon(不把學來的路線回報給教它這條路線的鄰居)或 poison-reverse(回報 ∞ 告訴對方「別把這條路算我」)這類機制來擋住壞消息繞圈子;而且爬升所花的輪數是被「鏈路成本的變化量」(60-1=59)決定的,不是被網路的節點數或直徑決定的——鏈路壞得越嚴重,就要繞越多輪才會停,跟網路本身大小無關。這正是為什麼真實世界的 Distance Vector 協定(例如 RIP)都會加上這些機制;而 OSPF 這類連結狀態協定因為每個節點看到的是全圖,壞消息一次就能傳到位,不會有這種慢慢爬的問題。

範例四:連結狀態 vs 距離向量,該知道什麼

範例四 · 連結狀態(Dijkstra)vs 距離向量(Distance Vector)

範例一和範例二分別示範了這兩種路由演算法本身怎麼算,這裡把它們放在一起整理成考試最常問的對照表,不需要手算,看懂就好:

連結狀態(Link-State,如 Dijkstra / OSPF)距離向量(Distance Vector,如 Bellman-Ford / RIP)
每個節點知道什麼整張網路的拓樸——每個節點都把自己連到哪些鄰居、成本多少「廣播(flood)」給全網路所有節點只知道自己到各目的地的距離估計值,以及直接鄰居回報的距離估計值
訊息怎麼傳每個節點把自己的連結資訊 flood 給所有節點,整體訊息量約 O(節點數 × 邊數)只跟直接相連的鄰居交換自己目前的距離向量,每輪訊息量小很多
怎麼算出最短路徑每個節點拿到完整拓樸後,各自在本地跑一次 Dijkstra(範例一)每個節點用範例二的更新規則,反覆跟鄰居交換、慢慢逼近正確值
收斂速度與正確性只要拓樸資訊傳到,節點本地算出來的就是正確答案,過程中不會有錯誤的繞圈子鏈路成本「變小」時收斂快;但鏈路成本「變大」時可能發生 count-to-infinity(範例三),要很多輪才會收斂,中途還可能出現暫時性的路由迴圈

記這張表的時候抓住一個主軸就好:連結狀態是「先讓大家都知道全圖,再各自在家裡算」,訊息成本高但算出來一定對;距離向量是「只跟鄰居講悄悄話,邊講邊算」,訊息成本低但遇到壞消息(成本變大)可能要繞很多輪才會反映過來。

上考場前的檢查清單

  • 五層(實體、資料鏈結、網路、傳輸、應用)的抽認卡都至少刷過一輪,而且整輪都標成「會了」。
  • 八種計算題型都練到不看詳解、自己也能算對,尤其 CRC 的模二除法和 CIDR 子網劃分最容易算錯進位或少看一個條件。
  • 路由演算法的四個範例都看懂逐步過程,能自己口述 Dijkstra 和 Distance Vector 的差別,以及 count-to-infinity 為什麼會發生。
