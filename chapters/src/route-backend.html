本路線的主線專題

這條路線的 Lab 串成 3 條主線專題(另外 1 條主線在別的路線,這裡也會用到)。一條主線是一份會長大的程式碼:前面 Lab 做好的零件,後面的 Lab 和專題直接拿來用。每條主線先定下最後的 Boss 戰,再拆成零件;每個零件的任務目標(含效能門檻)都說得出是哪一個 Boss 需要它。

🗺️
主線專題和地下城的對照

主線專題＝任務線;每個零件＝一個任務(有自己的資料夾);每組測試＝一個任務目標(打勾的格子);最後的整合測試＝Boss 戰。

〔公開〕的任務目標用 test(或 F5)自己跑;〔隱藏檢定〕在 submit 時才跑,只看得到名稱和一行說明;〔老師核可〕由老師人工看。零件過關之後,後面的專題一律用你自己的版本,規則見零件庫規則。

B1 借書 API:從 socket 到上線

任務線 bookapi · 程度:高中後段/大學
技能樹專題(依序是檢查點):🏆 手寫多執行緒 HTTP 伺服器、🏆 待辦清單 REST API(含資料庫與測試)、🏆 上線一個安全的服務(JWT＋Redis 快取＋Docker Compose)

只用 Python 標準函式庫,從 socket 寫起 HTTP 伺服器,加上執行緒池、SQLite 資料層、JSON API 與自己的測試,最後加認證與快取上線。三個技能樹專題是同一份程式碼的三個檢查點;第二個檢查點和組隊副本 R1「圖書館借書 API」同題(另一組隱藏測試)。

服務模式:判題時我們的啟動檔以 python3 -I main.py --port 8080 --db /tmp/app.db 呼叫你的服務;測試客戶端用另一個使用者從外面連 8080。檢查點 3(認證、快取)的零件還在 outline,它們的書(G17、G19)還沒寫。

Boss 戰(最後專題的驗收):

檢查點 1:🏆 手寫多執行緒 HTTP 伺服器

  • ⚔️ 靜態檔〔公開〕你的伺服器回傳一個靜態檔,狀態碼、Content-Type 與內容都對。用到:任務「HTTP 伺服器」、任務「執行緒池」
  • ⚔️ JSON 回應〔公開〕GET 一個 JSON 端點,回傳的 JSON 與 Content-Type 都對。用到:任務「HTTP 伺服器」、任務「執行緒池」
  • ⚔️ 找不到〔公開〕不存在的路徑回 404,伺服器繼續服務。用到:任務「HTTP 伺服器」
  • ⚔️ 畸形請求〔公開〕畸形的請求回 400,伺服器不能當掉。用到:任務「HTTP 伺服器」
  • ⚔️ 100 個併發連線〔隱藏檢定〕很多客戶端同時連線也不出錯。(效能:100 個客戶端同時開始,各依序連 10 次(每次 1 個請求,處理 10 ms),零錯誤,5 秒內)用到:任務「HTTP 伺服器」、任務「執行緒池」
  • ⚔️ 慢客戶端〔隱藏檢定〕只連線不送資料的客戶端不能擋住別人,逾時後被關掉。用到:任務「HTTP 伺服器」、任務「執行緒池」

檢查點 2:🏆 待辦清單 REST API(含資料庫與測試)

  • ⚔️ 公開 API 測試〔公開〕約 12 條公開測試:書目 CRUD、會員、借書、還書、逾期查詢的正常流程。用到:任務「借書資料庫」、任務「借書 REST API」
  • ⚔️ 邊界〔隱藏檢定〕隱藏測試類別「邊界」:分頁的極端值、空字串、本數 0 的書、Unicode 書名。用到:任務「借書資料庫」、任務「借書 REST API」
  • ⚔️ 錯誤處理〔隱藏檢定〕隱藏測試類別「錯誤處理」:壞 JSON、型別錯、找不到、不能借時的狀態碼與錯誤格式。用到:任務「借書資料庫」、任務「借書 REST API」
  • ⚔️ 資料一致〔隱藏檢定〕隱藏測試類別「資料一致」:借還之後的可借本數、重複還書、刪除有人借的書;同時借最後一本只能成功一次。用到:任務「借書資料庫」、任務「借書 REST API」、任務「執行緒池」
  • ⚔️ 規格細節〔隱藏檢定〕隱藏測試類別「規格細節」:201／204 的用法、Content-Type、列表排序與分頁、PATCH 只改給的欄位。用到:任務「借書 REST API」
  • ⚔️ 借還負載〔隱藏檢定〕借書 API 掛在自己的多執行緒伺服器上,很多人同時借還也不會超借。(效能:100 個客戶端同時各借還 10 次:零錯誤、沒有超借,10 秒內)用到:任務「執行緒池」、任務「借書資料庫」、任務「借書 REST API」
  • ⚔️ 突變測試〔隱藏檢定〕你的 tests/ 在參考解上全過,而且 8 個隱藏突變版每個都至少有一條測試失敗。用到:任務「測試借書 API」

檢查點 3:🏆 上線一個安全的服務(JWT＋Redis 快取＋Docker Compose)

  • ⚔️ 攻擊套件〔隱藏檢定〕SQLi、XSS、越權的攻擊腳本全部擋下,功能測試照樣全過(和資安 webfix 共用同一份攻擊套件)。用到:任務「認證與授權」、任務「借書 REST API」、任務「借書資料庫」
  • ⚔️ 快取延遲〔隱藏檢定〕熱門書目走快取;書目更新後快取要失效,不能讀到舊資料。(效能:200 個客戶端同時讀熱門書目 10 秒:p95 延遲 50 ms 內(估計值))用到:任務「快取層」、任務「借書 REST API」
  • ⚔️ 上線〔老師核可〕Dockerfile／Compose 把服務跑起來(沙盒做不了,老師核可)。
