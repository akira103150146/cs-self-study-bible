在深度學習之前,AI 是怎麼「思考」的?

1956 年夏天,達特茅斯學院(Dartmouth College)的一場研討會裡,一群科學家打賭: 只要給機器足夠精確的知識與推論規則,它就能表現出人類智慧。這場賭注催生了一門學科的名字—— 人工智慧(Artificial Intelligence, AI)。

在接下來的四十年裡,AI 幾乎等同於一種思路:符號主義(Symbolism)。 它的信念是:智慧的本質是符號的操縱。世界可以被描述成一組命題、規則與關係; 推論就是按照邏輯規則從已知推出未知;問題求解就是在符號構成的空間中搜尋答案。

這套方法論後來被冠上一個略帶嘲諷的綽號——GOFAI(Good Old-Fashioned AI,好老派的 AI)。 它的集大成之作是 Russell 與 Norvig 的《人工智慧:現代方法(Artificial Intelligence: A Modern Approach, AIMA)》, 這也是本章最重要的參考座標。

📜
符號 AI 的黃金年代

1970–90 年代,符號 AI 誕生了許多真實成就:IBM 的 Deep Blue 靠著 minimax 與 alpha-beta 在 1997 年擊敗卡斯帕羅夫; NASA 的 Remote Agent 用規劃演算法指揮深空探測器;各大醫院的專家系統(expert system)協助診斷。 這些成就在當時看來幾乎是奇蹟——但它們都有一個共同的瓶頸:知識必須由人類手動編碼進去。

本章的角色不是「考古」。符號 AI 的核心工具——搜尋、約束推理、邏輯—— 在今天依然在許多系統裡運作(路線規劃、排程、形式驗證、棋類 AI)。 更重要的是:理解 GOFAI 的邊界,才能真正理解為什麼深度學習({{ch:38-machine-learning}})在 2010 年代之後全面接管—— 不是因為搜尋「錯了」,而是因為有些問題根本無法靠手工知識解決。

符號 AI vs 統計 AI 的根本分歧

符號 AI:世界用符號(predicates, rules)表示;推論是邏輯演繹;知識由人類工程師編碼。

問題形式化:把世界塞進一個搜尋空間

符號 AI 的第一步,是把現實問題翻譯成一個精確的數學物件——狀態空間(state space)。 不管你要解的是 15-puzzle、路線規劃、西洋棋還是火星探測車的路徑,它們都可以用同一套語言描述。

以八數碼(8-puzzle)為例:狀態是 3×3 格的排列(共 9! = 362,880 種); 動作是空格上下左右移動;目標是 1 2 3 / 4 5 6 / 7 8 _;路徑代價是移動步數。 搜尋演算法要在 362,880 個狀態組成的圖中找出最短路。

路線規劃(如 Google Maps)的狀態就是「目前所在的路口」; 動作是「沿某條道路行駛至下一個路口」;代價是時間或距離。 你在{{ch:30-graph-algorithms}}學過 Dijkstra 與 A*, 現在我們把它們放進這個更大的 AI 框架來理解。

無資訊搜尋:盲目地把圖走過一遍

最素樸的搜尋策略不使用任何「離目標還有多遠」的資訊,只憑著系統性地展開節點前進。 這類方法稱為無資訊搜尋(uninformed search)或盲目搜尋。

廣度優先搜尋(BFS)與深度優先搜尋(DFS)

廣度優先搜尋(Breadth-First Search, BFS)用 FIFO 佇列展開邊界(frontier): 先把起點所有鄰居加入、再展開其鄰居的鄰居……這確保了找到的第一個解是步數最少的解。 代價:記憶體消耗是 $O(b^d)$($b$ = 分支因子、$d$ = 目標深度)。

深度優先搜尋(DFS)則用 LIFO 堆疊:一路往深處鑽,直到找到解或碰壁才回溯。 記憶體只需 $O(bd)$(路徑上的節點),但找到的解不一定最優, 而且在無限深度的圖裡可能永遠找不到(需加深度限制)。

迭代加深搜尋(Iterative Deepening Search, IDS)結合兩者優點: 依序對深度 $d = 1, 2, 3, \ldots$ 做 DLS(Depth-Limited Search), 既保有 BFS 的最優性又保有 DFS 的記憶體效率——時間複雜度仍是 $O(b^d)$,記憶體 $O(bd)$。

一致代價搜尋(UCS)

當每個動作有不同代價時,BFS 的「步數最少」就不等於「代價最低」。 一致代價搜尋(Uniform Cost Search, UCS)用優先佇列取代 FIFO, 每次展開累計代價 $g(n)$ 最小的節點——這正是你在{{ch:30-graph-algorithms}}學過的 Dijkstra 演算法。 UCS 在邊權非負時保證找到最優解。

⚠️
已探索集合(closed set)很重要

在圖搜尋(而非樹搜尋)中,同一個狀態可能從不同路徑抵達。 必須維護已探索集合,避免重複展開同一節點——否則在有環的圖裡會死迴圈。

無資訊搜尋的最大問題:對 $b = 10$、$d = 20$ 的問題,BFS 要展開 $10^{20}$ 個節點——這在宇宙年齡內跑不完。 我們需要一個指路針,告訴搜尋「往哪個方向看起來比較有希望」——這就是啟發式。

有資訊搜尋:啟發式與 A* 演算法

想像你在一個陌生城市裡找一家餐廳。你不知道確切路徑,但你知道目的地的方向—— 「往東北走感覺比較對」。這個直覺就是啟發式(heuristic): 一個對「距離目標還有多遠」的估計,幫助你優先探索看起來有希望的方向。

貪婪最佳優先搜尋

最直接的做法:優先展開啟發式值 $h(n)$ 最小的節點——「最接近目標的先走」。 這叫貪婪最佳優先搜尋(Greedy Best-First Search)。 它快,但不保證最優:可能被「看起來近、其實路況很差」的方向騙走。

A* 演算法

A* 結合了 UCS 的最優性保證與啟發式的方向感,用一個評估函數:

$$f(n) = g(n) + h(n)$$

其中 $g(n)$ 是從起點到節點 $n$ 的實際代價,$h(n)$ 是對「從 $n$ 到目標的代價」的估計。 A* 每次展開 $f(n)$ 最小的節點——兼顧「已走了多遠」與「還要走多遠」。

A* 的正確性依賴啟發式的兩個性質:

  • 可採納性(admissibility):$h(n) \leq h^*(n)$ 對所有節點 $n$ 成立, 其中 $h^*(n)$ 是從 $n$ 到目標的真實最優代價。啟發式「不高估」——它是個樂觀的估計。 例如:地圖上兩點間的直線距離永遠不超過真實道路距離。
  • 一致性(consistency,又稱單調性 monotonicity):對任一邊 $(n, n')$, $h(n) \leq c(n, n') + h(n')$(三角不等式)。 一致性強於可採納性:一致必然可採納,反之不然。 一致性保證每個節點只被展開一次——等同於圖搜尋的最優性。
🔑
A* 的最優性定理

若啟發式 $h$ 為可採納的,A*(樹搜尋版本)保證找到最優解。
若 $h$ 為一致的,A*(圖搜尋版本)保證找到最優解,且每節點只展開一次。
沿最優路徑,$f(n) = g(n) + h(n)$ 是非遞減的(consistent 的直接推論)。

A* 的 Python 實作:解八數碼

以下是 A* 解八數碼(8-puzzle)的完整實作。 啟發式用 Manhattan distance:每個數字距離目標位置的行列差之和。 這是可採納且一致的啟發式——它永遠不高估真實移動步數。 

import heapq

# ── 八數碼 A* ──────────────────────────────────────────────
# 狀態:長度 9 的 tuple,0 = 空格;
# 目標:(1,2,3, 4,5,6, 7,8,0)
GOAL = (1, 2, 3,
        4, 5, 6,
        7, 8, 0)

def manhattan(state):
    """Manhattan distance 啟發式:每個數字到目標位置的距離之和"""
    dist = 0
    for i, tile in enumerate(state):
        if tile == 0:
            continue
        gi = GOAL.index(tile)                      # 目標位置
        dist += abs(i // 3 - gi // 3) + abs(i % 3 - gi % 3)
    return dist

def get_neighbors(state):
    """傳回 [(代價=1, 新狀態), ...]"""
    result = []
    z = state.index(0)                             # 空格位置
    r, c = divmod(z, 3)
    for dr, dc in [(-1, 0), (1, 0), (0, -1), (0, 1)]:
        r2, c2 = r + dr, c + dc
        if 0 <= r2 < 3 and 0 <= c2 < 3:
            s = list(state)
            s[z], s[r2 * 3 + c2] = s[r2 * 3 + c2], s[z]
            result.append((1, tuple(s)))
    return result

def astar_puzzle(start):
    """傳回 (解法路徑, 步數);無解傳回 (None, -1)"""
    h0 = manhattan(start)
    # heap 元素:(f=g+h, g, 狀態, 路徑)
    heap = [(h0, 0, start, (start,))]
    best_g = {start: 0}

    while heap:
        f, g, state, path = heapq.heappop(heap)
        if g > best_g.get(state, float('inf')):
            continue                               # 已有更優路徑
        if state == GOAL:
            return list(path), g
        for cost, nxt in get_neighbors(state):
            ng = g + cost
            if ng < best_g.get(nxt, float('inf')):
                best_g[nxt] = ng
                heapq.heappush(heap,
                    (ng + manhattan(nxt), ng, nxt, path + (nxt,)))
    return None, -1

# ── 測試 ─────────────────────────────────────────────────
start = (1, 2, 3,
         4, 0, 5,
         7, 8, 6)   # 只差兩步

path, cost = astar_puzzle(start)
print(f"找到解法,共 {cost} 步")
for step, s in enumerate(path):
    print(f"  步驟 {step}: {s[:3]} | {s[3:6]} | {s[6:]}")

手算:Manhattan 與放錯位置的塊數各展開幾個節點

另一個常見的啟發式是放錯位置的塊數(misplaced tiles):不在目標位置的塊有幾塊(空格不算)。 每一塊放錯的,至少要移動一次,所以它不會高估;每一塊的 Manhattan 距離又至少是 1,所以 $h_{\text{放錯}} \le h_{\text{Manhattan}} \le h^*$。 兩個都可採納,但 Manhattan 比較「緊」。差多少?把展開的節點數數出來。下面的程式接著用上面的 GOAL、manhattan、get_neighbors: 

import heapq

def misplaced(state):
    """放錯位置的塊數(空格不算)"""

def astar_count(start, h, show=False):
    """回傳 (最短步數, 展開的節點數)。
    f 相同時先展開 h 小的;h 也相同時,先放進 open 的先展開。"""

    seq = 0
    expanded = 0
    while heap:

        if s in closed or f != g[s] + hs:
            continue                           # 過期的紀錄:跳過
        if s == GOAL:
            return g[s], expanded
        closed.add(s)
        expanded += 1
        if show:
            print(expanded, s, f'g={g[s]} h={hs} f={f}')
        for cost, nxt in get_neighbors(s):

            if ng < g.get(nxt, float('inf')):
                g[nxt] = ng
                closed.discard(nxt)            # 展開過的也重新打開
                seq += 1
                heapq.heappush(heap, (ng + h(nxt), h(nxt), seq, nxt))
    return None, expanded

為什麼要學

任務線 puzzle(解謎 AI)的任務「A* 搜尋」要求 solve 回傳最短的走法,Boss 戰「十五數碼」也一樣。 任務目標「啟發式不高估」會在 3×3 的每一個狀態檢查 manhattan ≤ heuristic ≤ 真實步數(真實步數用你在{{ch:30-graph-algorithms}}做的 distance_table); 「重新打開」會用一個不一致的啟發式考你。這段證明告訴你這兩條規則各自保護了什麼。

要證的事:邊的代價都 ≥ 0,而且 $h$ 可採納($h(n) \le h^*(n)$,目標的 $h$ 是 0)。 如果 A* 找到更短的路就更新 g(在 open 裡就 decrease_key,已經展開過就重新打開),那它取出目標時的 g 就是最短代價 $C^*$。

證明(參考)。拿一條最短路徑 s = n0 → n1 → … → nk = 目標。 先看一個一直成立的事實:在目標被取出之前,設 ni 是這條路上第一個還沒有用最短的 g 展開過的點 (目標還沒被取出,所以這樣的點一定有)。那 ni 一定在 open 裡,而且 g(ni) = $g^*(n_i)$。 理由:i = 0 時它是起點,g = 0 就是最短,還沒展開,所以在 open;i > 0 時,前一個點 ni−1 已經用最短的 g 展開過, 那一次展開讓 ni 的 g 變成 $g^*(n_i)$(push、decrease_key 或重新打開,三種情況都會讓它回到 open),而它之後還沒用這個 g 展開,所以還在 open。 這就是「重新打開」不能省的地方:如果 ni 以前用比較長的 g 展開過、又不准再打開,它就不在 open 裡,論證就斷了。

現在假設目標被取出時 g(目標) > $C^*$。那一刻,上面那個 ni 在 open 裡,而且 $f(n_i) = g^*(n_i) + h(n_i) \le g^*(n_i) + h^*(n_i) = C^*$ < g(目標) = f(目標)。 A* 每次取 f 最小的,應該先取 ni,不會取目標,矛盾。所以取出目標時一定是最短代價。 證明只在一個地方用到「不高估」:$h(n_i) \le h^*(n_i)$。

程式版:如果你知道真正的最短代價 $C^*$,每一次取出的 f 都不會超過它(上面的論證其實說明了:目標之前取出的點,f 都 ≤ $C^*$)。 下面的 check=True 就在每次取出時 assert f <= C*;check_heuristic 則把可採納性與一致性逐點、逐邊檢查一遍。 Lab 的「啟發式不高估」就是在 3×3 的 181,440 個狀態上做 check_heuristic 的前半段。 

INF = float('inf')

def dist_to_goal(graph, goal):
    """每個點到 goal 的真正最短代價 h*(反覆鬆弛;只給小圖用)。"""
    d = {u: INF for u in graph}
    d[goal] = 0
    for _ in range(len(graph)):
        for u in graph:
            for v, w in graph[u]:
                if d[v] + w < d[u]:
                    d[u] = d[v] + w
    return d

def check_heuristic(graph, h, goal):
    """回傳 (高估的點, 不一致的邊)。兩個都是空的才放心。"""
    hstar = dist_to_goal(graph, goal)
    over = [u for u in graph if h[u] > hstar[u]]
    jumps = [(u, v) for u in graph for v, w in graph[u] if h[u] > w + h[v]]
    return over, jumps

def astar_graph_trace(graph, h, start, goal, check=False):
    """小加權圖上的 A*,每取出一個點印一行。f 相同時先取 h 小的。
    check=True:每次取出都檢查 f ≤ 真正的最短代價(可採納時一定成立)。"""
    best = dist_to_goal(graph, goal)[start] if check else None
    g, parent = {start: 0}, {start: None}
    open_f = {start: h[start]}              # 還在 open 裡的點 → f
    closed = set()
    step = 0
    while open_f:
        u = min(open_f, key=lambda n: (open_f[n], h[n]))
        f = open_f.pop(u)
        step += 1
        if check:
            assert f <= best, f'第 {step} 步取出 {u},f={f} 超過最短代價 {best}'
        if u == goal:
            print(f'{step}. 取出 {u}(f={f}):到達目標')
            path = []
            while u is not None:
                path.append(u)
                u = parent[u]
            return g[goal], path[::-1]
        closed.add(u)
        events = []
        for v, w in graph[u]:
            ng = g[u] + w
            if ng >= g.get(v, INF):
                continue                      # 沒有變短:不動
            g[v], parent[v] = ng, u
            if v in closed:                   # 展開過的點找到更短的路
                closed.remove(v)
                events.append(f'reopen {v}(g={ng})')
            elif v in open_f:
                events.append(f'decrease_key {v}(g={ng})')
            else:
                events.append(f'push {v}(g={ng})')
            open_f[v] = ng + h[v]
        print(f'{step}. 取出 {u}(f={f}):', ';'.join(events) or '—',
              '| open:', ' '.join(f'{n}={open_f[n]}' for n in open_f))
    return None, None

選做:線性衝突。同一列裡已經在目標列的幾塊,如果左右順序和目標相反,至少要有幾塊先離開這一列再回來,每塊多 2 步。「至少要離開幾塊」＝那幾塊的個數減掉它們目標欄的最長遞增子序列長度({{ch:32-dynamic-programming}});每一行也一樣做。把這些加到 Manhattan 上仍然不會高估,Boss 那種盤面展開的節點通常少一半以上。只用 Manhattan 也過得了。

IDA*(迭代加深 A*)

對記憶體非常敏感的場景(如 15-puzzle 有 $10^{13}$ 個狀態),A* 的優先佇列本身就爆記憶體。 IDA*(Iterative Deepening A*)用 DFS + 閾值控制取代優先佇列: 從閾值 $f_0 = h(\text{start})$ 開始,做 DLS 只展開 $f(n) \leq$ 閾值的節點; 若找不到解,把閾值設為上次超出的最小 $f$ 值,重複。 記憶體只需 $O(d)$,時間與 A* 相當。

局部搜尋:爬山、模擬退火與基因演算法

前面的搜尋演算法都在追求「找到最優解的完整路徑」。 但對很多問題,我們只需要找「一個夠好的狀態」,不在乎怎麼到達—— 例如 8-Queens(放 8 個皇后讓彼此不互攻)或神經網路的超參數調整。 這類問題適合局部搜尋(local search)。

爬山演算法(Hill Climbing)

從當前狀態出發,每次移動到鄰居中目標函數值最高的那個,直到沒有更高的鄰居為止。 問題:容易卡在局部最大值(local maximum)、平台(plateau)或山脊(ridge)。 

def hill_climbing(init_state, neighbors, objective):
    """爬山演算法:傳回找到的(局部)最大值狀態"""
    current = init_state
    while True:
        nbs = neighbors(current)
        if not nbs:
            return current
        best_nb = max(nbs, key=objective)
        if objective(best_nb) <= objective(current):
            return current          # 無更高鄰居,停在局部最大值
        current = best_nb

模擬退火(Simulated Annealing)

靈感來自冶金退火:金屬降溫時允許少量「往壞方向走」,以跳脫局部最優。 以機率 $e^{\Delta E / T}$ 接受比當前更差的鄰居($\Delta E < 0$), 溫度 $T$ 隨時間降低——初期大膽探索,後期逐漸收斂。 在{{ch:109-optimization}}最佳化中有更完整的理論分析。

基因演算法(Genetic Algorithm)

維護一個狀態族群(population),用選擇(selection)、交叉(crossover)與突變(mutation) 模擬演化:好的個體更容易留下後代,基因池逐漸向高適應度方向漂移。 特別適合離散組合最佳化問題,如旅行推銷員問題的近似解。

何時用局部搜尋?

當狀態空間太大、無法維護完整路徑,或問題有良好的鄰域結構時使用局部搜尋。 代價:無法保證全域最優,也無法確認「無解」(只能說「沒找到」)。

對抗搜尋:minimax 與 alpha-beta 剪枝

迄今為止,我們假設環境是確定且合作的——只有我們一個玩家在搜尋。 棋類等零和賽局(zero-sum game)裡有個對手,他的目標與我們完全相反。 我們在{{ch:51-game-theory}}分析了賽局理論的均衡概念; 這裡我們聚焦在如何有效搜尋對抗賽局樹。

Minimax

把賽局展開成一棵賽局樹(game tree): 交替出現 MAX 層(我方最大化分數)與 MIN 層(對手最小化我的分數)。 minimax遞迴地從葉節點往上傳遞: MAX 層取子節點最大值,MIN 層取子節點最小值——假設雙方都以最優策略行動。

問題:完整賽局樹深度可觀。西洋棋平均分支因子 $b \approx 35$、深度 $d \approx 80$, 完整展開需要 $35^{80} \approx 10^{123}$ 個節點——宇宙中原子的數量都不夠。 實務上設定最大深度並用評估函數(evaluation function)估計非終局狀態的分數。

Alpha-Beta 剪枝

alpha-beta 剪枝(alpha-beta pruning)是 minimax 的優化,不影響結果,只減少計算量。 關鍵思想:如果我在 MAX 節點已知我能拿到至少 $\alpha$ 分,而正在評估的 MIN 子節點目前上界已降到 $\beta \leq \alpha$, 那個 MIN 節點的其餘子樹就可以剪掉——MAX 絕對不會選這個已經「跑輸」的分支。

維護兩個值: $\alpha$(MAX 目前確保的最低分,沿路傳下去)與 $\beta$(MIN 目前確保的最高分,沿路傳下去)。 條件 $\alpha \geq \beta$ 時剪枝。

Alpha-beta 正確性的直覺:被剪掉的子樹即使評估了也不會改變根節點的選擇—— 因為沿該路徑的對手(MIN)已確保分數不高於 $\beta \leq \alpha$,MAX 不會選那個分支。

最優情況(最好的移動最先展開):節點數從 $O(b^d)$ 降為 $O(b^{d/2})$——相當於搜尋深度加倍! Deep Blue 就是靠 alpha-beta + 深度優化評估函數在 1997 年擊敗世界棋王的。 

def minimax(node, depth, alpha, beta, is_max,
            children_fn, eval_fn, terminal_fn):
    """
    Minimax + alpha-beta 剪枝
    alpha: MAX 已確保的最低分(下界,路徑中傳入)
    beta:  MIN 已確保的最高分(上界,路徑中傳入)
    """
    if depth == 0 or terminal_fn(node):
        return eval_fn(node), None

    best_move = None

    if is_max:
        value = float('-inf')
        for move, child in children_fn(node):
            child_val, _ = minimax(child, depth - 1, alpha, beta, False,
                                   children_fn, eval_fn, terminal_fn)
            if child_val > value:
                value, best_move = child_val, move
            alpha = max(alpha, value)
            if alpha >= beta:            # β 截斷:MIN 絕不選此路
                break
        return value, best_move
    else:
        value = float('inf')
        for move, child in children_fn(node):
            child_val, _ = minimax(child, depth - 1, alpha, beta, True,
                                   children_fn, eval_fn, terminal_fn)
            if child_val < value:
                value, best_move = child_val, move
            beta = min(beta, value)
            if alpha >= beta:            # α 截斷:MAX 絕不選此路
                break
        return value, best_move

約束滿足問題(CSP):讓電腦解數獨

你玩數獨的時候,其實是在解一個約束滿足問題(Constraint Satisfaction Problem, CSP): 81 個格子每格填 1–9(定義域),行、列、3×3 宮格各不重複(約束)。 CSP 的形式化三元組:$(X, D, C)$。

  • 變數(Variables) $X$:需要賦值的物件。數獨中是 81 個格子。
  • 定義域(Domains) $D$:每個變數的合法值集合。$D_i \subseteq \{1,\ldots,9\}$。
  • 約束(Constraints) $C$:指定哪些變數組合的哪些賦值是合法的。

回溯搜尋(Backtracking Search)

最基本的 CSP 求解:依序為變數賦值,每次只選一個值, 若違反約束就回溯到上一個變數換個值——本質是帶有一致性剪枝的 DFS。

兩個關鍵啟發式大幅加速回溯:

  • MRV(Minimum Remaining Values,最少剩餘值): 優先賦值「合法值最少的」變數——直覺上是最可能失敗的那個,越早失敗越省事。
  • 度啟發式(Degree Heuristic): 合法值數目相同時,選與最多未賦值變數相連的那個——影響最廣、剪枝能力最強。

前向檢查(Forward Checking)與弧一致性

前向檢查(Forward Checking):每次賦值後,立即從未賦值的鄰居定義域中刪去 不相容的值。若某個鄰居定義域變空,立即回溯——不等到真正賦值到那個變數才發現矛盾。

AC-3(Arc Consistency 3) 更徹底:維護一個弧的佇列 $\{(X_i, X_j)\}$, 對每條弧檢查「$X_i$ 的每個值在 $X_j$ 中是否有相容值」。 若 $D_i$ 有值被刪去,則把所有指向 $X_i$ 的弧重新加入佇列。 時間複雜度 $O(cd^3)$($c$ = 弧數,$d$ = 最大定義域大小)。 

def is_consistent(var, value, assignment, graph):
    """確認 var=value 不違反任何已賦值鄰居的差異約束"""
    for neighbor in graph.get(var, []):
        if neighbor in assignment and assignment[neighbor] == value:
            return False
    return True

def backtrack(assignment, variables, domains, graph):
    """
    CSP 回溯搜尋 + MRV
    graph: {var: [鄰居變數, ...]} ── 差異(all-different)約束圖
    """
    if len(assignment) == len(variables):
        return assignment                          # 所有變數賦值完成

    # MRV:選剩餘合法值最少的未賦值變數
    unassigned = [v for v in variables if v not in assignment]
    var = min(unassigned, key=lambda v: len(domains[v]))

    for value in list(domains[var]):
        if is_consistent(var, value, assignment, graph):
            assignment[var] = value
            result = backtrack(assignment, variables, domains, graph)
            if result is not None:
                return result
            del assignment[var]                    # 回溯

    return None

六個區域 A–F 塗三種顏色 R、G、B,相鄰的不能同色。每試一個值,前向檢查就把這個值從「還沒填的鄰居」的定義域刪掉; 如果有鄰居的定義域被刪光,這個值馬上放棄,不必往下走。下一個要填誰,用 MRV:目前剩下的值最少的變數;一樣少時取字母前面的。值照 R、G、B 的順序試。

下面的程式和本章的 backtrack 不一樣:定義域會隨著搜尋縮小,MRV 看的就是縮小後的定義域。每試一個值印一行,縮排就是樹的深度:

def fc_search(order, nbrs, domains, assign=None, depth=0):
    """回溯 + MRV(看「目前」的定義域)+ 前向檢查;每試一個值印一行。"""
    if assign is None:
        assign = {}
    if len(assign) == len(order):
        return dict(assign)
    free = [v for v in order if v not in assign]
    var = min(free, key=lambda v: len(domains[v]))   # 一樣少時取 order 前面的
    for val in domains[var]:
        new = dict(domains)
        new[var] = [val]
        wiped = None
        for n in nbrs[var]:
            if n not in assign and val in new[n]:
                new[n] = [x for x in new[n] if x != val]   # 前向檢查
                if not new[n]:
                    wiped = n
        rest = ' '.join(v + '{' + ''.join(new[v]) + '}' for v in free if v != var) or '全部填完'
        print('  ' * depth + f'{var}={val} → {rest}'
              + (f'  ✗ {wiped} 沒有值了' if wiped else ''))
        if wiped:
            continue                     # 不往下走,直接試下一個值
        assign[var] = val
        result = fc_search(order, nbrs, new, assign, depth + 1)
        if result:
            return result
        del assign[var]                  # 回溯
    return None

看起來對但其實錯。「前向檢查之後沒有定義域變空,這條路就還有解。」深度 3 試 C=G 之後,E{R}、F{R} 都還有值,前向檢查沒有喊停; 可是 E 和 F 相鄰,兩個都只能塗 R,這條路其實已經死了,要再往下一層(E=R 把 F 刪光)才發現。 前向檢查只看「剛填的變數」和它的鄰居,不看兩個還沒填的變數之間;要提早抓到這種情況,得用本節前面說的 AC-3 檢查每一條弧。

自動規劃:STRIPS 與 PDDL

AI 不只要「找到答案」,還要「規劃行動序列達成目標」。 自動規劃(automated planning)的問題是: 給定初始狀態、目標條件與一套動作,找出一個動作序列讓初始狀態轉變為滿足目標的狀態。

這和搜尋問題很像——但規劃強調的是「動作的邏輯結構」而非圖的數值搜尋。 搜尋找的是一條路,規劃找的是一個有意義的行動腳本。

STRIPS 表示法

1971 年由 Fikes 與 Nilsson 提出的 STRIPS(STanford Research Institute Problem Solver) 是最經典的規劃語言。 它用命題邏輯表示世界狀態,每個動作(operator)有三個部分:

  • 前提條件(Preconditions):動作可以執行的必要條件(命題集合)。
  • 加入清單(Add-list):動作執行後新變成真的命題。
  • 刪除清單(Delete-list):動作執行後變成假的命題。
# STRIPS 積木世界(Blocks World)示例
# 目標:把積木 A 疊在 B 上,B 疊在 C 上(On(A,B), On(B,C))

def make_op(name, pre, add, delete):
    return {'name': name,
            'pre': set(pre), 'add': set(add), 'del': set(delete)}

ACTIONS = [
    make_op('Stack(A,B)',
        pre=['Clear(B)', 'Holding(A)'],
        add=['On(A,B)', 'ArmEmpty', 'Clear(A)'],
        delete=['Clear(B)', 'Holding(A)']),

    make_op('Unstack(A,B)',
        pre=['On(A,B)', 'Clear(A)', 'ArmEmpty'],
        add=['Holding(A)', 'Clear(B)'],
        delete=['On(A,B)', 'Clear(A)', 'ArmEmpty']),

    make_op('Pickup(A)',
        pre=['OnTable(A)', 'Clear(A)', 'ArmEmpty'],
        add=['Holding(A)'],
        delete=['OnTable(A)', 'ArmEmpty']),

    make_op('Putdown(A)',
        pre=['Holding(A)'],
        add=['OnTable(A)', 'ArmEmpty'],
        delete=['Holding(A)']),
]

def apply_action(state, action):
    """若前提條件成立,傳回新狀態;否則傳回 None"""
    if action['pre'].issubset(state):
        return (state - action['del']) | action['add']
    return None

PDDL 與現代規劃器

STRIPS 的繼承者是 PDDL(Planning Domain Definition Language)—— 一個標準化的規劃語言,用於 AI 規劃競賽(International Planning Competition, IPC)。 現代規劃器如 Fast Downward、Lama 以啟發式搜尋(連回 A*)結合領域無關啟發式 (如 $h^{\text{add}}$、$h^{\text{FF}}$)解複雜規劃問題。

規劃與搜尋的關係:規劃問題可以轉化為圖搜尋——狀態是命題集合、動作是邊、目標是目標節點。 差別在於:狀態空間的「結構」(命題的組合)讓我們能推導出更聰明的領域無關啟發式。

NASA JPL 的火星探測車、工業機器人的任務規劃、遊戲 AI 的高層策略,都有 PDDL 規劃器的身影。 近年來,LLM + 規劃器的混合架構也在 AI agent 中興起(見第 {{num:110-classical-ai}}–{{num:112-reinforcement-learning}} 章的 Agent 部)。

知識表示與推論:教電腦「懂」事情

搜尋與規劃都假設我們已經有了精確的狀態描述。但世界的知識如何表示、如何推論？ 這是知識表示與推論(Knowledge Representation and Reasoning, KRR)的核心問題。

命題邏輯與一階邏輯

命題邏輯(propositional logic)用原子命題(True/False)與連接詞($\land, \lor, \neg, \Rightarrow$) 表達知識。你在{{ch:13-discrete-math}}學過它的基礎。 問題:無法表達「對所有 X, 如果 X 是人則 X 會死」這樣的通用性陳述——命題邏輯無法量化。

一階邏輯(First-Order Logic, FOL)加入了變數、函數與量詞($\forall, \exists$):

  • 所有人都會死:$\forall x\; \text{Human}(x) \Rightarrow \text{Mortal}(x)$
  • 蘇格拉底是人:$\text{Human}(\text{Socrates})$
  • 因此蘇格拉底會死:推論得 $\text{Mortal}(\text{Socrates})$

FOL 足以表達複雜的世界知識,推論引擎可以從已知事實自動推出新事實。 這連到了你在{{ch:45-prolog}}學過的 Prolog—— 它就是一個 Horn clause 子集的 FOL 推論引擎。 

% Prolog:表達家族關係的知識庫
% 事實(facts)
parent(tom, bob).
parent(bob, ann).

% 規則(rules)──── 等同 FOL 的 Horn clause
grandparent(X, Z) :- parent(X, Y), parent(Y, Z).
ancestor(X, Z)    :- parent(X, Z).
ancestor(X, Z)    :- parent(X, Y), ancestor(Y, Z).

% 查詢:tom 是 ann 的祖父嗎?
% ?- grandparent(tom, ann).
% true.

Prolog 的推論機制是歸結反駁(resolution refutation)加上統一(unification): 把查詢否定、加入知識庫,若能推出矛盾就證明原查詢為真。 詳見{{ch:45-prolog}}的深入討論。

本體論與語意網(一瞥)

大規模的 FOL 知識庫叫本體(ontology)。 Cyc 計畫試圖手工編碼幾百萬條常識知識; 語意網(Semantic Web)的 OWL 語言讓不同資料庫間共享結構化知識。 這些系統都面臨同一個問題:知識量的增長遠比常識推論的品質增長快—— 而且真實世界充滿了模糊性、例外、隱喻,讓純邏輯推論捉襟見肘。

符號 AI 的侷限,以及統計式機器學習的崛起

1980 年代末,AI 遭遇了「AI 寒冬(AI Winter)」——不是因為研究者不聰明, 而是因為符號 AI 碰到了一面叫做知識瓶頸(knowledge bottleneck)的牆。

兩個最根本的問題:

  1. 脆性(brittleness):規則系統在設計範圍內能表現出色, 但稍微偏離設計假設就徹底崩潰。現實的語言、影像、聲音充滿無窮無盡的例外。 你能寫規則區分「貓」與「狗」嗎?要多少條規則才夠?
  2. 知識獲取瓶頸(knowledge acquisition bottleneck): 把現實世界的知識手動編碼成規則,既昂貴又無法規模化。 醫療專家系統需要領域專家花幾年時間編碼——知識一變,全部重來。
📜
符號 AI vs 聯結主義的百年爭論

符號主義與聯結主義(connectionism)(神經網路)的爭論幾乎貫穿整個 AI 史。 1969 年 Minsky 與 Papert 的《感知機》一書幾乎扼殺了神經網路。 1980 年代反向傳播的復興讓聯結主義捲土重來。 2012 年 AlexNet 在 ImageNet 競賽上碾壓所有傳統方法,聯結主義才真正佔據主流—— 但這次的勝利不是來自新理論,而是來自資料量與GPU 算力的爆炸性增長。

統計式機器學習(你在{{ch:38-machine-learning}}學過的那套)的核心轉向: 不再手工編碼知識,而是從大量資料中自動學習特徵與規律。 這讓 AI 在語音辨識、影像分類、自然語言處理上實現了質的飛躍。

但符號 AI 並沒有完全消失。它在以下場景仍不可取代:

  • 可解釋性要求高的場景:醫療診斷決策樹、法律推論系統。
  • 需要精確搜尋的場景:SAT 求解器、自動定理證明。
  • 有限狀態的最優規劃:工廠排程、航空公司機組員派遣。
  • 與 ML 混合:AlphaGo 結合了深度學習評估函數與 Monte Carlo 樹搜尋(MCTS);現代 AI agent 框架常把 LLM 與符號規劃器結合。
🔑
符號 AI 與統計 AI 的互補性

符號 AI 擅長精確推論、可解釋性、小資料場景;統計 AI 擅長感知、泛化、大資料場景。 未來的強 AI 幾乎可以確定是兩者的融合——也是當今「神經符號 AI(neurosymbolic AI)」研究的核心主題。

步驟 2:評估左 MIN 節點(α=-∞, β=+∞ 傳入):

  • 見葉 3:β = min(+∞, 3) = 3。α(-∞) < β(3),不剪枝。
  • 見葉 5:β = min(3, 5) = 3。左 MIN 傳回 3。

MAX 更新 α = max(-∞, 3) = 3。

步驟 3:評估右 MIN 節點(α=3, β=+∞ 傳入):

  • 見葉 1:β = min(+∞, 1) = 1。現在 α(3) ≥ β(1) → 剪枝! 葉 9 不評估。

右 MIN 傳回 1(或說 ≤ 1)。MAX 取 max(3, 1) = 3。

結論:根節點值 = 3;葉節點 9 不需要評估。這不影響結果:即使 9 被評估,右 MIN = min(1,9) = 1 < 3,MAX 仍選左邊。

一棵搜尋樹每個節點有 $b = 10$ 個子節點,目標在深度 $d = 5$。(1)BFS 最多產生幾個節點(深度 0 到 5 全部)? (2)迭代加深搜尋(IDS)依序做深度限制 0、1、2、3、4、5 的 DFS,每一輪都從頭開始,一共產生幾個節點? (3)重做這麼多次,IDS 比 BFS 多花了幾 %?為什麼「重做」的代價這麼小?

看解答

(2)深度 $k$ 的節點在限制 $k, k+1, \ldots, 5$ 這幾輪都會被產生,也就是 $6 - k$ 次: $6 \cdot 1 + 5 \cdot 10 + 4 \cdot 100 + 3 \cdot 1000 + 2 \cdot 10^4 + 1 \cdot 10^5 = 123{,}456$。

from collections import deque

def blocks_ops(blocks):
    """每一塊積木的四種動作。拿起來就不算 Clear,放下去才加回 Clear。"""
    ops = []
    for x in blocks:
        ops.append(make_op(f'Pickup({x})', [f'OnTable({x})', f'Clear({x})', 'ArmEmpty'],
                           [f'Holding({x})'], [f'OnTable({x})', f'Clear({x})', 'ArmEmpty']))
        ops.append(make_op(f'Putdown({x})', [f'Holding({x})'],
                           [f'OnTable({x})', f'Clear({x})', 'ArmEmpty'], [f'Holding({x})']))
        for y in blocks:
            if x != y:
                ops.append(make_op(f'Stack({x},{y})', [f'Holding({x})', f'Clear({y})'],
                                   [f'On({x},{y})', f'Clear({x})', 'ArmEmpty'],
                                   [f'Holding({x})', f'Clear({y})']))
                ops.append(make_op(f'Unstack({x},{y})', [f'On({x},{y})', f'Clear({x})', 'ArmEmpty'],
                                   [f'Holding({x})', f'Clear({y})'],
                                   [f'On({x},{y})', f'Clear({x})', 'ArmEmpty']))
    return ops

def plan_bfs(start, goal, ops):
    """前進搜尋:BFS 找動作數最少的計畫。"""
    start = frozenset(start)
    parent = {start: None}
    queue = deque([start])
    while queue:
        s = queue.popleft()
        if goal <= s:
            plan = []
            while parent[s] is not None:
                s, name = parent[s]
                plan.append(name)
            return plan[::-1]
        for op in ops:
            t = apply_action(set(s), op)
            if t is not None and frozenset(t) not in parent:
                parent[frozenset(t)] = (s, op['name'])
                queue.append(frozenset(t))
    return None

ops = blocks_ops('ABC')
print(plan_bfs(s0, goal, ops))
s2 = {'On(A,B)', 'OnTable(B)', 'OnTable(C)', 'Clear(A)', 'Clear(C)', 'ArmEmpty'}
print(plan_bfs(s2, goal, ops))

['Pickup(B)', 'Stack(B,C)', 'Pickup(A)', 'Stack(A,B)']
['Unstack(A,B)', 'Putdown(A)', 'Pickup(B)', 'Stack(B,C)', 'Pickup(A)', 'Stack(A,B)']

從 s0 最少 4 個動作,而且要先疊 B 再疊 A。如果先完成了 On(A,B) 這個子目標,還要 6 個動作,而且第一步就是把 A 拆下來: 子目標之間會互相干擾,「一個一個達成」不一定對。這就是規劃比單純搜尋難的地方。

我們從 1956 年達特茅斯會議的樂觀賭注出發,走過了符號 AI 的完整工具箱:

  • 狀態空間搜尋是一切的基礎:把問題轉化為「在狀態圖中找路」。 無資訊搜尋(BFS/DFS/UCS)保證完備性但代價昂貴; 有資訊搜尋(A*)靠啟發式大幅剪枝,在可採納+一致的條件下保證最優性。 這連回了你在{{ch:30-graph-algorithms}}學過的 Dijkstra/A*, 現在你知道它在 AI 框架中的完整意義。
  • 對抗搜尋把單人搜尋擴展到兩人零和賽局: minimax 假設雙方最優行動;alpha-beta 剪枝在不影響正確性的前提下大幅縮小搜尋空間(最優情況深度加倍)。 這是{{ch:51-game-theory}}賽局理論在算法層面的實現。
  • CSP 把問題表達為變數+定義域+約束,用回溯+MRV+前向檢查+弧一致性(AC-3)高效求解—— 適合所有「找合法賦值」的問題。
  • STRIPS/PDDL 規劃把「如何達成目標」形式化為邏輯動作的搜尋, 讓 AI 能自動生成行動序列。
  • 知識表示從命題邏輯到一階邏輯,讓 AI 能表達並推論複雜知識—— 連回{{ch:45-prolog}}的 Prolog 推論引擎。
  • 符號 AI 的侷限——脆性、知識瓶頸——解釋了為什麼{{ch:38-machine-learning}}的統計 ML 最終佔據主流; 同時也說明了兩者在現代系統中的互補關係。

符號 AI 給了我們一套精確的語言:狀態、動作、目標、約束、推論。 這套語言在今天 AI agent 的「高層規劃」模組裡依然活著—— 只是評估函數、啟發式與感知層換成了深度神經網路。 GOFAI 不是 AI 的失敗,而是 AI 的地基。
