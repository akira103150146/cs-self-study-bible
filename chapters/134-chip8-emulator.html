為什麼要自己寫一台模擬器

在第 21 章,你看過 Hack CPU 怎麼一拍一拍地執行指令, 也可以在那一章的動手實驗室(選修)用 Python 寫一個 Hack 模擬器。那台機器是為了教學設計的:沒有計時器、沒有聲音、螢幕只是一段記憶體。

這一章換一台「真的有人拿來寫遊戲」的機器:CHIP-8。它其實不是一顆晶片,而是一種直譯式語言(interpreted language), 1970 年代由 Joseph Weisbecker 為 RCA 的 COSMAC VIP 電腦設計。VIP 上跑一支 512 位元組的直譯器,直譯器讀 CHIP-8 的指令,一條一條執行。 今天的人寫「CHIP-8 模擬器」,其實是在重寫那支直譯器。

CHIP-8 很適合當第一台模擬器:指令只有 35 條、每條固定 2 個位元組、畫面只有黑白兩色。 但它已經有一台真電腦該有的麻煩事:旗標暫存器、呼叫堆疊、以 60 Hz 倒數的計時器、要等按鍵的指令, 還有「同一條指令,不同的直譯器做法不一樣」這種歷史包袱。把這些都處理好,你就有了寫 Game Boy、GBA 模擬器的基本功。

為什麼要學

這一章是任務線「模擬器三部曲」(emu)的第二站。第一站在第 51 章:任務「位元與記憶體匯流排」做出 emu/bits.h 與 emu/bus.c。 這一章的兩個任務「CHIP-8 CPU」與「CHIP-8 畫面與按鍵」都建在那個匯流排上,合起來就是 Boss 戰「CHIP-8 隱藏 ROM」與「CHIP-8 畫面重播」。 之後的 Game Boy(SM83 CPU、PPU、計時器與中斷)與 GBA(ARM7TDMI)用的是同一套主迴圈和同一個匯流排,只是指令多了很多。 取指、解碼、執行的寫法,也和 RISC-V 指令集模擬器、第 23 章的虛擬機是同一件事。

本章的範例程式都用 C 寫(C17 標準;只有把十六進位文字轉成 ROM 的小工具 hex2rom.py 是 Python),每一段 C 都可以這樣編譯,零警告:

gcc -std=c17 -Wall -Wextra -O2 chip8demo.c -o chip8demo

本章用到的測試 ROM 全部是我們自己寫的,一個位元組一個位元組地列在書裡。網路上很多現成的 CHIP-8 遊戲與測試 ROM 授權不明,本書不收錄,也不拿來判題。

CHIP-8 這台機器

先看整台機器有哪些零件。圖 52-1 左邊是記憶體,中間是 CPU 的狀態(也就是直譯器要記住的東西),右邊是畫面和鍵盤。

核心觀念

模擬器就是一個狀態加一個函式:狀態是上面這張表(記憶體、暫存器、計時器、畫面、按鍵), 函式是「執行一條指令,把狀態變成下一個狀態」。寫模擬器的工作,就是把每一條指令對狀態做了什麼,一條一條寫清楚。

記憶體地圖:為什麼程式從 0x200 開始

COSMAC VIP 的記憶體只有 2 KiB 到 4 KiB,直譯器自己就佔掉前面 512 位元組。所以 CHIP-8 程式一律從 0x200(十進位 512)開始放, 也不去碰 0x200 以下的位址。原機在記憶體的最上面也留了地方:EA0–EFF 放呼叫堆疊和直譯器的變數,F00–FFF 是畫面的內容。

模擬器不需要真的把直譯器放進記憶體,堆疊和畫面也另外存。於是 0x000–0x1FF 空了出來,大家習慣把內建字型放在這裡。 本書和地下城的 Lab 都把字型放在 0x050–0x09F。

內建字型:16 個 4×5 的數字

CHIP-8 內建十六進位數字 0–F 的字型,每個字 4 格寬、5 格高,一列用一個位元組(只用高 4 位元)。例如「0」: 

F0  1111 0000   ####
90  1001 0000   #  #
90  1001 0000   #  #
90  1001 0000   #  #
F0  1111 0000   ####

16 個字依序排好,每個字 5 個位元組,共 80 個位元組。字 d 的位址就是 0x050 + 5 × d,FX29 指令會幫你算。

指令長什麼樣子:四個 nibble

CHIP-8 每一條指令都是 2 個位元組,也就是 16 位元,寫成 4 個十六進位數字。一個十六進位數字是 4 個位元,叫做一個 nibble(半個位元組)。 解碼的訣竅只有一句:先看第一個 nibble 決定是哪一類,剩下的 nibble 是參數。參數只有五種切法(圖 52-2)。

圖 52-2 的文字版:opcode 由高到低是四個 nibble。第一個(位元 15–12)是種類;第二個叫 X、第三個叫 Y,都是暫存器編號(VX、VY); 最後一個叫 N。最後兩個 nibble 合起來叫 NN(一個 8 位元常數),最後三個合起來叫 NNN(一個 12 位元位址)。 D014 就是種類 D、X=0、Y=1、N=4:「在 (V0, V1) 畫一個 4 列高的 sprite」。

用 C 取出這些欄位,只要移位和遮罩(第 51 章的位元操作): op >> 12 是種類,(op >> 8) & 0xF 是 X,(op >> 4) & 0xF 是 Y, op & 0xF 是 N,op & 0xFF 是 NN,op & 0xFFF 是 NNN。

手算:把 opcode 拆開解碼

拿到一個 opcode,先寫出四個 nibble,看第一個 nibble 決定種類;種類是 0、8、E、F 時,再看後面的 nibble;最後把 X、Y、N、NN、NNN 代進去。每一列是一個 opcode。

opcode四個 nibble種類怎麼決定參數指令
6A1C6 | A | 1 | C6 → LD VX, NNX=A,NN=1CVA = 0x1C(28)
81248 | 1 | 2 | 48 → 再看 N=4 → ADD VX, VYX=1,Y=2V1 = V1 + V2,VF = 進位
83168 | 3 | 1 | 68 → 再看 N=6 → SHRX=3,Y=1VIP:V3 = V1 >> 1;現代:V3 = V3 >> 1
D014D | 0 | 1 | 4D → DRWX=0,Y=1,N=4在 (V0, V1) 畫 4 列
22082 | 2 | 0 | 82 → CALLNNN=208呼叫 0x208(X=2 在這裡沒有意義)
F155F | 1 | 5 | 5F → 再看 NN=55 → LD [I], VXX=1[I] = V0,[I+1] = V1
300A3 | 0 | 0 | A3 → SE VX, NNX=0,NN=0AV0 == 10 就跳過下一條
51215 | 1 | 2 | 15 → 最後一個 nibble 必須是 0N=1不合法的 opcode

下面這支小程式 disasm.c 就是解碼表的 C 版:它把 opcode 拆成 nibble,再用兩層 switch 查出是哪一條。拿它來驗算你的手算。

// disasm.c:把 CHIP-8 opcode 拆成 nibble,再查出是哪一條指令
// 編譯:gcc -std=c17 -Wall -Wextra disasm.c -o disasm
// 用法:./disasm D014 8326 F155 …
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>

static const char *name(uint16_t op) {
    unsigned n = op & 0xF, nn = op & 0xFF;
    switch (op >> 12) {                       // 先看最高的 nibble
    case 0x0: return op == 0x00E0 ? "CLS     清畫面"
                   : op == 0x00EE ? "RET     從副程式返回"
                   : "SYS NNN 呼叫機器碼(現代不做事)";
    case 0x1: return "JP NNN  跳到 NNN";
    case 0x2: return "CALL NNN 呼叫 NNN";
    case 0x3: return "SE VX,NN  VX == NN 就跳過下一條";
    case 0x4: return "SNE VX,NN VX != NN 就跳過下一條";
    case 0x5: return n == 0 ? "SE VX,VY  VX == VY 就跳過下一條" : NULL;
    case 0x6: return "LD VX,NN  VX = NN";
    case 0x7: return "ADD VX,NN VX = VX + NN(不改 VF)";
    case 0x8:                                  // 8 開頭:再看最低的 nibble
        switch (n) {
        case 0x0: return "LD VX,VY  VX = VY";
        case 0x1: return "OR VX,VY  VX = VX | VY";
        case 0x2: return "AND VX,VY VX = VX & VY";
        case 0x3: return "XOR VX,VY VX = VX ^ VY";
        case 0x4: return "ADD VX,VY VX = VX + VY,VF = 進位";
        case 0x5: return "SUB VX,VY VX = VX - VY,VF = 沒有借位";
        case 0x6: return "SHR VX,VY 右移 1 位,VF = 移出去的位";
        case 0x7: return "SUBN VX,VY VX = VY - VX,VF = 沒有借位";
        case 0xE: return "SHL VX,VY 左移 1 位,VF = 移出去的位";
        default:  return NULL;
        }
    case 0x9: return n == 0 ? "SNE VX,VY VX != VY 就跳過下一條" : NULL;
    case 0xA: return "LD I,NNN  I = NNN";
    case 0xB: return "JP V0,NNN 跳到 NNN + V0";
    case 0xC: return "RND VX,NN VX = 亂數 & NN";
    case 0xD: return "DRW VX,VY,N 在 (VX, VY) 畫 N 列";
    case 0xE: return nn == 0x9E ? "SKP VX    鍵 VX 按著就跳過下一條"
                   : nn == 0xA1 ? "SKNP VX   鍵 VX 沒按就跳過下一條" : NULL;
    case 0xF:                                  // F 開頭:看最低的兩個 nibble
        switch (nn) {
        case 0x07: return "LD VX,DT  VX = DT";
        case 0x0A: return "LD VX,K   等一個按鍵,VX = 鍵";
        case 0x15: return "LD DT,VX  DT = VX";
        case 0x18: return "LD ST,VX  ST = VX";
        case 0x1E: return "ADD I,VX  I = I + VX";
        case 0x29: return "LD F,VX   I = 字型「VX」的位址";
        case 0x33: return "LD B,VX   VX 的百、十、個位寫進 [I] [I+1] [I+2]";
        case 0x55: return "LD [I],VX V0..VX 寫進 [I]..[I+X]";
        case 0x65: return "LD VX,[I] [I]..[I+X] 讀進 V0..VX";
        default:   return NULL;
        }
    }
    return NULL;
}

int main(int argc, char **argv) {
    for (int k = 1; k < argc; k++) {
        uint16_t op = (uint16_t)strtoul(argv[k], NULL, 16);
        const char *s = name(op);
        printf("%04X  [%X|%X|%X|%X]  X=%X Y=%X N=%X NN=%02X NNN=%03X  %s\n",
               op, op >> 12, (op >> 8) & 0xF, (op >> 4) & 0xF, op & 0xF,
               (op >> 8) & 0xF, (op >> 4) & 0xF, op & 0xF, op & 0xFF, op & 0xFFF,
               s ? s : "(不認得的 opcode)");
    }
    return 0;
}

取指、解碼、執行:模擬器的主迴圈

和第 21 章的 Hack CPU 一樣,CHIP-8 也是一直重複三件事。差別是 Hack 每拍做一條指令,CHIP-8 的直譯器另外還要照顧計時器和畫面。 模擬器的骨架長這樣: 

每一幀(1/60 秒):
    重複 ipf 次:                       ← ipf = instructions per frame,每幀幾條指令
        取指:op = mem[PC] << 8 | mem[PC + 1]     (大端:高位元組在前)
              PC = PC + 2                          (先加,跳躍和跳過才會對)
        解碼:看 op 的第一個 nibble,必要時再看後面的
        執行:改暫存器、記憶體、堆疊或畫面
    DT 大於 0 就減 1;ST 大於 0 就減 1
    把畫面畫到螢幕上(有變的話)

幾個容易寫錯的地方:

  • PC 先加 2,再執行。這樣 2NNN 推進堆疊的就是「下一條」的位址,3XNN 的「跳過」只要再加 2。
  • 大端。記憶體 [200]=6A、[201]=1C,opcode 是 6A1C,不是 1C6A。
  • 位址只有 12 位元。PC 和 I+k 超過 0xFFF 要繞回 0x000(& 0xFFF),不能讀到陣列外面。
  • 計時器一幀減一次,不是一條指令減一次(後面的手算 52.4 會算給你看)。
🔑
核心觀念:每一步之後都要成立的不變式

不管執行了哪一條指令,下面這幾件事都要成立:PC ≤ 0xFFF;堆疊裡的返回位址個數 SP 在 0 到 16 之間;畫面每一格只有 0 或 1; 計時器只在一幀結束時改變(或被 FX15、FX18 設定)。本章的範例模擬器用 assert 檢查堆疊不會溢出或變成負的; 地下城的 Lab 要求更嚴:遇到這些情況要回傳錯誤碼,而且機器狀態一點都不能改,讓你事後看得到「是哪一條指令出事」。

ℹ️
和 Hack 模擬器比一比

如果你做過第 21 章的選修任務「Hack 模擬器」,主迴圈可以照搬:一樣是「讀 PC 指的指令 → 拆欄位 → 照種類分派」。 不同的是 CHIP-8 的指令用 switch 分派(Hack 用 comp、dest、jump 三張表),而且多了「一幀」這一層外迴圈。

算術與旗標 VF

種類 8 的九條指令是 CHIP-8 的 ALU。運算本身很簡單,難的是 VF:VF 是一個普通的暫存器(程式可以讀寫它), 同時也是旗標。8XY4 寫進位、8XY5 和 8XY7 寫「沒有借位」、8XY6 和 8XYE 寫移出去的那一位元。

  • 8XY4:VX = (VX + VY) 的低 8 位元;和超過 255 時 VF = 1,否則 0。
  • 8XY5:VX = (VX − VY) 的低 8 位元;VX ≥ VY(沒有借位)時 VF = 1,否則 0。
  • 8XY7:VX = (VY − VX) 的低 8 位元;VY ≥ VX 時 VF = 1。
  • 7XNN 不改 VF,就算溢位也一樣。這是新手最常寫錯的一條。

X 或 Y 剛好是 F 的時候,問題就來了。例如 81F4:V1 = V1 + VF。如果你先寫旗標再算結果,算結果時用到的 VF 已經被改掉了。 flags.c 把兩種寫法並排跑: 

// flags.c:8XY4 的 VF,先寫還是後寫?
// 編譯:gcc -std=c17 -Wall -Wextra flags.c -o flags
#include <stdint.h>
#include <stdio.h>

static void add_flag_first(uint8_t *V, unsigned x, unsigned y) {
    V[0xF] = (V[x] + V[y]) > 0xFF;       // 先寫旗標……
    V[x] = (uint8_t)(V[x] + V[y]);       // ……再算結果:VF 可能已經被改掉了
}

static void add_flag_last(uint8_t *V, unsigned x, unsigned y) {
    unsigned sum = V[x] + V[y];          // 先用舊值算好
    V[x] = (uint8_t)sum;
    V[0xF] = sum > 0xFF;                 // 最後才寫旗標
}

static void demo(const char *what, unsigned x, unsigned y, uint8_t vx, uint8_t vy) {
    uint8_t a[16] = {0}, b[16] = {0};
    a[x] = b[x] = vx;
    a[y] = b[y] = vy;
    add_flag_first(a, x, y);
    add_flag_last(b, x, y);
    printf("%s\n", what);
    printf("  先寫 VF:V%X=%02X VF=%02X\n", x, a[x], a[0xF]);
    printf("  後寫 VF:V%X=%02X VF=%02X\n", x, b[x], b[0xF]);
}

int main(void) {
    demo("81F4(V1=F0, VF=20):", 0x1, 0xF, 0xF0, 0x20);
    demo("8F14(VF=F0, V1=20):", 0xF, 0x1, 0xF0, 0x20);   // X 是 F:印出來的 VF 就是 VX
    demo("8124(V1=F0, V2=20):", 0x1, 0x2, 0xF0, 0x20);
    return 0;
}

⚠️
看起來對但其實錯:「8XY5 在 VX 大於 VY 時 VF 才是 1」

有些文件把 8XY5 的旗標寫成「VX > VY 時 VF = 1」。用 VX = 7、VY = 3 或 VX = 3、VY = 7 去試,兩種寫法的答案都一樣,看起來沒問題。 可是 VX = VY = 5 時:5 − 5 = 0,沒有借位,VF 應該是 1;用「>」寫的模擬器給 0。 VF 的意思是「沒有借位」,所以條件是 VX ≥ VY。試過的例子都對,不代表規則對;邊界(相等)一定要單獨測。

跳躍、跳過與副程式

CHIP-8 沒有「if」,只有「跳過下一條」:3XNN、4XNN、5XY0、9XY0 條件成立時 PC 再加 2。配上 1NNN(跳躍),就能寫出 if 和迴圈:

300A    V0 == 10 就跳過下一條
1202    (V0 還不是 10)跳回迴圈開頭
...     (V0 是 10)從這裡繼續

副程式用 2NNN 呼叫、00EE 返回。2NNN 執行時 PC 已經加過 2,所以推進堆疊的就是返回位址。 堆疊滿了(16 層)還要再呼叫,或堆疊是空的卻執行 00EE,都是程式的錯誤;模擬器要停下來回報,不能讀寫堆疊陣列外面的記憶體。

還有一個習慣:CHIP-8 沒有「停機」指令,程式結束時通常寫一個跳到自己的 1NNN(例如在 0x21C 寫 121C)。 本章的範例模擬器和地下城的判題驅動程式都把它當成「程式跑完了」。

計時器與「每幀幾條指令」

CHIP-8 有兩個 8 位元的計時器:DT(delay timer)和 ST(sound timer)。程式用 FX15、FX18 設定它們,用 FX07 讀 DT。 只要大於 0,它們就以每秒 60 次的速度減 1,減到 0 就停;ST 大於 0 的時候喇叭會響。遊戲用 DT 控制速度(「等 1/6 秒」就是設 DT=10 再一直讀到 0),用 ST 發出嗶聲。

那 CPU 跑多快?原機上每條指令花的時間不一樣(畫 sprite 最慢),沒有一個標準答案。模擬器通常這樣近似: 每一幀(1/60 秒)執行固定的 ipf 條指令,然後計時器各減 1。常見的設定是每幀十條左右(每秒幾百條); 有些遊戲要調快或調慢才好玩。地下城的 Boss 戰「CHIP-8 畫面重播」固定用每幀 30 條,這樣每個人的結果才能逐幀比對。

🔑
核心觀念

ipf 是規格的一部分。同一支 ROM、同一組按鍵,ipf 不同,結果就可能不同:讀 DT 的迴圈會多跑或少跑幾圈。 要讓兩台模擬器的結果可以比對,除了指令的規則,還要說好「一幀幾條指令、計時器在一幀的哪裡減」。

I=0x000  DT=0  ST=0  SP=0
(畫面全暗)
⚠️
看起來對但其實錯:「每執行一條指令,DT 就減 1」

把計時器放進「每條指令」的迴圈裡,寫起來最簡單,而且只要程式不看 DT,一切正常。可是上面的 timer.ch8 用 ipf = 10 跑, DT 會在第 1 幀內就從 5 減到 0,V2 只會是 2 左右,而不是 13;遊戲的速度也會跟著 ipf 一起變。計時器的單位是「幀」(1/60 秒),不是「指令」。

按鍵與 FX0A:等一個「放開」

CHIP-8 用三條指令讀鍵盤。EX9E、EXA1 只是「看一眼」:鍵 VX 現在有沒有按著,決定要不要跳過下一條。 FX0A 不一樣,它會停下來等,直到使用者按了一個鍵,才把鍵的編號放進 VX、往下走。

「停下來」在模擬器裡要小心寫:你不能在 FX0A 裡寫一個 while 迴圈等按鍵,因為等的時候主迴圈也停了,計時器不會倒數、畫面不會更新、按鍵事件也進不來。 正確的做法是:FX0A 這一步不把 PC 往下推,下一步又會取到同一條 FX0A,於是每一步都重新檢查一次;等的時候每一步照樣算一條指令,計時器也照常倒數。

還有一個細節:在 COSMAC VIP 上,FX0A 要等到鍵按下再放開才算數。地下城的 Lab 也照這個規則:FX0A 開始等之後,某個鍵由「按著」變成「放開」, 才把那個鍵交給 VX;按著不放不會繼續;FX0A 開始之前就按完放開的鍵不算。下面是一個例子(ipf = 10,DT 先設成 3): 

200: 6003   V0 = 3
202: F015   DT = 3
204: F30A   等一個按鍵,V3 = 那個鍵
206: F407   V4 = DT
208: 1208   停
幀這一幀開始前的按鍵事件這一幀裡發生的事幀尾的 PC幀尾 DT
1(沒有)6003、F015,然後 F30A 開始等;這一幀剩下的 7 條都是同一條 F30A2043 → 2
2按下 710 條都是 F30A:按下不算,要等放開2042 → 1
3按下 210 條都是 F30A2041 → 0
4放開 2F30A 看到 2 放開了:V3 = 2,PC 往下走;F407:V4 = DT = 0;1208 停住208(停住)
5放開 7程式已經停了,沒有影響208

結果 V3 = 2(先放開的那個鍵,不是先按下的 7)、V4 = 0,一共執行 10 + 10 + 10 + 3 = 33 條指令,其中 F30A 算了 8 + 10 + 10 + 1 = 29 次。 等按鍵的三幀裡,DT 照常從 3 倒數到 0。

本章的範例模擬器沒有鍵盤,遇到 EX9E、EXA1、FX0A 會停下來說「不支援」。把它們做出來是 Lab 的工作。

怪癖:同一個 opcode,兩種答案

CHIP-8 從來沒有一份正式的標準。1990 年前後,有人在 HP-48 計算機上重寫了直譯器(CHIP-48,後來擴充成 SUPER-CHIP), 有幾條指令的行為和 COSMAC VIP 原機不一樣;後來的人照著這些版本的文件寫模擬器,差異就一路傳下來。 這些差異叫做怪癖(quirk)。舊遊戲照 VIP 的行為寫,較新的遊戲照 CHIP-48/SUPER-CHIP 寫,同一台模擬器很難兩邊都跑對,所以好的模擬器把怪癖做成可以切換的設定。

指令COSMAC VIP(地下城 Lab 的預設)後來的做法(Lab 的 MODERN 設定)Lab 的旗標
8XY6、8XYE 移位先把 VY 放進 VX 再移:VX = VY >> 1、VX = VY << 1;VF = 移出去的位元(VY 的)只移 VX,不看 VYC8_Q_SHIFT_VY
FX55、FX65 存取多個暫存器做完之後 I 加 X + 1(I 停在最後一格的下一格)I 不變(SUPER-CHIP 的做法)C8_Q_LOAD_INC_I
BNNN 跳躍跳到 NNN + V0當成 BXNN:跳到 XNN + VXC8_Q_JUMP_V0
8XY1、8XY2、8XY3 邏輯運算做完之後 VF = 0(原機的機器碼副作用)VF 不變C8_Q_VF_RESET
DXYN 畫到邊緣超出右邊或下面的格子丟掉(裁切)從另一邊繞回來C8_Q_CLIP

地下城的兩個 CHIP-8 任務預設照 COSMAC VIP(C8_PROFILE_VIP:五個旗標全開),但五個旗標都要支援(cpu.c 處理四個,C8_Q_CLIP 由 display.c 處理); 隱藏檢定會用 MODERN 設定(五個全關)和「只開一個旗標」的設定,再跑同一批 ROM。本章的範例模擬器只做 VIP 一種。

ℹ️
「現代」不是一個標準

表格右欄只是 Lab 為了測試定出來的一組設定。真實世界的「現代」直譯器各有各的組合:例如很多直譯器移位照 SUPER-CHIP、畫圖卻照 VIP 裁切。 還有一個怪癖這張表沒列:VIP 畫 sprite 之前會等畫面的垂直空白期,所以每幀最多畫一次;地下城的 Lab 不模擬這一點。 想看各版本的完整差異,可以讀本章最後延伸資源裡的 opcode 對照表。

⚠️
看起來對但其實錯:「8XY6 在每個直譯器上都是把 VX 右移一位」

很多網路教學只寫「8XY6:VX = VX >> 1」。你照著寫,再拿 8336、8556 這種 X 等於 Y 的測試去試,答案都對,因為 VX 就是 VY。 可是 COSMAC VIP 原機做的是 VX = VY >> 1:前面 exec.ch8 那張表的 8316,VIP 得到 V3 = 64,「只移 VX」得到 22。 照 VIP 寫的老遊戲,在「只移 VX」的模擬器上就會算錯分數或亂跑。測試要挑 X ≠ Y、而且 VX 和 VY 不一樣的例子,才分得出來。

歷史小注

CHIP-8 出現在 1970 年代後期,作者 Joseph Weisbecker 在 RCA 設計了 1802 微處理器和 COSMAC VIP。VIP 是一台用十六進位鍵盤輸入的小電腦, CHIP-8 讓使用者不必寫 1802 的機器碼,也能寫小遊戲。1990 年,Andreas Gustafsson 在 HP-48 繪圖計算機上寫了 CHIP-48; Erik Bryntse 以它為基礎做出 SUPER-CHIP,加了更高的解析度和新指令。本書只做原本的 CHIP-8。

    0x62, 0xF0,   // 202: V2 = 0xF0
    0x81, 0x24,   // 204: V1 += V2 → 0x1D,VF = 1(進位)
    0x83, 0x26,   // 206: VIP:V3 = V2 >> 1 = 0x78,VF = 0

    0xF1, 0x33,   // 210: [I..I+2] = V1 的百、十、個位(I = 0,寫進 000..002)
    0x00, 0xEE,   // 212: return
};

static void run(uint32_t quirks) {
    Bus *bus = bus_new(C8_MEM);
    Chip8 c;
    chip8_init(&c, bus, quirks, 1);
    chip8_load(&c, rom, sizeof rom);
    for (int k = 0; k < 9; k++) chip8_step(&c);   // 9 條之後停在 20E
    chip8_dump(&c, stdout);
    printf("cycles=%llu mem[000..002]=%u %u %u mem[300..303]=%02X %02X %02X %02X\n",
           (unsigned long long)c.cycles, bus_read8(bus, 0x000), bus_read8(bus, 0x001),
           bus_read8(bus, 0x002), bus_read8(bus, 0x300), bus_read8(bus, 0x301),
           bus_read8(bus, 0x302), bus_read8(bus, 0x303));
    bus_free(bus);
}

int main(void) {
    run(C8_PROFILE_VIP);
    run(C8_PROFILE_MODERN);

    Bus *bus = bus_new(C8_MEM);
    Chip8 c;
    chip8_init(&c, bus, C8_PROFILE_VIP, 1);
    chip8_load(&c, rom, sizeof rom);

    chip8_dump(&c, stdout);                         // 堆疊裡有一個返回位址

    chip8_init(&c, bus, C8_PROFILE_VIP, 1);          // 重設 CPU;bus 裡前面寫進去的東西還在(chip8_init 不清 bus)
    const uint8_t bad[] = {0x00, 0xEE, 0x51, 0x21};
    chip8_load(&c, bad, sizeof bad);
    int r = chip8_step(&c);                       // 空堆疊的 00EE

    bus_free(small);
    bus_free(bus);
    return 0;
}

畫面:用 XOR 畫 sprite

CHIP-8 只有兩條畫圖指令:00E0 清畫面,DXYN 畫一個 sprite。sprite 是記憶體裡從 I 開始的 N 個位元組, 每個位元組是一列、8 格寬,最高位元在最左邊;N 可以是 1 到 15,所以 sprite 最大 8×15。N = 0 在 CHIP-8 裡什麼都不畫,VF = 0(SUPER-CHIP 才把它當成 16×16 的大 sprite)。

DXYN 不是「把 sprite 蓋上去」,而是XOR上去:

  • sprite 那一格是 0:畫面不變。
  • sprite 那一格是 1:畫面那一格翻面,暗變亮、亮變暗。
  • 只要有任何一格由亮變暗,VF = 1;否則 VF = 0。這叫碰撞旗標(collision flag)。

為什麼用 XOR?因為在同一個位置再畫一次同一個 sprite,它就消失了(1 XOR 1 = 0),而且背景不會被破壞。 CHIP-8 的遊戲移動東西都是這樣做的:在舊位置畫一次(擦掉),改座標,在新位置再畫一次。碰撞旗標則免費告訴你「剛剛畫的東西有沒有撞到畫面上已經有的東西」, 打磚塊的球撞到磚塊、俄羅斯方塊落到底,都是靠 VF 判斷。

看起來對但其實錯:「DXYN 之後 VF = 1,表示兩個 sprite 疊在一起了」

在小遊戲裡,VF = 1 常常剛好代表「球撞到磚塊」,於是很容易以為碰撞就是「兩個東西重疊」。可是圖 52-3 的兩個方框只在角落交叉, sprite 的 32 格(其中 20 格是亮的)裡只有 2 格兩邊都是 1,VF 一樣是 1。反過來,兩個 sprite 的範圍重疊、但亮的格子剛好錯開(例如一個畫偶數格、一個畫奇數格),VF 是 0。 VF 只回答一個問題:這一次畫圖,有沒有任何一格由亮變暗。它不說撞到哪裡、撞到幾格,也不說是誰撞到誰。

邊緣:裁切還是繞回

sprite 畫到畫面邊緣時,有兩條規則要分清楚:

  1. 起點先取餘數。VX、VY 是 0–255 的數,畫面只有 64×32,所以起點是 (VX % 64, VY % 32)。這一條所有直譯器都一樣。
  2. 超出去的部分:COSMAC VIP 把超出右邊或下面的格子丟掉(裁切,clipping);有些直譯器讓它從另一邊繞回來(wrapping)。 地下城的 Lab 用旗標 C8_Q_CLIP 選擇,預設是 VIP 的裁切。被裁掉的格子沒有畫,當然也不算碰撞。

sprite.ch8 的第三次畫圖把方框畫在 (60, 20):8 格寬的方框只有 x = 60..63 這 4 欄在畫面裡,右邊 4 欄被裁掉。

小技巧

DXYN 的 X 或 Y 可以是 F(例如 DF14,座標放在 VF)。規則和算術指令一樣:先讀 VX、VY 當座標,畫完最後才寫 VF。 範例模擬器把 V[x]、V[y] 當參數傳給 draw(),回傳之後才寫 V[0xF],就自然對了。

畫面全暗。I 指向兩個位元組 3C 66,VA = 124、VB = 63,執行 DAB2。

  1. 起點在哪裡?
  2. VIP 設定(裁切):哪些格子變亮?VF 是多少?
  3. MODERN 設定(繞回):哪些格子變亮?VF 是多少?
  4. 接著在同樣的位置再執行一次 DAB2,畫面和 VF 會怎樣?(兩種設定各答一次)
看解答
  1. 起點 = (124 % 64, 63 % 32) = (60, 31)。
  2. 第 0 列 y = 31,3C = 00111100,1 在第 2–5 位 → x = 62、63、64、65;64 和 65 超出右邊,裁掉。 第 1 列 y = 32 超出下面,整列裁掉。結果只有 (62, 31)、(63, 31) 兩格變亮;畫面原本全暗,VF = 0。
  3. 第 0 列 y = 31:x = 62、63,以及 64 → 0、65 → 1,所以是 (62, 31)、(63, 31)、(0, 31)、(1, 31)。 第 1 列 y = 32 → 0,66 = 01100110,1 在第 1、2、5、6 位 → x = 61、62、65 → 1、66 → 2, 所以是 (61, 0)、(62, 0)、(1, 0)、(2, 0)。一共 8 格變亮,VF = 0。
  4. 同一個 sprite 在同一個位置再畫一次,每一個剛才變亮的格子都再翻一次,全部變暗:畫面回到全暗,而且有格子由亮變暗,VF = 1。兩種設定都一樣。

// chip8/display.c 要寫的函式(宣告在 chip8.h 的後半)
void chip8_cls(Chip8 *c);            // 00E0:fb 全部清 0
int  chip8_draw(Chip8 *c, uint8_t x, uint8_t y, uint16_t addr, uint8_t n);
     // DXYN 的本體(cpu.c 呼叫它,把回傳值寫進 VF):
     // 起點 (x % 64, y % 32);畫 n 列,第 r 列讀 bus 的 (addr + r) & 0xFFF,XOR 進 fb。
     // 有任何一格由 1 變 0 → 回傳 1,否則 0;n 是 0 → 什麼都不畫,回傳 0。
     // C8_Q_CLIP 打開(VIP):超出右邊或下面的格子丟掉,不算碰撞;關掉(MODERN):繞回另一邊。
void chip8_key_event(Chip8 *c, uint8_t key, int down);
     // keys[key] = down ? 1 : 0;key > 15 忽略;
     // waiting 時某個鍵由按著變放開,而且 released 還是 0xFF → released = key(只記第一個)。
int  chip8_run_frame(Chip8 *c, unsigned ipf);
     // 一幀:最多 ipf 次 chip8_step,遇到負的回傳碼就停並回傳它(這一幀不減計時器);
     // 否則做滿 ipf 次(C8_WAIT 也算一次),然後 chip8_tick_timers 一次,回 C8_OK。
uint32_t chip8_fb_hash(const Chip8 *c);
     // FNV-1a 32 位元:h = 2166136261;fb 的 2048 個位元組(列優先,值 0/1)每個做 h ^= b; h *= 16777619。
void chip8_fb_text(const Chip8 *c, char *out);
     // out 至少 C8_TEXT_SIZE(2081)個字元:32 列,每列 64 個 '#'(亮)或 '.'(暗)再加 '\n',最後補 '\0'。

// display_demo.c:公開範例(用你的 emu/bus.c、chip8/cpu.c、chip8/display.c)
#include <stdio.h>
#include <string.h>
#include "chip8/chip8.h"

static const uint8_t rom[] = {
    0x60, 0x0A,   // 200: V0 = A(字型 A)
    0xF0, 0x29,   // 202: I = A 的字型
    0x61, 0x3E,   // 204: V1 = 62
    0x62, 0x01,   // 206: V2 = 1
    0xD1, 0x25,   // 208: 在 (62, 1) 畫 5 列:右邊超出畫面
    0xD1, 0x25,   // 20A: 同一個位置再畫一次:擦掉,VF = 1
    0xD1, 0x25,   // 20C: 第三次:畫回來
    0x12, 0x0E,   // 20E: 停
};

static void run(uint32_t quirks, const char *name) {
    Bus *bus = bus_new(C8_MEM);
    Chip8 c;
    chip8_init(&c, bus, quirks, 1);
    chip8_load(&c, rom, sizeof rom);
    for (int k = 0; k < 5; k++) chip8_step(&c);
    printf("%s 第一次 VF=%u hash=%08X\n", name, c.v[15], (unsigned)chip8_fb_hash(&c));
    chip8_step(&c);
    printf("%s 第二次 VF=%u hash=%08X\n", name, c.v[15], (unsigned)chip8_fb_hash(&c));
    chip8_step(&c);
    char text[C8_TEXT_SIZE];
    chip8_fb_text(&c, text);
    for (int y = 1; y <= 5; y++)                     // 只印第 1..5 列的頭尾各 4 格
        printf("  %.4s ... %.4s\n", text + y * (C8_W + 1), text + y * (C8_W + 1) + 60);
    bus_free(bus);
}

int main(void) {
    run(C8_PROFILE_VIP, "VIP");
    run(C8_PROFILE_MODERN, "MODERN");

    // 按鍵:E19E 在 V1 那個鍵按著時跳過下一條;F20A 等一個鍵「放開」
    const uint8_t keys[] = {0x61, 0x05, 0xE1, 0x9E, 0x63, 0x01, 0xF2, 0x0A, 0x12, 0x08};
    Bus *bus = bus_new(C8_MEM);
    Chip8 c;
    chip8_init(&c, bus, C8_PROFILE_VIP, 1);
    chip8_load(&c, keys, sizeof keys);
    chip8_key_event(&c, 5, 1);                       // 按下 5
    chip8_key_event(&c, 20, 1);                      // 不存在的鍵:忽略
    c.dt = 3;
    int r = chip8_run_frame(&c, 10);
    printf("frame1 r=%d PC=%03X V3=%u DT=%u waiting=%u\n", r, c.pc, c.v[3], c.dt, c.waiting);
    chip8_key_event(&c, 5, 0);                       // 放開 5
    r = chip8_run_frame(&c, 10);
    printf("frame2 r=%d PC=%03X V2=%u DT=%u cycles=%llu\n", r, c.pc, c.v[2], c.dt,
           (unsigned long long)c.cycles);
    bus_free(bus);
    return 0;
}

  • ☐ 效能〔隱藏檢定〕DXYN 只動 sprite 碰到的格子(不能每次重畫或複製整個畫面);hash 一次 O(2048)。門檻:3×106 條指令(4 成是 DXYF)＋36,000 幀(每幀 30 條指令、每幀算一次 hash),1 秒內。這個門檻來自 Boss 戰「CHIP-8 畫面重播」:4 支 ROM 各 3,600 幀(每幀 30 條指令),要在 2 秒內批改完。

規則:只交 display.c,只用 C 標準函式庫;要 #include "chip8/chip8.h"。編譯指令由檢定產生(-std=c17 -Wall -Werror -O2 -I ~/零件庫,加上你的 emu/bus.c 與 chip8/cpu.c),警告就是錯誤。

之後會用在:檢查點 1 的三場 Boss 戰:「CHIP-8 隱藏 ROM」「CHIP-8 畫面重播」與「面板上玩」(老師核可:畫面串流到終端旁的側邊面板、鍵盤從終端送;ROM 用自寫的,或老師核可、授權清楚的 homebrew)。之後 Game Boy 的 PPU 也是「一幀一幀畫、用 hash 比對畫面」。

這個零件過關之後,後面的專題一律用你自己的版本。規則見零件庫規則。

範例模擬器 chip8demo.c

把前面幾節的規則接起來,就是一台模擬器。下面的 chip8demo.c 大約兩百行,用一個 struct 存整台機器, step() 執行一條指令,main() 跑「每幀 ipf 條指令,然後計時器減 1」的主迴圈,停住之後印出暫存器和畫面。

它是刻意不完整的教學版:

  • 只做 COSMAC VIP 一種怪癖(移位用 VY、FX55/FX65 之後 I 往前、邏輯運算之後 VF = 0、畫面邊緣裁切)。
  • 沒有鍵盤:EX9E、EXA1、FX0A 會停下來說「不支援」。也沒有 BNNN(留給練習 52.3)。
  • 亂數用 C 標準函式庫的 rand():不同的系統給的亂數序列不一樣,所以用到 CXNN 的程式,結果沒辦法和別人的模擬器比對。
  • 記憶體就是 struct 裡的一個陣列;堆疊出錯時用 assert 直接中止。
  • 停住的條件是「1NNN 跳到自己」;沒有聲音,也不會即時畫到螢幕,只在最後印一次畫面。
// chip8demo.c:本章的範例 CHIP-8 模擬器(不完整,刻意的)
//   只做 COSMAC VIP 一種怪癖;沒有按鍵(EX9E、EXA1、FX0A)、沒有 BNNN;亂數用 rand()。
// 編譯:gcc -std=c17 -Wall -Wextra -O2 chip8demo.c -o chip8demo
// 用法:./chip8demo ROM檔 [最多幾幀=60] [每幀幾條=10] [trace]
#include <assert.h>
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

#define MEM_SIZE  4096
#define W 64
#define H 32
#define FONT_ADDR 0x050

enum { RUN = 0, HALT = 1, UNSUPPORTED = 2 };

static const uint8_t font[80] = {     // 0–F,每個字 4×5,一列一個位元組(只用高 4 位)
    0xF0,0x90,0x90,0x90,0xF0, 0x20,0x60,0x20,0x20,0x70,  // 0 1
    0xF0,0x10,0xF0,0x80,0xF0, 0xF0,0x10,0xF0,0x10,0xF0,  // 2 3
    0x90,0x90,0xF0,0x10,0x10, 0xF0,0x80,0xF0,0x10,0xF0,  // 4 5
    0xF0,0x80,0xF0,0x90,0xF0, 0xF0,0x10,0x20,0x40,0x40,  // 6 7
    0xF0,0x90,0xF0,0x90,0xF0, 0xF0,0x90,0xF0,0x10,0xF0,  // 8 9
    0xF0,0x90,0xF0,0x90,0x90, 0xE0,0x90,0xE0,0x90,0xE0,  // A B
    0xF0,0x80,0x80,0x80,0xF0, 0xE0,0x90,0x90,0x90,0xE0,  // C D
    0xF0,0x80,0xF0,0x80,0xF0, 0xF0,0x80,0xF0,0x80,0x80,  // E F
};

typedef struct {
    uint8_t  mem[MEM_SIZE];      // 自己的陣列當記憶體
    uint8_t  V[16];
    uint16_t I, PC;
    uint16_t stack[16];
    int      sp;                 // 堆疊裡有幾個返回位址
    uint8_t  delay, sound;       // DT、ST
    uint8_t  screen[H][W];       // 每格 0 或 1
    long     executed;           // 執行了幾條指令
} Machine;

static void reset(Machine *m) {
    memset(m, 0, sizeof *m);
    memcpy(&m->mem[FONT_ADDR], font, sizeof font);
    m->PC = 0x200;
}

static int load_rom(Machine *m, const char *path) {
    FILE *f = fopen(path, "rb");
    if (!f) return -1;
    size_t n = fread(&m->mem[0x200], 1, MEM_SIZE - 0x200, f);
    fclose(f);
    return (int)n;
}

// DXYN 的本體:XOR 畫上去,超出右邊或下面的格子丟掉(VIP 的裁切);有亮變暗就回傳 1
static uint8_t draw(Machine *m, uint8_t vx, uint8_t vy, unsigned n) {
    unsigned x0 = vx % W, y0 = vy % H;   // 起點先取餘數
    uint8_t hit = 0;
    for (unsigned row = 0; row < n; row++) {
        unsigned y = y0 + row;
        if (y >= H) break;
        uint8_t bits = m->mem[(m->I + row) & 0xFFF];
        for (unsigned col = 0; col < 8; col++) {
            unsigned x = x0 + col;
            if (x >= W) break;
            if (!(bits & (0x80u >> col))) continue;   // sprite 的 0 不改畫面
            if (m->screen[y][x]) hit = 1;            // 1 XOR 1 = 0:亮變暗
            m->screen[y][x] ^= 1;
        }
    }
    return hit;
}

// 8XYN:先算結果,最後才寫 VF(X 或 Y 是 F 時才不會算錯)
static int alu(Machine *m, unsigned x, unsigned y, unsigned n) {
    uint8_t a = m->V[x], b = m->V[y], r, f = 0;
    int set_f = 1;
    switch (n) {
    case 0x0: r = b; set_f = 0; break;
    case 0x1: r = a | b; break;                      // VIP:邏輯運算之後 VF = 0
    case 0x2: r = a & b; break;
    case 0x3: r = a ^ b; break;
    case 0x4: r = (uint8_t)(a + b); f = (a + b) > 0xFF; break;
    case 0x5: r = (uint8_t)(a - b); f = a >= b; break;    // 1 = 沒有借位
    case 0x6: r = b >> 1; f = b & 1; break;              // VIP:移的是 VY
    case 0x7: r = (uint8_t)(b - a); f = b >= a; break;
    case 0xE: r = (uint8_t)(b << 1); f = b >> 7; break;
    default:  return UNSUPPORTED;
    }
    m->V[x] = r;
    if (set_f) m->V[0xF] = f;
    return RUN;
}

static int step(Machine *m) {
    uint16_t at = m->PC;
    uint16_t op = (uint16_t)(m->mem[at] << 8 | m->mem[(at + 1) & 0xFFF]);   // 大端
    unsigned x = (op >> 8) & 0xF, y = (op >> 4) & 0xF, n = op & 0xF;
    uint8_t  nn = op & 0xFF;
    uint16_t nnn = op & 0xFFF;
    uint8_t *V = m->V;

    m->PC = (at + 2) & 0xFFF;
    m->executed++;
    switch (op >> 12) {
    case 0x0:
        if (op == 0x00E0) memset(m->screen, 0, sizeof m->screen);
        else if (op == 0x00EE) { assert(m->sp > 0); m->PC = m->stack[--m->sp]; }
        break;                                       // 其他 0NNN:不做事
    case 0x1: if (nnn == at) { m->PC = at; return HALT; } m->PC = nnn; break;
    case 0x2: assert(m->sp < 16); m->stack[m->sp++] = m->PC; m->PC = nnn; break;
    case 0x3: if (V[x] == nn) m->PC = (m->PC + 2) & 0xFFF; break;
    case 0x4: if (V[x] != nn) m->PC = (m->PC + 2) & 0xFFF; break;
    case 0x5: if (n) return UNSUPPORTED; if (V[x] == V[y]) m->PC = (m->PC + 2) & 0xFFF; break;
    case 0x6: V[x] = nn; break;
    case 0x7: V[x] = (uint8_t)(V[x] + nn); break;    // 溢位也不改 VF
    case 0x8: return alu(m, x, y, n);
    case 0x9: if (n) return UNSUPPORTED; if (V[x] != V[y]) m->PC = (m->PC + 2) & 0xFFF; break;
    case 0xA: m->I = nnn; break;
    case 0xC: V[x] = (uint8_t)(rand() & nn); break;
    case 0xD: V[0xF] = draw(m, V[x], V[y], n); break;     // 先讀座標,最後寫 VF
    case 0xF:
        switch (nn) {
        case 0x07: V[x] = m->delay; break;
        case 0x15: m->delay = V[x]; break;
        case 0x18: m->sound = V[x]; break;
        case 0x1E: m->I = (uint16_t)(m->I + V[x]); break;    // 不改 VF
        case 0x29: m->I = FONT_ADDR + (V[x] & 0xF) * 5; break;
        case 0x33:
            m->mem[m->I & 0xFFF]       = V[x] / 100;
            m->mem[(m->I + 1) & 0xFFF] = V[x] / 10 % 10;
            m->mem[(m->I + 2) & 0xFFF] = V[x] % 10;
            break;
        case 0x55: for (unsigned k = 0; k <= x; k++) m->mem[(m->I + k) & 0xFFF] = V[k];
                   m->I = (uint16_t)(m->I + x + 1); break;   // VIP:I 跟著往前
        case 0x65: for (unsigned k = 0; k <= x; k++) V[k] = m->mem[(m->I + k) & 0xFFF];
                   m->I = (uint16_t)(m->I + x + 1); break;
        default:   return UNSUPPORTED;                       // 含 FX0A
        }
        break;
    default: return UNSUPPORTED;                             // BNNN、EX9E、EXA1
    }
    return RUN;
}

static void show(const Machine *m) {
    printf("V0-V7:");
    for (int k = 0; k < 8; k++) printf(" %02X", m->V[k]);
    printf("\nV8-VF:");
    for (int k = 8; k < 16; k++) printf(" %02X", m->V[k]);
    printf("\nI=0x%03X  DT=%d  ST=%d  SP=%d\n", m->I, m->delay, m->sound, m->sp);
    int lit = 0;
    for (int y = 0; y < H; y++)
        for (int x = 0; x < W; x++) lit += m->screen[y][x];
    if (!lit) { printf("(畫面全暗)\n"); return; }
    printf("+%.*s+\n", W, "----------------------------------------------------------------");
    for (int y = 0; y < H; y++) {
        putchar('|');
        for (int x = 0; x < W; x++) putchar(m->screen[y][x] ? '#' : ' ');
        printf("|\n");
    }
    printf("+%.*s+\n", W, "----------------------------------------------------------------");
}

// trace:印出這一步改了什麼(只在除錯時用,每步複製整個機器,很慢)
static void trace(const Machine *before, const Machine *after) {
    uint16_t op = (uint16_t)(before->mem[before->PC] << 8 | before->mem[(before->PC + 1) & 0xFFF]);
    printf("%03X %04X ", before->PC, op);
    for (int k = 0; k < 16; k++)
        if (before->V[k] != after->V[k]) printf(" V%X:%02X->%02X", k, before->V[k], after->V[k]);
    if (before->I != after->I) printf(" I:%03X->%03X", before->I, after->I);
    if (after->PC != ((before->PC + 2) & 0xFFF)) printf(" PC->%03X", after->PC);
    if (before->sp != after->sp) printf(" SP:%d->%d", before->sp, after->sp);
    if (before->delay != after->delay) printf(" DT->%d", after->delay);
    if (before->sound != after->sound) printf(" ST->%d", after->sound);
    for (int a = 0; a < MEM_SIZE; a++)
        if (before->mem[a] != after->mem[a]) printf(" [%03X]=%02X", a, after->mem[a]);
    if (memcmp(before->screen, after->screen, sizeof before->screen)) printf(" 畫面變了");
    putchar('\n');
}

int main(int argc, char **argv) {
    if (argc < 2) { fprintf(stderr, "用法:%s ROM檔 [最多幾幀] [每幀幾條] [trace]\n", argv[0]); return 2; }
    static Machine m, before;            // 機器有 6 KiB 多,放靜態區
    reset(&m);
    if (load_rom(&m, argv[1]) < 0) { perror(argv[1]); return 1; }
    long frames = argc > 2 ? atol(argv[2]) : 60;
    int ipf = argc > 3 ? atoi(argv[3]) : 10;
    int tracing = argc > 4 && strcmp(argv[4], "trace") == 0;
    srand(1);

    int r = RUN;
    long f;
    for (f = 1; f <= frames && r == RUN; f++) {
        for (int k = 0; k < ipf && r == RUN; k++) {
            if (tracing) before = m;
            r = step(&m);
            if (tracing) trace(&before, &m);
        }
        if (r == RUN) {                  // 一幀結束:計時器各減 1
            if (m.delay) m.delay--;
            if (m.sound) m.sound--;
            if (tracing) printf("--- 第 %ld 幀結束 DT=%d ST=%d ---\n", f, m.delay, m.sound);
        }
    }
    f--;
    if (r == HALT)
        printf("停住:PC=0x%03X 跳到自己。執行了 %ld 條指令,在第 %ld 幀。\n", m.PC, m.executed, f);
    else if (r == UNSUPPORTED)
        printf("不支援的指令:0x%03X 的 %02X%02X。\n", (m.PC - 2) & 0xFFF,
               m.mem[(m.PC - 2) & 0xFFF], m.mem[(m.PC - 1) & 0xFFF]);
    else
        printf("跑完 %ld 幀(每幀 %d 條),執行了 %ld 條指令。\n", frames, ipf, m.executed);
    show(&m);
    return 0;
}

讀這支程式時,對照前面幾節:

  • step() 開頭就是取指(大端)和拆欄位,然後 PC 先加 2;switch (op >> 12) 是解碼表的第一層。
  • alu() 用區域變數 a、b 先存舊值,算完先寫 V[x]、最後寫 V[0xF]:這就是「VF 最後寫」。
  • draw() 先取餘數決定起點,超出畫面的格子 break 掉(裁切),只在「原本亮、sprite 也是 1」時設 hit。
  • main() 的兩層 for:外層是幀,內層是 ipf 條指令,幀尾減計時器。
  • trace() 是除錯用的:每一步把整台機器複製一份,比較前後有什麼不同。它很慢(每步複製 6 KiB),只在你要看細節時打開。

自己寫測試 ROM

沒有現成的 ROM,就自己寫。CHIP-8 的程式就是一串十六進位數字,本章用「一行一條指令、# 後面是註解」的文字檔來寫, 再用一支很短的 Python 程式轉成二進位的 .ch8 檔: 

# hex2rom.py:把「十六進位文字 + # 註解」轉成 CHIP-8 的二進位 ROM
# 用法:python3 hex2rom.py count.hex count.ch8
import sys

src, dst = sys.argv[1], sys.argv[2]
digits = []
with open(src, encoding="utf-8") as f:
    for line in f:
        digits.append(line.split("#", 1)[0].replace(" ", "").strip())
rom = bytes.fromhex("".join(digits))
with open(dst, "wb") as f:
    f.write(rom)
print(f"{dst}: {len(rom)} 位元組")

(有 xxd 的話,把註解拿掉之後 xxd -r -p 也可以做同樣的事。)

核心觀念:測試 ROM 要能「自己說對不對」

上面兩支 ROM 要你用眼睛看畫面、對暫存器。更好的測試 ROM 會自己檢查:算完之後用 3XNN、4XNN 比對答案,對了畫「1」,錯了畫「0」(練習 52.8)。 地下城的判題更進一步:用固定的驅動程式跑隱藏的 ROM,把暫存器、記憶體傾印、畫面的 hash 和參考答案逐項比對。 那些 ROM 也全部是自己寫的,只是不公開。

除錯:trace 與兩台模擬器對照

模擬器出錯時,最終畫面通常只告訴你「不對」,不告訴你「哪一條不對」。範例模擬器的第 4 個參數 trace 會把每一步改了什麼印出來 (格式:位址、opcode、改變的暫存器;PC 不是加 2 才印 PC;記憶體寫入印成 [位址]=值;每幀結束印一行分隔): 

$ ./chip8demo exec.ch8 1 20 trace
200 60FF  V0:00->FF
202 7002  V0:FF->01
204 61C8  V1:00->C8
206 6264  V2:00->64
208 8124  V1:C8->2C VF:00->01
20A 8125  V1:2C->C8 VF:01->00
20C 6345  V3:00->45
20E 8316  V3:45->64
210 A300  I:000->300
212 F333  [300]=01
214 F155  I:300->302 [301]=C8
216 1216  PC->216
停住:PC=0x216 跳到自己。執行了 12 條指令,在第 1 幀。
V0-V7: 01 C8 64 64 00 00 00 00
V8-VF: 00 00 00 00 00 00 00 00
I=0x302  DT=0  ST=0  SP=0
(畫面全暗)

這就是前面 exec.ch8 那張表(VIP 欄)。trace 只印「值改變了」的格子:212 那一行的 F333 寫了 [300]=01、[301]=00、[302]=00,但後兩格本來就是 0,所以沒印出來; 20E 的 VF 也是一樣,寫了 00,和原本相同。

有了 trace,就能做差異測試(differential testing):同一支 ROM 給兩台模擬器跑(例如你的模擬器和一個你信任的參考模擬器,或同一台的 VIP 與 MODERN 設定), 逐行比對 trace,第一個不一樣的行就是 bug(或怪癖)所在。第 21 章的任務「CPU 與電腦」和參考 CPU 逐拍比對、顯示第一個不同的拍,也是同一個原理。

💡
小技巧:最後狀態一樣,不代表每一步都一樣

count.ch8 用 VIP 和 MODERN 設定跑,最後的暫存器、記憶體和畫面完全一樣。可是中間 F265 之後,VIP 的 I 是 0x303,MODERN 是 0x300, 只是後面第三條的 F129(在 212)又把 I 蓋掉了。只比最後狀態的測試抓不到這種差異;比 trace 才抓得到。週期數也抓不到:兩種設定都是 41 個週期。所以判題除了最後的傾印,也用逐步 trace 或中途的多個檢查點。

✏️ 練習 52.1 思考

(1) 為什麼 CHIP-8 的程式從 0x200 開始?(2) 現代模擬器為什麼可以把字型放在 0x050?(3) ROM 最大可以多大?

看解答

(1) COSMAC VIP 上,直譯器本身佔了記憶體最前面的 512 位元組(0x000–0x1FF),程式只能從 0x200 開始放。 (2) 模擬器的直譯器是你寫的 C 程式,不住在 CHIP-8 的記憶體裡,0x000–0x1FF 就空出來了;程式照慣例不會去碰這一段,放字型不會被蓋掉。 (3) 0x200 到 0xFFF 共 0x1000 − 0x200 = 3584 位元組。地下城 Lab 的載入函式遇到比這個大的 ROM 要拒絕,一個位元組都不寫。

✏️ 練習 52.5 思考

timer.ch8 用 ipf = 3 跑,V2 最後是多少?停在第幾幀?先猜,再用 ./chip8demo timer.ch8 60 3 驗證。為什麼 ipf 越小,V2 越小?

看解答
$ ./chip8demo timer.ch8 60 3 | head -2
停住:PC=0x20C 跳到自己。執行了 22 條指令,在第 8 幀。
V0-V7: 05 00 05 00 00 00 00 00

V2 = 5,停在第 8 幀,共 22 條。迴圈一圈是 4 條指令,DT 的倒數速度固定(每幀減 1,共 5 幀), 所以 V2 大約等於「5 幀裡能跑幾圈」:ipf = 10 時約 2.5 圈/幀,ipf = 3 時不到 1 圈/幀。ipf = 3 時第 2 幀和第 6 幀甚至一次都沒讀到 DT(F107 剛好落在別的幀), 所以 DT 歸零之後,還要再等 F107 下一次被執行才會發現,一直到第 8 幀才停。

✏️ 練習 52.6 思考

判斷對錯,錯的舉一個反例(一組 opcode 和暫存器值):

  1. 「7XNN 溢位時,VF 會被設成 1。」
  2. 「8XY4 的 X 是 F 時,VF 最後是 VX + VY 的低 8 位元。」
  3. 「DXYN 回傳 VF = 0,表示 sprite 沒有碰到畫面上任何亮的格子。」
  4. 「FX1E 加完之後 I 超過 0xFFF,VF 要設成 1。」
看解答
  1. 錯。60FF 再 7002:V0 = 01,VF 不變(前面 exec.ch8 那張表的第 2 列)。只有 8XY4 會寫進位。
  2. 錯。先寫結果、最後寫旗標,所以 VF 最後是進位旗標。flags.c 的 8F14(VF = F0、V1 = 20):VF 最後是 01,不是 10。
  3. 錯。VF = 0 只表示「沒有格子由亮變暗」。sprite 的 0 位元蓋在亮的格子上不算碰撞; 在 VIP 設定下,被裁掉的部分就算「蓋在」繞回來那一邊的亮格子上也不算。例如畫面上 (0, 0) 亮著,在 (60, 0) 畫 FF:VIP 裁掉 x = 64..67,VF = 0。
  4. 錯。標準的 CHIP-8 裡 FX1E 不改 VF(地下城的 Lab 也這樣規定);I 是 16 位元暫存器,用它存取記憶體時才取低 12 位元。 有少數直譯器會設 VF,那是另一個沒有列入 Lab 的怪癖。
✏️ 練習 52.7 思考

用「按鍵與 FX0A」那一節的 ROM 和 ipf = 10。這次的按鍵事件是:第 2 幀開始前按下 5,第 3 幀開始前放開 5;第 1 幀開始前(F30A 還沒執行)按下又放開 9。 V3、V4 最後是多少?一共執行幾條指令?F30A 算了幾次?

看解答

第 1 幀:9 在 F30A 開始等之前就按完放開了,不算;6003、F015、F30A 開始等,剩下 7 條也是 F30A,DT 3 → 2。 第 2 幀:按下 5,按下不算,10 條 F30A,DT 2 → 1。第 3 幀:5 放開了,第一條 F30A 就完成:V3 = 5;F407 讀到 DT = 1,V4 = 1;1208 停。

V3 = 5、V4 = 1。指令數 10 + 10 + 3 = 23,F30A 算了 8 + 10 + 1 = 19 次。和本文的例子比,早一幀放開,V4 就從 0 變成 1:等按鍵的時候計時器照常倒數。

✏️ 練習 52.9 挑戰

一支 ROM 一直遞迴呼叫自己(例如 0x200 寫 2200)。(1) 範例模擬器執行到第幾條指令會出事?會怎樣? (2) 地下城的 Lab 規定「第 17 層呼叫回傳錯誤碼,而且機器狀態完全不變」。和 assert 中止比,這樣有什麼好處?

看解答

(1) 每一次 2200 推一個返回位址(0x202)。前 16 次把堆疊填滿,第 17 條指令(第 17 次呼叫)執行時 assert(m->sp < 16) 失敗,程式印出斷言訊息並中止,畫面和暫存器都看不到。 如果沒有這個 assert,m->stack[16] 會寫到陣列外面,可能蓋掉 struct 裡下一個欄位 sp(這是未定義行為,見第 51 章)。

(2) 回傳錯誤碼,呼叫你的程式(判題驅動程式、除錯器、面板)可以自己決定要怎麼辦:印出傾印、顯示「0x200 堆疊溢位」、或停在那裡讓人檢查。 狀態不變,表示傾印裡的 PC 還指著出事的那一條指令,SP 還是 16,和出事前一刻一模一樣,方便重現與比對; 如果 PC 已經加了 2、或 SP 已經變了,你看到的就是一個「做了一半」的狀態,很難判斷是哪裡錯。

✏️ 練習 52.10 挑戰

不跑程式,只用本章的規則判斷:count.ch8、sprite.ch8、timer.ch8、call.ch8、exec.ch8 這五支 ROM, 用 VIP 和 MODERN 兩種設定跑到停住,哪幾支的最後狀態(暫存器、I、記憶體、畫面)會不一樣?各是哪一條指令造成的?

看解答
  • exec.ch8:不一樣。20E 的 8316(移位怪癖)讓 V3、VF 不同,連帶 212 的 BCD 寫出不同的數字;214 的 F155 讓 I 不同。
  • sprite.ch8:不一樣。218 的第三次畫圖在 (60, 20),VIP 裁掉右邊 4 欄,MODERN 把它們繞到 x = 0..3。
  • count.ch8:最後一樣。20C 的 F265 讓 I 暫時不同(0x303 和 0x300),但 212 的 F129 又把 I 設成字型位址,蓋掉了差異。
  • timer.ch8、call.ch8:一樣。它們沒有用到任何有怪癖的指令。

這也說明了為什麼地下城的隱藏檢定要用「只開一個旗標」的設定再跑一次:每個怪癖都要有一支 ROM 讓它的差異留到最後,檢查才有意義。

把這一章串起來

  • 機器:4 KiB 記憶體(ROM 從 0x200 開始,字型放 0x050)、V0–VF(VF 兼當旗標)、16 位元的 I、PC、16 層堆疊、DT 與 ST、64×32 單色畫面、16 鍵鍵盤。
  • 解碼:opcode 是 4 個 nibble,第一個決定種類,0、8、E、F 再看後面;參數只有 X、Y、N、NN、NNN 五種切法。表裡沒有的組合要報錯。
  • 主迴圈:取指(大端)→ PC 加 2 → 解碼 → 執行;每幀 ipf 條,幀尾計時器減 1。ipf 是規格的一部分。
  • 旗標:先算結果、寫 VX,最後才寫 VF;7XNN 和 FX1E 不改 VF;8XY5 的 VF 是「沒有借位」(VX ≥ VY)。
  • 流程:跳過 = PC 再加 2;2NNN 推的是下一條的位址;程式用「跳到自己」表示結束;堆疊溢位與下溢要報錯。
  • 畫面:DXYN 用 XOR 畫,起點先取餘數;VF = 1 只代表「有格子由亮變暗」;邊緣 VIP 裁切、有些直譯器繞回。
  • 按鍵:FX0A 不能用 while 等,要讓 PC 停在原地、每步重新檢查;VIP 等的是「放開」。
  • 怪癖:移位用 VY 還是 VX、FX55/FX65 改不改 I、BNNN 還是 BXNN、邏輯運算重不重設 VF、裁切還是繞回。地下城 Lab 預設 COSMAC VIP,五個都做成旗標。
  • 測試:自己用十六進位寫 ROM;挑邊界值;讓 ROM 自己判斷對錯;用 trace 和差異測試找出第一個出錯的指令。
