資訊檢索的先驅

現代資訊檢索(information retrieval, IR)的理論基礎由 Gerard Salton 在 1960–80 年代奠定， 他發明了向量空間模型與 TF-IDF 的早期版本。 1996 年 Larry Page 與 Sergey Brin 在史丹佛提出 PageRank，翌年用它創辦了 Google。 深度學習嵌入向量的普及則是 2010 年代後的事。 今日的搜尋引擎是這三個時代的技術疊加。

里程碑 1 — 爬取與文件處理

搜尋引擎的食材是文字。在真實場景，爬蟲(web crawler)從種子 URL 出發， 持續抓取網頁、解析連結、再抓新頁面，形成廣度優先的圖遍歷 (正是第 30 章的 BFS)。 在我們的小專案裡，語料(corpus)直接存成純文字檔就好。

分詞與正規化

把原始文字切成可索引的詞語(token)，是搜尋的第一步。 典型的正規化流程包含：

  • 小寫化(lowercasing)：讓 "Python" 與 "python" 視為同一詞。
  • 停用詞(stop words)移除：濾掉 "the", "is", "的", "了" 等高頻但無資訊量的詞。
  • 詞幹提取(stemming) 或 詞形還原(lemmatization)：把 "running", "runs", "ran" 映射到同一詞根 "run"。
"""
milestone1_preprocess.py — 文件讀取、分詞、正規化
需要: pip install nltk
"""
import re, string
from pathlib import Path

# 簡易停用詞集(英文示範；中文可換 jieba + 停用詞表)
STOP_WORDS = {
    "the", "a", "an", "is", "in", "of", "to", "and", "for",
    "on", "with", "at", "by", "this", "that", "it", "as"
}

def tokenize(text: str) -> list[str]:
    """小寫 → 去標點 → 分詞 → 去停用詞"""
    text = text.lower()
    text = re.sub(r"[{}]".format(re.escape(string.punctuation)), " ", text)
    tokens = text.split()
    return [t for t in tokens if t not in STOP_WORDS and len(t) > 1]

def load_corpus(folder: str) -> dict[str, list[str]]:
    """讀取資料夾中的 .txt 檔，回傳 {doc_id: [token, ...]}"""
    corpus = {}
    for path in sorted(Path(folder).glob("*.txt")):
        doc_id = path.stem          # 以檔名(無副檔名)當 doc_id
        tokens = tokenize(path.read_text(encoding="utf-8"))
        corpus[doc_id] = tokens
        print(f"  載入 {doc_id}: {len(tokens)} 個 token")
    return corpus

if __name__ == "__main__":
    corpus = load_corpus("docs/")
    print(f"\n語料共 {len(corpus)} 篇文件")

核心觀念

分詞與正規化的品質直接決定搜尋精準度的上限——垃圾進、垃圾出。 停用詞移除可以讓索引縮小 30–50%，stemming 則能大幅提升召回率(recall)。

看解答

"is" 的 posting list 幾乎包含所有文件，AND 查詢時需要合併一份巨大的 list， 浪費時間且不提供任何過濾效果。移除停用詞後，"is" 不進索引， AND 合併只需處理 "python" 與 "fast" 這兩份較短的 posting list。 這正是第 28 章「早期截斷」的精神。

里程碑 2 — 倒排索引

有了分好的 token，下一步是建倒排索引(inverted index)。 它是資訊檢索的核心資料結構——一本「詞語 → 出現此詞的文件清單」的反向字典。 相對於「文件 → 詞語」的正向索引，倒排索引讓你從詞語出發，瞬間找到所有相關文件。 

"""
milestone2_index.py — 建立倒排索引
"""
from collections import defaultdict

def build_inverted_index(corpus: dict[str, list[str]]) -> dict[str, list[tuple]]:
    """
    回傳: { term: [(doc_id, tf), ...] }
    posting list 依 doc_id 排序，方便後續合併
    """
    # 先統計每篇文件裡每個詞的詞頻
    tf: dict[str, dict[str, int]] = defaultdict(lambda: defaultdict(int))
    for doc_id, tokens in corpus.items():
        for token in tokens:
            tf[token][doc_id] += 1

    # 整理成倒排索引，並按 doc_id 排序
    index: dict[str, list[tuple]] = {}
    for term, doc_freq in tf.items():
        # [(doc_id, freq), ...] 已按 doc_id 排序
        index[term] = sorted(doc_freq.items(), key=lambda x: x[0])
    return index

def index_stats(index: dict, corpus: dict) -> None:
    """印出索引統計"""
    total_postings = sum(len(pl) for pl in index.values())
    print(f"詞彙量(vocabulary): {len(index):,}")
    print(f"文件數: {len(corpus)}")
    print(f"總 posting 數: {total_postings:,}")
    # 最長的 10 條 posting list
    top = sorted(index.items(), key=lambda x: -len(x[1]))[:10]
    print("最高頻詞:")
    for term, pl in top:
        print(f"  {term!r:20s} → {len(pl)} 篇文件")

里程碑 3 — 布林檢索

有了倒排索引，最簡單的查詢模式是布林檢索(Boolean retrieval)： 回傳「完全匹配」條件的文件集合，沒有排名。 AND 查詢代表「兩個詞都要有」，OR 代表「至少有一個」，NOT 代表「不含某詞」。

AND 查詢的核心操作是「合併兩條已排序的 posting list 取交集」—— 這正是第 28 章的雙指標合併，時間複雜度 $O(|P_1| + |P_2|)$， 遠優於 $O(|P_1| \times |P_2|)$ 的暴力比對。 

"""
milestone3_boolean.py — 布林查詢
"""
def posting_ids(pl: list[tuple]) -> list[str]:
    """從 posting list 取出 doc_id 列表"""
    return [doc_id for doc_id, _ in pl]

def intersect(list1: list[str], list2: list[str]) -> list[str]:
    """AND: 雙指標合併取交集，O(m+n)"""
    result, i, j = [], 0, 0
    while i < len(list1) and j < len(list2):
        if list1[i] == list2[j]:
            result.append(list1[i]); i += 1; j += 1
        elif list1[i] < list2[j]:
            i += 1
        else:
            j += 1
    return result

def union(list1: list[str], list2: list[str]) -> list[str]:
    """OR: 雙指標合併取聯集"""
    result, i, j = [], 0, 0
    while i < len(list1) and j < len(list2):
        if list1[i] == list2[j]:
            result.append(list1[i]); i += 1; j += 1
        elif list1[i] < list2[j]:
            result.append(list1[i]); i += 1
        else:
            result.append(list2[j]); j += 1
    result.extend(list1[i:]); result.extend(list2[j:])
    return result

def boolean_query(index: dict, query: str) -> list[str]:
    """
    支援 AND / OR / NOT 的簡易查詢解析器
    例: "python AND fast"  "search OR index"  "python NOT slow"
    """
    if " AND " in query:
        terms = [t.strip() for t in query.split(" AND ")]
        results = posting_ids(index.get(terms[0], []))
        for term in terms[1:]:
            results = intersect(results, posting_ids(index.get(term, [])))
        return results
    elif " OR " in query:
        terms = [t.strip() for t in query.split(" OR ")]
        results = posting_ids(index.get(terms[0], []))
        for term in terms[1:]:
            results = union(results, posting_ids(index.get(term, [])))
        return results
    elif " NOT " in query:
        pos_term, neg_term = [t.strip() for t in query.split(" NOT ", 1)]
        pos = set(posting_ids(index.get(pos_term, [])))
        neg = set(posting_ids(index.get(neg_term, [])))
        return sorted(pos - neg)
    else:
        return posting_ids(index.get(query.strip(), []))

里程碑 4 — 排序:TF-IDF 與 BM25

布林檢索只能告訴你「有沒有」，無法告訴你「哪篇最相關」。 真實的搜尋引擎需要排序模型(ranking model)，給每篇文件算出一個分數，依分數由高到低回傳。

TF-IDF:詞頻-逆文件頻率

直覺：一個詞在一篇文件裡出現越多次(高 TF)，代表這篇文件越相關； 但如果這個詞在幾乎每篇文件裡都出現(高 DF)，它其實沒什麼鑑別力——IDF 用來懲罰這類詞。

設文件集大小為 $N$，詞 $t$ 的文件頻率為 $df_t$，TF-IDF 定義為：

$$\text{TF-IDF}(t, d) = \underbrace{f(t, d)}_{\text{詞頻 tf}} \cdot \underbrace{\log\frac{N}{df_t}}_{\text{逆文件頻率 idf}}$$

BM25:更強的排序公式

TF-IDF 有個問題：詞頻再高，分數也會一直上漲，沒有飽和效果。 BM25(Best Match 25) 是 Okapi BM25 的簡稱，加入詞頻飽和與文件長度正規化， 是目前工業界最常用的關鍵字排序基線：

$$\text{BM25}(q, d) = \sum_{t \in q} \text{IDF}(t) \cdot \frac{f(t,d)\,(k_1+1)}{f(t,d) + k_1\!\left(1 - b + b\,\dfrac{|d|}{\text{avgdl}}\right)}$$

其中 IDF 使用修正版公式(避免負值)：

$$\text{IDF}(t) = \ln\!\left(\frac{N - n_t + 0.5}{n_t + 0.5} + 1\right)$$

參數 $k_1 \in [1.2, 2.0]$ 控制詞頻飽和速度；$b \in [0, 1]$ 控制文件長度正規化強度($b=0.75$ 是慣例)。 $|d|$ 是文件長度，$\text{avgdl}$ 是語料平均文件長度。 

"""
milestone4_bm25.py — TF-IDF 與 BM25 排序
"""
import math
from collections import defaultdict

def compute_idf(index: dict, N: int) -> dict[str, float]:
    """計算每個詞的 IDF(BM25 修正版)"""
    idf = {}
    for term, pl in index.items():
        n_t = len(pl)
        idf[term] = math.log((N - n_t + 0.5) / (n_t + 0.5) + 1)
    return idf

def bm25_score(
    query_tokens: list[str],
    doc_id: str,
    tf_map: dict,          # {term: {doc_id: freq}}
    idf: dict[str, float],
    doc_len: int,
    avgdl: float,
    k1: float = 1.5,
    b: float = 0.75,
) -> float:
    """計算單篇文件對一個查詢的 BM25 分數"""
    score = 0.0
    for term in query_tokens:
        if term not in idf:
            continue
        f = tf_map.get(term, {}).get(doc_id, 0)
        numerator = f * (k1 + 1)
        denominator = f + k1 * (1 - b + b * doc_len / avgdl)
        score += idf[term] * numerator / denominator
    return score

def bm25_search(
    query: str,
    corpus: dict[str, list[str]],
    index: dict,
    top_k: int = 5,
) -> list[tuple]:
    """
    BM25 排序搜尋，回傳 [(doc_id, score), ...] top_k 筆
    """
    from milestone1_preprocess import tokenize  # 重用分詞函式
    query_tokens = tokenize(query)

    N = len(corpus)
    doc_lengths = {doc_id: len(tokens) for doc_id, tokens in corpus.items()}
    avgdl = sum(doc_lengths.values()) / N

    idf = compute_idf(index, N)

    # 建立 tf 查找表: {term: {doc_id: freq}}
    tf_map: dict[str, dict[str, int]] = defaultdict(dict)
    for term, pl in index.items():
        for doc_id, freq in pl:
            tf_map[term][doc_id] = freq

    # 只考慮包含至少一個查詢詞的候選文件
    candidates: set[str] = set()
    for token in query_tokens:
        for doc_id, _ in index.get(token, []):
            candidates.add(doc_id)

    # 計算 BM25 分數並排序
    scored = [
        (doc_id, bm25_score(
            query_tokens, doc_id, tf_map, idf,
            doc_lengths[doc_id], avgdl
        ))
        for doc_id in candidates
    ]
    scored.sort(key=lambda x: -x[1])
    return scored[:top_k]

import math

def cosine_tfidf_search(query: str, corpus, index, top_k=5):
    from milestone1_preprocess import tokenize
    from milestone4_bm25 import compute_idf
    query_tokens = tokenize(query)
    N = len(corpus)
    idf = compute_idf(index, N)
    # 查詢向量
    q_vec = {}
    for t in query_tokens:
        q_vec[t] = q_vec.get(t, 0) + 1
    for t in q_vec:
        q_vec[t] = (1 + math.log(q_vec[t])) * idf.get(t, 0)
    q_norm = math.sqrt(sum(v**2 for v in q_vec.values()))
    # 文件向量 & 相似度
    scores = {}
    for term, weight in q_vec.items():
        for doc_id, tf in index.get(term, []):
            d_weight = (1 + math.log(tf)) * idf.get(term, 0)
            scores[doc_id] = scores.get(doc_id, 0) + weight * d_weight
    # 除以範數(需預先算好文件 norm，此處省略)
    return sorted(scores.items(), key=lambda x: -x[1])[:top_k]

里程碑 5 — 連結分析:PageRank

關鍵字評分只看文件本身的內容；但網頁的「重要性」還取決於誰連到它。 1996 年，Larry Page 提出 PageRank：把超連結視為「投票」， 被高品質頁面連結的頁面本身也更有可能是高品質的——這是一個循環定義， 用線性代數的語言，它正是第 30 章圖的隨機遊走(random walk)的穩態分布。

設有 $N$ 個頁面，$B_u$ 是所有連結到 $u$ 的頁面集合，$L(v)$ 是頁面 $v$ 的出鏈數量，阻尼因子 $d \approx 0.85$：

$$PR(u) = \frac{1-d}{N} + d\sum_{v \in B_u} \frac{PR(v)}{L(v)}$$

直覺：想像一個隨機上網者，有 $d = 85\%$ 的機率點擊當前頁面的連結， 有 $1-d = 15\%$ 的機率隨機跳到任意頁面。PageRank 就是這個隨機遊走的長期停留機率。 它也等同於第 54 章轉移矩陣的主特徵向量(dominant eigenvector)。 

"""
milestone5_pagerank.py — 冪迭代法計算 PageRank
"""

def pagerank(
    graph: dict[str, list[str]],  # {page: [outbound_links]}
    d: float = 0.85,
    max_iter: int = 100,
    tol: float = 1e-6,
) -> dict[str, float]:
    """
    graph: 有向圖，{node: [neighbors]}
    回傳每個節點的 PageRank 分數
    """
    nodes = list(graph.keys())
    N = len(nodes)
    # 初始化:每個頁面得到相同 PR
    pr = {node: 1.0 / N for node in nodes}

    # 預先計算每個節點的出鏈數量
    out_degree = {node: len(links) for node, links in graph.items()}

    for iteration in range(max_iter):
        new_pr = {}
        for u in nodes:
            # 隨機跳轉的基礎分
            rank_sum = (1 - d) / N
            # 收集所有入鏈的貢獻
            for v, links in graph.items():
                if u in links:
                    if out_degree[v] > 0:
                        rank_sum += d * pr[v] / out_degree[v]
            new_pr[u] = rank_sum

        # 檢查收斂:所有 PR 值的變化量 < tol
        delta = sum(abs(new_pr[u] - pr[u]) for u in nodes)
        pr = new_pr
        if delta < tol:
            print(f"收斂於第 {iteration+1} 次迭代, delta={delta:.2e}")
            break
    else:
        print(f"達到最大迭代次數 {max_iter}")

    return pr

# ── 範例: 5 個頁面的小圖 ──────────────────────────
if __name__ == "__main__":
    graph = {
        "A": ["B", "C"],
        "B": ["C"],
        "C": ["A"],
        "D": ["C"],
        "E": ["D"],
    }
    scores = pagerank(graph)
    ranked = sorted(scores.items(), key=lambda x: -x[1])
    print("\nPageRank 排名:")
    for page, score in ranked:
        print(f"  {page}: {score:.6f}")
    # 預期 C 最高(被 A, B, D 連入)
⚠️
Dangling Nodes(懸掛節點)

沒有出鏈的頁面(dangling node)會造成 PageRank 的總質量洩漏。 常見處理方式：把它的 PR 值均分給所有頁面（等同於加一條連到所有節點的虛擬邊）。

里程碑 6 — 語意向量檢索

關鍵字搜尋有個根本的缺陷：它只比對文字，不理解語意。 搜尋「速度快的程式語言」找不到只提到「high-performance」的文件。 語意向量檢索(semantic vector search)用嵌入向量(embedding)解決這個問題： 把每篇文件和每個查詢映射到同一個語意空間，用餘弦相似度找最近鄰。

這正是第 96 章「手刻最小 RAG」的核心技術。 我們在這裡接上它，用 sentence-transformers 這個輕量函式庫取得語意嵌入。 

"""
milestone6_semantic.py — 語意向量檢索
pip install sentence-transformers numpy
"""
import numpy as np
from sentence_transformers import SentenceTransformer

# 載入預訓練多語言嵌入模型
model = SentenceTransformer("paraphrase-multilingual-MiniLM-L12-v2")

def embed_corpus(corpus: dict[str, list[str]]) -> dict[str, np.ndarray]:
    """把每篇文件(token 拼回字串)轉成嵌入向量"""
    doc_embeddings = {}
    doc_ids = list(corpus.keys())
    texts = [" ".join(tokens) for tokens in corpus.values()]
    vectors = model.encode(texts, convert_to_numpy=True, show_progress_bar=True)
    for doc_id, vec in zip(doc_ids, vectors):
        # L2 正規化，方便用點積計算餘弦相似度
        doc_embeddings[doc_id] = vec / np.linalg.norm(vec)
    return doc_embeddings

def semantic_search(
    query: str,
    doc_embeddings: dict[str, np.ndarray],
    top_k: int = 5,
) -> list[tuple]:
    """語意最近鄰搜尋"""
    q_vec = model.encode([query], convert_to_numpy=True)[0]
    q_vec = q_vec / np.linalg.norm(q_vec)
    # 計算餘弦相似度(已正規化，等於點積)
    scores = {
        doc_id: float(np.dot(q_vec, d_vec))
        for doc_id, d_vec in doc_embeddings.items()
    }
    return sorted(scores.items(), key=lambda x: -x[1])[:top_k]

def hybrid_search(
    query: str,
    corpus,
    index,
    doc_embeddings: dict,
    alpha: float = 0.5,
    top_k: int = 5,
) -> list[tuple]:
    """
    混合排序 = alpha * BM25 + (1-alpha) * 語意相似度
    alpha=1: 純關鍵字; alpha=0: 純語意
    """
    from milestone4_bm25 import bm25_search
    bm25_results = dict(bm25_search(query, corpus, index, top_k=20))
    sem_results  = dict(semantic_search(query, doc_embeddings, top_k=20))
    # 正規化分數到 [0,1]
    def normalize(d):
        if not d: return d
        lo, hi = min(d.values()), max(d.values())
        if hi == lo: return {k: 1.0 for k in d}
        return {k: (v - lo) / (hi - lo) for k, v in d.items()}
    bm25_n = normalize(bm25_results)
    sem_n  = normalize(sem_results)
    all_docs = set(bm25_n) | set(sem_n)
    combined = {
        doc: alpha * bm25_n.get(doc, 0) + (1 - alpha) * sem_n.get(doc, 0)
        for doc in all_docs
    }
    return sorted(combined.items(), key=lambda x: -x[1])[:top_k]
ℹ️
大規模近似最近鄰(ANN)

百萬文件量級時，暴力計算所有文件的餘弦相似度太慢($O(N)$ per query)。 工業界用 FAISS、HNSW 等近似最近鄰(Approximate Nearest Neighbor, ANN)演算法， 在亞線性時間找到 top-k，召回率 > 95%。 詳見第 96 章的向量資料庫小節。

🔑
里程碑 6 驗收

搜尋「高效能程式語言」，純關鍵字 BM25 與語意搜尋的排名可能不同。 混合排序(alpha=0.5)通常比任一單一方法都好。

里程碑 7 — 查詢介面與評估指標

搜尋引擎寫好了，怎麼知道它「夠好」？光看幾個例子不可靠——你需要量化的評估指標。 資訊檢索的評估體系從第 38 章的分類指標出發， 延伸到排序感知的 MAP 與 nDCG。

精準率與召回率

對一個查詢，設相關文件集合為 $R$，系統回傳的集合為 $A$：

$$\text{Precision} = \frac{|R \cap A|}{|A|} \qquad \text{Recall} = \frac{|R \cap A|}{|R|}$$

MAP — 平均精準率的平均

Average Precision(AP)對每個查詢計算「在每個相關文件被召回的位置上，precision 的平均值」； MAP(Mean Average Precision)再對所有查詢取平均：

$$\text{AP}(q) = \frac{1}{|R_q|}\sum_{k=1}^{|A|} P@k \cdot \text{rel}(k) \qquad \text{MAP} = \frac{1}{|Q|}\sum_{q \in Q} \text{AP}(q)$$

nDCG — 正規化折扣累積增益

MAP 把相關性視為二元(相關/不相關)；nDCG 支援多級相關性評分(例如 0–3 分)：

$$\text{DCG}@k = \sum_{i=1}^{k} \frac{2^{\text{rel}_i} - 1}{\log_2(i+1)} \qquad \text{nDCG}@k = \frac{\text{DCG}@k}{\text{IDCG}@k}$$ 
"""
milestone7_evaluate.py — 評估指標
"""
import math

def precision_at_k(retrieved: list[str], relevant: set[str], k: int) -> float:
    """P@k: 前 k 個結果中有幾個相關"""
    top_k = retrieved[:k]
    return sum(1 for doc in top_k if doc in relevant) / k

def average_precision(retrieved: list[str], relevant: set[str]) -> float:
    """AP: 相關文件出現位置的 precision 平均"""
    if not relevant:
        return 0.0
    hits, ap = 0, 0.0
    for i, doc in enumerate(retrieved, 1):
        if doc in relevant:
            hits += 1
            ap += hits / i
    return ap / len(relevant)

def ndcg_at_k(retrieved: list[str], relevance: dict[str, int], k: int) -> float:
    """
    nDCG@k: 正規化折扣累積增益
    relevance: {doc_id: grade}，grade 可為 0-3
    """
    def dcg(docs, rel, cutoff):
        return sum(
            (2 ** rel.get(doc, 0) - 1) / math.log2(i + 2)
            for i, doc in enumerate(docs[:cutoff])
        )
    ideal = sorted(relevance.values(), reverse=True)
    ideal_docs = [f"__ideal_{i}__" for i in range(len(ideal))]
    ideal_rel  = {d: g for d, g in zip(ideal_docs, ideal)}
    idcg = dcg(ideal_docs, ideal_rel, k)
    if idcg == 0:
        return 0.0
    return dcg(retrieved, relevance, k) / idcg

def evaluate_system(
    queries: dict[str, str],      # {qid: query_text}
    qrels:   dict[str, set[str]], # {qid: set of relevant doc_ids}
    search_fn,                    # callable: (query_text) -> [(doc_id, score)]
) -> dict:
    """對所有查詢計算評估指標並輸出報告"""
    aps, ndcgs, p10s = [], [], []
    for qid, query in queries.items():
        results = [doc_id for doc_id, _ in search_fn(query)]
        relevant = qrels.get(qid, set())
        ap  = average_precision(results, relevant)
        p10 = precision_at_k(results, relevant, k=10)
        ng  = ndcg_at_k(results, {d: 1 for d in relevant}, k=10)
        aps.append(ap); p10s.append(p10); ndcgs.append(ng)
    return {
        "MAP":     sum(aps)   / len(aps),
        "P@10":    sum(p10s)  / len(p10s),
        "nDCG@10": sum(ndcgs) / len(ndcgs),
    }

✏️ 練習 120.4 思考

一個系統回傳 20 篇文件，其中 10 篇相關，全部放在後 10 名； 另一個系統只回傳 5 篇，全部相關。哪個系統的 P@5 較高？哪個 MAP 較高？

看解答

P@5：第一系統前 5 名全不相關，P@5 = 0；第二系統前 5 名全相關，P@5 = 1.0。 第二系統勝。

MAP：第一系統的 10 個相關文件在位置 11–20，AP 很低（< 0.1）； 第二系統 5 個相關文件全在前 5，AP = 1.0。第二系統仍然勝。

這說明 MAP 同時獎勵高精準與早期召回，而 Recall 單指標會被第一系統矇騙。
