## 1. 動機與目標(why)

使用者要幫自己任教的大學部「計算機網路概論」學生準備**期中考**。這場考試偏傳統紙筆形式,題型是**名詞解釋**與**計算題**,範圍涵蓋整個學期(全部五層),**沒有**現成的講義/投影片/考古題可參考,因此內容直接依課本常見主題(本書第 25 章 + Kurose & Ross)自編,不追求貼合某一份特定教材的原題。

目標:在這個 repo 裡新增一頁**互動式考前衝刺附錄**,讓學生可以直接在瀏覽器裡:
1. 用抽認卡反覆自我測驗名詞解釋,直到五層的術語都「會了」。
2. 用會隨機換數字的計算題反覆練習到真正掌握公式與算法,而不是背答案。
3. 額外用固定範例題練習路由演算法的手算追蹤(因為這類題隨機出圖容易「答案不唯一」,見第 4.3 節)。

## 2. Non-goals / Anti-goals

- **不是**帶帳號、雲端進度同步的系統——純前端、不連後端,學生進度不跨裝置保存(可用 localStorage 做單機方便性,但不是硬需求)。
- **不取代**本書第 25 章的內文與現有 15 題「點開看解答」練習,是額外的附錄頁。
- **不追求窮舉**每一種可能的計算題型——聚焦在最常考的代表性題型(第 4.2 節六種 + 第 4.3 節路由),避免範圍無限擴張。
- Anti-goals(踩到就算失敗):
  - 頁面無法通過 `chapters/_validate_chapter.py` 或 `_check_chapter_refs.py`。
  - 隨機生成的計算題出現「無解」或「多組同樣合理的答案」(尤其 CIDR 子網、CRC、Shannon/Nyquist 的邊界值)。
  - 引入任何外部 JS 框架或 CDN——違反本書「純 vanilla JS + 既有資源」的既定慣例([唯一先例](../../..) 是 `assets/toi/*.js`)。
  - 名詞解釋或計算題的內容對一般大學部「計算機網路概論」期中考範圍而言過於進階(例如研究所等級的 queueing theory 證明)。

**詞庫草稿(共 50 條,按層分類;定義為初版文字,實作階段可微調措辭)**:

> 以下詞庫已併入 MIT OCW 調查(第 6 節)篩選出的補強詞彙(DNS 細節、編碼方式、交換技術、learning bridge/spanning tree、FEC vs ARQ),共 64 條。

#### 應用層
1. **HTTP**——全球資訊網的應用層協定,採用請求-回應(request-response)模式傳遞網頁內容。
2. **無狀態協定(Stateless protocol)**——伺服器不會記住先前請求的任何資訊,每個請求都獨立處理;HTTP 本身無狀態,需靠 Cookie 維持狀態。
3. **Cookie**——伺服器要求瀏覽器儲存的一小段資料,之後每次請求會附帶回傳,用來辨識使用者、維持登入狀態等。
4. **DNS(網域名稱系統)**——將人類易記的網域名稱轉換成 IP 位址的分散式資料庫系統。
5. **遞迴查詢 vs 迭代查詢**——遞迴查詢:被問到的伺服器代為向下一台問,直到拿到答案才回覆;迭代查詢:被問到的伺服器只回「下一個該問誰」,由發問端自己繼續問。
6. **Root / TLD / 權威名稱伺服器**——三層階層式架構:root 伺服器知道各 TLD 伺服器在哪,TLD 伺服器知道該網域的權威伺服器在哪,權威伺服器儲存真正的 DNS 記錄。
7. **Resolver:stub resolver vs recursive resolver**——stub resolver 是主機上簡單的查詢用戶端,只把問題轉給設定好的 recursive resolver;recursive resolver 代替使用者完整執行查詢流程。
8. **資源記錄(Resource Record)類型:A / NS / MX / PTR / CNAME**——A 記錄是網域對應的 IPv4 位址;NS 記錄指出該網域的權威伺服器;MX 記錄指出該網域的郵件伺服器;PTR 記錄用於反向查詢(IP 找網域名);CNAME 記錄是別名、指向另一個網域名。
9. **Zone 與 zone transfer**——zone 是 DNS 階層中由同一組織管理的一段命名空間;zone transfer 是主要伺服器把 zone 資料同步給次要伺服器的過程。
10. **正向快取 vs 負向快取與 NXDOMAIN**——正向快取存「查到的答案」;負向快取存「查不到」的結果(NXDOMAIN,表示該名稱不存在),避免重複查詢同一個不存在的名稱。
11. **in-addr.arpa 反向查詢**——把 IP 位址反過來寫成特殊網域名稱,用一般的 DNS 查詢機制查出對應的主機名稱。
12. **URL**——統一資源定位器,指出資源在網路上的位置(協定、主機、路徑等)。
13. **Web 快取(代理伺服器)**——代替客戶端儲存先前取得的網頁內容,之後相同請求可直接回應,減少延遲與流量。
14. **SMTP**——電子郵件在伺服器之間傳遞所使用的應用層協定。
15. **P2P 架構 vs Client-Server 架構**——P2P 每個節點同時是客戶端與伺服器、沒有一直在線的中心伺服器;Client-Server 客戶端向固定的伺服器請求服務。

#### 傳輸層
16. **TCP**——傳輸控制協定,提供可靠、有序、位元流導向、具流量與壅塞控制的連接導向服務。
17. **UDP**——使用者資料包協定,無連接、不保證送達與順序,但開銷小、延遲低。
18. **連接埠號與多工/解多工**——連接埠號區分同一台主機上不同的應用程式;多工是傳送端把多個 process 的資料加上埠號送出,解多工是接收端依埠號送回正確 process。
19. **三向交握(Three-way handshake)**——TCP 建立連線的過程:SYN → SYN+ACK → ACK,雙方交換初始序號以同步。
20. **滑動視窗(Sliding window)**——允許傳送端在收到確認前連續送出多個封包,視窗大小決定可同時在途的資料量。
21. **流量控制 vs 壅塞控制**——流量控制避免傳送太快讓接收端來不及處理(考慮接收端);壅塞控制避免傳送太快讓網路本身塞住(考慮網路狀況)。
22. **累積確認(Cumulative ACK)**——ACK 號碼表示「這個號碼之前的資料都已收到」,不是逐筆確認。
23. **Go-Back-N vs Selective Repeat**——Go-Back-N 一旦有封包遺失或逾時,從該封包開始後面全部重傳;Selective Repeat 只重傳真正遺失的那個封包。
24. **壅塞視窗(cwnd)與慢啟動(Slow start)**——cwnd 是傳送端依網路壅塞狀況自行調整的視窗;慢啟動階段 cwnd 指數成長,過門檻值後轉線性成長(AIMD)。
25. **RTT 與逾時重傳**——RTT 是封包來回一趟的時間;逾時時間依估計 RTT 與其變異動態調整,逾時沒收到 ACK 就重傳。
26. **Segment(區段)**——傳輸層的資料單位,TCP/UDP 標頭加上酬載後稱為 segment。

#### 網路層
27. **IP 位址與子網遮罩**——IP 位址分網路部分與主機部分,子網遮罩決定兩者的分界。
28. **CIDR**——跳脫傳統 A/B/C 類別的定長網路部分,改用「位址/前綴長度」表示,更彈性地分配位址空間。
29. **路由(Routing) vs 轉送(Forwarding)**——路由是決定封包該走哪條路徑的全域/長期決策(建立路由表);轉送是路由器收到封包後依路由表送到正確出口的本地/即時動作。
30. **距離向量 vs 連結狀態**——距離向量:每個節點只跟鄰居交換「自己到各目的地的距離」逐漸收斂(如 RIP);連結狀態:每個節點先取得全網拓樸,再各自用 Dijkstra 算出最短路徑(如 OSPF)。
31. **自治系統(AS)**——由同一個組織管理、使用同一套內部路由政策的一群網路集合。
32. **NAT**——網路位址轉換,讓多台使用私有位址的主機共用一個公開 IP 對外連線。
33. **DHCP**——動態主機設定協定,自動幫新加入網路的主機分配 IP 等設定。
34. **封包交換 vs 電路交換**——封包交換:資料切成封包各自獨立選路、共享頻寬;電路交換:傳送前先建立專用通道,整段期間獨占頻寬。
35. **資料包式路由 vs 虛擬電路**——資料包式(datagram routing):每個封包獨立帶完整位址、各自選路(如 IP);虛擬電路(virtual circuit):先建立一條邏輯路徑,之後封包沿同一路徑走、標頭只需簡短的電路編號。
36. **VC 識別碼:VPI/VCI**——虛擬電路中標示「這個封包屬於哪條虛擬電路」的編號,交換器依此查表轉送,類似簡化版的位址。
37. **來源路由(Source routing)**——由傳送端事先決定完整路徑,並把整條路徑資訊放進封包標頭,中間節點只需照著走。
38. **MPLS**——標籤交換技術,在 IP 封包前加一個簡短標籤,讓核心路由器用標籤查表轉送而不必查完整 IP 路由表,兼具電路交換的效率與封包交換的彈性。
39. **分片(Fragmentation)**——封包大小超過連結 MTU 時,切成多個較小片段分別傳送,到達目的地後再重組。
40. **TTL**——封包每經過一個路由器就遞減的欄位,到 0 就丟棄,避免封包在迴圈中無限繞行。
41. **ICMP**——用於回報網路錯誤與診斷(如 ping、traceroute)的網路層輔助協定。

#### 資料鏈結層
42. **MAC 位址**——燒錄在網路卡上、全球唯一的實體位址,用於同一區域網路內辨識裝置。
43. **ARP**——位址解析協定,把已知的 IP 位址查出同網段內對應的 MAC 位址。
44. **CSMA/CD**——載波感測多重存取/碰撞偵測,傳統乙太網路處理共用線路碰撞的機制:先聽再送、邊送邊聽、偵測到碰撞就停止並隨機延遲重送。
45. **交換器 vs 集線器**——集線器把訊號複製廣播到所有埠;交換器會學習 MAC 位址,只把訊框送到正確的埠。
46. **Learning bridge(自學習橋接器)**——交換器觀察收到訊框的來源 MAC 位址,記錄「這個位址在哪個埠」,之後同一目的位址就不用再廣播,只送到學到的那個埠。
47. **Spanning tree algorithm(展開樹演算法)**——多台交換器相連可能形成迴圈導致廣播風暴,展開樹演算法讓交換器們協調出一棵沒有迴圈的樹狀拓樸來轉送訊框(概念上與 Dijkstra 都是「找一棵樹」,但目標不同:一個是最短路徑樹,一個是避免迴圈的生成樹)。
48. **錯誤偵測:同位檢查 / CRC / Checksum**——同位檢查只能抓奇數個錯誤;CRC 用生成多項式做二進位除法得到餘數,偵錯能力強(乙太網路使用);Checksum 用補數加法,運算簡單但偵錯能力較弱(TCP/IP/UDP 使用)。
49. **錯誤恢復:FEC vs ARQ**——FEC(前向錯誤更正):傳送端多送冗餘資訊,接收端自己就能更正錯誤,不用重傳;ARQ(自動重傳請求):接收端只偵測錯誤,發現錯就要求重傳。
50. **訊框(Frame)**——資料鏈結層的資料單位,封包加上鏈結層標頭(含來源/目的 MAC)後稱為訊框。
51. **位元填塞(Bit stuffing)**——當資料本身恰好出現跟訊框起始/結束標記相同的位元組合時,故意插入額外位元打斷它,避免接收端誤判訊框邊界。
52. **VLAN**——虛擬區域網路,用邏輯方式把實體交換器的埠劃分成多個獨立的廣播網域。

#### 實體層
53. **類比訊號 vs 數位訊號**——類比是連續變化的訊號;數位是離散(通常 0/1)的訊號。
54. **導引媒介 vs 非導引媒介**——導引:訊號沿實體介質傳遞(雙絞線、光纖);非導引:訊號透過空間傳播(無線電波)。
55. **位元率 vs 鮑率**——鮑率是每秒傳送的訊號符號數;位元率是每秒傳送的位元數,位元率 = 鮑率 × 每符號位元數。
56. **數位訊號編碼:NRZ / NRZI / Manchester / 4B/5B**——NRZ(不歸零):0/1 直接對應高/低電壓,長串相同位元時難同步;NRZI:用「訊號是否反轉」表示 0/1;Manchester:每個位元中間一定有一次電壓轉換,方便同步但頻寬效率較低;4B/5B:把 4 個資料位元編碼成 5 個傳輸位元,保證有足夠的訊號轉換次數。
57. **Nyquist 定理**——無噪音理想通道下,頻寬 B、L 個訊號層次時,最大資料率為 2B·log₂L。
58. **Shannon 定理**——有噪音通道下,頻寬 B、訊號對雜訊比 SNR 時,理論通道容量為 B·log₂(1+SNR)。
59. **衰減 vs 雜訊**——衰減是訊號強度隨距離減弱;雜訊是傳輸過程中混入的非預期干擾訊號。
60. **多工:TDM / FDM / WDM / CDM**——TDM 分時、FDM 分頻;WDM(分波多工)是光纖世界的 FDM(用不同波長的光同時傳輸);CDM(分碼多工)讓所有使用者同時共用全部頻寬與時間,靠不同的編碼序列區分(行動通訊 CDMA 的基礎)。

#### 跨層共用概念
61. **OSI 七層 vs TCP/IP 模型**——OSI 分七層(多展示層、會議層);TCP/IP 實務上簡化成四或五層,兩者在網路層、傳輸層概念基本對應。
62. **封裝(Encapsulation)**——資料往下層傳遞時,每層都加上自己的標頭,形成訊息→區段→封包→訊框的過程。
63. **端到端原則(End-to-end principle)**——只要功能能由端點正確、完整實作,就不放進網路核心(路由器)做,讓網路保持簡單。
64. **延遲的四個組成**——節點處理延遲、佇列延遲、傳輸延遲(= 封包大小/頻寬)、傳播延遲(= 距離/傳播速度)。

### 4.2 計算題隨機驗算(八種題型,含 MIT OCW 調查補強的 C7/C8)

每題「換一題」時重新抽一組隨機參數,正解即時用同一套公式算出並比對使用者輸入(數字容許小範圍誤差),「看詳解」預設收合、展開後逐步代入**本次抽到的數字**顯示算式。

| 題型 | 題目骨架 | 隨機參數 | 公式/演算法 |
|---|---|---|---|
| C1 實體層:Nyquist / Shannon 通道容量 | 隨機二選一出題:(a) 給頻寬 B 與訊號層次 L,求 Nyquist 最大資料率;(b) 給頻寬 B 與 SNR(dB),求 Shannon 通道容量 | B∈{1,2,3,5,10,20}MHz;L∈{2,4,8,16};SNR∈{10,15,20,25,30}dB | Nyquist: C=2B·log₂L;Shannon: 先把 dB 轉線性 SNR=10^(dB/10),再 C=B·log₂(1+SNR) |
| C2 資料鏈結層:CRC 餘數 / 驗證 | 隨機二選一出題:(a) 給資料位元序列 D 與生成多項式位元 G,求附加的 CRC 檢查碼 R;(b)【MIT OCW 6.263J PS1 補強】給 G 與**收到的**字串 T,判斷傳輸有無錯誤(只需做除法看餘數是否為 0,不用重算出完整 R) | 用幾組常見教科書 generator(如 1001、1011、1101,r=3 或 4);D/T 長度 8–12 bits 隨機生成;(b) 題故意讓約一半的 T 帶錯誤 | D(或 T)補/含 r 個檢查位元後對 G 做模二(XOR)除法;(a) 餘數即 R,(b) 餘數非 0 即判定有錯;詳解逐步列出每輪 XOR |
| C3 網路層:CIDR 子網劃分 | 給網段 base/prefix、要切成 n 個等大小子網,求第 k 個子網的網路位址與可用主機數 | prefix∈{16,20,22,24};n∈{2,4,8,16}(皆 2 的冪,避免歧義);k∈[1,n];base 為該 prefix 下對齊的位址 | 新遮罩=prefix+log₂n;子網大小=2^(32−新遮罩);第 k 個網路位址=base + (k−1)×子網大小;可用主機數=子網大小−2 |
| C4 傳輸層:封包傳送總延遲 | 檔案大小 L 經 N 個路由器(N+1 段連結)送達,每段速率 R、傳播延遲 Dprop,求端到端總延遲(store-and-forward,忽略處理/佇列延遲) | L∈{1,2,4,8}MB;N∈{1,2,3,4};R∈{1,10,100}Mbps;Dprop∈{1,2,5,10}ms | Total = (N+1)×(L/R) + (N+1)×Dprop |
| C5 傳輸層:頻寬延遲乘積 | 給頻寬 R、RTT,求 BDP 並說明其意義 | R∈{1,10,100,1000}Mbps;RTT∈{10,20,50,100,200}ms | BDP = R × RTT(注意單位換算成 bits) |
| C6 傳輸層:TCP 視窗限制下的有效傳輸量 | 給 RTT、接收視窗 W(忽略 cwnd 限制),求最大有效傳輸量,並與連結頻寬 R 比較是否為瓶頸;【MIT OCW 6.263J PS2 補強,簡化版】隨機附帶一個 W = 1 個封包大小的變化題,退化為 stop-and-wait,效率 = 傳輸時間/(傳輸時間+RTT),當簡化前導題 | RTT∈{20,50,100,150,200}ms;W∈{8,16,32,64}KB;R∈{1,10,100}Mbps | Throughput = W / RTT;比較 throughput 與 R 判斷瓶頸;stop-and-wait 效率 = Ttrans/(Ttrans+RTT) |
| C7(新增,【MIT OCW 6.829 L1 補強】)資料鏈結層/電路交換:TDM 頻寬分配與 time slot 長度 | 給連結總頻寬 C 與通道數 N,求每通道頻寬 R;給封包大小 s,求 time slot 長度 | C∈{10,100,1000}Mbps;N∈{4,8,16,32};s∈{64,128,256,512}bytes(常見訊框大小) | R = C/N;time slot 長度 = s/C |
| C8(新增、選用/加分,【MIT OCW 6.829 L0 補強】)資料鏈結層:Slotted ALOHA 效率 | 給 N 個站點、每站傳送機率 p,求某時槓恰好一個站點成功傳送的機率(通道使用率);並討論 N→∞、p=1/N 時效率逼近 1/e≈36.8% | N∈{2,3,4,5,8};p∈{0.1,0.2,0.25,1/N} | 效率 = N·p·(1−p)^(N−1) |
