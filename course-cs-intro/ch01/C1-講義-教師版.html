C1.1 Layers of a Computing System｜計算系統的分層

Hardware, software, and data — organized as layers · 基礎
① 觀念
💡
Concept

A computing system is a dynamic entity made of hardware (the physical elements: chips, boards, wires, storage, I/O devices), software (the programs that give instructions to the hardware), and data (the information the system manages and manipulates).

The book organizes a computing system as layers, like an onion. From the inside out:

Layer What it is about Chapters
Information how numbers, text, images, audio, video are represented in binary 2–3
Hardware gates, circuits, CPU, memory, I/O 4–5
Programming machine language → assembly → high-level languages, algorithms, data structures 6–9
Operating systems managing memory, processes, files; letting programs share the machine 10–11
Applications spreadsheets, databases, AI, simulation, graphics, games 12–14
Communications networks, the Web, security 15–17

Each layer uses the services of the layer below it and offers services to the layer above it. Chapters 1 and 18 look at the system as a whole.

名詞對照
English中文說明
computing system計算系統硬體 + 軟體 + 資料,合起來完成工作的整體
hardware硬體摸得到的實體元件:晶片、主機板、記憶體、硬碟、鍵盤螢幕
software軟體指揮硬體做事的程式
data資料系統處理、儲存的資訊
layer層一組功能;只和相鄰的上下層打交道
application應用程式使用者直接操作的程式
operating system (OS)作業系統管理硬體資源、讓多個程式共用機器的軟體
白話說

電腦不是一個「東西」,而是很多層疊起來的系統。你按下 Enter 讓程式算出答案,這件事從上到下經過:應用程式 → 你寫的高階語言程式 → 編譯器翻成的機器碼 → 作業系統把程式載入、幫它讀鍵盤 → CPU 真正執行指令 → 最底下全部是 0 與 1。

分層的好處是每一層只要懂自己和隔壁。寫網頁的人不必懂電晶體,設計 CPU 的人也不必懂 HTML。這門課就是一層一層往外走,讓你每一層都看過一次。

後面會用到

這張分層圖就是整個資工系課程的地圖:資訊層 → 計算機組織、數位邏輯;硬體層 → 計算機組織;程式層 → 程式設計、資料結構、演算法、編譯器;作業系統層 → 作業系統;應用層 → 資料庫、人工智慧、電腦圖學;通訊層 → 計算機網路、資訊安全。

現代補充

今天的「一台電腦」可能是手機、雲端上的一台虛擬機,或一個容器(container)。層還是那些層,只是中間多了虛擬化:雲端上你看到的「硬體」其實是另一層軟體模擬出來的。第 10 章會再談。

原理為什麼成立

分層之所以有效,是因為每一層都對上層提供一個介面(interface),並把自己的實作細節藏起來。只要介面不變,下層可以整個換掉,上層完全不用改——例如同一支 C 程式可以在 Intel 和 ARM 的 CPU 上重新編譯執行,因為編譯器這一層吸收了兩種機器語言的差異。這個性質就是下一個觀念「抽象」的具體表現。

分層也有代價:每多一層就多一點開銷(翻譯、檢查、資料搬移)。效能要求極高的地方(例如作業系統核心、遊戲引擎)有時會刻意跨層,直接利用下層的細節。

② 老師講解
例 1

A user types echo "1 2 3" | ./sum and sees 6. List, from top to bottom, the layers involved and what each one does in this scenario.

  1. Application(應用層):使用者看到的是一個「加總數字」的小工具;他只關心輸入 1 2 3、輸出 6。
  2. Programming(程式層):sum 是用 C 寫的;一行 while (scanf(...) == 1) total += x; 描述了整個演算法。編譯器把它翻成組合語言、再翻成機器碼。
  3. Operating system(作業系統層):shell 請 OS 建立兩個行程(echo 與 sum),用管線(pipe)把前者的輸出接到後者的輸入;scanf 最後透過系統呼叫向 OS 要資料。
  4. Hardware(硬體層):CPU 依序抓取、解碼、執行機器指令;加法由 ALU 完成,變數放在暫存器或記憶體。
  5. Information(資訊層):鍵盤送進來的是字元 '1'、' '、'2'(ASCII 碼),scanf 把它們轉成二進位整數才能相加;印出時再轉回字元 '6'。
  6. Communications(通訊層):這個例子在單機上完成,沒有用到網路;若改成在遠端伺服器上執行(例如透過 ssh),就會多經過這一層。
例 2

Classify each item as hardware, software, or data: (a) the CPU, (b) a spreadsheet file grades.xlsx, (c) the Excel program, (d) the Linux kernel, (e) an SSD, (f) the text of an email.

  1. 看它是不是摸得到的實體:CPU、SSD 是實體元件 → (a)、(e) 是 hardware。
  2. 看它是不是「指令」:Excel 與 Linux 核心都是一串指揮硬體做事的指令 → (c)、(d) 是 software。其中 Linux 核心屬於作業系統層,Excel 屬於應用層。
  3. 看它是不是被處理的資訊:grades.xlsx 與郵件內文是被程式讀寫的內容 → (b)、(f) 是 data。
  4. 注意:程式本身存在硬碟上時也是一串位元組;「是軟體還是資料」要看它扮演的角色——被 CPU 執行時是軟體,被編譯器讀進來處理時就是資料。
易錯點
  • 把作業系統當成「硬體的一部分」:OS 是軟體,只是離硬體最近。
  • 以為分層是「由外往內」依序執行:其實每個動作都會同時用到很多層,分層是看系統的角度,不是時間順序。
  • 「程式 vs 資料」不是物品的固有屬性,而是角色;例 2 的第 4 步常被忽略。
教學提示

開場可以現場打 echo "1 2 3" | ./sum,再問「這一行按下 Enter 之後發生了哪些事?」讓學生七嘴八舌補,最後對應到六層。Lab 任務 2 的 layers.md 就是這個活動的書面版,建議課堂先示範一段。

    False。作業系統是軟體,屬於作業系統層;它管理硬體,但本身不是硬體。

C1.2 Abstraction｜抽象

Keep only the details you need right now · 基礎
① 觀念
💡
Concept

An abstraction is a mental model that removes complex details: it keeps only the information necessary to accomplish a goal and hides the rest.

In a computing system, every layer is an abstraction of the layers below it. A layer offers an interface (what you can ask it to do) and hides its implementation (how it actually does it). Users of the interface do not need — and should not rely on — the implementation details.

Examples:

  • A function hides its body behind its name and parameters.
  • A file hides disk blocks, sectors, and the physical location of bytes.
  • A high-level language hides registers and machine instructions.
  • A network socket hides packets, routing, and retransmission.
名詞對照
English中文說明
abstraction抽象只留下目前需要的細節,其他藏起來
interface介面外面看得到、可以使用的操作
implementation實作介面背後真正的做法
information hiding資訊隱藏刻意不讓使用者看到(或依賴)實作細節
black box黑盒子只看輸入輸出、不看內部的觀點
白話說

開車的人只需要方向盤、油門、煞車這組介面,不需要懂引擎怎麼噴油點火(實作)。車廠換了一顆引擎,你照樣會開——這就是抽象的價值:底下可以換,上面不用改。

寫程式也一樣。你呼叫 open("a.txt") 讀檔,不用知道檔案被切成哪幾個磁碟區塊;作業系統換了檔案系統,你的程式照跑。

後面會用到
  • 資料結構:抽象資料型別(ADT)就是「介面與實作分開」(本課第 8 章)。
  • 物件導向程式設計:封裝(encapsulation)是抽象的語言機制(第 9 章)。
  • 作業系統:行程、虛擬記憶體、檔案都是 OS 提供的抽象(第 10、11 章)。
  • 計算機網路:協定分層(TCP/IP)每一層都是下一層的抽象(第 15 章)。
原理為什麼成立

抽象讓人能處理複雜系統,是因為它限制了相依性:上層只依賴下層的介面,不依賴實作。形式上可以這樣想——若 A 只透過介面 I 使用 B,那麼任何滿足 I 的 B′ 都能替換 B,而 A 的正確性不受影響。

這也說明了抽象的兩個常見失敗:

  1. 洩漏的抽象(leaky abstraction):下層的細節還是透出來影響上層。例:檔案「抽象」看起來是一串連續位元組,但隨機讀取在傳統硬碟上比循序讀取慢很多——效能細節洩漏了。
  2. 使用者偷看實作:如果上層直接依賴下層的內部(例如直接讀某個私有欄位),下層一換就壞。Lab 任務 3 的隱藏測試會換掉區塊大小,專門抓這種情況。
② 老師講解
例 1

A RawDisk can only read or write whole blocks of a fixed size (for example 64 bytes). Design the interface of a key-value store built on top of it, and explain which details the interface hides.

  1. 先想使用者要什麼:存一個值、拿回一個值、刪掉、列出所有 key。所以介面是 put(key, value)、get(key)、delete(key)、keys()。
  2. 介面裡刻意不出現的東西:區塊編號、區塊大小、值被切成幾塊、索引存在哪。這些都屬於實作。
  3. 錯誤也要用抽象的語言表達:找不到 key 時丟 KeyError,而不是「區塊 17 是空的」這種實作層的訊息。
  4. 檢查抽象是否成立:同一段使用者程式,換一顆區塊大小不同的 disk 還能跑嗎?能 → 介面沒有洩漏區塊大小。
例 2

Identify the interface and the hidden implementation in each: (a) len(my_list) in Python, (b) a car's gas pedal, (c) printf("%d", x) in C.

  1. (a) 介面:「給我一個串列,回傳它的長度」。實作:CPython 的 list 物件內部存了一個長度欄位,len 直接讀它(O(1)),使用者不用知道。
  2. (b) 介面:「踩越深、加速越快」。實作:電子油門、噴油量、點火時間由引擎控制電腦決定。
  3. (c) 介面:「照格式把 x 印出來」。實作:把整數轉成十進位字元、放進緩衝區,最後透過 write 系統呼叫交給作業系統輸出。
  4. 共通點:使用者只靠介面就能正確使用;實作可以更新(例如 C 函式庫改版)而不影響使用者。
易錯點
  • 把「抽象」誤解成「模糊、不精確」:抽象的介面必須很精確(輸入什麼、回傳什麼、錯誤時怎樣),只是不談實作。
  • 介面設計洩漏實作:例如 get_block_for_key(key) 這種名字就把區塊暴露給使用者了。
教學提示

可以讓學生先嘗試「直接用 RawDisk 存一個 1000 位元組的值」,體會沒有抽象有多痛苦,再引入 KVStore。延伸專案 3 讓學生量測抽象層的成本,可在課堂提一句「抽象不是免費的」。

③ 換你練習
  1. 照做

    In one sentence each, define interface and implementation.

    介面:外部使用者可以呼叫的操作與其行為約定(輸入、輸出、錯誤)。實作:介面背後實際完成這些操作的程式碼或機制。

  2. 是非

    True or false: If two implementations provide exactly the same interface and behavior, a program that uses only the interface cannot tell which one it is using (ignoring speed).

    True。這正是抽象讓實作可以替換的原因;唯一可能透露差異的是效能等「洩漏」的細節。

  4. 應用

C1.3 History of Computing Hardware｜計算硬體的歷史

From the abacus to VLSI — and Moore's law · 基礎
① 觀念
💡
Concept

Early history. Devices to help people compute are old: the abacus; Blaise Pascal's mechanical adding machine (1642); Joseph Jacquard's loom controlled by punched cards (1801); Charles Babbage's Difference Engine and the design of the Analytical Engine, which already had a memory, an arithmetic unit, input and output; Ada Lovelace, who wrote what is considered the first program for it; Herman Hollerith's punched-card tabulating machine for the 1890 US census. In 1936 Alan Turing described an abstract machine that defines what can be computed. ENIAC (1946) was one of the first large electronic general-purpose computers.

Generations of hardware (the definition used in this course; a boundary year belongs to the new generation):

Generation Years Key technology
1 1951–1958 vacuum tubes; magnetic drum memory; punched cards and magnetic tape
2 1959–1964 transistors; magnetic core memory; magnetic disks
3 1965–1970 integrated circuits (IC); terminals; more memory
4 1971– LSI / VLSI: a whole CPU on one chip (the microprocessor); personal computers

After the fourth generation, progress is described less by component technology and more by parallel computing (many processors working together) and networking (Ethernet in the 1970s, the Internet).

Moore's law: Gordon Moore observed (1965; revised 1975) that the number of transistors on a chip doubles roughly every two years. As a model:

$$N(t) = N_0 \cdot 2^{(t - t_0)/2}$$

名詞對照
English中文說明
vacuum tube真空管第一代電子計算機的開關元件,體積大、耗電、易壞
transistor電晶體第二代起的開關元件,小、省電、可靠
integrated circuit (IC)積體電路很多電晶體做在同一塊矽晶片上
LSI / VLSI大型/超大型積體電路一顆晶片上有上萬到上億個電晶體
microprocessor微處理器整顆 CPU 做在一顆晶片上(Intel 4004,1971)
Moore's law摩爾定律晶片上的電晶體數約每兩年加倍的經驗法則
parallel computing平行計算多個處理器同時處理同一個問題
白話說

硬體的歷史就是「開關越做越小」的歷史:真空管(拇指大)→ 電晶體(米粒大)→ 積體電路(一片晶片上很多個)→ VLSI(一片晶片上幾十億個)。開關越小,就能放越多、跑越快、越省電,電腦也就從一整個房間縮到你的口袋裡。

摩爾定律是這股趨勢的量化說法:每兩年電晶體數翻倍。翻倍很可怕——20 年就是 $2^{10} \approx 1000$ 倍。

後面會用到
  • 計算機組織:為什麼 CPU 有快取(cache)、為什麼改成多核心,都要從「電晶體越來越多但時脈上不去」說起(第 5 章)。
  • 數位邏輯:電晶體如何組成邏輯閘(第 4 章)。
  • 演算法:指數成長的直覺——$2^{n}$ 長得多快——在分析演算法時一直出現(第 18 章)。
現代補充

摩爾定律在 2010 年代後明顯放慢:電晶體已經小到只有幾十個原子寬,再縮小很困難,而且時脈大約從 2005 年就停在幾 GHz(功耗與散熱的限制)。業界的回應是多核心、GPU(大量簡單核心做平行運算,也是今天 AI 訓練的主力)以及專用晶片(例如 AI 加速器)。

原理為什麼成立

為什麼翻倍模型用 $2^{(t-t_0)/2}$? 每過 2 年乘以 2,過了 $t - t_0$ 年就乘了 $(t - t_0)/2$ 次 2。取對數可以把指數成長變成直線:

$$\log_2 N(t) = \log_2 N_0 + \frac{t - t_0}{2}$$

所以在半對數座標(y 軸取 log)上畫實際晶片的電晶體數,若大致落在一條斜率 1/2 的直線上,就符合摩爾定律。反過來,用兩個資料點就能估計「實際的加倍週期」:

$$T = \frac{t_1 - t_0}{\log_2(N_1 / N_0)}$$

② 老師講解
例 1

Using the model $N(t) = 2300 \cdot 2^{(t-1971)/2}$ (the Intel 4004 had about 2,300 transistors in 1971), predict the transistor count in 1991, and compare with the Intel 80486 (1989, about 1.2 million transistors).

  1. 1991 − 1971 = 20 年,加倍 20 / 2 = 10 次。
  2. $N(1991) = 2300 \times 2^{10} = 2300 \times 1024 = 2{,}355{,}200$。
  3. 同一個模型預測 1989 年:$2300 \times 2^{9} = 1{,}177{,}600$。
  4. 實際 80486 約 1,200,000,和預測只差不到 2%——在 18 年、9 次加倍之後還這麼準,這就是摩爾定律驚人的地方。
例 2

Assign each machine to a hardware generation using this course's definition: UNIVAC I (1951), IBM 7090 (1959), Apollo Guidance Computer (1966), Intel 4004 (1971), ENIAC (1946).

  1. 先記住四個起始年:1951、1959、1965、1971;邊界年份屬於新的世代,1951 之前算第 0 代(早期)。
  2. UNIVAC I(1951)→ 第 1 代(真空管)。IBM 7090(1959)→ 第 2 代(電晶體化)。
  3. Apollo Guidance Computer(1966)→ 第 3 代(使用積體電路)。Intel 4004(1971)→ 第 4 代(微處理器)。
  4. ENIAC(1946)早於 1951 → 第 0 代(早期電子計算機)。
  5. 提醒:「世代」是用來整理歷史的框架,真實機器的技術常跨世代;考試與 Lab 一律用上面的年份定義。
易錯點
  • 邊界年份算錯:1959 是第 2 代,不是第 1 代。
  • 以為摩爾定律是物理定律:它是經驗觀察,而且近年已經放慢。
  • 把「每兩年加倍」誤算成「每兩年加 2 倍」或「每年加倍」。
教學提示

可以讓學生在半對數座標上畫出 Lab 資料集的 5 顆 CPU,看它們是否大致在一條直線上;這比背年份更有感。

③ 換你練習
  1. 照做

    Name the key switching technology of each of the four hardware generations.

    第 1 代真空管;第 2 代電晶體;第 3 代積體電路;第 4 代 LSI/VLSI(微處理器)。

  2. 是非

    True or false: Moore's law says that CPU clock speed doubles every two years.

    False。摩爾定律講的是晶片上的電晶體數,不是時脈;時脈大約從 2005 年起就沒有大幅提升。

  3. 變化

    Using $N(t) = 2300 \cdot 2^{(t-1971)/2}$, predict the transistor count in 2001.

    2001 − 1971 = 30 年 → 加倍 15 次;$2300 \times 2^{15} = 2300 \times 32768 = 75{,}366{,}400$。

  4. 應用

    A chip had 29,000 transistors in 1978 and one had 42,000,000 in 2000. Estimate the doubling period implied by these two data points.

    $T = (2000 - 1978) / \log_2(42{,}000{,}000 / 29{,}000) = 22 / \log_2(1448.3) \approx 22 / 10.50 \approx 2.10$ 年,和「約兩年」一致。

  5. 挑戰

    If transistor counts double every 2 years, how many years does it take to grow by a factor of 1,000,000? Explain why exponential growth makes long-term predictions fragile.

    $10^6 \approx 2^{19.93}$,需要約 19.93 次加倍 ≈ 39.9 年。指數模型對加倍週期非常敏感:若實際週期是 2.5 年而不是 2 年,同樣 40 年只會成長 $2^{16} \approx 65{,}536$ 倍,差了 15 倍左右。所以長期預測只要參數差一點點,結果就差很多。

C1.4 History of Computing Software｜計算軟體的歷史

Each generation puts another layer between the programmer and the machine · 基礎
① 觀念
💡
Concept

Generations of software (the definition used in this course; a boundary year belongs to the new generation):

Generation Years What appeared
1 1951–1958 programs written in machine language; then assembly language and assemblers that translate it
2 1959–1964 high-level languages (FORTRAN, COBOL, Lisp) and compilers; programmers no longer think in machine instructions
3 1965–1970 systems software: utility programs, loaders, linkers, and operating systems that manage the machine; time-sharing
4 1971–1989 structured programming (C, Pascal); application packages (spreadsheets, word processors, database systems) for non-programmers
5 1990– object-oriented design, the World Wide Web, open source, a huge user base; software everywhere

The long-term trend: each generation adds a layer of software between the user and the hardware. The programmer moves further from the machine, and the user of an application may never write a program at all.

Translators. An assembler translates assembly language into machine code. A compiler translates a high-level language program into machine code (or into assembly first). An interpreter executes a high-level program directly, one statement at a time, without producing a separate machine-code program. Today's C toolchain shows the layers explicitly: preprocess (gcc -E) → compile to assembly (gcc -S) → assemble to an object file (gcc -c) → link to an executable.

名詞對照
English中文說明
machine language機器語言CPU 直接執行的二進位指令
assembly language組合語言用助記符(add、mov)寫機器指令
assembler組譯器把組合語言翻成機器碼
high-level language高階語言接近人類思考的語言,如 C、Python
compiler編譯器把高階語言整個翻成機器碼(或組合語言)
interpreter直譯器一句一句讀、一句一句執行,不產生獨立的執行檔

白話說

最早的程式設計師要直接寫 0 和 1。之後有人想:「用 ADD 代替 0110 吧」,於是有了組合語言和組譯器。再後來:「能不能直接寫 total = total + x?」於是有了高階語言和編譯器。然後又有人寫了作業系統,讓大家不用自己管記憶體和印表機……

每一代都是把前一代的苦工自動化,在程式設計師和機器之間多蓋一層。到今天,多數使用者只用應用程式,根本不寫程式——他們和硬體之間隔了好多層。

後面會用到
  • 系統程式與計算機組織:組譯器、連結器、載入器怎麼運作(本課第 6 章)。
  • 編譯器:高階語言怎麼一步步變成機器碼(第 9 章)。
  • 作業系統:第三代的主角(第 10、11 章)。
現代補充

直譯與編譯的界線今天很模糊:Python 先把原始碼「編譯」成 bytecode(.pyc),再由虛擬機直譯;Java 與 JavaScript 引擎會在執行時把熱門的程式碼 JIT 編譯成機器碼。Lab 任務 2 會讓你同時看到 C 的機器碼與 Python 的 bytecode。

原理為什麼成立

為什麼要分成前處理、編譯、組譯、連結四步? 每一步解決不同的問題:

  1. 前處理:把 #include、#define 展開,讓編譯器只需要面對純粹的 C。
  2. 編譯:把 C 的結構(迴圈、變數、函式)翻成某種 CPU 的組合語言——這一步和 CPU 種類有關。
  3. 組譯:把組合語言一對一翻成機器碼,產生目的檔;此時呼叫 printf 的位址還不知道。
  4. 連結:把自己的目的檔和函式庫(例如 libc 的 printf)接起來,填上真正的位址,產生執行檔。

拆開的好處是分工與重用:改一個 .c 檔只要重新編譯它自己,再重新連結即可;組譯器與連結器可以給很多種語言共用。這正是第三代「系統軟體」的精神。

② 老師講解
例 1

Starting from sum.c, list the four steps of the C toolchain, the command for each, and the kind of file each step produces.

  1. 前處理:gcc -E sum.c -o sum.i → sum.i,仍是 C 原始碼,但 #include <stdio.h> 已被展開成數百行宣告。
  2. 編譯:gcc -S sum.i -o sum.s → sum.s,組合語言文字檔,可以看到 main: 標籤與 call 指令。
  3. 組譯:gcc -c sum.s -o sum.o → sum.o,可重定位的目的檔(file 指令顯示 relocatable),是二進位,但還不能執行。
  4. 連結:gcc sum.o -o sum → 執行檔(file 顯示 executable),printf 等外部函式的位址在這一步接上。
  5. 對照世代:組譯器(第 1 代)、編譯器(第 2 代)、連結器與載入器(第 3 代)全部在這一條管線裡。
例 2

Classify each as a compiler, an interpreter, or an assembler (or a combination), and justify: (a) gcc, (b) python3 running a script, (c) as, (d) a web browser running JavaScript.

  1. (a) gcc:編譯器(其實是整條工具鏈的指揮者,會依序呼叫前處理器、編譯器、as 組譯器與 ld 連結器)。
  2. (b) python3:先把原始碼編譯成 bytecode,再由虛擬機直譯執行 → 編譯 + 直譯的組合;不產生獨立的機器碼執行檔。
  3. (c) as:組譯器,組合語言 → 機器碼(目的檔)。
  4. (d) 瀏覽器的 JavaScript 引擎:一開始直譯,熱門程式碼再 JIT 編譯成機器碼 → 組合。
  5. 重點:判斷依據是「有沒有先把整個程式翻成另一種語言(特別是機器碼)再執行」。
易錯點
  • 以為「編譯 = 直接產生執行檔」:中間其實還有組譯與連結。
  • 以為 Python 完全沒有編譯步驟:有,只是編譯成 bytecode 而不是機器碼。
  • 世代邊界:1959 是第 2 代、1990 是第 5 代。
教學提示

C1.5 Computing as a Tool and a Discipline｜計算作為工具與學科

Who uses computing, who builds it, and the big ideas behind it · 基礎
① 觀念
💡
Concept

Computing is both a tool and a discipline.

As a tool, computers help people in every field solve problems: scientists simulate climate, doctors analyze scans, artists create images and music. Roughly three groups of people interact with computing systems:

  • Application users / specialists: use applications (possibly highly technical ones) to solve problems in their own field.
  • Programmers: build tools and applications for others.
  • Systems designers: build the systems software and hardware that everything else runs on.

As a discipline, computer science is the systematic study of algorithmic processes: their theory, analysis, design, efficiency, implementation, and application. Computing draws on mathematics (theory), science (experiments and models), and engineering (building reliable systems).

The big ideas of computing (as organized in the AP Computer Science Principles framework that this book follows): creative development, abstraction, data and information, algorithms, programming, computer systems and networks (the Internet), and impact of computing on society.

白話說

會開車的人很多,會修車的人少一些,會設計引擎的人更少。電腦也一樣:大部分人是使用者,資工系要把你訓練成能造工具(程式設計師)、甚至造出讓別人造工具的系統(系統設計者)的人。

資訊科學不只是「寫程式」。它問的是:什麼問題可以用步驟解決?怎麼解最快?怎麼證明是對的?怎麼蓋一個不會壞的系統?這些問題橫跨數學、科學與工程。

後面會用到
  • 程式設計、軟體工程:工具鏈(編輯器、編譯器、git、除錯器、測試)是每天的工作環境。
  • 演算法、計算理論:「演算法程序」的理論與分析(第 7、18 章)。
  • 資訊倫理:本課每章結尾的倫理議題,對應「計算的影響」。
現代補充

今天專業的開發工具鏈包括:git(版本控制)、容器(Docker,讓每個人的環境完全一樣——本課的 Lab 就是這樣跑的)、雲端(程式跑在別人的機房)、CI(每次提交自動跑測試),以及 AI 輔助寫程式。AI 可以大幅加快速度,但它會很有自信地寫出錯的程式——你一定要能讀懂、並用測試驗證它的產出。這正是紮實基礎的價值。

原理為什麼成立

為什麼資訊科學同時是數學、科學和工程?

  • 數學:演算法的正確性可以被證明;有些問題被證明「不可能用任何程式解決」(第 18 章的停機問題)。
  • 科學:效能、使用者行為、網路流量常常只能用實驗與模型研究,就像物理學研究自然現象。
  • 工程:真實系統要在有限的預算、時間、可靠度要求下蓋出來,需要設計、取捨與測試。

三者的方法不同:數學重證明,科學重實驗,工程重建造與取捨。一個好的資訊工程師要三種都會用。
