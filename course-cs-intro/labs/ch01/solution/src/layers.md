# 我的程式穿過了哪些層

## Application

使用者在終端機輸入 `echo "1 2 3" | ./build/sum`,期待看到 6。對使用者來說,這就是一個「加總數字」的工具,
他不需要知道底下有編譯器、作業系統或 CPU,這就是應用層看到的全部。

## High-level language

在 C 裡,整個工作只有一行迴圈:

`while (scanf("%lld", &x) == 1) total += x;`

這一行用變數、迴圈、函式呼叫描述「讀到沒有數字為止,一直加」,完全不用管暫存器或記憶體位址。
Python 版更短,連型別都不用寫;兩者都要經過翻譯才能在 CPU 上跑。

## Assembly

`gcc -S` 把 C 翻成組合語言。在 `build/sum.s` 裡可以找到函式的起點:

`main:`

後面接著的是 `mov`、`add`、`call` 這類指令,每一行幾乎對應一條機器指令;
`scanf` 變成一條 call,`total += x` 變成把記憶體裡的值載入暫存器、相加、再存回去。

## Machine code

`objdump -d` 把目的檔反組譯,左邊是真正存在檔案裡的位元組(十六進位),右邊是它代表的指令。
函式的標籤在這裡長成:

`<main>:`

CPU 只看得懂左邊那些位元組;右邊的文字只是給人看的翻譯。

## Operating system

執行 `./build/sum` 時,作業系統(Linux)負責把執行檔載入記憶體、建立行程、
接好標準輸入與輸出;`scanf` 最後會透過 read 系統呼叫請 OS 把鍵盤或管線的資料交給程式,
`printf` 則透過 write 系統呼叫輸出。

## Hardware

最底層是 CPU、記憶體與 I/O 裝置。CPU 依序抓取機器碼、解碼、執行;加法由 ALU 完成,
變數放在記憶體或暫存器裡。所有上面的層,最後都變成這裡的電訊號與位元運算。
