C3.1 Analog and Digital Data｜類比與數位資料

Continuous vs. discrete — and how many bits a set of things needs · 基礎
① 觀念
💡
Concept

Analog data is a continuous representation, analogous to the actual information it represents (a mercury thermometer, a vinyl groove, a voltage that varies smoothly). Digital data is a discrete representation: the information is broken into separate elements.

Computers store data digitally because digital signals can be regenerated. An electronic signal degrades as it travels (signal degradation) and picks up noise. With only two meaningful levels — high voltage for 1 and low voltage for 0 — a receiver can decide which level was meant and send out a fresh, clean pulse (pulse-code modulation). An analog signal cannot be restored this way, because every value between is meaningful.

Binary representations. $n$ bits give $2^n$ distinct patterns. To give a unique pattern to each of $k$ items we need

$$\lceil \log_2 k \rceil \ \text{bits}.$$

Digitizing an analog value means choosing one of $2^n$ levels: a range $[0, V_{\max}]$ split into $2^n$ levels has a step of $V_{\max} / (2^n - 1)$.

English中文說明
analog data類比資料連續變化、和真實量成比例的表示

白話說

類比就像用尺量:任何長度都可能出現。數位就像數顆數:只有 0、1、2……這些值。數位的好處是抗雜訊:訊號被干擾一點點,0 還是看得出是 0,只要重新整形就恢復原狀;類比訊號被干擾了,你永遠不知道原本是多少。

至於「要幾個位元」,就是問 2 的幾次方才夠:表示 5 種東西,2 位元只有 4 種不夠,3 位元有 8 種才夠。

  • 計算機網路:訊號在線路上衰減、中繼器(repeater)負責再生(第 15 章)。
  • 多媒體:C3.7 的聲音取樣就是把類比聲波數位化。
② 老師講解
例 1

How many bits are needed to represent (a) the 7 days of the week, (b) 52 playing cards, (c) 1000 different sensor readings?

  1. 找最小的 $n$ 使 $2^n \ge k$。
  2. (a) $k = 7$:$2^2 = 4$ 不夠,$2^3 = 8$ 夠 → 3 位元(會有 1 個樣子用不到)。
  3. (b) $k = 52$:$2^5 = 32$ 不夠,$2^6 = 64$ 夠 → 6 位元。
  4. (c) $k = 1000$:$2^9 = 512$ 不夠,$2^{10} = 1024$ 夠 → 10 位元。
  5. 注意:位元數只和「有幾種」有關,和這些東西本身的數值大小無關。
例 2

A sensor outputs 0 V to 5 V. It is digitized with 3 bits (levels 0–7, evenly spaced). Which level represents 3.2 V, and what voltage does that level stand for?

  1. 3 位元有 $2^3 = 8$ 個等級,編號 0 到 7;第 0 級是 0 V、第 7 級是 5 V。
  2. 相鄰等級差 $5 / 7 \approx 0.714$ V。
  3. $3.2 / 0.714 \approx 4.48$,四捨五入到 第 4 級(二進位 100)。
  4. 第 4 級代表 $4 \times 5/7 \approx 2.86$ V。原本是 3.2 V,誤差約 0.34 V——這就是量化誤差,位元越多、誤差越小。

C3.2 Representing Negative Values｜負數的表示

Sign-magnitude, one's complement, and two's complement · 進階
① 觀念
💡
Concept

With a fixed number of bits $n$, there are three classic ways to include negative integers:

  • Sign-magnitude: the leftmost bit is the sign (0 = +, 1 = −), the other $n-1$ bits are the magnitude. Range $-(2^{n-1}-1) \dots 2^{n-1}-1$. It has two zeros (+0 and −0), and addition needs special cases.
  • One's complement: a negative number is formed by flipping every bit of its positive counterpart. Same range as sign-magnitude, and it also has two zeros.
  • Two's complement: a negative number $-I$ is stored as $2^n - I$. Equivalently: flip all the bits and add 1. Range $-2^{n-1} \dots 2^{n-1}-1$ (one more negative value), only one zero, and ordinary binary addition works for signed numbers — just discard the carry out of the leftmost bit.

The book introduces the idea with ten's complement in decimal: with $k$ digits, $-I$ is represented by $10^k - I$ (for $k = 2$, $-3$ is stored as $97$, and $5 + 97 = 102$ → drop the carry → $02$). Two's complement is the same idea in base 2, and it is what every modern CPU uses.

Sign extension: to widen a two's complement number from $n$ bits to $m > n$ bits, copy the sign bit into the new high-order positions (1011 in 4 bits = −5 becomes 11111011 in 8 bits).

English中文說明
sign-magnitude符號大小表示法最高位當符號,其餘是絕對值
one's complement一補數負數 = 正數逐位元反轉

白話說

想像一個只有兩位數的里程表:從 00 倒退一格是 99。所以「99」可以當成 −1、「98」當 −2……這就是十補數。二補數完全一樣,只是在二進位:8 位元時,11111111 是 −1,10000000 是 −128。

二補數的好處是加法器不用知道數字是正是負:照一般二進位加法做,丟掉最左邊溢出的進位,答案自動就對。這讓 CPU 只需要一個加法器,減法就是「加上負數」。

後面會用到
  • 計算機組織:ALU 的加減法、旗標(N、Z、V、C)全部建立在二補數上(第 4 章的 ALU)。
  • 程式設計:C 的 int8_t、int32_t 都是二補數;(int8_t)200 為什麼是 −56。
  • 資訊安全:有號/無號混用造成的漏洞(例如長度檢查被負數繞過)。
② 老師講解
例 1

Represent $-37$ in 8 bits using sign-magnitude, one's complement, and two's complement.

  1. 先寫 $+37$:$37 = 32 + 4 + 1$ → 00100101。
  2. 符號大小:符號位改成 1,其餘不變 → 10100101。
  3. 一補數:全部反轉 → 11011010。
  4. 二補數:一補數再加 1 → 11011011。
  5. 驗算二補數:$2^8 - 37 = 219 = 128 + 64 + 16 + 8 + 2 + 1$ → 11011011 ✓。
例 2

Compute $5 + (-3)$ and $-4 + (-2)$ using 4-bit two's complement, and convert 1010 to decimal.

  1. $5$ = 0101;$-3$:0011 反轉 1100 加 1 → 1101。
  2. 0101 + 1101 = 10010,丟掉第 5 位的進位 → 0010 = 2 ✓。
  3. $-4$ = 1100,$-2$ = 1110。1100 + 1110 = 11010 → 丟掉進位 → 1010。
  4. 1010 的值:最高位是 1 → 負數。反轉加一 0101 + 1 = 0110 = 6,所以 1010 = −6 ✓。
  5. 另一種讀法:最高位的權重當成 $-2^{n-1}$:$-8 + 2 = -6$。

C3.3 Overflow｜溢位

When the true result does not fit in n bits · 進階
① 觀念
💡
Concept

Overflow occurs when the value we compute cannot fit into the number of bits we have allocated for the result.

  • For unsigned addition, overflow shows up as a carry out of the leftmost bit: in 8 bits, $200 + 100 = 300 > 255$, and the stored result is $300 - 256 = 44$.
  • For two's complement (signed) addition, the carry out is not the test. Overflow happens exactly when two numbers of the same sign produce a result of the opposite sign: positive + positive → negative, or negative + negative → positive. Adding numbers of opposite signs can never overflow.

When overflow happens in fixed-width hardware, the result wraps around modulo $2^n$: in 8-bit two's complement, $127 + 1$ becomes $-128$.

名詞對照
English中文說明
overflow溢位正確結果超出 n 位元的表示範圍
carry out最高位進位最左邊一位相加後產生的進位
wrap around繞回超出範圍後從另一端重新開始(模 $2^n$)
undefined behavior (UB)未定義行為C 標準沒有規定結果,編譯器可以任意處理
overflow flag (V)溢位旗標CPU 記錄有號加法是否溢位的位元
白話說

里程表是 999999 時再開 1 公里,會變成 000000——這就是繞回。對無號數來說,「有進位跑出去」就是溢位。

有號數比較狡猾:$-1 + 1$(11111111 + 00000001)也會有進位跑出去,但答案 0 是對的。真正的判斷是「兩個正數加起來變負數」或「兩個負數加起來變正數」——結果的符號不合理,才是溢位。

後面會用到
  • 計算機組織:CPU 有兩個旗標:C(進位,給無號數看)與 V(溢位,給有號數看);第 4 章的 ALU 要算出這兩個旗標。
  • 程式設計:C 的有號整數溢位是未定義行為(編譯器可能據此把你的 if 優化掉),無號整數則保證繞回。
  • 資訊安全:整數溢位造成配置的緩衝區太小,是經典漏洞(第 17、18 章)。
現代補充
  • 編譯時加 -fsanitize=undefined,有號溢位會在執行時被抓到(本課 Lab 預設就開)。
  • GCC/Clang 提供 __builtin_add_overflow(a, b, &r),C23 標準化為 ckd_add,可以安全地檢查。
  • Rust 在除錯模式下溢位直接中止程式;Python 的整數沒有位數上限,所以不會溢位(但 NumPy 的陣列會)。
② 老師講解
例 1

In 8-bit two's complement, compute $100 + 50$ and $-100 + (-50)$. Do they overflow? What values are stored?

  1. 範圍是 $-128$ 到 $127$。
  2. $100 + 50 = 150 > 127$ → 溢位。位元:01100100 + 00110010 = 10010110,最高位是 1,被讀成 $150 - 256 = -106$。兩正得負,符合判斷規則。
  3. $-100 + (-50) = -150 < -128$ → 溢位。10011100 + 11001110 = 1 01101010,丟掉進位得 01101010 = 106。兩負得正。
  4. 結論:硬體照樣算出一個位元樣子,但它的意義錯了;程式必須自己檢查(或靠 V 旗標)。
例 2

For each 8-bit addition, decide whether (a) unsigned overflow (carry out) and (b) signed overflow occur: 11111111 + 00000001, 01111111 + 00000001.

  1. 11111111 + 00000001 = 1 00000000:最高位有進位出去 → 無號溢位(255 + 1 = 256 > 255)。
  2. 有號解讀:$-1 + 1 = 0$,結果正確 → 沒有有號溢位(一負一正相加不可能溢位)。
  3. 01111111 + 00000001 = 10000000:沒有進位出去 → 沒有無號溢位(127 + 1 = 128 ≤ 255)。
  4. 有號解讀:$127 + 1$ 得到 −128,兩正得負 → 有號溢位。
  5. 同一組位元,無號與有號的溢位判斷完全不同——這就是 CPU 需要 C、V 兩個旗標的原因。

C3.4 Representing Real Numbers｜實數的表示(浮點數)

Sign, exponent, and fraction — IEEE 754 single precision · 挑戰
① 觀念
💡
Concept

A real number has a whole part and a fractional part separated by a radix point. Computers store reals in floating-point form, like scientific notation: $\text{sign} \times \text{mantissa} \times \text{base}^{\text{exponent}}$. In binary, every nonzero number can be normalized to $\pm 1.xxxx_2 \times 2^{e}$.

IEEE 754 single precision (32 bits, C float) has three fields:

Field Bits Meaning
sign $s$ 1 0 = positive, 1 = negative
exponent $E$ 8 stored with a bias of 127: actual exponent $e = E - 127$
fraction $F$ 23 the bits after the radix point; the leading 1 is implicit (hidden bit)

Value of a normal number ($1 \le E \le 254$): $(-1)^s \times 1.F_2 \times 2^{E - 127}$.

Special cases:

$E$ $F$ Meaning
0 0 $\pm 0$ (there are two zeros)
0 ≠ 0 denormal (subnormal): $(-1)^s \times 0.F_2 \times 2^{-126}$ — tiny numbers near 0
255 0 $\pm\infty$
255 ≠ 0 NaN (not a number), e.g. $0/0$

Double precision (64 bits, C double) uses 1 + 11 + 52 bits with bias 1023.

Because only 23 fraction bits are stored, most decimal fractions (such as 0.1) are rounded to the nearest representable value, and results like 0.1 + 0.2 == 0.3 can be false.

English中文說明
floating point浮點數小數點位置由指數決定的實數表示

白話說

浮點數就是二進位的科學記號:$-6.25 = -1.1001_2 \times 2^2$。IEEE 754 把它拆成三格存:符號(1 位)、指數(8 位,存成 $2 + 127 = 129$)、小數點後的位元(23 位,前面那個 1 不用存,因為正規化後一定是 1)。

指數要加 127 才存,是為了讓指數欄是無號數,比大小比較方便。全 0 與全 1 的指數被保留下來表示特殊值:零、非常小的數、無限大、NaN。

後面會用到
  • 計算機組織:浮點運算單元(FPU)、單精度與倍精度的效能差異。
  • 數值方法、機器學習:捨入誤差、累加誤差、為什麼 GPU 訓練模型可以用 16 位元浮點數(第 18 章會做浮點誤差實驗)。
  • 程式設計:永遠不要用 == 比較兩個浮點數,要比較差是否小於某個容許值。
現代補充

AI 加速器大量使用更短的浮點格式:FP16(1 + 5 + 10)、bfloat16(1 + 8 + 7,指數範圍和 float 相同但精度低)、甚至 FP8。原理和本節完全相同,只是欄位寬度不同——學會拆 float,就會拆它們。

② 老師講解
例 1

Encode $-6.25$ in IEEE 754 single precision.

  1. 轉二進位:$6 = 110_2$,$0.25 = 0.01_2$,所以 $6.25 = 110.01_2$。
  2. 正規化:$110.01_2 = 1.1001_2 \times 2^2$。
  3. 三個欄位:符號 $s = 1$(負);指數 $E = 2 + 127 = 129 = 10000001_2$;尾數取小數點後的位元 $1001$,右邊補 0 到 23 位。
  4. 組合:1 10000001 10010000000000000000000。
  5. 寫成十六進位:1100 0000 1100 1000 0000 … → 0xC0C80000。
例 2

Decode the single-precision patterns 0x3F400000 and 0x00000001.

  1. 0x3F400000 = 0 01111110 10000000000000000000000。
  2. 符號 0;$E = 126$ → $e = -1$;尾數 $1.1_2 = 1.5$。值 $= 1.5 \times 2^{-1} = 0.75$。
  3. 0x00000001 = 0 00000000 00000000000000000000001:$E = 0$ 且 $F \ne 0$ → 非正規數。
  4. 值 $= 0.F_2 \times 2^{-126} = 2^{-23} \times 2^{-126} = 2^{-149} \approx 1.4 \times 10^{-45}$——這是 float 能表示的最小正數。

C3.5 Representing Text｜文字的表示

Character sets — ASCII, Unicode, and the UTF-8 encoding · 進階
① 觀念
💡
Concept

To represent text, we list every character we need in a character set and give each one a number (its code point). The text is then stored as a sequence of those numbers.

ASCII uses 7 bits: 128 characters — control characters (0–31, e.g. 10 = newline), the space (32), digits '0'–'9' (48–57), uppercase 'A'–'Z' (65–90), lowercase 'a'–'z' (97–122), and punctuation. Upper- and lowercase letters differ by exactly 32, i.e. by one bit (0x20).

Unicode assigns a code point to every character of every writing system — over 150,000 characters, written U+4E2D (中), U+1F600 (😀). The first 128 code points are the same as ASCII.

A code point must still be turned into bytes; that is the job of an encoding. UTF-8 is the dominant encoding on the Web:

Code point range Bytes Bit pattern
U+0000 – U+007F 1 0xxxxxxx
U+0080 – U+07FF 2 110xxxxx 10xxxxxx
U+0800 – U+FFFF 3 1110xxxx 10xxxxxx 10xxxxxx
U+10000 – U+10FFFF 4 11110xxx 10xxxxxx 10xxxxxx 10xxxxxx

The x bits are the code point's bits, most significant first. Rules: ASCII text is valid UTF-8 unchanged; every continuation byte starts with 10; a character must use the shortest possible form (an overlong encoding such as C0 80 for U+0000 is invalid); code points U+D800–U+DFFF (surrogates) are not allowed.

白話說

「文字」在電腦裡就是一串數字。問題是:誰來規定「中」是幾號?這就是字元集(Unicode 說:U+4E2D)。第二個問題:4E2D 這個數字要存成哪幾個位元組?這就是編碼(UTF-8 說:E4 B8 AD)。

UTF-8 聰明的地方:英文字還是一個位元組、和 ASCII 一模一樣;中文字三個位元組;emoji 四個。而且每個位元組看開頭就知道自己是「字的開頭」還是「字的中間」,就算從中間開始讀也能重新對齊。

後面會用到
  • 程式設計:C 的 strlen 算的是位元組數,不是字數;Python 3 的 str 以碼位為單位。
  • 計算機網路、Web:HTTP 標頭的 charset=utf-8、網頁亂碼的來源(第 16 章)。
  • 資訊安全:接受過長編碼的解碼器曾被用來繞過 ../ 路徑檢查。
現代補充
  • UTF-16(Java、JavaScript、Windows 內部使用)用 2 或 4 個位元組;超過 U+FFFF 的字元(例如 emoji)要用一對 surrogate 表示,這就是 JavaScript 的 "😀".length 是 2 的原因。
  • 一個「看起來的字」(grapheme)可能由好幾個碼位組成:👨‍👩‍👧 是 5 個碼位(三個人 + 兩個 zero-width joiner)。延伸專案 4 會探討。
② 老師講解
例 1

Encode 中 (U+4E2D) in UTF-8.

  1. 判斷長度:U+0800 ≤ 0x4E2D ≤ U+FFFF → 3 個位元組,樣板 1110xxxx 10xxxxxx 10xxxxxx,共 16 個 x。
  2. 寫出 16 位元:0x4E2D = 0100 1110 0010 1101。
  3. 從高位依序填入:前 4 位 0100 → 11100100 = E4;接著 6 位 111000 → 10111000 = B8;最後 6 位 101101 → 10101101 = AD。
  4. 結果 E4 B8 AD。用 Python 驗證:"中".encode("utf-8").hex() → e4b8ad。
例 2

Decode the bytes F0 9F 98 80, and explain why C0 80 is rejected.

  1. F0 = 11110000 → 4 位元組字元,取出 000。
  2. 三個延續位元組 9F = 10011111 → 011111;98 = 10011000 → 011000;80 = 10000000 → 000000。
  3. 串起來:000 011111 011000 000000 = 0 0001 1111 0110 0000 0000 = 0x1F600 → 😀。
  4. C0 80:110 00000 + 10 000000 算出來是 U+0000,但 U+0000 只需要 1 個位元組(00)。用 2 個位元組是過長編碼,依規定必須拒絕。

C3.6 Text Compression｜文字壓縮

Keyword encoding, run-length encoding, and Huffman codes · 挑戰
① 觀念
💡
Concept

Data compression reduces the amount of space needed to store a piece of data. The compression ratio is the size of the compressed data divided by the size of the original (smaller is better; 0.6 means 40% saved).

  • Lossless compression can recover the original exactly (needed for text and programs).
  • Lossy compression throws away some information that people are unlikely to notice (used for audio, images, video).

Three lossless techniques for text:

  1. Keyword encoding: replace frequently used words with single characters that do not otherwise appear (for example the → ~, and → +).
  2. Run-length encoding (RLE): replace a long run of a repeated character by a flag, the character, and the count. This course's rule: a run of 4–9 identical characters becomes * + the character + the count digit (AAAAAAA → *A7); longer runs are split into pieces of 9; runs shorter than 4 are left alone, because the code itself costs 3 characters.
  3. Huffman encoding: give shorter bit strings to more frequent characters. Build the code by repeatedly merging the two least frequent nodes into a tree; the path from the root (0 = left, 1 = right) is each character's code. Huffman codes are prefix codes: no code is a prefix of another, so a bit stream can be decoded without separators.

白話說

壓縮的本質是找出重複與偏頗。重複的整個字(keyword)、連續重複的字元(RLE)、某些字元特別常見(Huffman)——各抓一種。

Huffman 的直覺像摩斯電碼:最常用的字母 E 只有一個點。越常出現的字,碼越短,整體平均就短。建樹的方法很機械:每次把最不常見的兩個合成一組,直到剩一棵樹。

後面會用到

  • 資料結構:二元樹的走訪、位元層級的輸入輸出。
  • 多媒體與網路:ZIP、gzip、PNG 用 DEFLATE(LZ77 + Huffman);JPEG 與 MP3 最後一步也是 Huffman(延伸專案 1 會做 LZ77)。

例 1

Build a Huffman code for the text AAAAABBCD (A:5, B:2, C:1, D:1), and compute the encoded length. Compare with a fixed-length code.

  1. 合併最小的兩個:C(1) + D(1) → 2。剩 A5、B2、[CD]2。
  2. 再合併最小的兩個:B(2) + CD → 4。剩 A5、[B CD]4。
  3. 最後合併:A(5) + 4 → 9(根)。
  4. 讀碼(左 0 右 1):A = 0、B = 10、C = 110、D = 111。
  5. 總長:$5 \cdot 1 + 2 \cdot 2 + 1 \cdot 3 + 1 \cdot 3 = 15$ 位元。用合併公式驗算:$2 + 4 + 9 = 15$ ✓。
  6. 固定長度:4 種字元要 2 位元,$9 \times 2 = 18$ 位元。Huffman 省了 3 位元(壓縮比 $15/18 \approx 0.83$)。
例 2

Apply this course's RLE to AAAAAAAAAAAABBBCDDDDD and compute the compression ratio.

  1. 12 個 A:超過 9,切成 9 + 3。9 個 → *A9;剩 3 個少於 4,照原樣 AAA。
  2. 3 個 B:少於 4 → BBB。1 個 C → C。
  3. 5 個 D → *D5。
  4. 結果 *A9AAABBBC*D5,長度 13;原文長度 21。
  5. 壓縮比 $13 / 21 \approx 0.62$。

C3.7 Representing Audio｜聲音的表示

Sampling rate, bit depth, Nyquist, and MP3 · 進階
① 觀念
💡
Concept

Sound is a continuous pressure wave. To store it digitally we sample it: measure its amplitude at regular intervals. Two numbers describe the result:

  • Sampling rate: samples per second (Hz). Audio CDs use 44,100 samples per second.
  • Bit depth (quantization): how many bits each sample uses. CDs use 16 bits, i.e. 65,536 levels.

The Nyquist–Shannon sampling theorem says that to capture frequencies up to $f_{\max}$ we must sample at a rate of more than $2 f_{\max}$. Humans hear up to about 20 kHz, which is why 44.1 kHz was chosen. A frequency above half the sampling rate is not lost silently — it shows up as a false lower frequency (aliasing): sampled at rate $r$, a tone of frequency $f$ is heard as the distance from $f$ to the nearest multiple of $r$.

The uncompressed (PCM) data size is

$$\text{bytes} = \text{rate} \times \frac{\text{bit depth}}{8} \times \text{channels} \times \text{seconds}.$$

Quantization noise: rounding each sample adds error. For an $n$-bit quantizer and a full-scale sine wave, the signal-to-noise ratio is about $6.02n + 1.76$ dB — each extra bit adds about 6 dB.

Audio formats: WAV stores PCM samples (with a small header); MP3 is lossy: it uses a psychoacoustic model to discard sounds humans cannot hear (too high, too quiet, or masked by louder sounds nearby) and then applies Huffman coding, reaching about 10:1 compression.

白話說

數位錄音就是「每秒拍 44,100 張照片,記下那一瞬間的音量」。拍得太慢,快速變化的聲音(高頻)就抓不到,甚至會被誤認成另一個較低的音——就像電影裡車輪看起來倒轉。

每張「照片」用幾個位元記錄音量,決定了細緻程度:8 位元只有 256 級,聽得出沙沙的雜音;16 位元有 65,536 級,人耳已經聽不出差別。

  • 計算機網路:串流的位元率決定頻寬需求(第 15 章)。
  • 演算法:MP3 的最後一步是 Huffman(C3.6)。

How many bytes does one minute of CD-quality stereo audio take uncompressed? What bit rate is that, and roughly how big is a 128 kbps MP3 of the same minute?

  2. 每秒:$44100 \times 2 \times 2 = 176{,}400$ 位元組。

  4. 位元率:$176400 \times 8 = 1{,}411{,}200$ bps ≈ 1411 kbps。

C3.8 Representing Images and Graphics｜影像與圖形的表示

RGB, color depth, raster vs. vector, and image formats · 進階
① 觀念
💡
Concept

Color is represented with the RGB model: each color is a mix of red, green, and blue intensities. The number of bits per pixel is the color depth: true color uses 24 bits (8 per channel, $2^{24} \approx 16.7$ million colors), sometimes 32 bits with an extra alpha (transparency) channel. Indexed color stores a small palette (for example 256 colors) and gives each pixel just an index into it, saving space at the cost of fewer colors.

A raster (bitmap) image is a grid of pixels; its resolution is the number of pixels. Uncompressed size:

$$\text{bytes} = \text{width} \times \text{height} \times \frac{\text{bits per pixel}}{8}.$$

A vector graphic instead describes shapes (lines, rectangles, curves) with their positions and colors. It scales to any size without becoming blocky and is usually small for drawings, but it is poor for photographs.

Common formats:

Format Kind Compression Typical use
BMP raster none (usually) simple, easy to read and write
GIF raster, indexed (≤ 256 colors) lossless (LZW) simple graphics, animation
PNG raster lossless (DEFLATE) screenshots, graphics, transparency
JPEG raster lossy (discards detail the eye barely sees) photographs
SVG vector text (can be gzipped) icons, diagrams, fonts

A 24-bit BMP stores rows bottom-up, pixels as B, G, R, and pads each row to a multiple of 4 bytes.

C3.9 Representing Video｜影片的表示

Codecs, temporal and spatial compression · 進階
① 觀念
💡
Concept

A video is a sequence of images (frames) shown quickly, typically 24–60 frames per second (fps). Uncompressed video is enormous:

$$\text{bytes per second} = \text{width} \times \text{height} \times \frac{\text{bits per pixel}}{8} \times \text{fps}.$$

A video codec (COmpressor/DECompressor) shrinks it with two kinds of compression:

  • Temporal compression exploits similarity between consecutive frames. A key frame is stored in full; the following frames store only the differences (deltas) from the previous frame. Key frames are repeated regularly so that playback can start or jump anywhere.
  • Spatial compression exploits redundancy within one frame, like image compression (large areas of similar color, detail the eye barely notices).

Most codecs are lossy (H.264/AVC, H.265/HEVC, AV1).

spatial compression空間壓縮利用同一影格內的相似

白話說

連續兩格影像通常幾乎一樣:主播在說話,背景完全沒動。所以只要記「哪些像素變了、變成什麼」。但如果每一格都只存差異,想從影片中間開始看,就得從頭一路算上來——所以每隔一段就放一張完整的關鍵影格。

關鍵影格越密,跳轉越快、但檔案越大;越疏,檔案越小、但跳轉慢,而且一出錯會影響後面很多格。這是一個取捨。

現代 codec 的差異影格不只是「像素變了」,還會找出「這一塊是從上一格的哪裡移動過來的」(motion vector),只存移動量與殘差。AV1 是由多家公司開發、免授權金的 codec,YouTube 與 Netflix 大量使用。

  1. 關鍵影格:$100 \times 100 = 10{,}000$ 位元組。
  2. 差異影格:改變 $5\% \times 10000 = 500$ 個像素,每個 3 位元組 → $1{,}500$ 位元組。
  3. 每 10 格:1 張關鍵影格 + 9 張差異影格 = $10000 + 9 \times 1500 = 23{,}500$ 位元組。
  4. 平均每格 $2{,}350$ 位元組,壓縮比 $2350 / 10000 = 0.235$。

C3.10 Byte Order (Endianness)｜位元組順序

Which byte of a multi-byte value comes first in memory · 進階 補充

補充內容:課堂不一定會教,有興趣可以自己讀、自己練。

① 觀念
💡
Concept

A value wider than one byte (for example a 32-bit integer) occupies several consecutive memory addresses. Byte order (endianness) is the rule for which byte goes where:

  • Big-endian: the most significant byte is stored at the lowest address. 0x12345678 is stored as 12 34 56 78.
  • Little-endian: the least significant byte is stored at the lowest address. 0x12345678 is stored as 78 56 34 12.

x86 and (in practice) ARM CPUs are little-endian. Internet protocols use big-endian, called network byte order. File formats choose one and document it: BMP and WAV headers are little-endian; PNG is big-endian. Code that reads a binary file must assemble multi-byte fields in the file's byte order, not the CPU's.

白話說

寫「一千二百三十四」,我們先寫千位(1234)——這就像大端序。小端序則是先寫個位、倒著寫(4321)。兩種都行,只要讀寫雙方講好。

麻煩出在「沒講好」:你在 x86(小端)上把一個整數直接寫進檔案,拿到大端機器上讀就會變成完全不同的數。所以讀二進位檔一定要照檔案規定的順序一個位元組一個位元組組起來。

② 老師講解
例 1

Show how 0x0A0B0C0D is laid out at addresses 100–103 on a big-endian and on a little-endian machine.

  1. 最高位位元組是 0A,最低位是 0D。
  2. 大端序:位址 100 放最高位 → 100: 0A、101: 0B、102: 0C、103: 0D。
  3. 小端序:位址 100 放最低位 → 100: 0D、101: 0C、102: 0B、103: 0A。
  4. 口訣:小端序「小的(低位)在小位址」。
例 2

The first bytes of a BMP file are 42 4D 36 00 0C 00 …. Bytes 2–5 are the file size as a little-endian 32-bit integer. What is the file size?

  1. 取第 2–5 個位元組:36 00 0C 00。
  2. 小端序:第一個是最低位。值 $= \text{0x36} + \text{0x00} \cdot 2^8 + \text{0x0C} \cdot 2^{16} + \text{0x00} \cdot 2^{24}$。
  3. $= 54 + 12 \times 65536 = 786{,}486$ 位元組。
  4. 合理性檢查:$786486 - 54 = 786432 = 512 \times 512 \times 3$,正好是一張 512 × 512 全彩影像加上 54 位元組的檔頭。
